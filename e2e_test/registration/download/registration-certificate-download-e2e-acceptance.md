# 注册证完整下载 E2E 验收流程

## Scope

本文档用于指导 Codex 在本机 `int_main` 环境，通过 Playwright 操作真实前端页面，验证注册证文件下载的完整闭环：

- 注册部经理可以直接下载注册证文件。
- 普通用户不能直接下载，只能申请下载。
- 普通用户提交申请后，按钮变为“申请中”。
- 注册部经理审批通过后，普通用户才能下载。
- 审批通过后的下载授权有效期为 24 小时；超过 24 小时后授权失效，需要普通用户再次申请下载权限。
- 下载产物必须真实保存到本地，并校验文件名符合业务规则。

不覆盖网络中断、审批驳回、文件损坏、重复申请撤回等异常分支。

## Fixed Test Context

- 环境：本机 `int_main`。
- 前端入口：`http://127.0.0.1:8081` 或 `http://localhost:8081`。
- 后端健康检查：`http://127.0.0.1:48081/actuator/health`。
- 租户：芋道源码。
- 注册部经理 B：`chudongchuan`。密码 Abcd1234!
- 普通用户 C：`wanglixuan`。 密码 111111
- 登录密码：由本轮用户提供；执行脚本时通过安全环境变量、本地临时输入或 Playwright secret fixture 注入，不写入仓库文档、日志、截图说明或提交信息。
- 下载保存目录：`E:\IntRuoyi\output\e2e\registration-download\YYYYMMDD-HHMMSS\`。
- 下载授权有效期：注册部经理审批通过后 24 小时内有效；超过 24 小时后必须失效。
- 测试数据标识：申请理由、审批意见、下载目录和证据文件名必须包含本次任务唯一标识，例如 `E2E-DOWNLOAD-YYYYMMDD-HHMMSS`。

## Required Preflight

1. 确认前端 `8081` 可访问，后端 `48081` health 为 `UP`。
2. 用真实登录页确认租户为“芋道源码”。
3. 确认注册部经理 B `chudongchuan` 能登录，并拥有注册证详情查看、注册证文件直接下载、审批中心待办处理权限。
4. 确认普通用户 C `wanglixuan` 能登录，并能进入注册证页签和注册证详情页。
5. 确认普通用户 C 未获得目标文件的直接下载授权；未获授权前详情页不应出现“下载”按钮。
6. 确认普通用户 C 能看到“申请下载”按钮。
7. 确认下载申请的审批候选包含注册部经理 B，且 B 能在审批中心处理该申请。
8. 确认至少存在一条可用于普通用户申请下载的目标注册证：有注册证文件、普通用户可查看详情、当前未处于“申请中”、未已有有效下载授权。
9. 确认至少存在一条带项目代码的目标注册证，用于验证基础文件名中的项目代码；若目标注册证没有项目代码，E2E 不得判定为失败，文件名前缀按空字符串处理。
10. 若要验证“仅下载变更文件”，确认目标注册证存在变更文件，且可以只对变更文件发起申请/授权/下载。
11. 若要验证“失效证件”，确认目标注册证处于失效状态，或本次 E2E 先通过正式页面创建/审批出一条可失效的任务自有注册证，再通过正式页面进入失效状态。
12. 若要验证“超过 24 小时授权失效”，优先使用系统正式时间推进能力或任务自有历史授权样本；不得通过 SQL 直接篡改授权时间冒充真实过期。
13. 若上述任一前置条件不满足，E2E 结论记为 `BLOCKED`，不得用 API-only、SQL 直改状态、管理员越权下载或切换账号替代真实页面路径。

## Filename Rules

下载完成后必须读取 Playwright download suggested filename，并保存真实文件。文件名按以下规则校验：

1. 基础格式：`项目代码_注册证批准日期_产品名称_注册证号 + 原扩展名`；若项目代码为空，则省略 `项目代码_` 前缀，不能报错。
2. `注册证批准日期` 指注册证版本上的批准日期，按 `yyyyMMdd` 格式化；若上传注册证版本没有批准日期，则使用首次获证日期。
3. 若仅下载变更文件，则在产品名称后追加 `变更文件` 字样：`项目代码_注册证批准日期_产品名称_变更文件_注册证号 + 原扩展名`；项目代码为空时同样省略前缀。
4. 若下载失效证件，则在文件名最后、扩展名前追加 `已失效` 字样：`项目代码_注册证批准日期_产品名称_注册证号_已失效 + 原扩展名`；项目代码为空时同样省略前缀。
5. 若“仅下载变更文件”和“失效证件”同时满足，则文件名应同时包含 `变更文件` 和 `已失效`：`项目代码_注册证批准日期_产品名称_变更文件_注册证号_已失效 + 原扩展名`；项目代码为空时同样省略前缀。
6. 文件名不得使用上传时的随机临时文件名、后端存储对象名、纯数字 ID、UUID 或浏览器默认 `download` 名称。
7. 文件名中的项目代码、产品名称、注册证批准日期、注册证号必须来自目标注册证详情页或审批摘要中的正式业务字段，不得由 E2E 脚本自行伪造；项目代码不存在时按空字符串校验。

## Test Data

建议每次执行准备三类目标数据。若当前环境已有满足条件的数据，可以只读复用；若没有，应通过注册证上传/变更/失效的正式页面链路创建任务自有数据。

### 数据 A：当前有效注册证完整文件

- 用途：验证注册部经理直接下载、普通用户申请审批后下载、基础文件名规则。
- 必须有：产品名称、注册证号、注册证文件；项目代码可以为空。
- 普通用户初始状态：可查看详情，但无直接下载授权。

### 数据 B：当前有效注册证变更文件

- 用途：验证仅下载变更文件时，文件名在产品名称后追加 `变更文件`。
- 必须有：产品名称、注册证号、变更文件；项目代码可以为空。
- 普通用户初始状态：可查看详情，但无该变更文件直接下载授权。

### 数据 C：失效注册证文件

- 用途：验证失效证件下载时，文件名最后追加 `已失效`。
- 必须有：产品名称、注册证号、注册证文件，且证件状态为失效；项目代码可以为空。
- 普通用户初始状态：可查看详情，但无直接下载授权。

- 注册部经理 B 不需要先点击“申请下载”。
- 点击“下载”后浏览器产生真实下载事件。
- 保存到本地的文件存在，文件大小大于 0。
- 下载文件名符合基础格式：`项目代码_注册证批准日期_产品名称_注册证号 + 原扩展名`；项目代码为空时省略前缀。

### Evidence

## E2E-6 超过 24 小时后下载授权失效并需要重新申请

### Operation

1. 准备一条普通用户 C 已获批、但审批通过时间距当前已超过 24 小时的目标下载授权。
2. 使用普通用户 C `wanglixuan` 登录“芋道源码”租户。
3. 进入“注册证管理 / 注册证”页签。
4. 打开该授权对应的注册证详情页。
5. 定位授权对应的附件区域。
6. 检查按钮状态。
7. 尝试点击可见的下载或申请入口。

### Expected Result

- 超过 24 小时后，普通用户 C 不应继续拥有该文件的直接下载能力。
- 详情页不应继续展示可直接使用的“下载”按钮。
- 页面应重新展示“申请下载”按钮，或在点击下载时明确提示授权已过期并引导重新申请。
- 普通用户 C 需要再次点击“申请下载”并重新走注册部经理审批后，才能再次下载。
- 过期判断应基于审批通过时间和系统授权有效期，不应依赖前端本地缓存。

### Evidence

- 记录原下载授权 requestId、审批通过时间、授权截止时间和当前验证时间。
- 保存过期后详情页附件区域截图。
- 记录“下载”按钮不可用或不可见，“申请下载”按钮重新可见。
- 如点击下载触发过期提示，保存提示截图并记录自然触发请求 URL、HTTP 状态和业务码。
- 只读核验授权记录已过期或不再被有效授权查询命中。

## Required Assertions

真实 E2E 脚本必须至少断言：

- 注册部经理 B 详情页“下载”按钮可见。
- 注册部经理 B 点击下载后产生 Playwright download 事件。
- 普通用户 C 未授权前“下载”按钮不可见。
- 普通用户 C 未授权前“申请下载”按钮可见。
- 普通用户 C 点击申请后出现“已申请下载”提示。
- 普通用户 C 点击申请后按钮变为“申请中”。
- 注册部经理 B 待办中能看到并处理该下载申请。
- 审批通过后普通用户 C 能看到“下载”按钮。
- 普通用户 C 获批后点击下载产生 Playwright download 事件。
- 审批通过 24 小时内普通用户 C 可下载。
- 审批通过超过 24 小时后普通用户 C 不可继续直接下载，需要重新申请。
- 下载文件真实存在且大小大于 0。
- 下载文件名包含正确的注册证批准日期、产品名称、注册证号；有项目代码时包含项目代码，没有项目代码时使用空字符串前缀且不得报错。
- 变更文件名包含 `变更文件`。
- 失效证件文件名包含 `已失效`。
- 页面 `pageErrors` 为空。
- 关键业务接口失败响应为空。

## Readonly Verification

Playwright 完成真实页面动作后，可以使用只读 API 或只读 DB 辅助核验：

- 下载申请记录存在，申请人为普通用户 C。
- 审批处理人为注册部经理 B。
- 下载授权记录存在且处于有效状态。
- 授权目标文件 ID 与页面点击的文件 ID 一致。
- 下载记录或响应头中的文件名与 Playwright suggested filename 一致。

只读核验不得替代页面点击、审批处理或真实下载动作。

## Failure Rules

出现以下情况时，E2E 结论必须记为 `FAIL` 或 `BLOCKED`：

- 普通用户未授权前可以看到或点击“下载”。
- 普通用户看不到“申请下载”。
- 点击申请下载后按钮没有变为“申请中”。
- 下载申请提交后提示“没有该操作权限”。
- 下载申请提交后提示“缺少项目代码”。
- 注册部经理待办中找不到普通用户的下载申请。
- 注册部经理无法审批通过。
- 审批通过后普通用户仍不能下载。
- 审批通过超过 24 小时后普通用户仍可直接下载。
- 审批通过超过 24 小时后页面没有重新提供申请下载入口，也没有明确授权过期提示。
- 浏览器没有产生真实 download 事件。
- 下载文件不存在或大小为 0。
- 有项目代码的目标文件名缺少项目代码，或文件名缺少注册证批准日期、产品名称、注册证号；没有项目代码时不应因为缺少项目前缀失败。
- 变更文件下载后文件名没有 `变更文件`。
- 失效证件下载后文件名没有 `已失效`。
- 页面报错、接口失败、console error 影响目标流程。
- 当前环境缺少可执行目标数据，且无法通过正式页面创建任务自有数据。

## Evidence Package

每次执行完成后，应在任务目录保存：

- `result.json`：机器可读结果。
- `trace.zip`：Playwright trace。
- `downloads/`：真实下载文件。
- `screenshots/`：关键页面截图。
- `verification-report.md`：人工可读验收报告。

`result.json` 至少包含：

- 环境、租户、执行账号标签。
- 目标注册证 ID、注册证号、项目代码、产品名称、注册证批准日期。
- 目标文件 ID、文件类型、是否变更文件、是否失效证件。
- 申请 requestId。
- 审批 taskId 或 processInstanceId。
- 审批通过日期。
- 授权截止时间。
- 授权过期验证时间。
- 下载 suggested filename。
- 下载保存路径。
- 下载文件大小。
- 文件名分段校验结果。
- 页面错误、console error、失败响应列表。

## Security Notes

- 不得在文档、日志、截图说明、result.json 或提交信息中写入密码、token、cookie、Authorization header、数据库连接密钥。
- Playwright trace 如包含登录请求，应在归档前确认不会暴露敏感字段；无法脱敏时，仅保存必要截图和 result.json，不提交 trace。
- 下载文件属于 E2E 产物，只能保存在本次任务输出目录，不得覆盖仓库中的固定样本文件。
