# 注册证上传正确分支 E2E 验收流程

## Scope

本文档用于指导 Codex 在本机 `int_main` 环境，通过 Playwright 操作真实前端页面，验证“上传注册证”从上传人提交到注册经理审批入库的正确分支闭环。

不覆盖填错、缺字段、权限不足、网络失败等失败分支。

## Fixed Test Context

- 环境：本机 `int_main`。
- 前端入口：`http://127.0.0.1:8081` 或 `http://localhost:8081`。
- 后端健康检查：`http://127.0.0.1:48081/actuator/health`。
- 租户：芋道源码。
- 上传人 A：`wanglixuan`。密码 `111111`。
- 注册经理 B：`chudongqian`。密码 `111111`。
- 普通用户 C：优先使用 `wanglixuan` 执行普通用户下载授权分支，前提是该账号不是注册部经理且没有注册证文件直接下载特权；若该账号已具备直接下载特权，执行前另选同租户内可查看注册证详情但无直接下载特权的普通用户账号，并记录账号名。
- 上传材料：`E:\IntRuoyi\e2e_test\registration\upload\upload_file.pdf`。
- 测试数据标识：注册证编号、产品名称、备注等字段必须包含本次任务唯一标识，例如 `E2E-UPLOAD-YYYYMMDD-HHMMSS`。

## Required Preflight

1. 确认前端 `8081` 可访问，后端 `48081` health 为 `UP`。
2. 确认上传材料文件存在：`E:\IntRuoyi\e2e_test\registration\upload\upload_file.pdf`。
3. 用真实登录页确认租户为“芋道源码”。
4. 确认 `wanglixuan` 已绑定注册证上传权限角色，并能看到“上传注册证”入口。
5. 确认 `chudongqian` 已绑定注册部经理权限角色，并能进入审批中心待办。
6. 确认注册证上传审批候选不为空，候选来源为注册部经理角色及上传审批权限。
7. 确认普通用户 C 能进入注册证详情页，但不具备注册证文件直接下载特权。
8. 确认普通用户下载申请的审批候选不为空，且注册部经理 B 能在审批中心处理该下载申请。
9. 若上述任一项不满足，E2E 结论记为 `BLOCKED`，不得用 API-only、SQL 直改状态或切换账号替代真实页面路径。

## Test Data

每次执行创建一组新的任务自有数据：

- 注册证编号：`E2E-UPLOAD-YYYYMMDD-HHMMSS`。
- 产品名称：`注册证上传E2E产品-YYYYMMDD-HHMMSS`。
- 分类：选择页面中正式可用的注册证分类。
- 所属公司：选择 `wanglixuan` 在芋道源码租户下可用的授权公司。
- 首次获证日期：选择不晚于生效日期的日期。
- 生效日期：选择早于有效期至的日期。
- 有效期至：选择晚于生效日期的日期。
- 生产方式场景一：自行生产=是，委托生产=否。
- 生产方式场景二：自行生产=否，委托生产=是，并选择正式受托企业。
- 下载授权有效期：普通用户下载申请审批通过后的有效期为 3 天，执行时记录具体授权通过时间、有效截止时间和验证时间。

## E2E-1 上传人提交首证上传审批

### Operation

1. 使用上传人 A `wanglixuan` 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”页。
3. 点击“上传注册证”。
4. 在上传弹框中选择所属公司。
5. 填写唯一注册证编号、产品名称、分类。
6. 填写合法日期：首次获证日期 <= 生效日期 < 有效期至。
7. 选择合法生产方式。
8. 若委托生产为是，选择正式受托企业。
9. 上传 `E:\IntRuoyi\e2e_test\registration\upload\upload_file.pdf`。
10. 点击提交。

### Expected Result

- 页面显示注册证上传审批提交成功的中文结果。
- 上传弹框关闭或进入明确提交完成状态。
- 自然触发的上传提交请求返回业务成功。
- 生成一条“注册证上传审批”申请。
- 本步骤不得直接把注册证写入当前注册证正式列表。

### Evidence

- 记录登录身份标签：芋道源码 / `wanglixuan`。
- 记录注册证编号。
- 记录上传提交请求 URL、HTTP 状态、业务码和 requestId。
- 保存提交成功后的页面截图或 trace 步骤截图。

## E2E-2 上传后状态正确

### Operation

1. 仍使用上传人 A `wanglixuan`。
2. 返回“注册证管理 / 注册证”当前列表。
3. 按本次注册证编号查询。
4. 进入审批中心待办。
5. 进入“我发起 / 已提交 / 流程记录”等发起人视角。

### Expected Result

- 审批通过前，当前注册证列表查询不到该注册证。
- `wanglixuan` 的待办中不出现这条“注册证上传审批”。
- `wanglixuan` 的发起人视角能看到该申请处于审批中。
- 该申请标题或业务名称为“注册证上传审批”，不是延续、变更或通用英文码。

### Evidence

- 当前列表查询截图，显示目标注册证未入正式当前列表。
- 上传人待办查询截图，显示无该目标待办。
- 上传人发起记录截图，显示目标申请处理中。
- 记录目标页签、筛选关键词、自然触发分页请求的业务码和 total。

## E2E-3 注册经理待办审批

### Operation

1. 退出上传人 A。
2. 使用注册经理 B `chudongqian` 登录“芋道源码”租户。
3. 进入审批中心待办。
4. 按本次注册证编号筛选。
5. 打开“注册证上传审批”待办详情。
6. 核对摘要和业务详情入口。
7. 点击同意或通过，填写审批意见并提交。

### Expected Result

- 注册经理 B 的待办中出现目标“注册证上传审批”。
- 待办摘要展示注册证编号、分类、产品、所属公司。
- 审批详情中的审核对象体现注册部经理审批语义。
- 业务详情入口能打开或展示注册证上传申请详情。
- 注册经理 B 可处理原指派人为其他用户的上传审批待办。
- 审批提交成功后，该待办从 B 的待办中消失。

### Evidence

- 注册经理待办列表截图。
- 审批详情截图，包含标题、摘要和审核对象。
- 审批通过后的成功状态截图。
- 记录审批提交请求 URL、HTTP 状态、业务码、processInstanceId 或 taskId。

## E2E-4 审批后注册证入库

### Operation

1. 使用注册经理 B 或重新登录上传人 A。
2. 进入“注册证管理 / 注册证”当前列表。
3. 按本次注册证编号查询。
4. 打开该注册证详情。
5. 查看基础信息、注册证附件和操作审计信息。
6. 刷新当前列表并再次按注册证编号查询。

### Expected Result

- 当前列表出现且只出现一条目标注册证。
- 列表字段正确展示注册证编号、所属公司、产品、分类、版本、状态、注册证文件、生效日、有效期至。
- 状态使用中文业务状态；审批通过后的待首次生效首证也必须在当前列表可见。
- 详情基础字段与上传弹框内容一致。
- 详情中可以查看注册证附件，文件来源为本次上传材料。
- 上传人显示 `wanglixuan`，上传时间为真实提交时间。
- 审批人显示 `chudongqian`，审批时间为真实审批时间。
- 当前列表重复刷新仍成功，不出现读审计冲突。

### Evidence

- 当前列表目标行截图。
- 详情页基础信息截图。
- 详情页附件查看区域截图。
- 详情页上传人/审批人/时间截图。
- 记录列表分页请求至少两次，均为 HTTP 成功、业务码成功。

## E2E-6 合法生产方式入库展示

### Operation

1. 自行生产=是，委托生产=否。
2. 自行生产=否，委托生产=是，并选择正式受托企业。

每组都按 E2E-1 至 E2E-4 完成上传、审批和详情核对。

### Expected Result

- 自行生产场景审批入库后，详情展示自行生产信息。
- 委托生产场景审批入库后，详情展示委托生产信息和受托企业。
- 生产方式由上传表单正式值入库，不由前端默认值或后端猜测值生成。

### Evidence

- 两组注册证编号。
- 两组上传表单提交前截图。
- 两组审批后详情生产方式截图。

## E2E-7 注册部经理在详情中直接下载注册证附件

### Operation

1. 使用注册经理 B `chudongqian` 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”当前列表。
3. 按已审批入库的目标注册证编号筛选。
4. 打开该注册证详情。
5. 定位本次注册证附件区域。
6. 点击查看，确认可在详情中预览或打开文件信息。
7. 点击下载。

### Expected Result

- 注册经理 B 能在详情中看到本次上传的注册证附件。
- 注册经理 B 可直接下载注册证附件，不需要先发起下载申请。
- 下载文件名或下载记录能对应本次上传材料 `upload_file.pdf`。
- 下载动作由真实前端点击触发，不能用接口直接下载替代。

### Evidence

- 注册经理登录身份截图。
- 详情页注册证附件区域截图。
- 下载触发前后截图或 Playwright download evidence。
- 记录自然触发下载请求 URL、HTTP 状态和文件名。

## E2E-8 普通用户申请下载并在 3 天内下载注册证附件

### Operation

1. 使用普通用户 C 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”当前列表。
3. 按已审批入库的目标注册证编号筛选。
4. 打开该注册证详情。
5. 定位本次注册证附件区域。
6. 点击下载申请或等价入口。
7. 填写申请理由，理由包含本次唯一标识。
8. 提交下载申请。
9. 退出普通用户 C。
10. 使用注册经理 B `chudongqian` 登录。
11. 进入审批中心待办，按注册证编号或唯一标识筛选下载申请。
12. 打开下载申请审批详情，核对申请人、注册证编号、文件名和申请理由。
13. 点击同意或通过，填写审批意见并提交。
14. 记录下载授权通过时间和系统显示的有效截止时间。
15. 在授权通过后 3 天内，重新使用普通用户 C 登录。
16. 打开目标注册证详情，点击下载本次注册证附件。

### Expected Result

- 普通用户 C 在未获授权前通过页面发起下载申请。
- 下载申请标题或业务名称能明确体现注册证文件下载申请语义。
- 注册经理 B 的待办中出现该下载申请并可审批通过。
- 审批详情展示申请人、注册证编号、文件名和申请理由。
- 审批通过后 3 天内，普通用户 C 可以在详情中下载本次注册证附件。
- 3 天内下载不需要重复提交下载申请。
- 下载文件名或下载记录能对应本次上传材料 `upload_file.pdf`。

### Evidence

- 普通用户下载申请提交截图。
- 注册经理下载申请待办和审批详情截图。
- 下载授权通过后的成功状态截图。
- 授权通过时间、有效截止时间和 3 天内下载验证时间。
- 普通用户 3 天内下载触发前后截图或 Playwright download evidence。

## E2E-9 普通用户下载授权超过 3 天后重新申请下载

### Operation

1. 使用已完成 E2E-8 的同一普通用户 C 和同一目标注册证。
2. 在下载授权超过 3 天后登录普通用户 C。
3. 进入目标注册证详情。
4. 定位本次注册证附件区域。
5. 点击下载入口。
6. 页面引导普通用户重新发起下载申请，或下载入口恢复为申请状态。
7. 再次填写申请理由，理由包含本次唯一标识和二次申请标记。
8. 提交第二次下载申请。
9. 使用注册经理 B 审批通过第二次下载申请。
10. 普通用户 C 在第二次授权通过后 3 天内再次下载本次注册证附件。

### Expected Result

- 超过第一次下载授权 3 天后，普通用户 C 不能继续沿用第一次授权直接下载。
- 页面提供重新申请下载的正式入口。
- 第二次下载申请可由注册经理 B 审批通过。
- 第二次审批通过后，普通用户 C 在新的 3 天有效期内可以下载本次注册证附件。
- 第二次授权通过时间、有效截止时间与第一次授权分开记录。

### Evidence

- 超过 3 天后的详情页文件区域截图，显示需要重新申请或等价状态。
- 第二次下载申请提交截图。
- 第二次审批详情和审批通过截图。
- 第二次授权通过时间、有效截止时间和下载验证时间。
- 第二次下载触发前后截图或 Playwright download evidence。

## Execution Notes For Codex

- 所有业务动作必须由 Playwright 在真实页面完成。
- API 或数据库只允许做只读核验，不能承担上传、审批、正式化、状态修改或权限绕过。
- 除本文档 Fixed Test Context 中按用户要求保留的测试账号密码外，不得在脚本、日志、截图、trace 或提交记录中记录密码、token、Cookie、私钥、连接串密钥。
- 截图、trace 和日志文件应放入当前任务目录下的 `artifacts/`，并记录是否属于当前任务数据。
- 若执行前需要给 `chudongqian` 分配注册部经理角色，或给 `wanglixuan` 分配注册证上传角色，必须先按当前任务授权、正式角色 code 和菜单权限精确执行，并记录角色 code、用户账号、租户和影响范围；不得扩大到其它账号或其它角色。
- 验证普通用户下载授权 3 天有效期时，优先使用系统自然时间推进；若测试环境提供正式业务日期推进或每日任务触发入口，必须通过产品认可入口操作并记录入口、操作人和具体时间，不得直接改数据库时间或接口伪造授权过期。
- E2E 完成后，记录目标注册证编号、申请状态、审批状态、当前列表状态、下载授权状态、授权有效期和清理/保留策略。
