# 注册证延续正确分支 E2E 验收流程

## Scope

本文档用于指导 Codex 在本机 `int_main` 环境，通过 Playwright 操作真实前端页面，验证“注册证延续”从申请人提交到注册经理审批，再到待生效或立即生效的正确分支闭环。

不覆盖填错、缺字段、权限不足、网络失败等失败分支。

## Fixed Test Context

- 环境：本机 `int_main`。
- 前端入口：`http://127.0.0.1:8081` 或 `http://localhost:8081`。
- 后端健康检查：`http://127.0.0.1:48081/actuator/health`。
- 租户：芋道源码。
- 延续申请人 A：`wanglixuan`。 密码 111111
- 注册经理 B：`chudongchuan`。 密码 Abcd1234!
- 延续上传材料：`E:\IntRuoyi\e2e_test\registration\yanxu\yanxu.pdf`。
- 测试数据标识：注册证编号、产品名称、备注等字段必须包含本次任务唯一标识，例如 `E2E-RENEWAL-YYYYMMDD-HHMMSS`。

## Required Preflight

1. 确认前端 `8081` 可访问，后端 `48081` health 为 `UP`。
2. 确认延续上传材料文件存在：`E:\IntRuoyi\e2e_test\registration\yanxu\yanxu.pdf`。
3. 用真实登录页确认租户为“芋道源码”。
4. 确认 `wanglixuan` 已具备注册证延续提交权限，并能在 CURRENT 注册证行看到“延续”入口。
5. 确认 `chudongchuan` 已绑定注册部经理权限角色，并能进入审批中心待办。
6. 确认注册证延续审批候选不为空，候选来源为注册部经理角色及延续审批权限。
7. 准备至少两张任务自有 CURRENT 注册证：
   - 一张用于“未来生效日期”延续审批。
   - 一张用于“当天或过期日期立即生效”延续审批。
8. 若需要验证“类别变更=是”，再准备一张任务自有 CURRENT 注册证，避免与前两组数据互相污染。
9. 若上述任一项不满足，E2E 结论记为 `BLOCKED`，不得用 API-only、SQL 直改状态或切换账号替代真实页面路径。

## Test Data

每次执行创建或选取任务自有数据：

- 基准注册证：状态为 CURRENT，当前列表可见，且行级“延续”入口可见。
- 延续文件：`E:\IntRuoyi\e2e_test\registration\yanxu\yanxu.pdf`。
- 批准日期：不晚于当前真实日期，且不晚于生效日期。
- 生效日期：
  - 未来生效场景：晚于当前业务日期。
  - 立即生效场景：小于或等于当前业务日期。
- 有效期至：晚于生效日期。
- 类别不变场景：类别否变更=否。
- 类别变更场景：类别否变更=是，并填写变更后的注册证号和类别。

## E2E-1 申请人提交延续注册证审批

### Operation

1. 使用延续申请人 A `wanglixuan` 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”页。
3. 按任务自有基准注册证编号筛选当前列表。
4. 确认目标行状态为 CURRENT，且“延续”入口可见。
5. 点击“延续”。
6. 在延续弹框中核对证件编号、产品、当前生效日、当前有效期。
7. 填写批准日期、生效日期、有效期至。
8. 选择“类别否变更=否”。
9. 上传 `E:\IntRuoyi\e2e_test\registration\yanxu\yanxu.pdf`。
10. 点击“提交审批”。

### Expected Result

- 页面显示注册证延续审批提交成功的中文结果。
- 延续弹框关闭或进入明确提交完成状态。
- 自然触发的延续提交请求返回业务成功。
- 生成一条“注册证延续审批”申请。
- 审批通过前，目标注册证的当前版本事实不发生正式切换。

### Evidence

- 记录登录身份标签：芋道源码 / `wanglixuan`。
- 记录基准注册证编号、当前版本号、延续申请使用的日期。
- 记录延续提交请求 URL、HTTP 状态、业务码和 requestId。
- 保存提交成功后的页面截图或 trace 步骤截图。

## E2E-2 提交后状态正确

### Operation

1. 仍使用延续申请人 A `wanglixuan`。
2. 返回“注册证管理 / 注册证”当前列表。
3. 按基准注册证编号查询。
4. 进入审批中心待办。
5. 进入“我发起 / 已提交 / 流程记录”等发起人视角。

### Expected Result

- 审批通过前，当前列表仍展示基准注册证的当前事实，不显示已经审批通过的新版本结果。
- 目标行不再开放重复延续入口，或页面以正式状态阻止重复延续。
- `wanglixuan` 的待办中不出现这条“注册证延续审批”。
- `wanglixuan` 的发起人视角能看到该申请处于审批中。
- 该申请标题或业务名称为“注册证延续审批”，不是上传、变更或通用英文码。

### Evidence

- 当前列表目标行截图。
- 申请人待办查询截图，显示无该目标待办。
- 申请人发起记录截图，显示目标申请处理中。
- 记录目标页签、筛选关键词、自然触发分页请求的业务码和 total。

## E2E-3 注册经理待办审批

### Operation

1. 退出申请人 A。
2. 使用注册经理 B `chudongchuan` 登录“芋道源码”租户。
3. 进入审批中心待办。
4. 按基准注册证编号筛选。
5. 打开“注册证延续审批”待办详情。
6. 核对摘要和业务详情入口。
7. 点击同意或通过，填写审批意见并提交。

### Expected Result

- 注册经理 B 的待办中出现目标“注册证延续审批”。
- 待办摘要展示注册证编号、分类、产品、所属公司。
- 审批详情中的审核对象体现注册部经理审批语义。
- 业务详情入口能打开或展示注册证延续申请详情。
- 注册经理 B 可处理原指派人为其他用户的延续审批待办。
- 审批提交成功后，该待办从 B 的待办中消失。

### Evidence

- 注册经理待办列表截图。
- 审批详情截图，包含标题、摘要和审核对象。
- 审批通过后的成功状态截图。
- 记录审批提交请求 URL、HTTP 状态、业务码、processInstanceId 或 taskId。

## E2E-4 未来生效延续审批后进入待生效

### Operation

1. 使用未来生效日期提交一条延续审批。
2. 注册经理 B 审批通过。
3. 回到“注册证管理 / 注册证”当前列表。
4. 按基准注册证编号或延续后注册证编号查询。
5. 打开注册证详情，查看版本、附件和操作审计。
6. 进入“老证”页按基准注册证编号查询。

### Expected Result

- 审批通过后生成待生效延续版本，状态使用中文业务状态。
- 当前列表能展示该证的正式管理状态。
- 目标行不再开放重复“延续”入口。
- 旧版本尚未进入老证归档结果，因为未来生效日期尚未到达。
- 详情中能看到延续文件或延续记录。
- 延续操作人显示 `王立轩`，并在证据中另行记录登录身份标签为 `wanglixuan`；延续操作时间为真实提交时间。
- 延续审批人显示真实审批人的页面姓名或账号标识，并在证据中另行记录登录身份标签为 `chudongchuan`；延续审批时间为真实审批时间。

### Evidence

- 当前列表目标行截图。
- 详情页延续记录或附件区域截图。
- 详情页延续操作人/审批人/时间截图。
- 老证列表查询截图，证明未来生效场景下旧版本未提前归档。
- 记录列表分页请求至少两次，均为 HTTP 成功、业务码成功。

## E2E-5 当天或过期日期延续审批后立即生效

### Operation

1. 使用另一张任务自有 CURRENT 注册证。
2. 申请人 A 提交延续审批，生效日期小于或等于当前业务日期。
3. 注册经理 B 审批通过。
4. 回到“注册证管理 / 注册证”当前列表。
5. 按注册证编号查询新当前证。
6. 打开详情核对延续文件、版本和审计。
7. 进入“老证”页按原注册证编号或原版本信息查询。

### Expected Result

- 审批通过后新延续版本立即成为唯一当前证。
- 当前列表只出现一条目标当前证记录。
- 当前证版本号、日期和附件对应本次延续提交。
- 原当前版本进入老证列表。
- 老证页显示原版本，状态文案为已失效或等价中文状态。
- 旧证失效日期取旧证自身有效期至，不取新证生效日期或当前日期。
- 新当前证可再次按业务规则发起下一次延续，前提是没有待审批或待生效延续。

### Evidence

- 当前列表新当前证目标行截图。
- 详情页基础信息、延续附件和审计截图。
- 老证列表原版本截图。
- 记录当前列表和老证列表分页请求 URL、业务码、total。

## E2E-6 类别变更延续正确回显

### Operation

1. 使用第三张任务自有 CURRENT 注册证。
2. 申请人 A 打开“延续”弹框。
3. 选择“类别否变更=是”。
4. 填写变更后的注册证号。
5. 选择变更后的类别。
6. 上传延续文件并提交审批。
7. 注册经理 B 审批通过。
8. 按生效日期场景，在当前列表和详情中核对新注册证号、类别和延续文件。

### Expected Result

- 类别变更字段随延续申请进入审批事实。
- 审批通过后，新注册证号和新类别按正式生效规则展示。
- 未到生效日期时，不提前把旧当前版本归档。
- 已到生效日期时，新版本成为当前证，旧版本进入老证。

### Evidence

- 延续弹框提交前截图，包含类别变更字段。
- 审批详情摘要截图。
- 审批后当前列表和详情截图。

## Execution Notes For Codex

- 所有业务动作必须由 Playwright 在真实页面完成。
- API 或数据库只允许做只读核验，不能承担延续提交、审批、版本切换、状态修改或权限绕过。
- 除本文档 Fixed Test Context 中按用户要求保留的测试账号密码外，不得在脚本、日志、截图、trace 或提交记录中记录密码、token、Cookie、私钥、连接串密钥。
- 截图、trace 和日志文件应放入当前任务目录下的 `artifacts/`，并记录是否属于当前任务数据。
- 若执行前需要给 `chudongchuan` 分配注册部经理角色，或给 `wanglixuan` 分配注册证延续提交权限，必须先按当前任务授权、正式角色 code 和菜单权限精确执行，并记录角色 code、用户账号、租户和影响范围；不得扩大到其它账号或其它角色。
- 若缺少任务自有 CURRENT 注册证，可先按上传注册证 E2E 文档创建并审批入库一张任务自有首证，再将其作为延续基准证；创建和审批动作仍必须走真实页面。
- E2E 完成后，记录目标注册证编号、延续申请状态、审批状态、当前/待生效/老证状态和清理/保留策略。
