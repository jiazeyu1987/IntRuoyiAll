# 审批中心模块测试方案

1、范围：39项功能、77条唯一用例，其中73条需要其他模块配合；“模块交叉sheet”重复展示关联用例，不另计数。按用户要求排除A33-02（副本修改对原稿及已发布版本的影响）、A36-01和A36-02（流程表单与分类），不再验证，不重新编号。

2、执行人员或测试执行工具依据当前仓库规则组织测试，自行准备工具和独立worktree环境。每轮记录实际前后端地址、Git提交、源码改动、构建来源和已加载版本；不依赖旧机器的端口、缓存、固定脚本或历史通过结论。凭据由环境提供方单独交接，不写入计划或报告。

3、仅使用本轮专属数据，P代表执行端选定的唯一数据前缀。甲为发起人，乙为审核人，戊为独立批准人，丙为只读或抄送接收人，丁为无权对照。租户统一称为测试租户甲、测试租户乙，按用例选择具备授权的测试环境，不绑定具体企业名称。角色和账号按当前环境创建或确认，实际租户、账号及ID记入本轮报告。正式闭环必须分离发起与审批对象，只读丙不得承担正式审核决定。

4、被验收业务动作通过Playwright真实前端完成，不以API、数据库写入或Mock替代页面通过。数据准备遵守执行端当前授权；如明确获准接口造数，报告逐项注明接口准备范围，接口发起不能算页面发起入口通过。接口或数据库不得直接伪造审批决定、轨迹、签名或业务终态。

5、先准备账号及查询权限，再配置专属模型。配置保存与非法输入用例使用单独样板；业务闭环另配合法表单、独立审核人乙、批准人戊及抄送丙，发布并记录版本。通过真实可见发起路径准备通过、驳回和撤销申请，另备超过一页且标题时间不同的任务和编号全集。

6、按依赖执行：先入口与空态、个人列配置，再有数据的筛选、分页、排序、详情与轨迹；之后测输入校验、签名失败、取消、通过、驳回、重复并发、正文预览和网络异常。每次决定后核对待办、已办、发起记录、正式业务状态及证据，不以成功提示或跳转代替业务结果。

7、交叉前置分别准备：DCC需本轮真实受控文件、目录分类及审批矩阵；eDHR需专属活跃订单和生产/PQC前置，生产放行与上市放行分别核对；展厅先经主数据模块建立专属产品；SRM需门户申请及审核权限；MES需订单、派工及真实报工事件；电子签名需独立签署人及合法签名基线。

8、eDHR表单中心从当前可见生产表单入口进入，准备专属模板、策略和生效任务。用户分组、表达式、业务策略和OA请假仍在范围，需可见入口和授权；缺入口只阻塞依赖项，不跳隐藏业务路由绕过。BPM四视图及各来源能力按当前实现核对，不支持的视图应明确提示。

9、A35-02另建本轮未部署草稿，丁为该草稿管理人；先仅授模型查询验证无删除入口，再临时授删除打开确认框，管理员在独立会话撤权，丁从旧框确认。应明确拒绝，刷新草稿及对照模型保留，重新加载删除入口消失；结束恢复丁原授权。只操作本轮专属角色和模型。

10、权限撤回保留原会话；跨租户使用两个已授权测试租户及各自专属单据；并发使用独立会话；网络异常仅控制本浏览器。缺少入口、签名、资料或数据时记具体阻塞，其余可独立执行；不得办理他人正式待办或修改共享生产配置。

11、判定：全部子场景和本轮证据齐全才记“成功”；业务不符记“失败”；缺少前提记“阻塞”；仅做部分记“部分执行”；未开始保持“未执行”。新增、删除、取消及越权均核对ID、集合和持久化结果；静态检查单独记录，不替代页面业务验收。

12、每次更换测试版本新建轮次。复制报告模板，填写版本、对象、结果、截图日志相对路径、缺陷及复验。计划清单结果留空、模板全部未执行；现有历史测试结论不自动带入。报告位置见README.md。
