# 权限角色模块测试方案

1、范围：26项功能、57个唯一用例，含32条交叉用例；交叉sheet是重复展示，不另计数。审计、审查及已有历史任务不测试。

2、执行端Codex自行组织测试和准备工具，遵守当前仓库规则。本轮记录实际前后端地址、版本、租户、账号及数据ID，不依赖旧机器的端口、缓存、脚本或配置。账号凭据由测试环境提供方单独交接，不写入本目录。缺少前提的用例记阻塞，其余可独立执行。

3、所有业务准备和被验收动作走Playwright真实前端，不用API、数据库写入或mock替代。来源为芋道源码，迁移目标为瑛泰集团；隔离租户用于普通角色功能，独立套餐边界租户用于R22-02，其套餐允许角色查询/导入等测试功能但不含system:role-category:create。不得修改其他任务的共享套餐。

4、P是执行端选定的本轮唯一数据前缀。来源和隔离租户各自准备分类A/B（P_a、P_b）、角色A/B（P_read、P_create），同名逻辑对象的ID不能跨租户混用。U为隔离租户普通用户，isolatedAdmin为独立管理员；boundaryUser为套餐边界租户普通用户；targetUser为目标迁移用户。上述均为逻辑名称，实际账号由执行端创建或确认并记入报告。

5、隔离A只授用户页面和查询，B在此基础上增加用户新增，不授删除；普通用户无管理员、临时角色或动态扩大授权。管理员和普通用户使用独立会话，按用例恢复U无角色、仅A、A+B或仅B的状态。撤权用例保留U原会话。R12临时授U角色页面查询以调整列；R22-03单独准备仅角色页面查询角色，验证后恢复授权。

6、来源A角色移入B后，A分类为空、B含两角色，分别用于空分类删除、非空拒绝和JSON导出。分页使用本轮专用分类及N>10条角色，记录完整ID集合。数据范围账号scopeUser/Peer同部门，Other异部门，三个账号无扩大范围的其他角色。批删另外准备两条待删角色和未选中对照。

7、测试输入由执行端自行准备：有效JSON以本轮页面导出的v3包为基础，改为尚不存在的分类/角色编码；更新包保持同编码。异常分别构造空文件、坏JSON、非v3、缺角色编码、第二角色引用不存在菜单；套餐边界分别构造越界包、第一角色合法第二角色越界包和合法包，依据当前环境核对菜单键。异常前后核对集合，不能将合法菜单缺失误判为业务通过。

8、eDHR以本轮来源新角色P_migrate、两个专用来源账号及真实页面导出文件准备样本。迁移副本仅保留任务账号/角色，按本轮导出关系填写目标映射，不借用旧目标编码。另备空/非xlsx/超5MB、重复目标映射、不存在或停用目标样本。目标用户只保留本轮原角色，迁移角色尚不存在；迁移前先建立并验证新密码和新测试签名基线，密码不入报告。

9、执行次序由执行端依据依赖安排：先分类/角色创建编辑，再授权和用户联动、导入导出，最后清空菜单和删除。R04-01需等B有角色后补改名与关联保留；R15人数补齐0→1→0；R27先做预览与异常，再首次确认和重复确认。每项完成所有子场景才可判通过，变更版本另建轮次。

10、通过需全部断言及本轮证据；业务不符记失败，缺前提记阻塞，只做部分记部分执行，未开始保持未执行。取消核对前后集合；新增/删除核对ID及人数/数量；权限生效由普通用户真实操作验证；文件导出读回数量、内容与范围。填写报告模板并关联证据，失败保留缺陷及复验记录，不采用历史通过结果。报告位置见README.md。
