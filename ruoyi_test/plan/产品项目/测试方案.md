# DCC产品目录与项目代码联合测试方案

## 1. 目标与计数

把产品目录与项目代码视为一个测试单元，核对普通资料管理、真实页面入口、权限、唯一性、引用约束及双方映射一致性。共44条唯一用例：目录11、项目11、权限5、模块关联5、申请审批12。用例编号和通过标准以测试清单为准。关联用例不重复计数。

## 2. 边界与不执行项

- 不测注册证关联、解除、导入同步、变更延续、有效期、提醒及证件资料维护。
- 包含本轮虚拟数据的联合新增、申请、审核通过、驳回重提及其审批中心待办、已办与必要签名。只验收两模块的当前流程，不扩展其他审批、独立签名系统或受控文件发布。审核配置仅核对当前角色与本轮账号，不停用或改写共享角色、他人任务配置。
- 两模块新建入口均进入项目产品申请，直接创建接口在服务层拒绝。新增必须从前端申请并由有效项目审核员决定；当前ROLE_SINGLE_REVIEW_V1为单次审核后事务建档，不制造历史二次批准合同，也不从API创建。
- 产品目录“绑定”是目录、项目、注册证三方绑定，不能拆成纯两模块绑定写操作，因此排除绑定及解除绑定；正式联合新增产生的项目产品关系属于本轮；已有三方映射只作只读前提，不操作其注册证过程。
- 目录工具栏整包导入导出包含注册证、公司与绑定数据，不能与注册证分离，因此整项排除，不上传空注册证包规避。
- 普通项目导入/导出、待审撤回、完整优先级与启用状态筛选，以及需要底层关系展示的用例，因当前无完整前端入口，按用户要求移除I01/I02/I03/N14/P02/X01/X06/N09，不纳入执行、阻塞或通过计数。
- 不测关联文件上传、分类、批记录识别、工艺路线、QA规程及其他主数据模块；既有文件夹或属性可仅作为删除引用保护前提，不操作其业务流程。

- 按用户追加要求，移除C12独立无引用目录删除、X07仅产品映射的项目删除约束、P12无引用项目成功删除；累计移除11项，删除的数据前提用例不再作为交付阻塞，也不计通过。

## 3. 通用环境与逻辑账号

执行前读取当前AGENTS.md、docs/worktree-restrictions.md、docs/branch-runtime-ports.md。独立worktree预约稳定槽位；检查端口归属，禁止借用或停止其他线程服务。前后端需同一可追溯版本、后端包来源校验通过；记录提交与是否存在未提交差异。

逻辑账号：A为任务申请/管理账号；V为项目审核员；R为仅查询/READER；E为普通EDITOR；O为OWNER；N为无权限对照。账号必须任务自有，不假定管理员等同普通主体权限。凭据按当前仓库规则安全读取，仅在前端登录，不写计划或报告。若需准备账号，只通过已授权前端完成，不把账号管理纳入被验收模块。

仅使用任务前缀隔离的数据。目录A/B、项目J/K通过本轮真实申请审核生成，D为专属可处置对象。先新增后执行普通测试，最后测试删除；审批历史保留。不得伪造完成态或使用他人数据；缺少合法前提仅阻塞依赖项。产品目录可能是共享数据，须先确认本轮拥有修改/删除权限，不能把共享可见当可处置。

## 4. 已核对的实现链路（路径均相对仓库根）

前端入口：IntRuoyiFronted/src/views/dcc/controlled-file/basic-data/product-catalog/index.vue、project-code/index.vue，分别挂载../components/ProductCatalogTabPanel.vue、ProjectCodeTabPanel.vue。

产品链路：ProductCatalogTabPanel中的getList、openForm、submitForm、handleDelete → src/api/dcc/controlledFile/productCatalog.ts → 后端yudao-module-dcc下DccProductCatalogController → DccProductCatalogServiceImpl → DccProductCatalogMapper → dcc_product_catalog。更新按dataSource+originalRowNo定位；查询补充dcc_data_relation中的projectCodeId。普通编辑未在该调用链同步项目表。

项目链路：ProjectCodeTabPanel普通行编辑/删除 → src/api/dcc/controlledFile/projectCodes.ts → DccProjectCodeController → DccProjectCodeServiceImpl → DccProjectCodeMapper → dcc_project_code。更新控制器校验可读性与EDITOR/OWNER；服务校验存在、启停、唯一性，事务更新。非空代码按代码唯一，空代码按名称+空代码组合唯一。删除检查文件、文件夹、属性引用。

关联链路：目录项目链接依赖现有projectCodeId，路由/mdm/project-code?projectCodeId=目标身份；目录读取从dcc_data_relation补充身份，该关系涉及注册证，不能新建。本次同时核对已存在dcc_project_product_relation的项目产品身份；它由本轮申请审核后的建档写服务生成，仅保留现有页面可达的项目精确跳转及普通字段同步核验；需要展示正式关系ID、删除后物理关系和事务结果的用例已移除。两种关联表不可互相推断或补齐。项目页没有已确认的反向目录查看入口，双向一致性通过两页分别查询核对，不能编造反向按钮。

权限链路：目录CRUD复用dcc:project-code权限；项目页查询还接受controlled-file查询权限；项目普通编辑/删除除菜单权限外还需项目主体权限。正式OWNER/EDITOR/READER权限与本轮项目审核员主体边界均测试。不得将管理员菜单权限等同于项目OWNER或审核角色成员。

新增审批链路：ProductCatalogTabPanel.submitProjectProductRequest → projectProductRequests.ts → DccProjectProductCreateController.create → DccProjectProductCreateServiceImpl.createRequest，验证当前审核角色就绪、负责人、模板、默认属性和三个唯一身份，写dcc_project_product_create_request与dcc_project_product_identity_claim；待审阶段不写正式两表。审批中心index.vue → approval API及DCC任务提供器 → DccProjectProductTaskDelegate.review → reviewSingleRole；当前角色成员身份和意见校验后，同一事务调用DccProjectProductCreateWriteService.writeApprovedRequest，生成dcc_project_code、负责人OWNER、模板目录、dcc_product_catalog、dcc_project_product_relation，并将申请改为COMPLETED。驳回释放占用；重提保留历史并关联唯一后继。新申请没有历史二次批准节点。

导入导出：本轮清单不包含该类用例，不因后端接口存在而恢复测试范围。

## 5. 执行顺序与数据保护

先记录版本和专属账号权限；从两个入口执行新增校验、申请、驳回重提及通过建档，记录正式映射和自动生成结构，再执行查询/筛选/树/分页/列配置、普通编辑校验与取消、唯一性、映射修改、引用删除约束，最后执行保留范围内的删除及引用保护测试。所有写入只针对本轮专属对象；删除前截图记录完整目标身份。两模块变更后分别刷新页面重新查询，核对名称、代码、稳定身份和对照对象。

禁止通过浏览器注入组件状态、直接调用接口或数据库写入绕过页面入口。浏览器只保留脱敏截图和必要业务文字，不能保存认证网络日志。文件如确需下载，用OfficeCLI读表核对内容；只能操作范围内且本轮专属文件。

异常重点：清空、空白、代码冲突、无编辑主体、已有引用、取消。失败后刷新同一对象并核对其他待改字段与两模块映射均未部分写入。若某异常无法从前端合法触发，记录未执行原因，不篡改请求、故障注入或强行制造无效状态。

## 6. 判定和交付

清单结果列保持空白。每轮报告模板复制后才填实际结果。状态为通过、失败、阻塞、部分执行、未执行；“通过”必须完成该条全部动作和实际读回，有对应脱敏证据。静态风险不计业务失败/通过，应另列代码依据与待复现影响。入口缺失和数据缺失均记阻塞，不算通过。

轮次目录：../../report/DCC产品目录与项目代码/{轮次标识}/。使用测试报告.xlsx逐条记录、执行报告.md说明环境/未完成原因、代码链路与风险.md保留审查依据，evidence/存脱敏证据。缺陷必须含业务节点、复现步骤、预期/实际、稳定对象标识、代码位置、影响和复验状态。没有运行证据不得声称整条链路通过。

结束时核对44条计划用例状态计数守恒，5条关联只计一次；环境阻塞也交付完整四份计划与逐项报告。工作树与槽位保留状态据实记录，不默认提交、推送、合并、释放槽位或清理其他资产。
