# 系统管理员主链执行说明

## 任务入口与范围

先读本文件，再读01—09。用户说“执行系统管理员主链测试”时，按本目录执行，普通管理员指所选服务器对应租户的 yingtaigroupadmin（本地租户为测试1，其他服务器见下表）。上层 Agents.md 的超级管理员租户创建、删除操作属于另外的任务，不在本次主链中执行。

本目录只测试本租户的用户、部门、岗位、直属主管、密码、离职转岗登记、启停、角色分类及授权。排除全部导入导出、钉钉导入、外部模块协同、待办交接、生产质量审批、历史业务签名追溯、跨租户测试。被排除的内容不执行、不准备样本，也不记成失败或存疑。

本目录是执行手册，编写完成不表示实际测试通过。用户仅要求修改文档时不得启动测试。

## 每轮对象命名与账号清单

新一轮生成运行编号R：北京时间yyyyMMddHHmmss加4位随机小写字母或数字。整轮不变。例如时间部分14位、随机部分4位，共18位；随机部分仅用于避免并行重名。

账号格式为sa加R加下表后缀，只包含字母数字，总长不超过30。昵称为“主链”加R加后缀。所有对象备注填写“系统管理员主链测试，运行编号R”，R替换为实际值。先查询全名不存在再新建，不能接管其他轮次或其他任务对象。

建立角色分类“主链R”，标识sa加R加cat；分类及角色顺序均填1，状态启用。建立“主链甲R”“主链乙R”“主链状态R”，标识分别sa加R加a、b、s。角色只使用本轮分类，不移动已有分类和角色。记录实际编号，名称用于找对象，编号用于再次确认。

## 专用账号密码规则

所有新建测试账号初始密码P0为Sa!加R加a0；若首次登录要求改密，改成同一格式末尾a1，记为当前密码P1。这里的“加”表示直接拼接，不输入中文或空格。

04专用账号继续使用后缀a2、a3直至a9作为本轮不同的新密码。全新账号加不同R可避免前一轮密码历史冲突。每次成功修改后马上记录“当前密码版本P几”，不在普通执行记录写密码值；新Codex可用本文件规则与R还原。失败或取消不得推进密码版本。

密码应满足页面现行规则；如果这些规则生成的密码被拒绝，报告明确原因并暂停相关账号操作，不盲目重试触发锁定，也不修改管理员密码。不得试用无关账号。

## 页面入口与授权矩阵

所有业务动作使用Playwright操作真实页面；不得直接调用接口、fetch或写数据库。先用管理员通过系统管理菜单查找入口并记录实际浏览器地址，后续直接访问验证只打开这些已记录的前端地址。

| 对象或操作 | 页面入口 |
| --- | --- |
| 部门 | 系统管理 → 部门管理；也可使用用户管理左侧的新增部门、编辑部门 |
| 岗位 | 系统管理 → 组织角色；用户表单中字段叫“岗位” |
| 用户 | 系统管理 → 用户管理；新增在“高级 → 新增”，编辑及更多操作在目标行 |
| 直属主管 | 用户管理 → 目标行更多 → 设置直属主管 |
| 离职转岗 | 用户管理 → 目标行更多 → 离职/转岗 |
| 角色分类及角色 | 系统管理 → 权限角色；左侧角色分类，右侧新增、编辑、菜单权限、分配 |
| 员工密码 | 个人中心的修改密码入口 |

名称以实际部署页面为准，按照目标页面的标题和字段确认；找不到入口即记录阻塞，不通过隐藏组件或接口补做。不得点击任何导入导出入口。

角色甲只授予用户管理查询和组织角色查询；角色乙只授予权限角色查询和组织角色查询；状态角色与甲相同，但单独配置，不复制导入文件。三者只勾选对应必要上级目录、页面与查询项，不授予新增、修改、删除、重置密码、角色分配及导入导出权限。

| 用户管理查询，system:user:query | 是 | 否 | 是 |

角色乙可查询角色列表，但“查看分配人员”按钮可能需要用户查询权限，该按钮不属于乙的预期权限，不能为显示它额外授予用户查询。

## 顺序、依赖和失败续跑

按01准备全部对象及初始授权，再按02、03、04、05、06、07、08、09执行。各链使用不同专用员工；05停用账号不会破坏06—09的账号。

01的用户、部门或岗位创建失败时只阻塞依赖该对象的节点；角色配置失败不阻塞已可进行的账号维护。每条链开始先核对所需账号、角色和状态，缺少条件如实记录，不假定前链成功。

各链内失败后先只读查询实际结果，再决定是否可继续独立节点。遇到提交超时或无提示，不重复点击提交；先按全名及编号查询。确认未保存且原因已消除才允许再次提交。仍不确定则保留该节点存疑，不重复创建或反复改密。

在岗位output下为本轮建立R目录，记录服务器、租户、R、开始时间、对象用途、完整名称及编号、账号当前启停/角色/密码版本、每个节点已通过/失败/未执行、页面地址及证据位置。每次改变账号状态或授权后更新记录，便于无上下文续跑。报告中不写密码、令牌和会话内容。

用户说“继续上一轮”时读取指定R的记录并通过页面复核状态，再从未完成节点继续；找不到记录或不能确定R时询问，不猜测。用户说“重新测一轮”时生成新R、新对象及新目录；不复用被离职停用、改过密码或撤过权的旧账号。

## 权限和数据范围核对边界

员工会话与管理员会话必须隔离，单独浏览器上下文，不能只开同一会话的两个标签页。会话恢复后也先核对账号。页面访问拒绝可能强制退出，应按该专用账号当前密码重新登录后继续，不借管理员会话。

涉及授权调整时，在员工已经登录的原会话上先验证，再用独立新登录验证，分别记录结果。菜单或按钮隐藏只证明UI限制；直接前端地址拒绝只证明该访问路径的限制，不宣称完整后端越权测试已通过。

数据范围只验证本模块：如实际页面存在角色数据权限入口，用甲、乙、丙部门的本轮用户作样本，在用户管理页面核对。没有入口则该节点记未通过（缺少入口）；不得改用生产、文控、同步等外部业务模块。其余有条件节点继续。

## 留存与结果

本轮结束记录每个对象最终状态。离职、转岗登记样本保持已登记状态，已停用人员保持停用；不删除本轮样本，不恢复不可逆登记，不强制清理历史轮次。本轮角色与对象只服务本轮测试，不授予真实业务人员。

报告保存到岗位report目录，文件名为北京时间yyyyMMddHHmmss.xlsx，已有同名文件时生成新的实际时间文件名，不覆盖原报告。使用officecli及其技能生成Excel，三个sheet为“已通过、未通过、存疑”，每个case最后一列附证据截图。描述用通俗文字，包含主链节点、操作对象、预期、实际结果和证据，不放JSON或密码。

功能报错、状态不符合预期及缺少必需页面入口记未通过；环境不可达、缺少有效会话、执行中断或结果无法确认记存疑，说明依赖和未执行节点。排除项不计入通过率。独立节点继续，全部可执行主链结束后一次汇报；不能以部分通过宣称整轮通过。
