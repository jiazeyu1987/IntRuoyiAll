# 离职转岗登记与账号停用主链

## 环境

执行前确认的服务器及对应租户（本地为测试1，其他服务器见00）；命名和凭据规则见00。01准备leave、transfer、off三个独立账号，角色甲、启用、当前密码版本已记录。

## 参与账号

yingtaigroupadmin办理本轮登记、调岗、撤权及停用；三个员工分别使用独立会话。无待办接收人，无外部模块协同。

## 测试主链

1. 分别用leave、transfer、off登录并打开获授权用户管理页面，记录当前状态。三者不得是本轮部门主管或其他人员直属主管，避免连带影响其他链。
2. 管理员定位leave，打开“离职/转岗”，选离职单，单号saRleave，单据时间取当前页面允许时间，生效时间取提交前当前时间（不设长时间未来生效）。核对确认信息后提交一次。
3. 回查leave的离职单号、生效时间、账号状态及“联动停用时间”列。若异步生效，每30秒刷新一次，最多观察5分钟，记录实际等待过程；超时仍未停用记未通过，不重登单据、不重启服务。
4. leave原会话重新访问受保护页面应不可继续，新登录应被拒绝。若提交后出现交接弹窗，只关闭或选稍后交接，不办理任何待办；不能因此声称已交接。
5. 对transfer先在用户管理将部门从甲改为乙，岗位保持本轮岗位；撤销角色甲，填写原因并回查，原会话和重新登录后不能继续查看用户管理。记录调岗没有自动增加角色。
6. 再对transfer登记转岗单，单号saRtransfer，单据时间、生效时间按第2步规则；按第3—4步核对登记、到期停用、原会话及新登录拒绝。保留转岗单和停用状态，不尝试恢复不可逆登记。
7. 对off只操作列表状态开关“停用”，确认后核对状态及会话失效、重新登录拒绝；如出现交接弹窗仅关闭。核对off没有被误记成离职或转岗登记，不用该开关替代第2、6步。
8. 记录三个账号最终状态、单据编号和时间。05仅验本模块登记、调岗撤权及停用；不准备、查询或交接外部业务待办，不验证生产、文控或历史签名。
