## 测试主链

登录指定服务器和租户，核对工艺、车间、设备维护及发布审批的参与账号、实际权限和本次操作范围 → 记录现有项目、产品、路线版本、工序、工艺、工作站、设备及车间的关联基线，准备可唯一识别的测试名称、参数、产能和有效SOP附件 → 按编码查重后新增测试车间，核对名称、状态、保存及刷新结果，验证缺项、重复编码、取消编辑和修改结果 → 由设备维护岗位在目标车间新增测试设备，核对编码、名称、类型、品牌型号、所属车间、标准小时产能和状态，验证必填、编码重复及修改后未改字段保持原值，不为方便后续测试擅自改变设备状态 → 按所属项目新增测试工序，核对自动生成的工序编号、名称、状态、人工产能及SOP，验证缺少项目、名称和错误附件的提示 → 在设备工序明细中建立设备与目标工序的关联并维护单台标准小时产能，刷新后从设备和工序两端核对，区分设备主数据产能、设备逐工序产能和人工产能 → 在工艺库为目标工序新增工艺及参数，核对参数编码、名称、类型、单位、标准说明、上下限、默认值、选项、小数位数和顺序，验证缺项及不合法参数组合的明确反馈 → 新建工艺路线，选择同一目标项目、车间和测试工序，核对路线编号及名称，验证缺少关联资料、重复名称和保存失败时的提示 → 核对各工序自动生成的工作站、所属车间、所属工序和按工序设备配置带入的设备，避免重复手建同一工作站 → 从工作站详情检查并维护本次测试设备资源、数量及适用人工资源，验证添加、移除、取消和重新保存后的结果，再从车间、工序、设备、路线资源表交叉核对同一关联及产能来源 → 进入路线草稿或候选版本，配置工序顺序与流转关系、适用生产系数、超量比例和设备组，核对草稿保存、刷新及退出后重开，按已确认规则验证缺失配置和非法流转的拦截 → 为每道适用工序选择所属工艺及执行设备并应用到当前工序，核对参数来自所选工艺、设备来自当前工序配置，验证重复工艺、同一设备重复分配给多个工艺及未配置执行设备时的提示 → 分别核对工序开始条件、逐工序正式批记录表单绑定和表单槽位绑定，表单槽位仅取 formBindings，三条链分别检查，不互相补齐、不用名称相似的表单代替正式绑定 → 核对目标项目与产品关联、适用产品BOM、SOP及发布前所需配置，预览待发布内容和差异，确认变更范围内外的路线、产品及工序 → 提交候选版本发布，按系统实际发布策略由有效审批人核对后办理，分别覆盖适用的通过、驳回及补正重提，核对草稿、审批中、驳回、已发布等实际状态，不把保存草稿或提交审批当成正式生效 → 发布后重新查询路线与正式版本，逐项核对工序顺序、工作站、车间、设备、工艺参数、产能及独立表单绑定，检查路线资源表、工序设置和工作站详情的一致性 → 对已发布路线创建下一候选版本，在测试对象内修改工序配置、工艺或执行设备，核对发布前原正式版本仍保持原配置，取消或驳回时不误报新版已生效，再按正常流程发布并核对新旧版本及变更记录 → 对本次测试专用工艺修改参数，填写原因并预览全部影响路线，确认影响对象均在授权范围内后办理关联流程升级，核对各路线候选版本、审批结果及统一生效结果；影响到范围外对象时停止该变更，不扩大修改范围 → 在已有且获授权的测试订单上核对其锁定路线版本和工序配置，新版发布后检查历史订单与历史记录是否仍按各自锁定版本展示，缺少订单或前端入口时将该项记为阻塞，不借用真实生产单或通过接口补造 → 分别在车间、设备、工作站、工序、工艺和路线页面验证编码或名称搜索、适用组合筛选、分页、无结果、详情跳转和不同账号的可见及操作范围 → 仅对本次专门准备的无引用测试对象验证删除与取消删除，对存在引用的对象核对实际限制和提示，不删除历史记录或其他对象来解除限制，不执行整库重置 → 对照基线核对范围外资料及原正式配置，保留本次版本、审批和变更证据，将测试结果放入本岗位 output 下的本次测试文件夹，汇总通过、失败、阻塞、待确认、未执行及不适用项。
