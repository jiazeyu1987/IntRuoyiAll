# IDI上传、培训与版本更新主链
依据：CR-004行7、CR-011～017行15～21、CR-021～023行26～28。

1. 陈佩佩选择IDI项目、目录、类型，核对三个属性、矩阵及各自独立的会签和下发名单；上传正文及多个附件，手填编号和初版A/1，选择“文控审核后立即生效”、不培训。确认框核对全部信息后提交；取消不得创建任务。
2. 走00共同审批段，指派与会签分别签名。批准人只批准，不另选负责人。文控签名时记实际生效时间；受控成功时另记受控时间，盖章后下发。日常入口须已生效且受控，核对张鑫悦搜索、阅读和授权下载的版本及正文附件。
3. 陈佩佩检出；核对锁、人和时间。袁宏伟再次检出、检入或撤销他人检出均须拒绝，原有效版仍可授权阅读。陈佩佩本人在检入前撤销检出，应释放锁、不生成版本、不改变受控正文，记录人、时间和原因。
4. 陈佩佩重新检出，修改正文，上传多个对应附件及修改说明后检入。全部保存成功才释放锁；页面只显示“草稿”，不得显示内部小版本号。草稿不替换受控版，历史附件不被覆盖。若发生真实上传/保存失败，应不报成功、不放锁；不能安全触发时该异常分支记未覆盖，不破坏有效版。
5. 从草稿发起局部变更，选择“文控审核后立即生效”并选择培训，再走完整审批。文控签名即记录实际生效时间，但培训完成前不得受控或切换日常旧版。陈佩佩组织模拟培训并成功上传保存本轮记录后才完成培训；受控成功、盖章后切版及下发，不等签收。核对正文、版本附件、培训记录及旧版归档。
6. 再检出、修改、检入，发起换版，选择“文控审核后立即生效”、不培训，完整重审并验证新旧替代。版本示例A/1→A/2→B/1须按适用升版规则核对，不能因当前页面显示就认定正确。全过程保留历史记录。

## 执行与记录
沿用[00基线](00-测试基线与链条索引.md)的环境、真实账号及共同审批段。各独立文件样本使用独立编号；同一对象撤回/驳回重提及升版保留原编号和版本关系。使用明确标记的软件模拟正文、附件及适用培训材料，不冒称真实线下培训。凭据和PIN不写入记录。只从前端执行业务动作，API/DB仅最终只读核验。
记录账号、申请/轮次、对象、版本、前后状态、时间、页面证据和下载内容。明确需求不符为失败；缺必要数据、账号或授权为阻塞，写清影响；CRD明确要求的功能入口缺失记需求不符，并记录该场景无法执行；未做为未覆盖。本文仅为执行方法，没有新增实测结论。

## 各版本的独立验收点
来源补充：CR-024行29（选小版本升版）、CR-028行33（切版）、CR-035行41、CR-042行50（版本及审批历史）、CR-053行61。
准备初版、局部版、换版三份标明不同内容的模拟正文；每版至少两个可区分附件，记录预期正文和附件清单；培训材料标本轮申请和版本。工作草稿身份与正式版分开记录。
初版、局部A/2和换版B/1分别在其仍为当前有效版期间，由张鑫悦搜索编号、查看正文、逐项核对附件、下载并打开正文及附件、核对对应版本内容和下载留痕，完成该版记录后才继续升版。不得用最终版下载代替局部版下载。作废旧版由赵海辰通过作废归档核验。
陈佩佩检出成功后从维护入口下载本人检出文件的未作废版本及对应附件，包括草稿和待生效版本；普通账号不得因他人检出、通知或日常入口得到这些权限。作废旧版仅文控可下载。本人撤销和再次检出分别留证。
