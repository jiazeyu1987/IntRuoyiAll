# 三部门分发签收主链
依据：CR-056/057行65～66、CR-017行21。

1. 陈佩佩在本次申请独立核对下发名单为生产制造中心、质量体系中心、新品开发部；不得从会签名单或既有7人名单推定正确。
2. 完整流程受控、盖章且生效后，核对系统下发给尚磊、徐建海、周红欣三位对应负责人，不能自动派给部门全员；待生效时不得创建签收任务。
3. 尚磊、徐建海本人签名签收。周红欣在签收任务内单独指定危家豪，保存指定人、指定时间及版本；此前会签指派不能代替此指定。指定后尚未签名须仍为待签收，由危家豪本人签名才完成。
4. 分别核对发送结果、负责人、合法指定人、实际签名人及时间。指定关系不授正文权限，无正文权限者不得通过通知或签收绕过。
5. 不要求7人全签；新版同时受控且生效即切换，不以全部签收作为切版条件。未签收如实记录，不捏造完成。

## 执行与记录
沿用[00基线](00-测试基线与链条索引.md)的环境、真实账号及共同审批段。各独立文件样本使用独立编号；同一对象撤回/驳回重提及升版保留原编号和版本关系。使用明确标记的软件模拟正文、附件及适用培训材料，不冒称真实线下培训。凭据和PIN不写入记录。只从前端执行业务动作，API/DB仅最终只读核验。
记录账号、申请/轮次、对象、版本、前后状态、时间、页面证据和下载内容。明确需求不符为失败；缺必要数据、账号或授权为阻塞，写清影响；CRD明确要求的功能入口缺失记需求不符，并记录该场景无法执行；未做为未覆盖。本文仅为执行方法，没有新增实测结论。

## 版本及签收状态记录
每次固定文件编号与版本，记录负责人、指定关系、签收前后状态及实际签名；签收只表示收到，阅读不等于签收，签收也不是批准。具有正文权限的实际签收人查看核对本版本内容；无权限不得因指定而获阅读权。
再执行本轮已授权换版流程，核对新版产生独立下发签收任务；旧指定和旧签名保留但不得当作新版完成证据，新版未签名仍待签收。合法名单外自动多派须按CR-056/057记录不符，不能把7人或部门全员默认为正确收件名单。
