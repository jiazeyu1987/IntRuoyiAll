| D12 | PDF批注采用“页码＋文字”；PDF对比采用同页渲染叠加和像素差异高亮 | 不做正文编辑、手写批注、OCR、语义差异、自动页面匹配 |

## 3. 主流程

### 3.1 项目准备

1. 项目负责人新建或选择已有产品，填写唯一产品编码；选择对应注册证建立正式关联。
2. 新建项目时填写唯一项目编码并配置正式OWNER、EDIT、VIEW权限。产品编码和项目编码分别唯一，不合并为一个字段。
3. 打开项目目录模板，默认只有“项目文件”根节点；负责人可添加子目录、调整名称和顺序。叶子目录选择允许的文件类型。
4. 保存模板使其成为当前有效快照；启用项目时选择该快照，一次性生成本项目目录。
5. 以后修改模板只影响后续启用/新项目目录生成，不自动移动已有目录和文件。第一版不提供已有项目目录自动升级。

### 3.2 首次上传至受控

1. 有编制权限的用户进入项目和具体叶子目录，上传不可编辑浏览版PDF，按需上传可编辑源文件，填写名称、文件类型、初始版本、负责人、资料说明；可上传依据附件并选择关联文件。
2. 服务端检查名称占用、项目与目录归属、类型允许范围、不可编辑PDF、可编辑源文件票据和当前权限；缺浏览版PDF直接拒绝，重复名称提示“文件名称已存在，请先走作废或者升版路线”。
3. 按文件类型加载文控人员、必需会签职能和必需人员；每个必需职能必须至少有一名有效人员。上传人可增加合格会签人。
4. 点击送审后冻结内容、版本、目录、类型、附件、会签名单和职能快照，生成第1轮。
5. 文控查看只读PDF及资料，勾选核查清单、写意见、本人签名批准，或写原因签名驳回。
6. 文控通过后全部会签人并行办理；任一驳回结束本轮，取消其余待办并保留已办证据。
7. 全员批准并覆盖必需职能后，系统在本轮锁定的不可编辑PDF副本上加受控章，保存到本轮选定项目目录，成功后自动受控；日常在线浏览使用该不可编辑链路，不使用可编辑源文件。
8. 生效失败显示失败原因，并复用现有重试入口；不重新批准、不重新使用其他内容、不显示虚假受控。

### 3.3 驳回、撤回与重新送审

1. 驳回进入“驳回待修改”；发起人审批完成前可填写原因撤回，进入“撤回待修改”。
2. 原文件详情显示“修改后重新送审”。上传人可换不可编辑浏览版PDF，或修改目录、分类、类型、说明、依据和会签补充人员；可编辑源文件可同步替换但不是必填；名称、项目、文件编号保持不变，避免把返工变成新建文件。
3. 至少提交一项实际内容或信息变化；只改分类允许沿用相同浏览版PDF字节，但仍形成新快照。新分类必须与所选目录允许范围相符。
4. 同一业务版本号建立第2轮、第3轮等，重新读取当时有效审批配置，再从文控审核开始。
5. 旧轮PDF、信息、批注、意见、签名均保留；关闭撤回记录删除入口。旧批准不能计入新轮。

### 3.4 小版本与大版本

1. 当前受控文件检出，填写原因，显示检出人和时间；其他用户仍按原权限查看。
2. 撤销检出只释放锁并记操作，不产生版本。
3. 小版本：检出人上传新的不可编辑浏览版PDF，可选上传可编辑源文件，填写说明、确认一般修改，系统生成下一小版本、自动盖章并切换当前有效版本，不建BPM。
4. 大版本：检出人具有项目OWNER权限，上传新的不可编辑浏览版PDF，可选上传可编辑源文件，填写修订原因、主要变更和涉及范围；生成下一大版本后直接送文控审核，再走完整会签。
5. 大版本审批期间原有效版本继续有效；批准生效后原版失效。驳回修正使用本次业务版本的新轮次，不再额外增加业务版本号。
6. 小版本和例外替换后的页面明确显示“免审批变更”、操作者、时间和来源版本；旧审批位于历史中，不标为新内容的有效批准。

### 3.5 作废与重新上传

1. 有作废权限的人填写原因，页面列出直接关联、引用及负责人，勾选“已核对影响”。无关联时也明确显示0项。
2. 复用作废审批；批准前文件仍受控，驳回后不改变文件状态。
3. 批准后文件作废、退出默认有效列表、释放名称及可复用的新建身份占用，历史永久保留并通知直接受影响负责人。
4. 分类错误的已受控文件必须先作废，再按正确分类以同名新建，生成新的逻辑文件ID并记录被作废来源；不得复活原文件或继承批准。

### 3.6 例外替换

1. 文控对当前有效不可编辑浏览版PDF选择“例外替换”，填写原因、极小改动声明并上传新的不可编辑浏览版PDF；可编辑源文件可选替换。
2. 页面显示替换前后预览；文控使用本人签名确认执行，签名含义是“执行替换”，不冒充内容审批。
3. 新内容沿用业务版本号，内部内容修订序号递增，自动盖章后切换当前有效内容；旧内容标记失效并保留所有证据。
4. 已有关联和引用仍指向旧内容，通知负责人评估；不做自动替换引用。

### 3.7 关联、引用、对比

1. 新文件上传时及受控后的详情均可维护关联；项目目录提供“引用其他项目文件”。维护需要专门权限并校验项目范围。
2. “关联”选择同正式产品的文件；“引用”在本项目目录下选择其他项目文件，显示来源产品/项目、名称和明确版本，填写引用负责人，不要求先建一份本项目文件。
3. 选择时只允许目标当前受控快照；建立后即使目标失效，历史关系仍保留原版本，按权限从历史入口查看。
4. 维护人可添加、解除，或点“更新至当前版本”；更新前显示旧版与目标版，确认后才变更关系并留痕。
5. 来源变更通知到达后，负责人自行决定保留旧版或更新；通知不直接修改任何关系。
6. 历史页选择两份PDF，打开同页对比，显示新增、删除、变化页和像素差异；扫描PDF也按页面图像比较。
