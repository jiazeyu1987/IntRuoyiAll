# DCC 最小实现验收与TDD计划

## 1. 验收边界

配套：[业务范围](README.md)、[技术设计](implementation.md)、[双文件上传设计](dual-artifact-upload.md)。本文件定义未来实施验收，当前所有业务场景均为“计划，未执行”。本次文档校验通过不等于产品测试通过。

保留覆盖主流程的服务/Mapper测试和前端关键交互测试。新增行为先写Given/When/Then，再记录真实RED、GREEN和定向回归。旧功能已有有效测试时直接复用并调整预期，不为字符串是否存在堆叠测试。无需压测、混沌测试、故障矩阵或罕见并发交错穷举。

唯一名称、单一有效版本、本人签名、必需会签全员、内容不可覆盖、明确授权是业务成立条件，仍须测试。文件存储/盖章失败保留旧有效内容属于主流程失败处理，也须有一例。

E2E仅在用户当轮明确授权时运行。授权后使用Playwright真实前端、真实测试账号和任务自有数据完成全部被验收动作；禁止fetch/apiGet、API或数据库承担创建、审批、检入、作废等动作。数据库/API只可在允许范围内只读核验。账号凭据使用仓库指定测试环境配置，不写入开发文档。

## 2. BDD逐项验收

### BDD-M01 产品、项目与注册证

- Given：存在有效产品及注册证，另有项目编码P001。
- When：负责人新建并关联产品/项目/注册证，再以不同项目名称创建编码P001。
- Then：合法关联保存；重复编码明确拒绝；产品编码继续由正式产品主数据唯一校验，不以名称代替身份。

### BDD-M02 简易目录模板

- Given：新项目正式OWNER进入未配置模板的项目详情。
- When：初始化简易模板，新增两层目录，重命名、排序并保存。
- Then：得到有效模板快照；VIEW用户不能修改；模板叶子必须配置有效文件类型。

### BDD-M03 启用生成目录

- Given：未启用项目已有有效模板快照V1。
- When：选择V1启用项目，然后修改模板保存V2。
- Then：项目目录与V1一致且只生成一次；V2不移动原目录和文件，后续新实例可以使用V2。

### BDD-M04 指定目录双文件上传

- Given：用户有项目编制权限，叶子目录允许类型T1。
- When：输入模板清单中没有的合法名称、版本和资料，上传不可编辑浏览版PDF，可选上传可编辑源文件，并选择T1送审。
- Then：保存名称、所选目录和浏览版PDF；未上传可编辑源文件也可继续；缺浏览版PDF、浏览版不是真实PDF、其他项目目录或不允许类型均拒绝，不能静默改目录/类型，也不能用源文件兜底预览。

### BDD-M05 全项目名称唯一

- Given：同租户项目P1中已有未作废文件“检验规程”，包含待审/驳回/撤回情形。
- When：在P2或另一分类新建同名文件。
- Then：提示“文件名称已存在，请先走作废或者升版路线”；最终写入受唯一约束保护；受控文件小版本及重提同Master不误报重名。

### BDD-M06 文件类型路线

- Given：类型T1和T2分别配置不同文控及会签人员。
- When：分别提交两个类型的文件。
- Then：两者均按文控→并行会签执行，但办理人来自各自配置；不生成额外的任一人批准及文控最终批准节点。

### BDD-M07 必需会签、职能与手选

- Given：研发职能必需人员甲、质量职能必需人员乙，上传人增加合格人员丙。
- When：甲乙批准但丙未批准；随后丙批准。
- Then：前一时点不能受控，后一时点可生效。缺任一必需职能人员、试图删除甲乙或选择无签名资格人员均阻止送审；同一人覆盖多职能必须有明确快照。

### BDD-M08 路线快照

- Given：文件第1轮已按名单甲乙启动。
- When：配置改成甲丁，继续办理第1轮，并在驳回修正后提交第2轮。
- Then：第1轮仍使用甲乙，完成记录不改；第2轮使用甲丁；既有旧四阶段在途实例仍按原定义办理。

### BDD-M09 文控资料核查

- Given：待文控文件有PDF、资料说明和依据附件。
- When：查看附件及六项核查，少勾一项尝试批准，再全部确认并签名批准。
- Then：未勾满不能批准；完成后保存清单与本人意见；驳回只需原因和签名，不要求勾满。

### BDD-M10 批注与只读

- Given：办理人打开本轮PDF第2页。
- When：添加页码文字批注，再完成审批并打开历史。
- Then：PDF正文哈希不变，批注保留作者时间；历史不可改批注，非办理人不能写；审批页面和接口均不能替换正文。

### BDD-M11 自动盖章及归档

- Given：所选项目目录为D1，类别默认目录为D2，本轮所有签名已齐全。
- When：最后一人批准。
- Then：服务端使用本轮不可编辑浏览版PDF生成盖章副本并归D1，不要求另上传盖章PDF，也不改到D2；存储或盖章失败不能显示受控。

### BDD-M12 签名绑定

- Given：同版本有不同PDF的第1轮和第2轮。
- When：本人对第2轮输入密码、意见批准并导出签名证据。
- Then：证据指向第2轮精确内容快照、版本、哈希、本人、节点、意见、结果和时间；第1轮签名不能满足第2轮全员条件。

### BDD-M13 任一驳回终止

- Given：会签甲已批准，乙丙尚待办。
- When：乙写原因并签名驳回。
- Then：本轮结束为驳回待修改，丙待办取消且不能继续批准；甲乙意见和签名继续可查。

### BDD-M14 分类纠正后重提

- Given：首次上传A/1第1轮因分类错误被驳回，尚无受控内容。
- When：原上传人在原文件下选择正确目录/分类，只改信息后重新送审。
- Then：Master及业务版本仍相同，生成第2轮和新内容快照，从文控开始；第1轮分类和PDF保持原样。已受控文件的大版本返工不能借此修改原分类。

### BDD-M15 撤回修改重提

- Given：审批中的A/1已存在一名办理人的意见。
- When：发起人填写原因撤回、替换不可编辑浏览版PDF并重新送审，可选替换可编辑源文件。
- Then：旧意见及签名保留；新轮读取新的不可编辑浏览版PDF重新文控审核；其他人不能撤回，受控后也不能撤回。

### BDD-M16 独立轮次及历史不可删

- Given：A/1第1轮驳回，第2轮撤回，第3轮受控。
- When：从历史分别预览三轮并尝试删除旧撤回记录。
- Then：三份内容和审批实例可分别追溯，业务版本未被改成A/2或A/3；界面无删除入口，直接调用旧删除写接口也拒绝；三轮附件均保留。

### BDD-M17 小版本免审批受控

- Given：A/1为当前受控版本，用户有编辑权限且已本人检出。
- When：上传新的不可编辑浏览版PDF、填写说明及一般修改声明，可选上传可编辑源文件，执行MINOR检入。
- Then：生成A/2并直接受控，A/1失效，锁释放，BPM实例数不增加；新内容无继承的批准签名。首次上传或驳回候选调用该入口不能绕过审批。

### BDD-M18 版本规则设置

- Given：旧Master已冻结默认A/1规则。
- When：将新文件初始大版本设B、显示分隔符设点，新建文件并检入小版本。
- Then：新文件显示B.1→B.2，旧文件规则不变；存储规范值和版本比较一致，不以展示字符串排序。

### BDD-M19 大版本修订

- Given：A/2当前受控，项目OWNER本人检出。
- When：上传新的不可编辑浏览版PDF并填写修订原因、主要变更、涉及范围，可选上传可编辑源文件，执行MAJOR检入。
- Then：生成B/1并进入文控审核；缺任一修订资料拒绝；B/1受控前A/2继续有效，普通EDIT不能升大版本。

### BDD-M20 原子切换与历史阅读

- Given：旧版是唯一有效内容，新版准备通过审批或免审批动作生效。
- When：执行切换，再使用默认阅读及指定旧snapshotId历史入口。
- Then：只有一个当前有效指针；默认读新版，旧版显示失效且历史可读。盖章失败时旧版仍有效，不能出现两份当前有效内容。

### BDD-M21 PDF版本差异

- Given：两份有权限查看的PDF，第2页一处变化，新版多一页；另有一份无正文权限PDF。
- When：选择前两份进行并排/叠加对比，再尝试选择无权限PDF。
- Then：第2页变化有高亮，新增页有明确标识；相同页无虚假差异；无权限对象拒绝。扫描PDF使用页面图像比较，不显示未经实现的语义结论。

### BDD-M22 作废影响确认

- Given：当前受控文件有一个关联方和一个跨项目引用方。
- When：发起作废，查看直接影响清单，勾选核对并提交审批。
- Then：申请保存影响事实；批准前仍受控；批准后作废并通知负责人。无权限或未确认核对不能提交；拒绝作废申请不改变文件状态。

### BDD-M23 作废释放及同名重传

- Given：文件“检验规程”因分类错误批准作废。
- When：按正确分类、同名称和可复用编号重新上传。
- Then：成功生成不同MasterID，记录作废来源；旧内容和批准历史仍可查，新文件必须重新文控及全员会签。作废审批未通过时不得释放名称。

### BDD-M24 同版例外替换

- Given：A/2内容修订1当前受控且无开放变更。
- When：文控填写例外申请、上传变化PDF、勾选极小改动并本人签名执行。
- Then：A/2内容修订2成为有效内容，原内容和签名保留，BPM实例数不增加；新记录显示执行签名而非继承全员批准。普通用户拒绝，名称/分类变更拒绝。

### BDD-M25 同产品关联维护

- Given：两个项目正式关联同一产品，各有受控文件，用户有关系维护权限。
- When：在受控后新增关联、更新明确目标版本、填写原因解除关联。
- Then：三个动作均可完成并有前后审计；源和目标的正文、版本、状态、批准和权限均不被修改；同名产品文本但不同产品ID不能冒充同产品。

### BDD-M26 跨项目引用

- Given：P1有可维护的项目目录但没有本项目文件，P2文件当前受控且名称可见。
- When：在P1目录选择引用P2指定快照并填写引用负责人。
- Then：目录显示来源产品/项目、版本和内容修订；只新增引用关系，不复制PDF或新建空壳Master，也不重复占用名称；没有正文权限仍不能借引用预览正文。

### BDD-M27 固定旧引用与人工更新

- Given：P1目录引用P2的A/1快照。
- When：P2升版或同版例外替换，P1负责人先保留旧引用，再显式确认更新目标。
- Then：确认前仍指向原snapshotId，确认后才改到明确新快照；原引用变更记录保留；不作废或新建P1文件。

### BDD-M28 直接负责人通知

- Given：一份文件有直接关联/引用方，各自有明确负责人。
- When：分别完成小版本、大版本、作废和例外替换。
- Then：各动作均向直接关联双方文件负责人和引用负责人发送站内通知，同一切换的新版生效与旧版失效不重复发送；第二次升版仍能找到继续引用更早版本的关系。不递归通知多层文件；发送失败有记录而非假成功。

### BDD-M29 受控分类禁止直接修改

- Given：文件已受控，文控具备基础信息管理权限。
- When：分别通过详情、metadata接口及相关导入/识别修正入口尝试改变分类、类型、项目或目录。
- Then：全部拒绝并提示作废重传；不能通过另一入口改同一身份字段。负责人和关系的独立维护动作仍可正常执行。

### BDD-M30 生命周期与审批进度

- Given：分别存在待审、受控、被新版本替代和作废的内容。
- When：浏览默认列表、详情和历史。
- Then：默认有效结果只包含受控内容；生命周期统一为受控/失效/作废，未生效候选显示尚未受控；待文控、待会签、驳回待修改、撤回待修改作为独立进度。

## 2.1 双文件上传专项验收

以下场景来自[双文件上传设计](dual-artifact-upload.md)，后续实现时与M04、M10、M11、M17、M19、M20、M30一起进入RED/GREEN，不单独降级为页面文案检查。

| 编号 | 覆盖目标 |
|---|---|
| BDD-D01 | 仅上传不可编辑浏览版PDF即可提交，`sourceFileId` 可为空，在线浏览正常 |
| BDD-D02 | 同时上传可编辑源文件和浏览版PDF时，两种文件分别保存，签名盖章只绑定PDF |
| BDD-D03 | 只上传可编辑源文件时，前后端均拒绝提交，不创建业务对象 |
| BDD-D04 | 将非PDF伪装为浏览版PDF时服务端拒绝 |
| BDD-D05 | 可编辑源文件槽位上传PDF时拒绝，不能自动挪用为浏览版 |
| BDD-D06 | 小版本和大版本检入同样要求新的浏览版PDF，可编辑源文件仍可选 |
| BDD-D07 | 浏览件或受控派生件缺失时返回明确错误，禁止回退源文件 |
| BDD-D08 | 可编辑源文件下载走独立权限、缺失提示和审计 |
| BDD-D09 | 历史数据没有显式浏览版时，新的内容变更必须补齐，不自动猜测 |

## 3. 最小定向测试包

| 包 | 覆盖场景 | 实现层验证重点 |
|---|---|---|
| T1 项目与上传身份 | BDD-M01—BDD-M05、BDD-M23、BDD-M29 | 服务＋Mapper唯一约束、目录实例化、名称占用释放、直接改分类各入口 |
| T2 审批与证据 | BDD-M06—BDD-M13 | 两阶段真实流程模型解析、全员/职能验证、快照冻结、本人签名、PDF来源和目录 |
| T3 轮次与历史 | BDD-M14—BDD-M16 | 新行新流程、同业务版本、旧签名不复用、旧记录不能删除 |
| T4 生命周期 | BDD-M17—BDD-M20、BDD-M22、BDD-M24、BDD-M30 | 小版/替换无BPM，大版有BPM，事务切换、旧版保留、状态投影 |
| T5 关联通知 | BDD-M25—BDD-M28 | 正式产品身份、跨项目授权、snapshot锁定、人工更新、直接通知去重 |
| T6 前端PDF | BDD-M10、BDD-M21及关键表单 | 页码批注保存、两页对比真实差异、权限错误可见、表单提交实际调用链 |
| T7 双文件上传 | BDD-D01—BDD-D09、BDD-M04、BDD-M11、BDD-M17、BDD-M19 | 浏览版PDF必填、可编辑源文件可选、预览禁止fallback、源文件下载独立授权 |

T2不能只用字符串断言证明并行全员；须验证BPM模型多实例完成条件和业务生效判定。T4不能只断言返回成功，须核对旧/新状态、当前指针、审批实例数和历史内容。PDF对比用固定真实PDF样本验证，不将左右两个预览当作差异功能通过。

开发任务日志逐包记录：BDD范围、RED命令/失败原因、GREEN命令/结果、定向回归结果和未执行项。实际类名/脚本名在编码时按现有测试目录确定，不能预写不存在的命令并宣称通过。

## 4. 获授权后的真实页面验收顺序

1. 用任务自有产品、项目、注册证和账号完成模板→启用→上传；实际页面验证编码和名称判重。
2. 文控查看依据、写批注、核查并签名；多个真实会签账号分别批准，验证最后一人前后状态。
3. 新文件另走一次驳回改分类重提、一次撤回换PDF重提，逐轮查看历史及签名。
4. 对受控文件检出撤销，再小版本检入；随后大版本检入重审并检查默认阅读切换。
5. 建立同产品跨项目关联、其他项目引用；来源再升版，查看通知并人工更新引用。
6. 选择两个真实PDF版本进行差异对比。
7. 文控执行同版例外替换，验证旧引用仍在原内容及通知。
8. 发起并批准作废，再同名上传；核对旧文件历史及新文件重新审批。

仅在用户当轮要求E2E时把上述计划变成实际验收；没有授权时明确记录未执行，不用API/DB操作或旧任务截图代替。

## 5. 开发交付条件

- M01—M31均有对应代码、页面入口及至少一个匹配BDD的通过证据。
- BDD-D01—BDD-D09均有对应RED/GREEN记录；任何普通在线浏览路径都不能读取可编辑源文件。
- 旧规则冲突已经按[变更记录](../changes/20260918-dcc-minimal-main-flow.md)处理，新旧在途审批没有被重算。
- 没有用历史批准给小版本、重提或例外替换的新内容伪造有效批准。
- 没有把未执行E2E、未授权迁移、未部署代码或环境阻塞写成PASS。
- 若用户仍只要求本文档交付，则只验证文档结构、覆盖、链接、锚点和编码，不运行本节产品测试。
