# IntRuoyi Task And Closeout Rules

## 执行与授权

- 根据任务需要读取相关规则；同一任务中未变化的规则不重复读取，不因行政记录缺失阻断本来可以执行的工作。
- 同一任务、同一范围的授权持续有效；续做不重复询问，超出授权范围或用户撤回授权时再确认。
- 以当前磁盘上的全局及项目 AGENTS.md 和用户最新明确要求为准；旧规则快照、历史任务或技能中的默认流程不能重新引入已取消的门禁。
- 局部阻塞仅暂停依赖它的动作，其余已授权工作继续；调查从实际失败和相关调用链开始，非阻断细节不新增完成门槛。

## 验证

- 完成与改动风险匹配的必要验证，如实报告通过、失败、未运行和阻塞原因。
- BDD、TDD、独立评审按任务需要选用；不强制先写失败测试、RED/GREEN 标记或逐组件独立验收。
- 已通过的检查仅在新改动、失败或未解决疑点需要时重跑。
- 文档修改核对修改内容、结构及相关引用；文档检查不代表业务流程或 E2E 已通过。
- 用户调整范围后按最新范围执行，不让已取消的验证成为完成阻塞，也不把未执行的验证写成通过。

## 记录

- 按任务需要保留简短记录；不强制任务目录、固定文件集合、逐里程碑更新、状态格式或多份文档同步。
- 历史记录用于追查，不要求完成当前任务前整理所有重复目录或补齐历史状态。
- 日志和文档不得泄露密码、令牌、私钥等凭据。

## Git

- 仅在用户已授权范围内提交和推送；本地实现及验证完成不以推送成功作为通用门槛。
- 提交前核对工作区及暂存文件，只提交本任务改动，不混入其他任务、用户改动或临时产物。
- 不默认提交全部脏改动，不强制拆分基线、实现和收尾提交，也不为普通收尾追加一次提交。
- 所要求的验证或提交推送失败时如实报告，不能把失败写成成功。

## 清理与总结

- 有本任务临时产物需要清理时才执行清理；无清理对象时不强制运行 preview/apply 或状态解析流程。
- 清理前核对目标路径和归属，只处理本任务产物，不删除历史记录、不回滚他人改动。
- 经验沉淀仅在有可复用经验或用户要求时进行，不作为每次总结的前提。
- 总结实际完成的工作、必要验证结果和剩余问题；不以格式、文档数量或清理技能回执判定任务完成。
