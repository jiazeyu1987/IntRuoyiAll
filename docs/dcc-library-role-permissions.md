# QMS、通用文件夹权限设置

QMS 和通用文件夹均使用系统权限角色。两库独立授权；编辑包含浏览和原文件下载。原来的文件夹人员授权入口已停用。

| 菜单权限节点 | 权限标识 | 用途 |
| --- | --- | --- |
| QMS文件夹浏览 | `dcc:library:qms:view` | 浏览 QMS 文件、读取正文 |
| QMS文件夹编辑 | `dcc:library:qms:edit` | QMS 编辑资格，包含浏览和原文件下载 |
| 通用文件夹浏览 | `dcc:library:general:view` | 浏览通用文件、读取正文 |
| 通用文件夹编辑 | `dcc:library:general:edit` | 通用文件编辑资格，包含浏览和原文件下载 |

## 设置角色

1. 使用有角色管理、菜单授权权限的管理员登录。
2. 打开 **系统管理 → 角色管理 → 权限角色**。QMS、通用文件夹左侧的 **权限角色授权** 按钮也可进入此页面。
3. 选择左侧角色分类。迁移角色在 **文件夹原授权** 分类下；也可以选择业务分类并点击 **新增权限角色**，填写名称、唯一标识、顺序、所属分类，状态选择 **开启**，保存。
4. 找到目标角色，点击这一行的 **菜单权限**。
5. 先关闭 **父子联动（选中父节点，自动选择子节点）**，避免勾选“受控浏览”时同时选中其他子权限。
6. 展开 **文控中心 → 受控浏览**，保留角色已有菜单权限，勾选“文控中心”“受控浏览”入口，再按职责勾选所需的文件夹权限。只读选“浏览”；需要编辑选“编辑”即可，编辑已包含浏览。两个库需要分别选择。
7. 填写 **变更原因**，点击 **确定**。
8. 新建纯文件夹角色时，点击该角色 **数据权限**，按实际职责设置；若只用于文件夹授权，选择 **仅本人数据权限**，避免同时扩大其他模块的数据范围。

当前菜单树已有两个同名“受控浏览”节点，请展开后选择包含上述四个文件夹权限的那个；另一个包含“DCC Review”，不是本次文件夹授权节点。

## 将角色分配给用户

1. 打开 **系统管理 → 用户管理**，找到目标用户。
2. 点击该用户的 **分配角色**，保留其已有角色，再添加刚配置的文件夹角色。
3. 填写角色 **变更原因**，点击 **确定**。
4. 用户退出后重新登录，进入 **文控中心 → 受控浏览 → QMS文件夹 / 通用文件夹** 验证。

用户拥有多个角色时，权限取并集。需要撤销权限时，要检查所有已分配角色；若还有其他角色授予同一库的编辑权限，移除浏览角色不会变成只读。

文件夹编辑资格沿用现有业务边界：上传、编辑、作废等具体操作仍需对应功能权限和流程前置条件；它不授予审批、审核或系统角色管理权限。作废文件夹仅允许具有 `doc_control` 文控角色及原有“文控作废归档”权限的用户查询、读取和下载。升版作废旧版与申请作废完成的文件自动按作废状态归入；普通用户保留作废引用提示，不能申请下载，历史获批申请也不再授予下载权限。

## 原授权保留方式

迁移脚本 `IntRuoyiBackend/sql/mysql/20261105_dcc_library_role_permissions.sql` 将已有永久人员 VIEW/EDIT 授权转为角色与用户角色关系，角色名称为 **QMS文件夹浏览（原授权）**、**QMS文件夹编辑（原授权）**、**通用文件夹浏览（原授权）**、**通用文件夹编辑（原授权）**，只为实际存在的授权创建角色。

原用户的其他角色保持不动。旧人员规则保留审计记录并停用，不再用于文件夹权限判断；以后统一维护权限角色，重复执行迁移不会用旧规则恢复已撤销的授权。超级管理员沿用系统既有全权限规则。

若其他环境存在部门、岗位、角色主体或带有效期的旧文件夹规则，迁移会明确报错并回滚，须先制定相应迁移方案，避免把限时授权变成永久授权。
