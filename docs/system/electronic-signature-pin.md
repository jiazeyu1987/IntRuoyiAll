# 电子签名：PIN 码与密码

- 系统账号和无系统账号的 MES 员工档案均支持 `PIN`、`PASSWORD` 两种签名方式。用户保存所用方式，服务端只校验该方式，不尝试另一种凭据。
- 新增和存量身份默认使用 PIN，初始值为 `888888`。PIN 必须是六位 ASCII 数字，保留前导零，允许重复或连续数字；按用户要求不设置复杂度、到期、错误计次或锁定。
- 系统账号的密码签名使用登录密码；密码修改继续沿用既有强度、历史、到期和会话失效规则。员工档案保留独立签名密码及原密码规则。
- 账号停用、员工停用、租户隔离、角色权限及业务前置条件仍须通过。PIN 不参与原密码错误计数，也不清除原密码锁定状态。

## 用户入口

- 个人中心 → 电子签名设置，或电子签名 → 我的签名：修改 PIN、保存签名方式。保存前验证本人当前登录密码；修改登录密码可进入原修改密码页。
- 一线生产页面 → 当前员工的签名设置：验证当前所选签名凭据，可修改 PIN、独立签名密码或签名方式。切换密码前必须具备有效签名密码。
- 签署弹框统一提示输入所选方式对应的 PIN 或密码。原有请求字段名如 `password`、`signaturePassword` 保留，含义为所选方式的签名凭据，不由字段名选择认证方式。

## 存储与证据

- `system_users` 和 `mes_pro_process_pool_team_employee_profile` 增加 `signature_pin_hash`、`signature_credential_type`，PIN 仅保存 BCrypt 哈希。
- 修改 PIN 或签名方式由数据库触发器递增凭据版本，使修改前已完成认证但尚未签署的请求失效。
- 正式记录分别写入 `SESSION_PLUS_PIN`、`SESSION_PLUS_SELECTED_USER_PIN`、`SESSION_PLUS_EMPLOYEE_PROFILE_PIN`，保留身份上下文，并纳入原证据哈希及审计链；历史 PASSWORD 记录不改写，按原身份边界核验。
- 设置请求关闭正文日志，审计事件仅保存身份、操作类型与凭据版本，不保存 PIN、密码或哈希。

## 部署

- 在部署新应用前执行 `IntRuoyiBackend/sql/mysql/20261110_signature_pin_and_password.sql`。前置条件是 V2 凭据版本列及对应更新触发器已存在；已执行或部分执行时明确报错，禁止重复执行。
- 迁移保留原密码和历史签名，初始化现有身份为 PIN，同时递增版本；新增身份使用数据库默认 PIN 设置。
- SQL 已在任务独立 MySQL 8.0.39 验证，并于 2026-11-10 按用户授权应用到本机 `int_main`；没有部署到远程服务器。迁移核对原密码、原用户资料及历史签名保持一致。页面验收范围与运行包记录见 [本机验证记录](electronic-signature-pin-verification-20261110.md)。
- 不自动删除 PIN 列或回写历史记录。已有 PIN 签名后，回退应用也必须保留 PIN 证据读取能力。
