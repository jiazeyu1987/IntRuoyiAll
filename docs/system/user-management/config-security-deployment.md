# 用户管理配置、安全与交付设计

## Purpose and Scope

保持现有部署形态，保护 [架构](architecture.md) G3。职责分离不能破坏真实事务、账号/令牌统一锁序、权限审计、租户隔离与失败可见性。第一阶段仅查询投影，不修改安全策略、配置、账号、数据库或运行服务。

## Evidence Reviewed

已读 E03/E07/E10—E19、`UserProfileController.updateUserProfilePassword`、`PermissionCommandProtocol.beginInternal` / `finishInternal`、`TokenAuthenticationFilter.buildLoginUserByToken` / `mockLoginUser`、源码 application-local.yaml 的 mock-enable 项。源码本地配置启用 mock，不等于当前运行环境使用相同配置；本轮没有检查运行态或据此修改服务。

## Configuration

保留既有租户、数据权限、密码规则、令牌有效期、初始密码与注册开关配置来源。初始密码缺失、密码策略不通过、GxP 策略/激活/回执缺失应明确失败；不把配置缺失解释成默认账号可用或默认审计成功。

proposed page/Q2 不新增配置中心、事件总线或备用数据源。查询预算、未来错误码等作为代码合同和验证断言，不通过任意配置关闭权限/对账。现有 pageSize 最大 200 保留。

未来开发前只读确认目标测试服务的配置归属、实际数据库/Redis、租户过滤和数据权限是否启用；日志记录配置名称与已确认状态，不输出连接秘密。真实认证验收要求 mock-enable=false 并核对实际生效值。不能因为源码有 mock 分支就偷偷删除或启用它，也不能以 mock 身份生成安全验收 PASS。

## Secrets

密码、旧/新密码、签名凭据、令牌、密钥、连接凭据仅在正式受保护通道和所属内部逻辑处理；文档、请求日志、操作日志、异常与截图不得包含这些秘密。名单 DTO、内部 IdentityLookup 和审计上下文不得带 passwordHash 或整个 AdminUserDO。

现有重置与个人改密接口关闭请求日志并指定敏感键清理，保留 S-01 行为；重置操作上下文只存 targetNickname 等非敏感必要字段。未来新增 DTO/签名重新认证端口必须同步核对 filter、ApiAccessLog、操作日志表达式及失败输出，不只在 Controller 注解上做过滤。错误说明不能复述密码或令牌。

## Permissions

| 用例 | 当前权限/身份 | 目标原则 |
| --- | --- | --- |
| page / get / get-for-update | system:user:query | 当前租户+部门/本人范围；page 摘要限定已授权页内主体 |
| Q2 query-dept-tree（proposed） | system:user:query | 只提供用户查询允许的最小组织上下文，不获取 dept:query |
| 新增/修改/删除 | user:create/update/delete | 第一阶段不扩大或缩小写权限 |
| 重置密码 | system:user:update-password | 独立权限及敏感审计脱敏 |
| 角色分配 | system:permission:assign-user-role | 原因、幂等、受限角色和正式 GxP 审计，不由 user:query 赋权 |
| 导入/导出 | user:import/export | 不因查询重用绕过数据范围；UM-02 未实施 |
| 本人资料/改密 | 服务端登录用户 | ID 来自会话，不能信请求中的另一个用户 ID |
| MES 对象/签名 | MES/签名动作权限与对象归属 | 用户存在/启用校验不替代 MES 对象授权 |

批量名称读取是已授权主体的关系投影。查询应用先产生可见用户集合，再按这些 ID 读关系和同租户主数据；不能查询任意用户 ID 的角色再在前端删掉。角色/岗位命名摘要不包含菜单权限、授权候选全集或敏感审计数据。

E19 当前内部拼接 API 关闭数据权限，未来最小身份 API 的服务端调用要明确用途与调用模块已完成的对象授权；仍要求租户与身份完整。不可将此 API 直接公开为用户页的查询替代。公开列表和 Q2 不允许执行 ignore DataPermission。

## Security Controls

### 现行必须保留的安全事务

- UM-04：实际 Spring 可写事务，锁当前租户用户→原始 JSON与有效关系→正式岗位；岗位集合按 ID 稳定锁，JSON/关联/正式主数据差异拒绝，资料与差量任职写入失败整体回滚。既有停用可保留/移除，新增须启用。
- UM-05/S-01：改密、重置、账号停用和到期生命周期停用与正式会话撤销保持同事务语义；旧哈希历史与凭据状态一起更新。Redis 删除失败原样传播，DB 回滚；部分已删缓存不补回，后续 DB 仍是权威。
- ADMIN 发令牌、刷新、撤销共同使用用户→access（行 ID 顺序）→refresh（行 ID 顺序），孤立 refresh 也必须发现并撤销。用户 ID 0 仅是既有机器协议，无人员假对象；人类登录/签名不可借 ID 0 绕过账号锁。
- 密码登录快照发令牌时重新比对租户、用户、hash、更新时间、凭据状态；修改密码与并发登录只能有符合锁内现时状态的结果。权限验证用正式 DB token 和当前用户状态，旧 Redis token 不可独立建立登录身份。
- `readOfficialAccessToken` 以 NOT_SUPPORTED 离开外层旧读快照，按正式 access/refresh 身份验证；保留现有 refresh-as-bearer 协议及其正式验证，本设计不以禁止 fallback 为由擅改既有协议。
- 现有授权审计先 acquireLedgerLock，再激活/策略/回执/事件当前读，再 user 与授权关系；当前错误传播和精确重放规则保留。

“拆 service”不能删除调用前的事务断言、换为异步撤销、把 TransactionTemplate 调整成脱离外层的独立提交、或让缓存失败仅写 warn 后返回成功。专用主体锁端口只做所属行的当前锁定读与明确租户检查，不反向调用会话或广义用户命令。

### 统一锁图与未来抽取门禁

已有上述顺序是当前链局部事实；MES/签名跨对象全部写入口尚未在本轮穷尽，不宣称全系统已有无环锁图。未来每个受影响用例必须先列全资源及入口，目标统一偏序为：必要的 GxP ledger/政策/幂等锁前置 → 用户主体按 ID 升序 → 相应用例关系按稳定 ID 顺序 → 岗位/角色主数据按 ID 升序 → access 按 ID → refresh 按 ID。已有只取子集的用例不强行获取无关锁。

若 MES 业务对象锁、签名账本锁或另一路令牌操作与这个目标顺序冲突，先记录完整循环与重新编排方案并单独验证，不在本轮悄悄调整。审计锁绝不能在已持有用户锁后新增成反向依赖。历史/证据追加的唯一键及事务位置也须加入图。没有全调用图不能宣称安全职责抽取可以放行。

### 失败和并发

租户不匹配、主体缺失、非法状态、资格过期、账号停用、正式关系不一致、事务缺失、SQL/Redis异常和写入行数异常明确拒绝。结构性缺依赖不得换备用实现；正式摘要缺失不得返回默认“无关系”。页面失败不能写审计成功。

签名重新认证现有 noRollbackFor=ServiceException 的语义、失败计数在外层签名失败时是否仍需保留，需要在后续安全阶段独立审查；本轮不猜测自调用/嵌套事务可以达到目的。未来不得以登录已认证替代本次签名密码验证。

乐观版本只用于经明确确认的资料/授权等用例，不能替代账号行锁与正式状态复核；第一阶段只读，不添加 version 列或把未知版本字段当现有能力。

## Deployment

第一阶段可在同一 server 部署新增内部查询实现与响应摘要，原 page 路径保留；服务端与对应页面需作为同一发布单元评估，不为旧页面搭建永久备用查询。部署前明确所有 page 调用者对增量字段的兼容行为，不改 export/选择器/编辑详情的合同。

本轮无发布。后续开发需依项目规则在独立 worktree 预约槽位，核对任务归属与端口矩阵，不占 48081 或停止主服务。真实 E2E 当轮另获明确要求，使用正式脚本和真实前端；API/DB只读。schema 变更、数据库写入、Git 提交/推送及服务器/发布分别遵守当轮授权，不以本设计放行当部署授权。

迁移与回退按 [数据设计](data-model.md) 的来源清单/差异/备份/可恢复性门禁。安全撤销不能因发布分批而暂时异步；未知现场 schema 不执行猜测 DDL。

## Observability

proposed 查询记录脱敏 requestId、耗时、结果数、基础/范围 SQL计数、按层深度、协议/完整性失败类别；不记录角色目录全文或手机号等不必要隐私。1/10/200 用户的查询计数对照与执行计划证明无 N+1；不得拿浏览器 HTTP 数量代替数据库查询证据。

安全写记录真实 actor/target/tenant/action、原因（必要时）、事务结果、撤销条数和审计证据 ID，避免令牌原文。Redis/DB异常应可关联错误与回滚结果；后续告警阈值依真实基线制定，不凭空承诺 SLA。身份快照缺失以明确业务错误/受控状态呈现，不后台默默填充。
