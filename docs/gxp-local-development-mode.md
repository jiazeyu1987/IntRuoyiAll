# 本机 GXP 开发模式

## 2026-10-25 当前授权范围

用户明确要求主环境及 checkpoint-c6 独立环境关闭 GxP 审计，并清空 gxp_audit_event。此次维护同时清空其外键关联表 gxp_audit_event_relation，保留编号分配下限、其他业务数据和独立签名记录。此为单独授权的维护操作，开发模式本身仍不会自动删除历史数据。

独立容器现允许关闭审计，但必须仅使用 local profile，INTRUOYI_CHECKPOINT_SPACE 与 intruoyi.checkpoint.space-id 一致，且非回环 MySQL 地址必须精确指向该空间的 MySQL 容器和 ruoyi-vue-pro 数据库。其他远程地址仍拒绝。关闭模式下的业务验证不能作为完整 GxP 审计验收。

本机开发可关闭 GXP 记录、查询及依赖审计的校验，继续验证真实业务流程。该模式不是完整审计验收，不能用于证明审计链完整或合规通过。

## 配置

`application-local.yaml` 的 `yudao.gxp-audit.development-disabled` 默认取环境变量 `INTRUOYI_GXP_AUDIT_DEVELOPMENT_DISABLED`，本机默认值为 `true`。只允许单独启用 `local` profile，且 master/slave MySQL 地址必须为回环地址；其他环境申请关闭会拒绝启动。未配置该开关的其他 profile 默认启用正式审计。

设置环境变量为 `false` 并重启后端，可以恢复正式审计。不要把开发模式的数据当成正式审计验收数据；恢复后需使用独立的正式测试数据重新验收。

## 行为

- 不写入 GXP 事件，不读取 GXP 事件、关系、策略或序号表。遗漏的直接审计 Mapper 访问会明确报错，避免再次执行审计 SQL。
- 审计列表返回空列表；登录后的页面持续显示“开发模式”提示。运行模式通过需要登录的 `/system/gxp-audit-event/runtime-mode` 页面请求读取。
- 保留登录、签名密码认证、签名身份、签名内容摘要、时间一致性、权限及业务状态规则。
- 仅跳过依赖 GXP 创建事件、事件哈希和事务关联的校验，不伪造已验证的审计事件。
- 部分业务回执的审计关联字段非空，因此使用负数开发标记和 `DEVELOPMENT_DISABLED` 状态；这些标记不对应真实审计事件。正式模式不会将其认作正式审计证据。
- 不删除历史审计记录，不修补历史业务数据，不自动重试结果未知的提交。

## 验证范围

开关环境限制、审计关闭后不调用持久层、遗漏审计查询阻断、正式审计回归、签名校验和 MES 来源/生产签名回归已进行针对性单元测试。真实前端启动核验与完整业务用例验收分开记录；开发模式业务运行即使通过，也不代表完整审计验收通过。

## 开发环境原生产提交的恢复核对

运行模式页面同时显示本次 JVM 启动 UTC 时间；工序提交详情总表显示完整工序的正式提交数及数量。它们是只读事实，不生成报工或修改运行状态。

独立测试平台只在开发模式、服务启动晚于原运行最后停止时间时，使用“未生效”恢复路径：校验生产订单、原成功重置时间及人员、全部工序与原运行成功核对的正式 DCC 编码，然后要求目标工序正式提交数和提交数量均为 0。服务未重启、周期变化、明细不全、编码变化或已有正式提交，均不得据此清除未知写入。ERP 样例编码不能代替原运行已验证的 DCC 正式编码。

此路径针对本机同步事务提交及已确认独占的测试工单；不能推广为分布式、多实例或异步写入的失败判据。历史完整运行结果保持未完成，资源释放使用平台保存的恢复核对与确认流程。
