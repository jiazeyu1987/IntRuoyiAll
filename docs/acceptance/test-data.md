# Codex 测试管理测试数据计划

## Purpose and Scope

本文档定义测试管理功能所需的租户、用户、角色、测试项、检查点、执行记录和临时截图数据。测试数据必须可追踪、可清理，并且不得修改生产租户、admin 基线数据或无关业务记录。

## Evidence Reviewed

- 用户已确认业务工单号由用户手写并可随时更改。
- `docs/login-access.md`：默认只允许本机开发和 E2E，凭据来源不写入文档。
- `docs/e2e-rules.md`：写入型 E2E 必须使用确认的测试租户和账号，并创建可追踪测试数据。
- `docs/system/data-model.md`：测试项和执行记录模型。

## Required Test Data

- 角色：`测试管理员`，code 为 `codex_test_admin`。
- 用户：tenant 1 启用的 `admin` 用户拥有 `codex_test_admin`。
- 菜单：`系统管理 > 测试管理` 和按钮权限 `system:codex-test:*`。
- 测试租户：一个已确认可用于自动化测试的启用租户。
- Runner 凭据映射：目标测试租户的登录账号和密码保存在 Runner 本地安全配置中。
- 基础测试项：名称包含任务标识，例如 `Codex 自动测试管理验收 <runId>`。
- 检查点：至少 2 条用于 UI 结果展示，一条可通过，一条可构造失败截图。
- 业务样例测试项：自然语言中包含 `881MO093613,881MO093615` 等用户手写工单号；这些值只作为样例，不由系统自动生成。
- 临时截图：失败用例由 Runner 上传到后端临时目录，artifact 元数据记录 `expiresAt`。

## Reset Procedure

- 测试项数据通过名称前缀或 runId 定位，执行后可软删除或保留历史。
- 执行记录保留到配置的执行记录周期，清理时只清理本次测试创建的执行批次。
- 临时截图按 `artifact-retention-hours` 自动清理，清理后保留失败文本结果。
- 角色、菜单和 admin 赋权属于正式权限种子，不作为普通 E2E 清理对象。
- 用户手写业务数据不由测试管理功能自动清理；如果业务测试项会写入 MES、DCC 或其他业务数据，测试项描述必须说明数据归属和清理方式。

## Data Ownership

- 测试项模板归创建它的登录租户和创建人所有。
- 执行批次记录归发起用户所在租户所有，目标租户通过 `targetTenantId` 明确记录。
- Runner 只拥有执行中临时 artifact 上传权，不拥有测试项增删改权限。
- 失败截图归执行批次所有，前端只能通过 artifact 接口读取。
- 用户手写的工单号、产品编号和其他业务数据归测试项维护人负责确认可用性。

## Test Blockers

- 无确认测试租户时，写入型真实 E2E 阻塞。
- Runner 缺少目标租户凭据映射时，执行测试阻塞。
- 用户手写工单号在目标租户不存在时，业务用例不能替换其他工单号；应记录失败或阻塞。
- 临时截图目录不可写时，失败截图验收阻塞。
