# 生产一线报工工序池 E2E 计划

## Purpose and Scope

本文档定义 10 个可先做功能点的真实用户路径验收。E2E 必须使用 Playwright 操作真实前端页面；API 和数据库只允许用于最终只读核验、测试数据准备和清理证据记录。

## User Paths

- 路径 1：设备账号登录后进入一线报工入口。
- 路径 2：设备账号选择绑定工艺路线下的工序。
- 路径 3：在当前工序内切换实际填写员工，且不触发重新登录或二次验证。
- 路径 4：页面根据实际员工 + 当前工序加载固定模板。
- 路径 5：生产员工填写设备参数、完成或输出数量、损耗数量和必要不良明细，完成电子签名并确定提交；页面不出现上一个工序输入数量手填项。
- 路径 6：PQC 员工填写检测成功或检测失败，完成电子签名并确定提交。
- 路径 7：管理人员查看工序池事件、报工来源、记录本来源和原始 payload。
- 路径 8：系统按生产工单计划开始时间执行或展示 FIFO 分配结果。
- 路径 9：管理人员打开工序池时间轴 / 甘特图，按日期、员工、工序、设备、模板类型、生产工单过滤。
- 路径 10：审核人员从工序池事件生成审核副本，查看原始值和上下限修正值，完成审核电子签名。
- 路径 11：一线员工修改未 FIFO 分配的原始记录，填写修改原因并重新电子签名。
- 路径 12：一线员工尝试修改已 FIFO 分配的数量字段，页面和后端明确拒绝。
- 路径 13：生产班组长打开提交看板，只看到负责范围内员工提交并复核员工提交。
- 路径 14：PQC 班组长打开 PQC 提交看板，只看到负责范围内 PQC 提交并复核。
- 路径 15：班组长查看所有生产工单，标记异常、填写异常说明并发起上报，同时提交看板仍按负责范围过滤。
- 路径 16：班组长添加员工、禁用员工，并验证后续候选变化和历史追溯不变。
- 路径 17：班组长维护不良原因列表，并验证损耗 / PQC 模板可选择新增原因。
- 路径 18：班组长给工序增加设备、设置设备参数上下限，并验证一线原始提交不被硬拦截、审核副本使用该上下限。

## Browser or Client Steps

1. 使用 Playwright 打开本机前端入口。
2. 使用已确认的设备账号登录。
3. 进入现有报工入口或一线报工模式，断言入口仍体现“报工”路径。
4. 选择设备账号绑定的工艺路线和工序，断言未授权工序不可见或不可选。
5. 打开员工切换控件，断言候选员工只来自当前工序绑定员工。
6. 切换到目标实际员工，断言登录账号未改变且未出现密码、验证码、扫码或二次验证弹窗。
7. 等待固定模板渲染，断言生产模板只展示输入数量、设备、设备参数、输出数量、损耗数量，不展示可编辑时间字段。
8. 输入超出审核范围的设备参数值，例如 `50` 或 `10`，断言页面允许继续提交。
9. 点击确定提交，完成目标实际员工的电子签名。
10. 等待提交成功响应，记录页面返回的报工、记录本或工序池事件标识。
11. 通过只读接口或页面详情核验 `feedbackId`、`recordbookEntryId`、`processPoolEventId` 互相关联。
12. 使用 PQC 员工重复路径，选择 PQC 简化模板，只提交检测成功或检测失败。
13. 打开工序池时间轴 / 甘特图，按当天过滤，断言生产事件和 PQC 事件均展示。
14. 使用员工、工序、设备、模板类型、生产工单组合过滤，断言结果收敛。
15. 打开事件详情，断言显示登录账号、实际填写员工、电子签名员工、服务端提交时间、原始 payload、FIFO 状态、审核副本状态和修改历史摘要。
16. 使用审核账号打开审核副本入口，针对超限字段 `pressure=50` 生成副本，断言页面同时显示原始值 `50` 和修正值 `40`。
17. 审核账号提交审核副本并完成电子签名，断言审核副本状态、审核人、审核服务端时间和签名可追溯。
18. 返回原始事件详情，断言原始 payload 仍为 `pressure=50`，未被审核副本改写。
19. 对一条未 FIFO 分配的事件打开原始记录修改入口，修改设备参数或输出数量，填写修改原因并重新电子签名。
20. 断言修改成功后可查看字段级 diff、修改前值、修改后值、修改原因、修改人、修改服务端时间和新电子签名。
21. 对一条已 FIFO 分配的数量片段尝试修改输出数量或损耗数量，断言页面拒绝提交，后端原始 payload 未变化，未生成成功 revision。
22. 使用生产班组长账号登录，进入班组长提交看板，断言只展示负责员工的生产提交、报工状态、复核状态、PQC 状态、异常状态和详情入口。
23. 打开一条负责员工提交，执行复核，填写复核说明，断言复核成功后原始 payload、报工来源、记录本来源、电子签名和提交时间未变化。
24. 尝试通过生产班组长账号访问非负责员工提交详情，断言页面或后端明确拒绝。
25. 使用 PQC 班组长账号进入 PQC 提交看板，断言只展示负责范围内 PQC 成功 / 失败提交，且详情只读。
26. 使用班组长账号打开生产工单列表，断言列表包含负责员工关联工单和非负责员工关联工单；再回到提交看板，断言仍只展示负责员工提交。
27. 对测试工单标记异常、填写说明并上报，断言生产工单异常状态和上报记录可追溯。
28. 复查关联工序池事件和 FIFO 分配明细，断言异常标记没有改写一线原始提交、审核副本或分配明细。
29. 班组长在负责工序内添加新员工，回到设备账号一线入口，断言该员工进入后续可选员工列表。
30. 班组长禁用已有员工，回到设备账号一线入口，断言该员工不再作为后续可选员工；打开历史时间轴，断言该员工历史提交仍可追溯。
31. 班组长新增不良原因，进入损耗或 PQC 失败模板，断言新增原因可选择；历史提交原因未被改写。
32. 班组长给目标工序新增设备并设置参数上下限 `20~40`，进入一线模板，断言该设备可选。
33. 一线员工使用新增设备提交 `pressure=50`，断言原始提交成功且原始值仍为 `50`；审核人员生成审核副本时断言修正值为 `40`。

## API Verification

- 只读核验报工记录存在且生产工单、工序、数量字段正确。
- 只读核验记录本条目和记录本事件存在，且保存原始字段值。
- 只读核验工序池提交事件存在，且关联 `feedbackId`、`recordbookEntryId`、实际员工、登录账号、电子签名、服务端提交时间。
- 只读核验超限原始值没有被裁剪。
- 只读核验 PQC 成功 / 失败记录归入对应工序池。
- 只读核验 FIFO 分配明细只指向生产工单，不使用排产目标字段。
- 只读核验时间轴查询接口无写入副作用。
- 只读核验审核副本保存 `rawValue`、`correctedValue`、修正规则、审核签名、审核状态，且原始工序池事件和记录本来源未被改写。
- 只读核验原始记录 revision 保存字段级 diff、修改原因、重新电子签名、服务端修改时间。
- 只读核验已 FIFO 分配字段的修改请求没有更新 payload、没有生成有效 revision、没有改变分配明细。
- 只读核验班组长提交看板接口只返回负责范围内员工提交，且不返回越权详情。
- 只读核验班组长复核记录保存复核状态、复核人、服务端时间、复核说明和来源工序池事件，不改写原始 payload。
- 只读核验班组长生产工单异常列表返回全量生产工单，但生产工单详情不得暴露非负责员工提交明细。
- 只读核验生产工单异常记录和上报记录保存生产工单、异常说明、上报人、服务端时间和状态流。
- 只读核验员工添加 / 禁用记录保存维护人、生效范围和审计日志；禁用员工历史提交仍可查询。
- 只读核验不良原因新增记录保存生效范围和审计日志，并能被损耗 / PQC 模板引用。
- 只读核验工序设备绑定和参数上下限记录保存维护人、生效范围、上下限和审计日志；一线原始提交未被上下限裁剪。

## Console and Log Checks

- Playwright 捕获 `pageerror` 和 console error，未解释错误必须导致 E2E 失败或阻塞。
- 记录关键网络请求：组合提交、记录本写入、工序池事件创建、PQC 入池、审核副本生成/提交、原始记录修改、时间轴查询、班组长看板查询、复核、异常上报、员工启停、不良原因维护、工序设备和参数上下限维护。
- 记录 MES 写请求数量和目标，确保时间轴和看板查询路径无写请求，审核副本、原始修改、复核、异常上报和班组维护写请求只发生在对应入口。
- 日志和证据不得包含密码、token、cookie、Authorization 或电子签名明文密钥。
- 失败时记录页面 URL、租户/账号标签、生产工单编码、工序编码、事件 ID、截图路径和业务错误信息。

## Test Blockers

初始定义和解除条件见 `docs/acceptance/production-line-process-pool/open-questions-blockers.md`；真实 E2E 前置缺失时记录 BLOCKED，不用 mock、API-only 或静态合同代替。

- 本机前端或后端未运行。
- 缺少登录前置、测试租户、设备账号、实际员工、设备、工作站。
- 设备账号未绑定 `X >= 1` 个工艺路线。
- 工序未绑定员工或员工未绑定固定模板。
- 缺少可写入测试生产工单或生产任务。
- 缺少电子签名测试能力。
- 缺少正式工序池模型和组合提交接口。
- 缺少审核副本模型、上下限元数据、审核权限、审核电子签名或审核状态枚举。
- 缺少原始记录 revision 模型、字段级 diff、修改原因、重新电子签名或 FIFO 锁定查询。
- 缺少班组长负责范围、复核状态、全量生产工单异常入口权限、异常上报状态、员工启停状态、班组维护审计模型或班组长测试账号。
- 缺少不良原因列表、工序设备绑定、设备参数上下限规则或审核副本读取参数上下限的正式接口。
- 缺少生产工单 `plannedStartTime`，且业务未确认空值处理规则。
- 缺少 PQC 成功 / 失败对可分配数量的正式规则时，FIFO E2E 只能验证“不消费非可分配状态”，不能宣称 PQC 业务闭环通过。

## Initial E2E Defaults

- 若生产工单 `plannedStartTime` 为空或重复，E2E 应验证页面/接口明确阻塞 FIFO，而不是准备替代排序数据。
- 若班组长范围配置存在，E2E 应同时验证“提交看板范围过滤”和“生产工单异常列表全量可见”；若范围配置不存在，班组长看板、复核和维护路径均阻塞。
- 若设备计量效期字段不存在，E2E 不验证计量效期，但必须验证新增设备来自设备台账且维护动作有审计。
- 审核副本 E2E 使用 `20~40` 上下限规则：原始 `10/50` 保留，副本修正为 `20/40`，且一线提交不被拦截。
