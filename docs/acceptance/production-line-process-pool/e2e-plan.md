# 生产一线报工工序池 E2E 计划

## Purpose and Scope

本文档定义 6 个可先做功能点的真实用户路径验收。E2E 必须使用 Playwright 操作真实前端页面；API 和数据库只允许用于最终只读核验、测试数据准备和清理证据记录。

## User Paths

- 路径 1：设备账号登录后进入一线报工入口。
- 路径 2：设备账号选择绑定工艺路线下的工序。
- 路径 3：在当前工序内切换实际填写员工，且不触发重新登录或二次验证。
- 路径 4：页面根据实际员工 + 当前工序加载固定模板。
- 路径 5：生产员工填写上一个工序输入数量、设备参数、输出数量、损耗数量，完成电子签名并确定提交。
- 路径 6：PQC 员工填写检测成功或检测失败，完成电子签名并确定提交。
- 路径 7：管理人员查看工序池事件、报工来源、记录本来源和原始 payload。
- 路径 8：系统按生产工单计划开始时间执行或展示 FIFO 分配结果。
- 路径 9：管理人员打开工序池时间轴 / 甘特图，按日期、员工、工序、设备、模板类型、生产工单过滤。

## Browser or Client Steps

1. 使用 Playwright 打开本机前端入口。
2. 使用已确认的设备账号登录。
3. 进入现有报工入口或一线报工模式，断言入口仍体现“报工”路径。
4. 选择设备账号绑定的工艺路线和工序，断言未授权工序不可见或不可选。
5. 打开员工切换控件，断言候选员工只来自当前工序绑定员工。
6. 切换到目标实际员工，断言登录账号未改变且未出现密码、验证码、扫码或二次验证弹窗。
7. 等待固定模板渲染，断言生产模板只展示输入数量、设备、设备参数、输出数量、损耗数量，不展示可编辑时间字段。
8. 输入超出审核范围的设备参数值，例如 `50` 或 `10`，断言页面允许继续提交。
9. 点击确定提交，完成目标实际员工的电子签名。
10. 等待提交成功响应，记录页面返回的报工、记录本或工序池事件标识。
11. 通过只读接口或页面详情核验 `feedbackId`、`recordbookEntryId`、`processPoolEventId` 互相关联。
12. 使用 PQC 员工重复路径，选择 PQC 简化模板，只提交检测成功或检测失败。
13. 打开工序池时间轴 / 甘特图，按当天过滤，断言生产事件和 PQC 事件均展示。
14. 使用员工、工序、设备、模板类型、生产工单组合过滤，断言结果收敛。
15. 打开事件详情，断言显示登录账号、实际填写员工、电子签名员工、服务端提交时间、原始 payload、FIFO 状态、审核副本状态和修改历史摘要。

## API Verification

- 只读核验报工记录存在且生产工单、工序、数量字段正确。
- 只读核验记录本条目和记录本事件存在，且保存原始字段值。
- 只读核验工序池提交事件存在，且关联 `feedbackId`、`recordbookEntryId`、实际员工、登录账号、电子签名、服务端提交时间。
- 只读核验超限原始值没有被裁剪。
- 只读核验 PQC 成功 / 失败记录归入对应工序池。
- 只读核验 FIFO 分配明细只指向生产工单，不使用排产目标字段。
- 只读核验时间轴查询接口无写入副作用。

## Console and Log Checks

- Playwright 捕获 `pageerror` 和 console error，未解释错误必须导致 E2E 失败或阻塞。
- 记录关键网络请求：组合提交、记录本写入、工序池事件创建、PQC 入池、时间轴查询。
- 记录 MES 写请求数量和目标，确保时间轴路径无写请求。
- 日志和证据不得包含密码、token、cookie、Authorization 或电子签名明文密钥。
- 失败时记录页面 URL、租户/账号标签、生产工单编码、工序编码、事件 ID、截图路径和业务错误信息。

## Test Blockers

- 本机前端或后端未运行。
- 缺少登录前置、测试租户、设备账号、实际员工、设备、工作站。
- 设备账号未绑定 `X >= 1` 个工艺路线。
- 工序未绑定员工或员工未绑定固定模板。
- 缺少可写入测试生产工单或生产任务。
- 缺少电子签名测试能力。
- 缺少正式工序池模型和组合提交接口。
- 缺少生产工单 `plannedStartTime`，且业务未确认空值处理规则。
- 缺少 PQC 成功 / 失败对可分配数量的正式规则时，FIFO E2E 只能验证“不消费非可分配状态”，不能宣称 PQC 业务闭环通过。
