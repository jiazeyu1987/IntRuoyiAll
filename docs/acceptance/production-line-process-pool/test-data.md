# 生产一线报工工序池测试数据计划

## Purpose and Scope

本文档定义实现和 E2E 验证所需的任务自有测试数据。写入型 E2E 必须使用确认的测试租户和账号，创建带任务标识的数据，并在任务结束时按记录清理。

## Required Test Data

| 数据类型 | 最小要求 |
| --- | --- |
| 测试租户 | 一个明确授权用于 MES 写入型 E2E 的租户。 |
| 设备账号 | 可登录前端，作为现场设备/共享操作账号，不代表实际填写员工。 |
| 实际员工 A | 绑定目标生产工序和生产模板。 |
| 实际员工 B | 绑定同一工序或另一工序，用于验证切换员工和 UI 切换。 |
| 越权员工 C | 不在目标班组长负责范围内，用于验证看板和复核越权拒绝。 |
| PQC 员工 | 绑定目标 PQC 模板和过程检验工序。 |
| 生产班组长账号 | 负责实际员工 A/B 和目标生产工序，可查看负责员工提交、复核员工提交、查看所有生产工单并标记异常、维护员工和设备参数。 |
| PQC 班组长账号 | 负责 PQC 员工和目标 PQC 工序，可查看负责范围内 PQC 提交并复核，可查看所有生产工单用于异常处理。 |
| 班组长负责范围 | 明确绑定生产班组长 -> 员工 A/B、目标工序；PQC 班组长 -> PQC 员工、目标 PQC 工序；不包含越权员工 C。 |
| 设备和工作站 | 设备账号对应的设备 `EQ-CODEX-PP-01` 和工作站 `WS-CODEX-PP-01`。 |
| 工艺路线 | 绑定给设备账号，至少包含两个普通生产工序和一个 PQC 过程检验场景。 |
| 工序绑定员工 | 当前工序只绑定员工 A/B，另准备一个未绑定员工用于负向校验。 |
| 固定模板 | 生产简化模板和 PQC 简化模板；生产模板包含输入数量、设备参数、输出数量、损耗数量。 |
| 生产工单 | 至少三张，具备明确 `plannedStartTime`；其中两张用于 FIFO 排序，一张用于验证班组长可查看非负责员工关联工单但不能查看非负责员工提交明细。 |
| 工序池事件 | 由真实组合提交产生，不直接 SQL 伪造用于通过 E2E。 |
| 电子签名 | 可用于测试的签名账号/签名记录，不在文档中记录明文凭据。 |
| 审核范围规则 | 一个字段范围 `20~40`，用于验证一线提交保留原始 `50` / `10`。 |
| 审核账号 | 具备生成和提交审核副本权限的账号，以及一个无审核权限账号用于负向验证。 |
| 审核副本样本 | 同一模板字段准备 `10`、`30`、`50` 三类原始值，分别验证下限修正、范围内不变、上限修正。 |
| 字段映射元数据 | 原始 payload 字段到固定模板字段定义的正式映射，包含字段编码、字段名称、上下限和是否影响分配。 |
| 原始记录 revision 样本 | 一条未 FIFO 分配事件用于修改成功路径，一条已 FIFO 分配事件用于修改拒绝路径。 |
| 修改原因样本 | 有效修改原因、空原因、空白原因，用于验证 F6 阻塞。 |
| 生产工单异常样本 | 测试生产工单 `WO-CODX-ABN-01` 和非负责员工关联工单 `WO-CODX-ABN-OUT-01`，用于班组长全量生产工单列表、异常标记、填写说明并上报。 |
| 不良原因样本 | 初始原因 `外观不良`，新增原因 `封口不良`，用于验证维护、生效范围和模板选择。 |
| 可新增设备样本 | 设备 `EQ-CODEX-PP-NEW-01`，用于班组长给目标工序增加设备。 |
| 设备参数上下限样本 | 参数 `pressure` 下限 `20`、上限 `40`，用于验证一线原始 `50` 不被拦截、审核副本修正为 `40`。 |
| 班组维护审计样本 | 员工添加/禁用、不良原因、工序设备、参数上下限维护均需生成维护人、维护时间、生效范围和变更前后值。 |

## Reset Procedure

- 所有测试数据命名包含任务标识，例如 `CODX-PPOOL-<runId>`。
- 生产工单、工序池事件、记录本条目、报工记录、FIFO 分配明细按任务标识或来源关联清理。
- 审核副本、审核副本字段明细、原始记录 revision 和字段级 diff 按来源工序池事件和任务标识清理。
- 班组长复核记录、生产工单异常记录、异常上报记录、班组员工绑定、员工禁用状态、不良原因、工序设备绑定、参数上下限和维护审计按任务标识清理或恢复。
- 若测试涉及全局配置或权限绑定，执行前记录原始状态，执行后恢复并复验。
- 已经用于验证“FIFO 分配后不可修改”的记录不得通过物理删除掩盖业务状态；清理必须按测试数据生命周期策略执行。
- 已用于验证审核副本和原始记录修改的事件必须保留到只读核验完成后再清理，不得先删除来源再声称副本或 revision 可追溯。
- 已用于验证班组长复核和异常上报的原始提交、生产工单和维护审计必须保留到只读核验完成后再清理。
- 失败时保留本次任务证据，但不得修改生产租户、admin 基线数据或无关真实业务记录。

## Data Ownership

- 设备账号、员工、设备、工作站、路线和模板绑定属于当前任务测试前置数据。
- 报工、记录本条目、工序池提交事件、PQC 记录、FIFO 分配明细属于当前任务写入数据。
- 时间轴 / 甘特图 E2E 只读查看本任务创建的工序池事件。
- 审核副本、修正规则、审核签名和审核状态属于当前任务写入数据。
- 原始记录 revision、字段级 diff、修改原因和重新签名属于当前任务写入数据。
- 班组长负责范围、复核记录、生产工单异常记录、异常上报记录属于当前任务写入或配置数据。
- 员工添加/禁用、不良原因、工序设备绑定、设备参数上下限和维护审计属于当前任务配置数据，必须可恢复。
- 电子签名凭据和登录凭据只保存在安全配置或运行环境，不写入 Markdown。

## Test Blockers

- 没有可授权的写入型测试租户。
- 没有设备账号或设备账号不能绑定工艺路线。
- 没有可作为实际员工的用户，或无法绑定到工序。
- 没有电子签名测试能力。
- 没有正式记录本模板、固定模板或工序池模型。
- 没有审核副本模型、字段上下限元数据、审核权限和审核电子签名能力。
- 没有原始记录 revision 模型、字段级 diff 生成能力、修改原因字段或 FIFO 锁定查询能力。
- 没有生产班组长 / PQC 班组长测试账号、负责范围配置、全量生产工单异常入口权限、复核状态、异常上报状态或班组维护审计能力。
- 没有不良原因列表、工序设备绑定、设备参数上下限规则，或上下限无法被审核副本读取。
- 没有具备 `plannedStartTime` 的生产工单。
- 数据清理策略不明确时，不得运行写入型 E2E。

## Initial Test Data Defaults

- 工序池样本数据必须包含同一生产工单同一工序的多员工多次提交，用于验证数量累计和原始事件不覆盖。
- FIFO 样本生产工单必须准备不同 `plannedStartTime` 的正向数据，以及空值/重复值的负向数据。
- PQC 样本必须同时准备成功和失败记录；成功样本进入可分配，失败样本进入不可分配并带失败原因。
- 班组长样本必须同时准备负责员工、非负责员工、负责员工关联工单和非负责员工关联工单，用于验证范围过滤与工单全量可见并存。
- 设备参数上下限样本默认使用 `pressure` 下限 `20`、上限 `40`，覆盖原始 `10/30/50` 三类值。
