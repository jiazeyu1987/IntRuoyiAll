# 生产一线报工工序池 Open Questions / Blockers 初始定义

## Purpose and Scope

本文档把当前线程中尚未完全冻结的业务点，先按当前 IntRuoyi 系统业务给出可讨论、可测试、可阻塞的初始定义。

适用范围：

- 一线入口：现有“报工”入口的一线简化模式，同时写入记录本。
- 核心模型：新增正式工序池、工序池提交事件、PQC 过程检验、审核副本、原始记录 revision、生产工单 FIFO 分配。
- 管理入口：生产班组长 / PQC 班组长提交看板、复核、异常上报，以及班组员工、不良原因、工序设备和设备参数上下限维护。
- 非范围：不考虑排产系统；订单只按生产工单理解；不把现有 `mes_pro_feedback_surplus_pool` 当作本方案工序池。

## Definition Rules

| 类型 | 初始定义 | 处理规则 |
| --- | --- | --- |
| Open Question | 业务方向已明确，但字段口径、配置入口、状态枚举、排序细则、UI 范围或归属模块还需要确认。 | 可以继续做模型草案、BDD/TDD、接口草案；不能把未确认点写死为不可变生产规则。 |
| Blocker | 缺少后会导致正式链路无法正确落库、验收、审计、权限隔离或数量分配的前置条件。 | 对应功能不得用默认值、mock、文本备注、API-only、前端隐藏或现有余量池替代；必须 fail fast。 |
| Initial Definition | 在业务未进一步确认前，按当前系统和用户已确认口径给出的第一版建议。 | 后续用户或业务确认后，可升级为 Decision；若被否定，需要同步更新 BDD/TDD 和实现计划。 |

## Current System Business Baseline

Open Questions 和 Blockers 的初始定义按以下现有系统业务基线理解。后续如果业务确认结果与本基线不同，必须同步调整本文档、BDD/TDD 和实现计划。

| 现有系统能力 | 初始定义中的定位 | 可复用部分 | 不可替代或待补齐部分 |
| --- | --- | --- | --- |
| 生产报工 | 一线主入口；一线点击“确定提交”时，既完成报工，也触发记录本和工序池写入。 | 现有报工表单、报工数量、损耗数量、生产任务/生产工单累计逻辑。 | 需要组合提交事务和正式来源关联；不能由前端串联多个接口模拟同一提交。 |
| eDHR 记录本 | 承载一线原始事实数据，保留员工原始输入、设备参数、记录本事件和修改历史来源。 | 记录本模板、记录本条目、记录本事件、字段审计基础能力。 | `min/max` 不能作为一线提交拦截；审核限值必须进入审核副本规则。 |
| 正式批记录 | 承载审核后的正式表达和归档追溯，不直接替代一线原始记录。 | 批记录执行、逐工序批记录表单绑定、字段审计和审核视图。 | 批记录表单来源只能按工序设置正式绑定读取；不得由 `formBindings`、工序开始或记录本模板推断。 |
| 生产工单 | FIFO 的订单口径；工序完成数量判断围绕生产工单/生产任务累计数量。 | `plannedStartTime` 作为 FIFO 主排序候选，生产任务/工单已生产数量累计能力。 | 缺 `plannedStartTime` 时必须阻塞；不能 fallback 到排产、创建时间、工单号或当前时间。 |
| 报工余量池 | 现有余量/超产池，只能作为参考或工序池下游余量承载。 | 余量池数量字段、来源报工、已分配数量和分配流水经验。 | 不能替代新增正式工序池；缺工序池提交事件、PQC、记录本、电子签名、实际员工和生产工单 FIFO 目标。 |
| 工艺路线 / 工序 / 设备 / 用户 | 作为一线报工上下文、账号可切换范围、员工候选和模板解析的基础主数据。 | 现有路线、工序、设备、用户、权限和候选人能力。 | 需要正式表达账号到路线、路线到可切换工序、工序到员工、员工/工序到模板的绑定关系。 |
| 电子签名 / 审计 | 每次提交、复核、审核副本、原始记录修改的责任凭证。 | 现有 eDHR/批记录签名和审计能力可优先复用。 | 必须补齐签名场景、签名员工等于实际员工、字段级 revision 和维护审计；不能用普通登录态替代签名。 |
| 班组长权限 | 负责范围内查看、复核员工提交和维护班组配置；可查看生产工单并标记异常。 | 现有用户、角色、菜单、权限、生产工单查询能力。 | 需要班组长负责范围模型和维护审计；全量生产工单异常处理不得扩大非负责员工提交明细权限。 |

## Initial Open Questions

| ID | 问题 | 初始定义 | 当前建议 | 未确认时的影响 |
| --- | --- | --- | --- | --- |
| OQ-01 | 工序池归集维度 | 工序池不是全局资源池，至少围绕生产工单、生产任务、路线/路线工序、MES 工序、模板类型和质量状态归集。 | 设备、工作站、班次、日期作为事件明细或查询维度优先，不默认参与池唯一维度；产品、物料、批号从生产工单/任务快照带入。 | 可以先做草案；最终 schema 和唯一约束未确认前，不能冻结模型。 |
| OQ-02 | 与现有报工余量池关系 | `mes_pro_feedback_surplus_pool` 是现有报工余量/超产余量池，不是本方案工序池。 | 新增工序池作为主模型；是否向现有余量池同步可分配余量作为后续集成问题。 | 不阻塞新增工序池设计；阻塞“用余量池直接替代工序池”的实现。 |
| OQ-03 | 组合提交接口 | 一线点击“确定提交”必须同一事务完成报工、记录本、工序池提交事件和来源关联。 | 建议新增一线组合提交应用服务/API，内部复用现有报工和记录本能力；不由前端串联多个普通接口。 | 未确认接口形态前，可写契约测试；不能进入前后端最终联调。 |
| OQ-04 | 报工/记录本/批记录字段映射 | 同一页面 payload 要拆成报工数量字段、记录本原始事实字段、后续批记录审核字段。 | 先按四类字段定义：上工序输入数量、设备/设备参数、输出数量、损耗数量；用正式字段映射表，不靠备注或文本匹配。 | 缺映射时组合提交不能宣称可追溯。 |
| OQ-05 | 固定 UI 模板范围 | 员工 UI 固定几类模板，不做无限自由配置。 | 第一版建议：生产简化模板、PQC 简化模板、损耗补充模板；班组长复核/维护属于管理页面，不算一线填报模板。 | 未确认模板清单前，前端页面和模板接口只能做草案。 |
| OQ-06 | 设备账号/路线/工序/员工/模板配置入口 | 有限设备上登录共享操作账号，账号绑定 `X >= 1` 个工艺路线，账号内切换工序和实际员工。 | 配置必须是正式数据来源：账号到路线、路线投影工序、工序到员工、员工/工序到模板；可以复用现有用户、设备、路线和工序配置，但缺口要建正式绑定。 | 缺正式来源时，F4/F9/F10 权限和 UI 切换不能实现。 |
| OQ-07 | 登录账号和实际员工字段落点 | 登录账号、实际填写员工、电子签名员工、设备、工作站必须分离留痕。 | 工序池提交事件保存登录账号和实际员工；电子签名员工必须等于实际员工；设备和工作站保存现场上下文。 | 字段落点不清会阻塞审计、时间轴和班组长责任范围。 |
| OQ-08 | 电子签名来源 | 每次提交、复核、审核副本提交、原始记录修改都需要唯一签名场景。 | 优先复用现有 eDHR/批记录签名能力；若现有能力缺少场景或签名主体校验，需要补正式签名契约。 | 缺正式签名接口或测试签名能力时，对应写入功能阻塞。 |
| OQ-09 | 服务端时间 | 一线员工不手填时间；提交时间、审核时间、修改时间由服务端生成。 | 前端不展示可编辑时间字段；后端拒绝使用前端传入时间作为事实时间。 | 不阻塞模型草案；阻塞任何依赖手填时间的提交实现。 |
| OQ-10 | 工序完成数量口径 | 工序完成由生产工单/任务下该工序累计数量判断，不由路线顺序或记录本完整性判断。 | 第一版建议以输出/完成数量累计判断完成；PQC 通过数量和可分配数量用于质量和 FIFO 消耗口径，是否替代完成数量需按工序确认。 | 未确认时，工序完成状态和看板完成率阻塞。 |
| OQ-11 | PQC 失败影响 | PQC 第一版只录成功/失败，但失败必须进入工序池质量过程明细。 | 初始定义：PQC 失败进入不可分配/失败质量状态；是否扣减待检、可分配或触发返工需要业务确认。 | 未确认时，FIFO 只能消费已明确可分配数量，不能宣称完整 PQC 闭环。 |
| OQ-12 | FIFO 排序和并列排序 | FIFO 只按生产工单，不按排产；主排序为生产工单计划开始时间。 | `plannedStartTime ASC`；同一时间建议再按生产工单编码或 ID 稳定排序，需要业务确认。 | 缺计划开始时间必须阻塞；二级排序未确认会阻塞并列样本验收。 |
| OQ-13 | `plannedStartTime` 为空 | 生产工单缺计划开始时间时不能参与 FIFO。 | 初始定义为整体阻塞本次分配，不 fallback 到创建时间、工单号或当前时间。 | 该规则可直接作为测试 blocker。 |
| OQ-14 | 原始记录修改规则 | 原始记录提交后允许修改，但必须保留字段级日志并重新电子签名。 | 修改原因必填；审批是否必需暂不纳入第一版，除非业务确认；已 FIFO 分配影响数量/质量/可分配状态的字段禁止修改。 | 缺 revision、字段 diff、修改原因或 FIFO 锁定查询时，F6 阻塞。 |
| OQ-15 | 审核副本规则 | 审核副本不改写原始值，只处理超出限制的值并保留 raw/corrected。 | 第一版只做上下限自动夹紧：低于下限取下限，高于上限取上限；是否允许审核人二次手改，暂按不允许。 | 缺上下限元数据、字段映射、审核签名或状态枚举时，F5 阻塞。 |
| OQ-16 | 班组长提交范围 | 生产班组长和 PQC 班组长只看自己负责员工/PQC 员工的提交详情。 | 全量生产工单可用于异常标记和上报，但不得扩大非负责员工提交明细权限。 | 缺班组长负责范围模型时，F9 看板和复核阻塞。 |
| OQ-17 | 班组长复核语义 | “复核员工提交”是新增复核记录，不是修改员工原始提交。 | 复核只写状态、复核人、服务端时间、说明/结果、签名或审计；不得改写 payload、报工、记录本、FIFO、审核副本。 | 缺复核状态模型或审计记录时，F9 复核阻塞。 |
| OQ-18 | 班组维护范围 | 班组长可添加/禁用自己范围内员工，维护不良原因、工序设备和设备参数上下限。 | 维护动作必须受班组/工序范围限制，并写审计；禁用员工只影响未来候选，不改历史记录。 | 缺范围校验和维护审计时，F10 阻塞。 |
| OQ-19 | 压力泵设备编码和产能异常 | `B09032/G01160` 已确认表示两台设备；其它斜杠编码默认按多设备候选处理仍需确认。 | `A03378/A03377` 与设备数量 `1`、末尾孤立产能值只作为待确认主数据问题，不自动导入正式主数据。 | 阻塞自动导入压力泵工序主数据，不阻塞手工配置试点。 |
| OQ-20 | 批记录/记录本/表单槽位边界 | 正式批记录表单仍来自工序设置逐工序绑定；记录本保存一线事实。 | `formBindings` 表单槽位和“工序开始”配置不得替代批记录表单；组合提交只建立正式来源关联。 | 任何缺正式批记录绑定却用表单槽位补齐的实现必须阻塞。 |

## Initial Blockers

| ID | Blocker | 初始定义 | 阻塞的工作 | 解除条件 |
| --- | --- | --- | --- | --- |
| BLK-01 | 缺少正式工序池模型 | 没有工序池主表、提交事件、数量片段、PQC 明细、FIFO 分配明细等正式模型。 | F1/F7/F8/F9 及任何生产工单 FIFO 实现。 | 新增并验证工序池 schema，且明确不复用 `mes_pro_feedback_surplus_pool` 作为主模型。 |
| BLK-02 | 缺少组合提交事务 | 报工、记录本和工序池事件无法在同一事务内保存并建立来源关联。 | F2 一线入口、记录本追溯、时间轴来源核验。 | 组合提交契约和服务通过 RED/GREEN，失败时整体回滚。 |
| BLK-03 | 缺少固定模板和字段映射 | 无法确定哪些字段进入报工、记录本、审核副本或 PQC。 | F3 前端、payload 拆分、审核副本字段修正。 | 形成第一版模板清单、字段编码、字段名称、上下限和影响分配标记。 |
| BLK-04 | 缺少电子签名能力 | 无法证明提交、复核、审核、修改的责任主体和唯一性。 | F1/F2/F5/F6/F9 的写入验收。 | 正式签名接口、签名场景、签名员工校验和测试签名数据可用。 |
| BLK-05 | 缺少设备账号和员工绑定来源 | 账号无法限定路线/工序，工序无法限定员工，员工无法解析模板。 | F4 一线切换、F9/F10 范围权限。 | 正式绑定配置、查询接口和越权失败测试通过。 |
| BLK-06 | 缺少数量完成与 PQC/FIFO 规则 | 无法判断工序完成、可分配数量和 PQC 失败后的消耗状态。 | F5/F7/F8 看板、FIFO 分配和工序完成状态。 | 完成数量、合格数量、PQC 通过/失败、可分配数量口径确认并进入测试。 |
| BLK-07 | 生产工单缺 `plannedStartTime` | 生产工单无法按 FIFO 主排序参与消耗。 | F7 FIFO 分配。 | 数据补齐计划开始时间，或业务明确该工单不得进入 FIFO。 |
| BLK-08 | 记录本 `min/max` 仍拦截一线原始值 | 一线输入 `10` 或 `50` 会被提交阶段拒绝或裁剪，破坏原始记录保留规则。 | F2/F3/F5。 | 拆分结构校验和审核限值规则；一线保留原始值，审核副本再夹紧。 |
| BLK-09 | 缺少审核副本和 revision 模型 | 原始/修正值、修改日志、重新签名和字段级 diff 无正式承载。 | F5/F6 和审核追溯。 | 审核副本表、字段明细、revision、字段 diff、修改原因、签名和 FIFO 锁定查询可用。 |
| BLK-10 | 缺少班组长范围与审计 | 班组长看板、复核、异常上报、员工/原因/设备/参数维护无法做权限隔离。 | F9/F10。 | 班组长负责范围、维护范围、复核记录、异常记录和维护审计模型可用。 |
| BLK-11 | 缺少真实测试数据 | 没有测试租户、设备账号、员工、工序、路线、模板、生产工单、签名能力。 | 真实 E2E 和写入型验收。 | 建立任务自有测试数据和清理策略，且不污染生产租户或 admin 基线。 |
| BLK-12 | 压力泵主数据存在未确认异常 | 设备编码拆分、设备数量冲突、孤立产能值未确认。 | 自动导入正式压力泵主数据。 | 业务确认异常行含义，或明确这些字段只人工配置、不进入自动导入。 |

## Current Non-Blocking Defaults

- 报工是生产一线主入口；记录本不是另一个割裂入口，而是同一次提交的记录本落点。
- 工艺路线可配置，但一线提交不按路线前后置强制限制。
- 员工提交时间、审核时间、修改时间均使用服务端时间。
- 员工在共享设备账号内切换到本人时不额外验证身份；电子签名代表本次身份确认。
- 审核副本第一版只处理上下限，不处理复杂工艺规则、损耗比例规则或人工任意改值。
- 原始记录修改必须重新电子签名；已 FIFO 分配给生产工单且影响分配的字段不能修改。
- 班组长能看所有生产工单用于异常标记，但提交明细仍受负责员工/PQC 范围限制。

## Verification Use

- BDD 文档引用 OQ 编号描述尚待业务确认的边界。
- TDD 文档引用 BLK 编号记录 RED 失败原因和 GREEN 解除条件。
- E2E 计划中遇到 BLK-11 类型前置缺失时，必须记录 BLOCKED，不得用 API-only 或 mock 替代真实路径。
- 实现阶段若某 Open Question 被用户确认，应把对应 OQ 从本文档同步升级到 `docs/inception/project-brief.md` 的 Decisions 或实现任务文档。
