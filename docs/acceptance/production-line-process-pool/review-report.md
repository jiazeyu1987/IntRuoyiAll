# 生产一线报工工序池子 Agent Review 报告

## Review Scope

本报告审查 6 个子 agent 产出的功能点文档草案，并按 21 条需求门禁判断是否可进入后续设计 / 开发拆分。

审查对象：

- F1 工序池基础模块，子 agent A。
- F2 报工 + 记录本一体提交模块，子 agent B。
- F3 固定模板录入模块，子 agent C。
- F4 设备账号内切换员工模块，子 agent D。
- F7 生产工单 FIFO 分配模块，子 agent E。
- F8 工序池时间轴 / 甘特图查询模块，子 agent F。

## Review Result

文档层面结论：**放行**。

放行范围仅限于 BDD/TDD/验收文档进入下一步系统设计和实现拆分。生产代码实现仍未放行；实现阶段必须重新按 `RED -> GREEN -> REGRESSION` 执行，并补齐正式 schema、接口、测试数据和 E2E 前置条件。

## Adjustments Applied

- 将 6 份草案合并到 `docs/acceptance/production-line-process-pool/`，避免覆盖既有 `docs/acceptance/*.md` 中的 Codex 测试管理文档。
- 将“审核副本上下限”和“原始记录修改重签名”明确为本轮 6 个功能点必须保留的边界约束，而不是在本轮文档中伪装已经实现。
- 将 FIFO 的 `plannedStartTime` 空值处理明确为 blocker，禁止 fallback 到创建时间、工单号或当前时间。
- 将 PQC 成功/失败对可分配数量的最终业务影响标记为待确认；FIFO 模块只消费工序池已经正式标记为可分配的数量。
- 将固定模板名称保留为建议枚举，不作为业务已确认最终命名。
- 强化批记录表单、表单槽位 `formBindings`、工序开始配置不得混用。

## Subagent Findings

### F1 工序池基础模块

结论：PASS。

理由：草案正确区分新增工序池与 `mes_pro_feedback_surplus_pool`，覆盖“工序池提交事件”、唯一电子签名、唯一提交时间、PQC 入池、原始 payload 和路线不阻断。

需保留的 blocker：正式工序池模型缺失时不能进入实现。

### F2 报工 + 记录本一体提交模块

结论：PASS。

理由：草案正确把一线入口定义为报工和记录本组合入口，要求同一事务写入报工、记录本和工序池事件，并覆盖服务端时间、实际员工签名、路线不阻断、原始超限值不拦截。

需保留的 blocker：组合提交采用新增接口还是扩展现有报工接口需要系统设计统一。

### F3 固定模板录入模块

结论：PASS，带命名待确认。

理由：草案覆盖固定模板、四类生产字段、PQC 成功/失败、员工切换后 UI 变化、不手填时间、不用 `min/max` 拦截。

修正：模板枚举名只作为工程建议，不作为业务最终命名。第一版模板清单仍需业务确认。

### F4 设备账号内切换员工模块

结论：PASS。

理由：草案完整覆盖有限设备、设备账号、路线范围、工序候选、员工候选、不二次验证、实际员工签名和完整身份留痕。

需保留的 blocker：账号绑定路线、工序绑定员工、员工工序模板绑定的正式配置入口需要确认。

### F7 生产工单 FIFO 分配

结论：PASS，带 blocker。

理由：草案正确排除排产系统，以生产工单 `plannedStartTime` 为 FIFO 排序依据，要求分配流水追溯到工序池事件和数量片段，并锁定已分配记录。

修正：`plannedStartTime` 缺失不得 fallback；PQC 对可分配数量的影响由上游质量状态决定，FIFO 模块不临时推断。

### F8 工序池时间轴 / 甘特图

结论：PASS。

理由：草案覆盖按天查看谁提交了什么、多条件过滤、生产/PQC/损耗/设备参数摘要、身份区分、FIFO 状态、审核副本状态、修改历史和只读边界。

需保留的 blocker：甘特图事件时长未确认；当前只有唯一提交时间时，第一版应按时间点事件或固定视觉宽度展示。

## Release Conditions For Implementation

进入代码实现前必须先完成：

- 工序池主模型、事件模型、数量片段、分配明细、修改日志、审核副本关联的系统设计。
- 报工、记录本、工序池事件的组合提交契约。
- 设备账号、路线、工序、员工、模板的配置来源。
- 电子签名正式接口和测试签名方案。
- 固定模板第一版清单和字段映射。
- PQC 成功/失败对质量状态和可分配数量的规则。
- 生产工单 `plannedStartTime` 空值处理规则，或明确阻塞策略。
- E2E 测试租户、设备账号、员工、设备、工作站、生产工单、路线、工序、模板和签名数据。
