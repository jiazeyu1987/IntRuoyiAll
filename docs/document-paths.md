# 文档路径约定

- 项目根目录指当前 Git 仓库根目录，不绑定电脑盘符、用户名或安装目录。文档中新归一化的 `./IntRuoyiBackend`、`./IntRuoyiFronted`、`./docs`、`./resource` 等路径均相对此目录；命令明确要求其他工作目录时，先进入该目录，再调整命令中的相对路径。
- Markdown 链接相对链接所在文档的目录解析；行内路径和命令路径不能直接当作同一层级的 Markdown 链接。
- 项目规则、设计依据和执行说明只引用本仓库收录的文件。旧维护仓已有对应内容的，使用本仓库实际存在的文档；没有收录的历史外部材料取消文件引用，不证明相关历史验证已在当前环境复跑。
- 测试所需真实材料放在本项目 `resource/` 或 `e2e_test/` 的任务目录，通过实际相对路径指定；目录示例不代表材料已经存在。执行前检查文件，缺失时报告缺少输入，不生成假材料、不跳过验证。
- Java、Node、Maven、浏览器等工具按当前环境配置。命令优先使用 PATH 中的入口，JDK 使用当前进程的 `JAVA_HOME`；不引用个人工具安装目录或个人技能文件。
- Website、发票打印助手等有实际集成关系的独立项目可以保留引用。`../Website`、`../erp-invoice-voucher-print-assistant` 是同级检出布局示例，使用前明确实际相对目录；不存在时报告集成前置条件缺失，不自动换目录。
- `../IntRuoyiWorktree` 仅表示本项目附加 Git worktree 的相对布局示例。实际根目录由使用者选择并通过 `-WorktreeRoot` 等现有参数约束，不作为跨电脑的强制目录。端口登记和路径边界以 `docs/worktree-restrictions.md`、`docs/branch-runtime-ports.md` 为准。
- 本次仅整理文档引用。控制台、发布及其他操作仍需本项目实际具备对应实现和必要配置；文档改为相对路径不代表旧维护仓的程序、配置或历史证据已迁入本项目。缺少实现或入口时明确阻断依赖它的操作。
