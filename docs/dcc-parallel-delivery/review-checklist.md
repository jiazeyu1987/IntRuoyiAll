# 主管理 Review 门禁

主管理逐小批次Review，先确认需求和Owner，再看生产实现与测试。当前仅完成任务计划Review，代码交付尚未提交。

## R0 基线与范围

- 基线共同、分支实际身份正确、工作区指纹差异有说明，既存修改已确认归属。
- 所改文件均在Owner允许范围；公共文件差异经主管理接入，没有用重复类/接口绕过归属。
- 每个新行为都有Given/When/Then和业务有效RED；依赖缺失失败不能冒充RED。
- 明确未获授权的Git/数据库/服务/E2E动作未执行；未把未运行写PASS。

## R1 数据与接口

- 项目默认≠申请实际快照；三路径分别初始化，作废申请不改原版本；草稿不会被新默认覆盖。
- 最新受控≠当前执行；所有读写调用点采用统一定位，关联可指待生效，但执行下载/打印不提前使用。
- 变更类型存实际动作，历史不猜；名称以完整源件名称大小写精确比较，受控PDF派生名不参与原名称唯一键。
- 数据库唯一、租户、版本分配、引用计数、保留期身份与服务比较一致；H2结果不能替代实际MySQL字符比较。
- 新迁移有dependsOn、首次/重跑合同和历史零回写保护；不改历史签名/版本事实。

## R2 流程与权限

- 上传升版六阶段准确，培训可选；作废批准结束，没有多余文控节点。
- 指派与实际会签分别签名，每部门义务完整；审批中心/模块详情/FormCenter所有入口一致，不能快速批准绕过指派。
- 文控审核驳回返工，旧轮签名不能当新轮通过；培训完成标准明确，不空名单/任意附件自动过关。
- 项目负责人权限有正式账号事实，引用/取消前后端检查，admin菜单不旁路。
- 所有失败准确报错，不fallback第一人、管理员、旧正文、旧票据或假成功。

## R3 事务、异步及恢复

- 新版提前受控不作废旧版；到生效日期同一事务完成新版生效、旧版作废和执行定位，具备锁、幂等与审计。
- 生效失败不留下无执行版；跨文件存储操作不先挪走旧版正文造成数据库回滚但文件缺失。
- 受控事件与生效事件明确分开，D整改通知只在真实受控成功后触发一次；撤回/驳回/失败零通知。
- 占用保留不因独立作废立即release；期满仍有当前版的身份不被误释放。
- 引用与取消计数事务、最后一个引用颜色变化正确，不删源文件或关联。
- 新/旧流程在途切换明确；原生监听器与FormCenter效果不双执行作废。

## R4 UI与证据

- 操作顺序、二次确认、取消保留、失败保持和旧响应不串上下文正确。
- 正文、日期、版本、属性、关系使用同一正式版本；历史查看不加载当前配置覆盖证据。
- 术语统一受控版本，待生效/已作废有明确文字；引用颜色同时有文字说明。
- 测试真实执行、数量非零、新测试覆盖失败与并发；旧测试只因旧行为变化时同步合同，不删测试造PASS。
- 定向回归后无P0/P1问题才accepted_for_integration；集成后I-01..I-08通过才能结束代码Review阶段。

## Review 输出格式

每条问题包含：编号/优先级、具体触发、用户影响、文件及方法/行锚点、正确规则、最小修复范围、验证场景、处理状态。不要仅写“建议优化”。

P0/P1阻断整合；P2按影响决定是否纳入当前验收，不能凭“已有测试通过”忽略真实需求错误。Review无问题时写“本批次范围内未发现阻断问题”，不声称全系统正确。

## 最终报告

逐AC列已满足/部分满足/未满足/待确认/未运行，附当前基线证据；列出集成提交范围、SQL执行状态、构建/测试/E2E结果和未授权事项。主管理对最终用户报告负责，模块自行宣布完成不能代替主管理Review。
