## 1. 各线程固定验证顺序

1. 写Given/When/Then，注明需求AC编号、模块BDD编号、失败与并发边界。
2. RED：在共同基线上执行新业务测试，记录真实失败原因；依赖或配置失败不是有效业务RED，先准确记录阻塞。
3. GREEN：实现后运行同一测试及对应模块回归，记录命令、cwd、退出码、实际测试数量。
4. 编译与前端类型：先定向测试，再主管理统一检查公共模型、组件接入和构建。不启动多个全量vue-tsc争用内存。
5. Review后纳入集成矩阵；不同Owner交叉行为需组合测试，不以各自单测都通过代替。

后端Java17及Maven，前端pnpm。Maven带点号的-D参数整体加引号；PowerShell命令不得用&&，命令失败不能继续记作成功。禁止修改测试库配置为真实业务库。

## 3. 必测的跨模块组合

- **I-01 B→A：**项目默认值被本申请修改，进入指派、会签、批准、培训、文控审核、受控、下发均显示同一冻结实际值。
- **I-02 C→A：**检入小版→局部/换版选定小版→审批→提前受控→生效自动作废旧版。新旧正文、版本号、类型及日期一致。
- **I-03 A→D：**受控成功后当前关联更新及所选整改人通知；未来生效只切执行旧版，不重复发受控整改通知。
- **I-04 A→C：**独立作废批准结束，名称编号保留；同一文件链升版复用身份，不被自己的作废历史阻断。
- **I-05 B→D：**目标项目负责人可引用/取消；普通成员、其他项目负责人、未任该负责人admin被拒；计数按项目而非文件夹。
- **I-06 D→C→主管理：**跨项目关联当前版、历史版查看、源码名精确判重都以正式身份查询，不能用标题文本或缓存代替。
- **I-07 并发/重放：**生效定时任务、BPM回调、指派会签、引用计数、名称分配重试均去重，失败后不制造部分完成。
- **I-08 授权边界：**名称搜索不取得正文权限；引用不取得编辑权；错租户、错任务或签名失败所有入口拒绝。

## 4. 统一构建门禁

主管理在合入各模块并无待修问题后，于IntRuoyiBackend运行包含各模块新测试的DCC reactor测试及主应用编译；BPM、FormCenter、签名等跨模块变动对应测试另列，不能被DCC单测覆盖假设。

```powershell
mvn -pl yudao-server -am "-DskipTests" compile
```

此命令只证明编译，不能作为测试PASS。IntRuoyiFronted单次运行：

```powershell
$env:NODE_OPTIONS='--max-old-space-size=8192'
pnpm ts:check
pnpm build:local
```

记录两条命令各自真实结果；build也通过不代表业务页面验收。缺依赖、基线冲突、无关全量错误明确分类，禁止静默删测试或放宽类型规避。Git差异和端口守卫按仓库规则在授权整合时执行。
