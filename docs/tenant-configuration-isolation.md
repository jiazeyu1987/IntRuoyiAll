# 租户配置与资源隔离

## 业务要求

租户修改业务参数、对接账号、测试开关、模板或文件时，不改变其他租户的内容。完整租户复制必须包含数据库记录、对象存储文件及配置，并为新租户建立独立资源引用；只复制数据库中的文件 URL 不满足要求。

## 最新范围调整：不处理历史数据

- 用户已明确“不用管历史数据”。本次不再要求整理存量文件/消息的租户归属、回填历史记录、搬迁历史 MinIO/NAS 对象或修复旧直链；这些工作不作为后续开发的前提。
- 不处理历史数据不代表删除、清空历史数据，也不允许把无归属旧数据默认开放给所有租户。后续以切换后新增记录、配置修改和文件操作互不影响为验收范围。
- 主动执行“复制租户”仍遵循原始要求：复制所选源租户的数据、配置与文件，目标租户具有独立副本。这与提前清理平台存量历史数据是两项工作。
- 下文历史迁移与验证内容保留为已有实现记录，不再表示当前必须完成的工作。现有文件归属和消息历史迁移脚本仍含历史归属前置检查，需要调整配套切换方案后才能部署；不能直接跳过建表/字段变更，也不能以猜测归属代替历史迁移。

## 当前已实现的本地改动（尚未发布）

- `infra_tenant_config` 按租户保存参数。同名参数可以分别存在；读取、更新、分页、导出与删除都限制当前租户。即使调用链忽略自动租户拦截，也有显式租户条件。
- 原有 `ConfigService` 通用参数入口改用租户存储，覆盖使用该入口的 NAS、登录策略、业务设置、AI 语音凭据及展厅参数。ERP 连接选择与外部写入开关使用同一租户存储。
- 新建租户时，在创建事务及新租户上下文内，从既有参数模板一次性复制独立记录。初始化失败使租户创建失败；运行时不会因参数缺失而读取全局业务参数。
- NAS 多项配置整体事务保存。参数支持多次删除、重建，数据库唯一约束只限制未删除记录。
- 展厅自动发布按租户读取状态与设置，并校验目标站点归属；某租户失败不阻止其他租户执行，失败最终仍上报。讲解任务执行锁按租户区分，异步任务显式携带发起租户。

## 通知配置与历史记录隔离（本地代码）

- 邮件账号、邮件模板、短信渠道、短信模板、站内信模板改用 `system_tenant_*` 独立表。每个租户拥有独立记录及账号/渠道引用；原表只作为初始化模板与历史留档。
- 消息记录、发送日志及短信验证码同样分租户。新增强制租户标记，即使调用方设置忽略租户，也不能跳过这些表的租户过滤；缺少租户上下文直接失败。
- 邮件与短信异步消息携带发起租户，消费者进入该租户后发送并恢复工作线程上下文。短信回执根据渠道与发送记录确定唯一租户及日志编号，无法确定时失败。
- 删除混入其他租户编号时整批拒绝；邮件模板不能关联其他租户的账号。移除通知配置的无租户缓存，确保修改只由当前租户读取。
- 新租户创建事务内复制通知配置，后续创建步骤失败时一起回滚。展厅待办查询、生产任务关联审计及工作台写入检查已同步使用新消息表；历史消息编号保持不变。

迁移脚本 `20261112_tenant_notification_resources.sql` 依赖 `20260815_system_notify_message_business_key.sql`，需与配套应用一起切换，并先排空旧版本发送任务。原始记录保留，重复迁移不覆盖租户已修改的配置。旧邮件/短信日志不能确定归属时，迁移事务失败；应根据业务证据填写 `system_tenant_message_log_owner` 后重试，禁止猜测归属或把日志复制给所有租户。短信验证码保留原使用及过期状态。

历史站内信的原始模板编号保存为 `source_template_id`，当前租户模板引用保存为 `template_id`。原始模板已被物理删除时，保留完整消息快照与原始编号，当前引用为空；不重建未知模板，不把原始编号当作当前模板编号。详情明确显示“历史模板已删除”。新消息仍须由真实模板发送；数据库约束禁止两种编号同时为空。历史消息编号与已有目标消息发生身份冲突时，迁移事务失败。

## 字典及配置包隔离（本地代码）

- 字典类型和值改用 `system_tenant_dict_type/system_tenant_dict_data`，强制按当前租户读写；同名字典与同一字典键值可以分别存在于不同租户。混入其他租户编号的批量删除整批拒绝。
- Excel 字典缓存键包含租户，采用当前线程同步加载，避免异步刷新丢失租户上下文。字典提交成功及配置包导入提交后，仅清除当前租户缓存。
- 前端字典缓存包含租户与登录会话；切换访问租户立即停止显示原租户字典，丢弃原租户延迟返回的请求。空字典会清空旧内容，保存、删除、导入后使当前租户缓存失效。
- 同租户及跨租户配置包导入都只替换目标租户字典；跨租户导入生成独立记录编号。菜单与租户套餐仅作平台定义一致性检查，差异直接阻断，不再清空或重建全局表。审批资格版本只锁定、递增目标租户。
- `20261112_tenant_dictionaries.sql` 从原字典为现有租户建立独立副本，旧表保留为初始化模板。`system_tenant_dict_snapshot` 记录已初始化租户，防止重跑迁移恢复租户删除的字典；新租户在创建事务内完成同样初始化。源字典存在孤立值、重复有效类型、名称或键值时失败并回滚复制。
- 字典迁移必须与配套应用一起切换；未来业务 SQL 应明确更新目标租户的新字典表，修改旧模板不改变已有租户。字典不再支持运行时读取全局模板作为缺失值的补充。
- 54 项 Java 测试通过，覆盖真实租户 SQL 拦截、CRUD、缓存、创建事务、配置包隔离与审计失败回滚；前端缓存 5 项通过，独立 MySQL 字典迁移 3 项通过。服务端 Maven reactor 编译、受影响前端 ESLint、菜单迁移检查及迁移元数据检查通过。未执行前端 E2E或线上迁移。

## 必须保留的平台设置

- `system.gxp.audit-mode`：当前实现是在进程启动时确定的审计模式，属于整套服务设置。租户参数入口禁止创建、改名为或修改该配置，仅允许明确的只读查询。
- `runtime-control.*`：发布包与服务运行设置由平台部署维护，租户参数入口禁止修改；发布服务明确读取平台配置。
- 程序版本、服务端口、数据库连接池、平台基础权限定义等同样属于平台职责。服务器可以共用，但共用服务器不表示租户业务记录或文件可共用可写副本。

平台权限边界已增加本地实现：`system:menu`、`system:tenant`、`system:tenant-package`、`infra:codegen`、`infra:data-source-config` 必须在有效平台租户内，由同租户登录身份使用；平台人员访问业务租户期间同样不能执行。校验先于动态权益、永久超级管理员及临时角色，且平台身份本身不会额外授予权限。登录权限及导航返回剔除被拒绝的平台入口，原有业务字典等租户权限保留。权限服务回归 58 项通过。

这不等于所有运维接口已审查。调度任务、运行控制以及文件资源的完整访问链仍需分别处理；没有把可编辑的租户文件配置简单归为平台公用配置。

## 核查中确认的其他共享入口

- 文件配置、文件元数据和数据库文件内容已增加本地租户隔离；历史对象的实际归属、已有直链及前端预览仍需配套处理。路径前缀不能替代对象存储的访问权限。
- 系统配置包已停止修改全局菜单和套餐；菜单、租户、套餐管理及平台开发工具入口已增加平台身份边界。
- OAuth2 客户端、调度任务和日志、代码生成及数据源配置仍有全局表。平台运行定义可以共用，但租户的业务接入凭据、任务参数以及修改权限需逐入口核对；本轮尚未改造这些入口。

## 尚未完成的原始需求

- MinIO 文件配置、文件元数据、数据库文件内容和下载/删除授权已增加本地租户边界；尚需完成全部前端适配、历史对象迁移与存储端访问控制。NAS 配置已独立不等于 NAS 中的文件已复制。
- 完整租户复制尚未形成真实数据库与对象存储的完整操作链。需要逐表处理引用关系、复制文件对象、校验数量与内容，并处理复制失败恢复。
- 新租户不能仅靠复制相同凭据就取得外部系统隔离。测试账套、文件目录及对外发送/写入行为必须在克隆流程中明确处理，避免访问同一外部可写资源。

因此，目前不能宣称“所有租户配置和资源均已隔离”，也不能将现有离线 JSON 克隆脚本当作完整租户复制功能。

## 文件存储配置独立副本（本地代码，不能单独上线）

- `infra_tenant_file_config` 以 `(id,tenant_id)` 标识记录，原配置编号在每个租户内保留，避免修改既有文件的配置引用。配置读取、更新、删除和默认切换使用强制租户拦截。原 `infra_file_config` 保留为初始模板。
- 默认存储不再使用全局缓存；配置读取同步执行，随后创建或刷新该租户的客户端。批量文件删除工作线程携带发起租户并在结束时清理上下文。
- `20261112_tenant_file_configuration.sql` 为现有租户生成独立配置；初始化标记防止重跑覆盖已修改或已删除记录。源模板缺失默认配置或存在多个默认配置时停止。新租户在原创建事务内初始化存储配置。
- 此迁移只复制配置，不复制 MinIO/NAS 对象，也不改变旧对象的存储位置。不同租户仍可能使用同一个外部桶、目录或凭据，文件元数据归属及路径授权尚需改造。
- 缺少租户上下文的文件访问现在不能选择配置；旧匿名下载、公开展厅资源及其他后台调用必须结合各自正式业务归属继续适配。不得直接给匿名请求补一个默认租户，也不得把客户端传入的租户编号视为文件授权。
- 配套上线必须等文件元数据、对象路径、下载凭证及历史归属迁移完成；当前不能作为完整文件隔离版本发布。

## 文件归属、写入目录与读取边界（本地代码，尚未完成上线链路）

- `FileDO` 和 `FileContentDO` 使用 `TenantBaseDO/@TenantIsolated`。文件分页、编号读取、移动、删除及 DB 文件内容均强制按租户过滤，忽略租户标志不能绕过。
- 后端上传、流式上传、归档上传及预签名上传生成 `tenants/{tenantId}/...` 对象键；拒绝相对目录、编码目录穿越和其他租户命名空间。移动目标也限定在当前租户目录。展厅及生产资料原有留存保护仍适用。
- 通用前端上传登记只接收当前租户路径，通过当前租户配置计算 URL；仍需补齐上传凭证、对象存在性和内容验证，不能视为已完成直传闭环。
- 文件内容读取和保留证据查询必须存在当前租户的对应元数据；预签名下载使用文件自身的配置，不能把任意 URL 交给默认存储签名。跨租户编号混入批量删除时，在任何存储删除之前拒绝。
- `/infra/file/{configId}/get/**` 已取消匿名和忽略租户访问，安全配置与方法均要求登录。客户端仅提交 `tenant-id` 不能授权。前端图片、普通直链和公开资源的访问方式仍需改造；当前版本不可直接发布。
- 文控历史原件登记和名字占用证据查询已改用当前租户文件及存储配置；既有证据仍须匹配原文件内容和身份，没有取消审计或原件核验。
- eDHR 保留存储是平台维护的不可变归档策略，保留明确的负编号运行时来源，不读取租户普通默认存储。注册客户端按租户执行，归档文件路径和数据库记录仍归属当前租户；未知负编号拒绝访问。复制到测试租户的外部写入策略仍需单独落实。
- `20261112_tenant_file_ownership.sql` 依赖文件配置迁移。历史文件必须先以业务证据填写 `infra_file_tenant_owner`；归属缺失、配置不存在、同一配置和路径分属多租户、数据库内容没有对应记录时拒绝迁移。数据库内容从正式文件归属赋值，编号和字节保持原样；成功标记防止重跑覆盖新数据。
- 迁移切换前需停止旧版本写入；MySQL DDL 独立提交，DDL 失败后必须修复并验证，不能假设整个脚本可事务回滚。此脚本不执行对象复制，也不证明不同配置没有指向同一实际对象；共用对象与凭据仍需存储端核验和复制。

### 文件管理页面适配

- 文件管理页预览/下载通过带登录与租户身份的后端请求读取文件，不再直接打开对象 URL；图片/PDF 在页内预览，其余文件下载。移除不能代表访问授权的复制直链操作。
- 切换租户或登录会话时立即关闭预览、释放对象 URL、清空列表和选择项；旧会话延迟返回的文件内容与列表不会重新展示。
- 页面保护规则同步识别租户目录下的展厅媒体。其他上传组件、头像、公开展厅等入口尚未完成同样适配。
- 3 项前端行为测试通过，覆盖切换租户后清除与丢弃预览、旧列表响应拒绝回填、使用后端路径下载；受影响源码 ESLint 通过。没有宣称已执行真实页面 E2E。
