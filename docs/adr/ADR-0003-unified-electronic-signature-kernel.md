# ADR-0003：采用统一电子签名内核与模块适配器

## Status

Accepted for audit-baseline design。用户于 2026-09-07 同意统一电子签名内核、各业务模块保留业务入口并分阶段迁移，并要求优化到按文档完整开发后能够满足检查项 4.1 至 4.12。生产上线仍以代码、配置、SOP、培训、迁移和运行证据通过为门禁。

## Context

当前电子签名能力分散在系统账户、DCC、BPM 和 MES/eDHR：DCC 已具有密码验证、授权、失败锁定、文件哈希和 HMAC 证据；BPM 记录签名人、审批结果和签名图片，但缺少统一内容哈希；MES/eDHR 有多种签名动作、人工显示时间、部分内容哈希和临时人员独立密码路径。周期复核目前也没有形成统一持久化事实源。

分散实现导致密码策略、锁定、内容绑定、正式时间和审计证据不一致，无法以一套验证逻辑覆盖检查项 4.1 至 4.12。

## Decision Drivers

- 所有正式签名必须使用一致的身份、密码、锁定、时间和内容绑定规则。
- DCC、BPM、MES/eDHR 的业务状态机和权限不能被一个巨型通用业务接口取代。
- 内容快照必须来自业务模块服务端权威数据，不能由客户端决定。
- 签名证据必须可独立验证、版本化、不可静默修改。
- 迁移期间不允许长期双写、fallback 或默认有效。
- 现有历史签名不得改写。

## Options Considered

### Option 1：继续由各模块独立加固

每个模块分别补密码、锁定、时间、哈希和审计。

优点是单次改动较小；缺点是规则继续复制，后续策略变化和漏洞修复容易漂移，周期复核无法形成可靠单一事实源。

### Option 2：把所有业务动作合并为一个通用 HTTP 签名接口

浏览器直接向统一接口提交模块、对象、动作和签名数据。

优点是表面接口数量少；缺点是通用接口必须理解所有业务状态，容易绕过业务权限，且客户端可能控制对象、签名人或内容哈希。

### Option 3：统一内部签名内核，业务模块提供服务端适配器

业务 Controller 保留，业务事务通过内部签名服务完成重新认证、权威快照、证据生成和持久化。业务适配器负责模块状态、权限、内容和流程顺序。

优点是统一安全控制且保留领域边界；缺点是需要新增模块、统一数据模型，并分阶段迁移所有写入路径。

### Option 4：新旧签名服务长期双写

新表和旧表同时写入，逐步观察后再决定切换。

优点是短期回退看似容易；缺点是形成两个事实源，事务失败时难以证明一致性，也会延长不符合路径寿命。

## Decision

选择 Option 3。

1. 新增独立内部模块 `yudao-module-signature`，集中身份重新认证、授权、失败锁定、服务器时间、内容哈希、证据 HMAC、幂等、验证和周期复核。
2. 系统账户提供统一身份安全 API；所有签名人包括临时人员使用独立系统身份，不保留平行临时签名密码体系。
3. DCC、BPM、MES/eDHR 保留业务 HTTP 入口，在自身模块实现签名主题适配器。
4. 签名主体和租户取自服务端安全上下文，内容快照由适配器从权威业务数据生成，客户端不得指定正式签名人、正式时间或权威哈希。
5. 业务状态变更、统一签名写入和签名 ID 绑定使用同一事务；认证失败审计独立持久化。
6. 新签名使用统一不可变证据表。旧表在模块切换后只读，并按证据完整度展示验证能力。
7. 按账户安全、签名内核、DCC、BPM、MES/eDHR、临时人员、周期复核顺序迁移；每个模块切换后删除旧写入职责。
8. 不提供运行时 fallback 或长期双写。
9. 首版最低密码基线为 8 位四类字符、90 天、禁止当前及前 5 次历史；登录与签名失败在 15 分钟内累计 5 次锁定 30 分钟。
10. 账户标识在租户内永久不可复用；所有签名人包括临时人员必须有独立实名账户、本人领取和禁止共享确认。
11. 正式签名绑定最近 5 分钟内、同步正常且绝对偏差不超过 1 秒的受控时间证据；不满足时失败关闭。
12. 变更签名保存可读前后快照、字段级差异和两侧哈希，不能用哈希替代审计对比。
13. 系统每季度自动建立全模块复核批次，重大策略、密钥、时间、篡改和账户事件触发专项复核；批次绑定 SOP、责任人、替补和培训证据。
14. 对用户提供检查项 4.12，最低验收为当前实名账户会话加签名时重新输入本人密码，但不将其宣称为密码学意义的 MFA；外部标准要求独立第二因子时，未实现真正 MFA 必须阻断放行。
15. 复用项目统一 GxP 审计内核同事务记录对象序号和哈希链；租户每日清单进入正式 WORM/Object Lock，并以独立特权审计、机器可读全写入口登记和自包含归档恢复补齐整链删除与 DBA 风险。

## Consequences

正面影响：

- 一套策略和验证逻辑覆盖所有正式签名。
- 内容、身份、时间、含义和审批节点形成统一可验证证据。
- 业务模块仍拥有业务状态机和授权判断。
- 周期复核可以直接读取统一事实源。
- 安全修复和策略变化不再需要复制到多个签名服务。

成本和风险：

- 需要新增 Maven 模块、统一表和跨模块 API。
- BPM 和 MES/eDHR 必须补齐规范化内容快照。
- 临时人员需要领取独立账户，现有操作流程会变化。
- 账户管理、电子签名和周期复核必须配套 SOP、培训、责任替补和持续运行证据，代码完成不等于审查完成。
- 历史记录存在不同验证能力，不能全部升级为完整有效。
- 模块产生首条新正式签名后不能简单回退旧写入代码。

## Rejected Options

- 拒绝 Option 1，因为分散复制无法长期保证策略一致。
- 拒绝 Option 2，因为通用浏览器写入口会削弱业务授权和服务端事实源。
- 拒绝 Option 4，因为双写违反单一事实源和失败关闭要求。

## Verification and Operational Impact

- 自动化追踪检查项 4.1 至 4.12。
- 边界测试覆盖 7/8 位、四类字符缺项、89/90/91 天、当前及第 1/5/6 次历史、15 分钟/5 次/30 分钟锁定、4:59/5:00/5:01 时间证据和 999/1000/1001 毫秒偏差。
- 单元和集成测试验证身份状态、失败锁定、内容/证据哈希、时间、幂等和事务。
- 静态门禁禁止业务模块直接匹配签名密码或写正式签名表。
- 每个模块执行迁移前后数据对账和经授权真实页面 E2E。
- 运行监控覆盖密钥、时间、证据写入、验证失败、旧写入调用和周期复核逾期。
- 生产切换需要备份恢复证明、策略批准和历史签名盘点。
- 生产放行还需账户本人领取/禁止共享/离职停用、有效 SOP、培训、季度自动建批、专项触发、逾期升级和可读字段差异导出证据。
- 还需验证对象链修改/插入/删除/换序、每日密封水位、WORM 回执、独立特权审计、全写入口 CI 以及清空隔离环境后仅归档包恢复。

## Revisit or Rollback Conditions

- 如果模块无法生成稳定、确定性的服务端内容快照，应停止该模块迁移并重新设计适配器，不得降低为只绑定业务 ID。
- 如果审查要求真正 MFA，应扩展统一身份 API；MFA 不可用时不得回退密码单因子。
- 新模块尚无正式签名写入时可回退部署；产生正式记录后只能向前修复或恢复切换前完整备份。
- 如果未来需要外部可信签名服务，应保持当前适配器和证据合同，另行 ADR 决定密钥托管与外部依赖，不直接替换为静默远程 fallback。
