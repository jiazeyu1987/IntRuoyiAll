# 清洗介质改为纯化水并区分工序默认值

## Request

- 来源：用户在精洗清洗参数修复完成后提出正式变更。
- 请求：下拉选项由“自来水 / 纯净水”改为“自来水 / 纯化水”；精洗默认纯化水，粗洗默认自来水。

## Baseline

- 粗洗和精洗已共用固定清洗参数专用面板及正式 `SELECT` 运行态合同。
- 当前前端模板和数据迁移仍使用“自来水 / 纯净水”，且两个工序默认值均为“自来水”。
- 当前正式身份为 `ROUGH_WASH_MEDIUM` 与 `FINE_WASH_MEDIUM`，无需新增 API 字段。

## Classification

- 类型：已接受的产品行为和数据枚举变更。

## Impact

- Product：用户可选介质改为自来水、纯化水；不再提供纯净水。
- Design：保持现有下拉控件，仅更新选项和工序默认值。
- Data：更新正式数据迁移，使粗洗默认自来水、精洗默认纯化水，并迁移已有规则。
- API：字段结构不变，继续使用 `optionValues/defaultText`。
- Test：更新粗洗/精洗静态合同、迁移合同，并通过真实页面分别验证默认值。
- Release：正式环境必须随发布执行更新后的数据迁移；本任务仅自动修改本机验证库。
- Operations：无新增服务或依赖；执行前继续使用迁移前置检查和备份/恢复要求。

## Decision

- Accept。该变更边界明确，沿用现有正式参数编码和数据链路，不增加 fallback 或兼容选项。

## Required Approvals

- 用户已明确提出并批准业务值变更。
- 远端测试服、备份服或生产库执行仍需独立发布授权。

## Downstream

- 重新运行 `frontend-feature-delivery`：更新模板、表单重置、保存校验和静态合同。
- 重新运行 `database-schema-delivery`：更新正式迁移、迁移合同和本机迁移验证。
- 使用 Playwright 通过真实一线页面验证粗洗/精洗默认介质。

## Blockers

- 暂无。

## Next Action

- 先将静态合同改为新期望并取得 RED，再实施前端和迁移变更。
