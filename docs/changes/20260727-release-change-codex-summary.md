# Release Change: Codex Plain-Language Git Summary

## Request

- Source: user clarification in the current task.
- Request summary: 发布内容不要展示原始 Git 提交信息；只展示当前版本与上个版本之间的变更，并由 Codex 总结成普通人能读懂的中文，每次最多 10 条。

## Current Baseline Reviewed

- `IntRuoyiBackend/script/deploy/publish-int-ruoyi.ps1` currently derives `changeSet.gitChanges` from raw `git log` entries containing repository labels, short hashes, and commit subjects.
- `IntRuoyiFronted/src/components/ReleaseInfoDock/ReleaseInfoDock.vue` already limits visible Git entries to 10 and does not render the previous metadata sections.
- Existing release tests cover previous-release Git range detection, the 10-item cap, and writing `release-info.json` before Docker context preparation.
- Project rules require fail-fast behavior and prohibit raw-commit or placeholder fallback when a required Codex dependency is unavailable.

## Classification

- Requirement change: release-facing content must be human-readable plain Chinese generated by Codex.
- Release automation change: the publish script must invoke the installed Codex CLI and validate structured output.

## Impact

- Product: operators and ordinary users see understandable version-to-version change summaries instead of commit identifiers.
- Data/API: `release-info.json.changeSet.gitChanges` remains an array of strings; a new `summaryGenerator` provenance field identifies `codex`.
- Tests: add contract coverage for Codex invocation, JSON schema validation, the 10-item limit, raw-commit rejection, and fail-fast missing/invalid output.
- Release: a build must stop before producing release information if Codex is unavailable or returns invalid summaries.
- Operations: the release environment must provide an authenticated `codex` executable; no new secret is stored in the repository.

## Decision

- Accepted.
- Scope is limited to release change-summary generation and its tests.
- No fallback to raw Git subjects, hashes, package metadata, placeholder text, or another model/data source.

## Required Approvals

- No additional approval required for this user-requested release-content change.
- Real server publish is not part of this task and remains unauthorized.

## Downstream Skill Reruns

- `ci-cd-environment-delivery`: record local release-script contract and fail-fast environment requirements.
- `openai-docs`: verify the supported `codex exec --output-schema` invocation shape.
- `project-experience-consolidation`: update the existing release preflight experience entry after verification.

## Blockers And Next Action

- Blocker: none for local implementation.
- Next action: implement and verify the Codex-backed summary contract.
