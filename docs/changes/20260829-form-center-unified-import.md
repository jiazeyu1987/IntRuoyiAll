# 20260829 表单中心统一导入变更决策

## Request Summary And Source

来源：用户当前会话。用户希望表单模板与批记录表单共用一套解析、编辑、查看、填写配置、链接和后续能力；当前先在新 worktree 中新增“批记录 / 表单”导入选择，并用指定 DOCX 验证，暂不影响现有批记录流程。

## Current Baseline Reviewed

- 已确认主工作区存在大量并行改动，本任务在独立 worktree 中开展。
- 已确认项目规则要求新增功能使用任务文档、BDD/TDD 和定向验证。
- 已确认业务方向是以现有批记录表单能力为准，表单模板后续逐步切换到新流程。

## Classification

需求变更 / 架构收敛 / 前后端功能新增。

## Impact

- 产品影响：批记录与表单统一显示在一个列表，页签后续改名为“表单中心”。
- 设计影响：表单模板独立入口后续应逐步退场，新增流程先不切旧引用。
- 数据影响：需要区分记录是“批记录”还是“表单”，但前期不加额外限制或判定。
- API 影响：导入接口或请求参数需要能表达导入类型。
- 测试影响：需覆盖批记录原流程不变、表单新流程可导入、统一列表可展示。
- 发布影响：本任务只在 worktree 验证，不直接发布或合并。
- 运维影响：如启动服务验证，必须使用 worktree 独立端口槽位。

## Decision

accept

接受最小实现：先新增导入类型选择和表单类型链路，复用批记录表单现有能力；不在本阶段删除旧表单模板，不自动切旧绑定，不添加额外业务判定。

## Required Approvals

当前任务无需额外审批；后续删除旧表单模板入口、批量迁移绑定关系或发布上线前需要用户单独确认。

## Downstream Skill Reruns

- 前端实现需按前端功能规则执行。
- 后端实现需按后端 API 规则执行。
- 真实页面验证需按 E2E 规则执行。

## Result

最小实现已完成：新增“批记录 / 表单”导入选择，批记录保持原流程，表单使用 `FORM` 类型进入批记录表单统一列表，并准备菜单名称改为“表单中心”的 SQL 变更。已用指定 DOCX 完成真实页面验证，表单导入、同列表显示、预览、填写配置入口、链接入口和测试数据页面删除均通过。

## Blockers And Next Action

当前最小实现验证无阻塞。旧表单模板绑定关系切换、旧入口退场和打印闭环未在本阶段执行；下一步应在用户确认后设计旧绑定迁移和菜单/引用切换验收。
