# DCC 三套流程规则变更记录

日期：2026-09-21。性质：待实施开发设计。依据本轮用户明确确认的上传、升版、作废及部门负责人会签需求。

权威入口：[DCC 三套流程开发需求](../dcc-three-workflows/README.md)。此次仅交付文档，不代表代码、数据库或 BPM 已变更。

| 原文档/现状 | 本次替代范围 | 保留范围 |
|---|---|---|
| [原主流程文档](../dcc-main-flow-no-training-distribution.md)不考虑培训、分发 | 普通上传/升版必须分发，按 checkbox 决定培训 | 与本次流程无冲突的文件身份、权限规则 |
| [最小主流程设计](../dcc-minimal-main-flow/README.md) D04/D05：两阶段审批、允许追加会签人 | 会签 -> 批准 -> 可选培训 -> 分发 -> 文控审核；部门矩阵及唯一负责人 | 双文件合同、历史内容留存等无冲突范围 |
| 同文档 D07/M17：小版本检入直接受控 | 新方案 D05 默认所有受控升版均走升版流程，实施前核对业务范围 | 版本号策略及检出/检入归属校验 |
| [后端规范](../backend-development.md)部分旧条款描述独立发布、固定四阶段 | 本次三流程中文控最后审核后自动执行生效，不增加人工发布节点；旧阶段校验须同步更新 | 权限、签名真实性、事务、幂等和审计门禁 |
| 当前普通文件跳过培训分发，其他路径按类别 trainingRequired | 新三流程按实例 needTraining；分发始终必经 | 其他明确不在本次范围的专门业务链 |
| 当前会签使用 USER/POSITION，提交时冻结人员 | 新三流程会签使用部门，创建任务时解析唯一负责人 | 旧历史记录保留实际人员和原定义身份 |

本变更不直接修改共享规范，以免把“计划实施”误报为“当前行为”。实施任务必须把受影响的规范、接口、迁移及测试一并更新。新方案 D01-D07 为显式默认设计，不标记为用户已经逐条确认。
