# 注册证文件按 DCC 项目代码归类变更评估

## Request Summary and Source

- 来源：用户在当前线程确认“按照这个逻辑执行”。
- 需求：注册证模块下如果绑定了 DCC 项目代码，注册证文件、变更文件、延续文件都归到该 DCC 项目代码的“注册证”分类下；分类不存在时新增。同时，注册证上传审批、注册证延续审批的业务摘要只显示注册证编号、分类、产品、所属公司名称。

## Current Baseline Reviewed

- 已核对注册证主表存在 `project_code_id`，但注册证业务文件表目前未保存 DCC 项目代码和文件类型分类字段。
- 已核对 DCC 项目代码关联文档列表当前主要读取受控文件表，注册证业务文件不会自然出现在该列表中。
- 已核对流程摘要已有注册证上传/延续的独立摘要分支，需要将标签口径锁定为用户指定的四项。

## Classification

- 需求变更 + 后端行为变更 + 数据库 schema 变更 + 前端关联文档入口变更。

## Impact

- 产品影响：绑定 DCC 项目代码的注册证相关文件会在 DCC 基础条目关联文档中按“注册资料汇编 / 注册证”聚合展示。
- 设计影响：使用 DCC 文件类型五级分类树，不把注册证文件伪装成 DCC 受控文件。
- 数据影响：注册证业务文件表需要新增项目代码和分类路径字段，支持后续查询与统计。
- API 影响：DCC 项目代码关联文档分页需要合并注册证业务文件，并用来源字段区分受控文件与注册证文件。
- 前端影响：关联文档列表打开注册证来源文件时进入注册证详情，不再用受控文件详情打开。
- 测试影响：新增/更新后端定向测试、流程摘要测试和前端静态合同。
- 发布/运维影响：需要应用新增 schema 迁移；未应用迁移时新后端应暴露缺列错误，不能静默降级。

## Decision

- accept。

## Required Approvals

- 无额外审批。用户已明确要求按该逻辑执行。

## Downstream Skill Reruns

- `database-schema-delivery`：新增注册证业务文件归类字段与迁移证据。
- `backend-api-delivery`：实现正式绑定、查询合并和审批摘要口径。
- `frontend-feature-delivery`：项目代码关联文档前端识别注册证来源并跳转注册证详情。
- `behavior-driven-development`：以 Given/When/Then 锁定用户可观察行为。
