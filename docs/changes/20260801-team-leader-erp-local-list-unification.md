# 生产班组长 ERP 本地列表与活跃订单口径统一

## Request Summary and Source

用户裁定前一轮“冲突分析”中的若干点应统一为正式口径：ERP 数据由系统夜间同步到本地列表，班组长根据纸质订单编号和纸质调拨单号在本系统本地列表中过滤搜索，选择加入活跃订单池或关联调拨单；活跃订单、FIFO、工序完成数量、设备绑定和参数上下限按本记录执行。

## Classification

需求口径变更与产品文档统一。

## Product Impact

- 订单加入入口不直接查询实时 ERP，而是查询系统夜间同步后的本地生产订单列表。
- 调拨单关联入口不直接查询实时 ERP，而是查询系统夜间同步后的本地调拨单列表。
- 活跃订单定义为：班组长从本地生产订单列表中过滤搜索后加入、未异常终止、可参与报工分配的生产订单。
- 工序完成数量按 `生产订单数量 × 工序生产系数`。
- 异常上报第一版暂时只允许从活跃订单发起。
- FIFO 第一版按活跃订单加入时间排序。
- 班组长只能从设备台账选择设备并绑定到工序，不随意创建主设备。
- 参数上下限只用于提示、复核、异常判断和审核副本，不覆盖员工原始提交。

## Design Impact

- 需要区分 ERP 夜间同步任务、本地生产订单列表、本地调拨单列表、活跃订单池和物料追溯关联。
- 活跃订单加入时间成为 FIFO 的正式排序字段。
- 设备绑定应引用设备台账主数据。
- 设备参数上下限判断不能修改原始报工 payload。

## Data Impact

- 本地生产订单列表需保留 ERP 单据号、纸质订单编号可检索字段、同步时间和加入活跃订单时间。
- 本地调拨单列表需保留 ERP 调拨单号、物料、数量、批次、同步时间和订单关联关系。
- 活跃订单记录需保留加入人、加入时间、来源本地生产订单。
- 配置审计需保留设备绑定和参数上下限变更记录。

## API Impact

- 生产订单加入接口应从本地同步订单列表选择，不应要求实时 ERP 查询。
- 调拨单关联接口应从本地同步调拨单列表选择。
- 报工分配接口只接受活跃订单。
- 异常上报接口第一版只接受活跃订单。

## Test Impact

- 增加/更新测试覆盖本地订单列表搜索加入活跃订单。
- 增加/更新测试覆盖本地调拨单列表搜索并关联订单。
- 更新工序完成测试为生产系数口径。
- 更新设备维护测试为设备台账选择绑定。
- 更新参数上下限测试，确认超限不覆盖员工原始提交。

## Release Impact

仅更新产品文档和变更裁定记录，未修改生产代码。本次不触发发布。

## Operations Impact

- ERP 夜间同步失败时，班组长无法从本地列表找到新订单或调拨单，应作为开工前置阻塞。
- 活跃订单加入时间影响 FIFO 分配，需要稳定记录且不可被随意改写。

## Decision

Accept。
