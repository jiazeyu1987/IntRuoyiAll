# MES工序页签与映射列表变更评估

## Request

来源：2026-07-30 当前线程用户请求。

在现有“工序设置”和“工艺流程”两个同级页签之间新增“MES工序”页签。页签内只提供一个只读列表，不考虑新增、编辑、删除、启停或页面导入。

列表以 `压力泵工序.xlsx` 的 `二代压力泵` 工作表为当前数据范围。只有设备和执行工序建立真实关联：

- 设备字段关联现有设备主数据。
- 执行工序字段关联现有“工序设置”中的工序，表示报工或工序执行时实际使用的正式工序。
- 其它字段只按来源数据展示，不关联产品、工艺路线、批记录表单、价格、人力或其它系统对象。

第一版列表字段：

| 字段 | 说明 |
| --- | --- |
| 产品名称 | 来源表中的普通展示文本，不关联产品主数据。 |
| MES工序编码 | 普通展示值；没有编码时显示为空，不生成假编码。 |
| MES工序名称 | 一线员工报工和切换工序时看到的名称。 |
| 设备 | 真实关联现有设备主数据，展示设备编码和可选设备名称；一条 MES 工序可显示多台设备。 |
| 设备数量 | 来源表中的展示值。 |
| 10.5小时日产能 | 来源表中的展示值，不参与当前产能计算或排产联动。 |
| 日常工序人力 | 来源表中的展示值。 |
| 工序单价 | 来源表中的展示值。 |
| 是否报工 | 来源表中的展示值，当前不改变报工行为。 |
| 是否形成批记录 | 来源表中的展示值，当前不建立批记录关联。 |
| 批记录工序名称 | 来源表中的展示文本，当前不关联批记录表单或正式批记录工序配置。 |
| 执行工序 | 真实关联现有“工序设置”中的工序。 |

## Baseline

- 当前生产菜单下，“工序设置”是 `system_menu.id=5710`、排序 `2`，“工艺流程”是 `system_menu.id=5720`、排序 `3`，二者是同级菜单。新增同级菜单并调整顺序在导航层面可实现。
- 当前“工序设置”页面的数据对象是 `mes_pro_process`。前后端代码将其称为“MES生产工序”，但它实际上已经承担正式工序主数据、工艺路线引用、工作站、关系清单和批记录表单绑定入口等职责。
- 当前工序分页已展示工序编码、工序名称、所属工艺路线、关系清单、工作站、生产系数和批记录表单。
- 当前系统已有设备主数据、设备与工序产能关系 `mes_dv_machinery_process`、工作站与设备绑定，以及路线工序返回设备列表的能力。
- 当前球囊工序导入逻辑直接把 Excel 工序写入 `mes_pro_process`，没有单独的一线 MES 工序层。
- 当前不存在一个正式独立对象来表达“MES工序名称/编码 -> 多台设备 -> 工序设置正式工序”的映射。

## Classification

本请求属于产品展示能力变更和只读目录扩展。

当前版本不引入 MES 工序维护流程，也不改变报工、工艺路线、批记录或排产业务。它只增加一个 MES 工序只读目录，并保留设备和执行工序两种必要关联。

## Impact

### Product Impact

- 新增同级“MES工序”菜单，位置在“工序设置”和“工艺流程”之间。
- 页面只显示列表，不提供维护按钮。
- 当前不改变一线报工入口、工艺流程执行、批记录生成或工序池逻辑。
- 用户可从列表查看 MES 工序、设备和执行工序对应情况。

### Design Impact

- UI 标签为“MES工序”，内部只读目录对象仍应避免与现有 `mes_pro_process` 命名混淆。
- 一条 MES 工序建议作为一行主记录，设备以标签或展开明细展示；多台设备不能保存成一个斜杠字符串。
- 除设备和执行工序外，其它列直接展示目录快照值，不提供点击跳转、配置状态或关联校验。

### Data Impact

- 需要一个只读 MES 工序目录或等价读模型，承载来源表中的展示字段。
- 设备身份继续复用 `mes_dv_machinery`，执行工序继续复用 `mes_pro_process`。
- 一个目录行可关联多台设备，并关联一个执行工序。
- 产品名称、MES 工序编码/名称、设备数量、产能、人力、单价、报工标记、批记录标记和批记录工序名称均作为展示快照，不建立其它外键或业务联动。
- 当前不需要版本、生效时间、修改审计或删除规则，因为页面不提供维护能力。

### API Impact

- 只需要 MES 工序只读分页或列表查询接口。
- 返回目录展示字段、设备关联信息和执行工序关联信息。
- 当前不需要新增、修改、删除、启停、导入或报工提交接口改造。

### Test Impact

- 菜单顺序、权限和路由可见性测试。
- 二代压力泵列表字段和行数展示测试。
- MES 工序多设备、无设备名称和空编码展示测试。
- 设备和执行工序关联展示测试。
- 其它字段不产生产品、工艺路线、排产或批记录跳转和联动的边界测试。
- 页面不存在新增、编辑、删除和导入操作的测试。

### Release And Operations Impact

- 需要数据库迁移、菜单和权限迁移。
- 二代压力泵目录数据需要作为发布种子或其它只读数据来源写入。
- 斜杠设备编码需要拆成多条设备关联，不能作为一个设备编码。
- 当前不迁移或改造现有报工、工艺路线、批记录和历史工序数据。

## Decision

`ACCEPT`

接受用户收窄后的只读列表需求。

确认的第一版边界：

- 页面只读，无维护功能。
- 当前数据范围只看 `二代压力泵` 工作表。
- 设备关联现有设备主数据。
- 执行工序关联现有工序设置工序。
- 其它字段只列出，不做任何关联、校验、跳转或业务联动。
- 当前不改变报工、工艺流程、批记录、排产和工序池。

Required approvals：当前产品范围已经明确，可以进入只读页面设计和实施规划。

## Downstream

按以下顺序继续：

1. 更新当前线程项目构想和只读列表验收标准。
2. 运行 `system-design-docs`，确定只读目录数据结构、设备关联和执行工序关联。
3. 运行 `database-schema-delivery` 设计目录种子、关联字段、索引和回滚。
4. 运行 `backend-api-delivery` 实现只读查询接口。
5. 运行 `frontend-feature-delivery` 新增菜单和只读列表。
6. 运行 BDD/TDD 与真实 E2E，覆盖菜单、字段、设备、执行工序和无维护操作。

## Blockers

- 产品需求无剩余阻塞项。
- 实施时只需确认二代压力泵每行对应的现有设备 ID 和执行工序 ID；无法唯一匹配的数据必须明确列为导入/种子错误，不猜测关联。
