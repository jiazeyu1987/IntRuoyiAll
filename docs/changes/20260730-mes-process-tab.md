# MES工序页签与映射列表变更评估

## Request

来源：2026-07-30 当前线程用户请求。

在现有“工序设置”和“工艺流程”两个同级页签之间新增“MES工序”页签。页签内提供列表，用于维护或展示 MES 工序、实际设备和“工序设置”中正式工序的对应关系。

建议的第一版列表字段：

| 字段 | 说明 |
| --- | --- |
| 适用产品/范围 | 当前 MES 工序适用的产品、包装形态或路线范围。 |
| MES工序编码 | 可选编码；没有编码时不得自动生成假编码。 |
| MES工序名称 | 一线员工报工和切换工序时看到的名称。 |
| 设备 | 选择现有设备主数据，展示设备编码和可选设备名称。 |
| 设备数量 | 当前 MES 工序配置的设备数量。 |
| 10.5小时日产能 | 当前 Excel 使用的 MES 工序参考产能。 |
| 对应工序设置 | 显式选择现有“工序设置”中的正式工序。 |
| 是否报工 | 决定该 MES 工序是否形成生产报工。 |
| 批记录信息 | 从对应正式工序及其正式批记录绑定只读带出，不在此重复维护。 |
| 状态 | 启用或停用，不建议直接删除已经产生业务记录的 MES 工序。 |
| 操作 | 查看、编辑、停用；导入能力是否首期提供待确认。 |

## Baseline

- 当前生产菜单下，“工序设置”是 `system_menu.id=5710`、排序 `2`，“工艺流程”是 `system_menu.id=5720`、排序 `3`，二者是同级菜单。新增同级菜单并调整顺序在导航层面可实现。
- 当前“工序设置”页面的数据对象是 `mes_pro_process`。前后端代码将其称为“MES生产工序”，但它实际上已经承担正式工序主数据、工艺路线引用、工作站、关系清单和批记录表单绑定入口等职责。
- 当前工序分页已展示工序编码、工序名称、所属工艺路线、关系清单、工作站、生产系数和批记录表单。
- 当前系统已有设备主数据、设备与工序产能关系 `mes_dv_machinery_process`、工作站与设备绑定，以及路线工序返回设备列表的能力。
- 当前球囊工序导入逻辑直接把 Excel 工序写入 `mes_pro_process`，没有单独的一线 MES 工序层。
- 当前不存在一个正式独立对象来表达“MES工序名称/编码 -> 多台设备 -> 工序设置正式工序”的映射。

## Classification

本请求属于产品需求变更和领域模型扩展，不是简单增加一个只读页签。

它引入一层新的“一线 MES 报工工序”主数据，并要求与现有正式工序、设备和后续报工/记录本链路建立正式关联。

## Impact

### Product Impact

- 新增同级“MES工序”菜单，位置在“工序设置”和“工艺流程”之间。
- 一线报工以后应优先选择 MES 工序，再由映射找到正式工序、路线工序、设备和批记录上下文。
- 管理员需要查看未绑定正式工序、未绑定设备、设备数量冲突和产能缺失等状态。

### Design Impact

- UI 标签可以叫“MES工序”，但内部领域对象建议命名为“现场报工工序”或 `frontlineMesProcess`，避免与现有 `mes_pro_process` 混淆。
- 一条 MES 工序建议作为一行主记录，设备以标签或展开明细展示；多台设备不能保存成一个斜杠字符串。
- 正式批记录名称和表单只读展示，仍由现有正式工序/路线工序绑定提供。

### Data Impact

- 需要新增正式 MES 工序主数据或等价独立模型，不能继续把 MES 工序名称覆盖写入现有正式工序。
- 建议关系基数为：一个 MES 工序只对应一个正式工序；一个正式工序允许对应多个 MES 工序；一个 MES 工序允许关联多台设备。
- 设备身份继续复用 `mes_dv_machinery`。若多个 MES 工序映射到同一正式工序但使用不同设备，必须有 MES 工序级设备绑定，不能只依赖正式工序级设备关系。
- 已产生报工或工序池事件的 MES 工序和映射不应硬删除；至少需要启停状态和修改审计，是否需要版本/生效时间待设计确认。

### API Impact

- 需要 MES 工序分页、详情、新增、修改、启停和映射校验接口。
- 需要设备选择、正式工序选择和映射完整性查询。
- 报工组合提交需要同时保存 `mesProcessId` 和映射后的正式 `processId`；路线工序定位仍需结合生产工单的有效工艺路线。
- 如果提供 Excel 导入，需要正式导入契约和错误报告，不能静默忽略设备、正式工序或范围缺失。

### Test Impact

- 菜单顺序、权限和路由可见性测试。
- MES 工序一对一、多对一正式工序映射测试。
- MES 工序多设备、无设备名称、设备数量不一致和设备停用测试。
- 报工提交同时追溯 MES 工序、正式工序和设备的测试。
- 映射修改后历史报工仍保持原快照的测试。
- 正式批记录绑定不被 MES 工序页签覆盖的边界测试。

### Release And Operations Impact

- 需要数据库迁移、菜单和权限迁移。
- 二代压力泵数据需要经过确认后导入，不能直接把 Excel 原始斜杠设备编码写入单字段。
- 上线前需要处理当前已把一线工序直接写入 `mes_pro_process` 的历史数据边界，确认哪些保留为正式工序、哪些迁移为 MES 工序。

## Decision

`ACCEPT_WITH_BLOCKERS`

建议接受该需求，并把它作为一线报工、设备和批记录正式工序之间的主数据桥梁。当前不建议立即编码，先确认 Blockers 中的业务规则。

建议第一版边界：

- 新“MES工序”是独立的一线报工工序，不是当前“工序设置”的改名。
- 一个 MES 工序对应一个正式工序；一个正式工序允许对应多个 MES 工序。
- 一个 MES 工序允许配置多台设备。
- 设备和正式工序从现有主数据选择。
- 批记录绑定仍在现有工序设置/路线工序中维护，新页签只读带出。
- 历史已使用记录不硬删除，只允许停用并保留修改审计。

Required approvals：用户确认关系基数、适用范围、设备使用方式、产能归属和首期维护方式后，才能进入设计与开发。

## Downstream

用户确认 Blockers 后，按以下顺序继续：

1. 更新当前线程项目构想、PRD 和验收标准。
2. 运行 `system-design-docs`，确定 MES 工序主表、设备绑定、正式工序映射、审计和历史快照。
3. 运行 `database-schema-delivery` 设计迁移、索引和回滚。
4. 运行 `backend-api-delivery` 实现查询、维护、映射校验和报工上下文。
5. 运行 `frontend-feature-delivery` 新增菜单、列表和维护交互。
6. 运行 BDD/TDD 与真实 E2E，覆盖菜单、映射、多设备、报工和批记录边界。

在 Blockers 未确认前，不修改生产代码、数据库或菜单。

## Blockers

1. MES 工序的适用范围需要确认：按产品、包装形态、工艺路线还是路线版本维护。建议至少按产品维护，必要时增加路线范围。
2. 关系基数需要确认：是否同意“一个 MES 工序只对应一个正式工序，一个正式工序可对应多个 MES 工序”。
3. 多台设备需要区分：本工序必须同时使用多台、现场任选一台，或按提交时选择实际设备。
4. 产能需要确认：`10.5小时日产能` 是 MES 工序总产能、单台设备产能，还是需要同时维护两者。
5. 首期维护方式需要确认：只支持页面增删改查，还是同时支持从 `二代压力泵` 工作表导入。
6. 已产生报工后的映射变更规则需要确认：是否要求版本、生效时间、修改原因和审批。
7. `工序是否报工`、`工序是否形成批记录` 是否都放入 MES 工序主数据，需要最终确认。
