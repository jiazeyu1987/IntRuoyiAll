# 测试阶段停用可信时间偏差阈值

## Request Summary And Source

- 来源：用户当轮明确要求先去掉 `100 ms` 限制，正式环境再启用，重启服务器，并增加证据包导出按钮。

## Baseline

- 当前可信时间采集在缺少 `INTRUOYI_TRUSTED_TIME_MAX_OFFSET_MILLIS` 时阻断。
- 运行控制台已经存在“导出时间戳证据”按钮并已通过真实页面验证。

## Classification

- 测试阶段运行约束变更。
- 远程重启属于独立运维动作。

## Impact

- 产品：测试阶段仍展示并导出 Last/RMS 偏差，但不按偏差数值阻断。
- 设计：不增加第二个按钮，复用现有导出入口。
- 数据/API：不改数据库和接口结构；`maxOffsetMillis` 未启用时为空。
- 测试：新增“未配置阈值仍采集、其它异常仍阻断”的后端测试，复验现有导出按钮。
- 发布：正式环境启用前必须恢复正数阈值并重新生成上线证据。
- 运维：移除当前两台服务器 `.env` 中的测试阈值；远程服务重启需要明确目标，正式服/审查服还需要 `PROD` 明文确认。

## Decision

- ACCEPT：测试阶段停用偏差阈值；保留所有时间证据和非偏差类失败门禁。
- ACCEPT：复用并复验现有“导出时间戳证据”按钮，不重复开发。
- BLOCK：远程重启目标不明确，且尚未收到项目要求的 `PROD` 明文确认。

## Required Approvals

- 代码和本地测试：用户已授权继续。
- 正式服/审查服重启：需用户明确目标并回复 `PROD`。

## Downstream Reruns

- 更新当前任务 PRD、开发计划和测试计划。
- 重新执行 P2 后端严格 TDD、P3 导出按钮回归和 P4 独立真实页面验证。

## Blockers And Next Action

- 先完成代码与本地运行闭环。
- 收到远程目标和 `PROD` 后，才移除对应服务器阈值并执行受控重启。
