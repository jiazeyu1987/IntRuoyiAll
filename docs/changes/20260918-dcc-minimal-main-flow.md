# DCC 主流程最小实现需求与规则变更记录

## 来源与状态

2026-09-18用户先给出上传受控、大小版本、生命周期、文件关联引用的完整需求，再要求：“所有的没有实现的部分按照最小实现来做，越简单的实现越好，不考虑小概率的情况，只考虑主流程，按照这个思路来形成你认为需要的开发文档”。

本记录只确立开发文档的设计范围和冲突解释，不表示代码已修改、数据库已迁移或产品已验收。具体最小实现选择由本轮方案提出，其中原“待讨论”的版本替代与引用策略均标为方案默认值，不改写为用户此前已逐条确认。

正式入口：[DCC主流程最小实现开发方案](../dcc-minimal-main-flow/README.md)。配套：[技术设计](../dcc-minimal-main-flow/implementation.md)、[双文件上传设计](../dcc-minimal-main-flow/dual-artifact-upload.md)、[双文件上传Review](../dcc-minimal-main-flow/dual-artifact-upload-review.md)、[验收计划](../dcc-minimal-main-flow/acceptance.md)。

## 新旧口径对应

| 主题 | 旧文档/代码口径 | 本次设计口径 |
|---|---|---|
| 小版本 | WORKING检入，仍须审批/发布后才有效 | 当前受控文件小版本检入免审批直接受控；首次上传及候选不能绕行 |
| 审批结构 | 文控审核、会签审核、任一人批准、文控批准 | 新流程文控审核＋全员并行会签；旧实例不改 |
| 手选会签 | 必须与矩阵名单完全相等 | 保留必需人员，允许增加合格人员，所有人均须批准 |
| 必需职能 | 主要检查合并后人员列表 | 每个必需职能都要有明确人员及批准覆盖 |
| 名称 | 项目分类编号身份，名称选模板清单 | 名称自由必填，租户全DCC范围占用；保留编号身份约束 |
| 项目目录 | 分类/类别默认目录及模板文件名清单 | 项目负责人维护目录树，启用时实例化，按送审选定目录归档 |
| 上传文件角色 | 单个源文件或图纸PDF承担源文件、原始文件和预览职责 | 不可编辑浏览版PDF必填，可编辑源文件可选；在线浏览和签名盖章只使用不可编辑链路 |
| 盖章 | 最终文控上传盖章PDF | 服务端对送审锁定PDF自动盖章，不接受新流程另传替代正文 |
| 驳回/撤回重提 | 通过新增业务小版本或复用原件重提 | 同业务版本新增审批轮次和内容快照，信息/内容可修正 |
| 历史删除 | 有撤回记录删除入口 | 送审后内容及证据不可删除，包括被驳回、撤回轮次 |
| 已受控分类 | 文控可直接改metadata | 必须批准作废后新建重审；关闭相关写入入口 |
| 作废名称 | 没有全局占用释放，旧逻辑身份仍冲突 | 批准作废释放名称/有效身份，同名新Master重新审批 |
| 例外替换 | 不在旧第一阶段范围 | 文控独立申请即执行，不走BPM，内容修订及执行签名保留 |
| 关联范围 | 上传时同项目关联，检入继承 | 同产品手动关联，受控后可维护；另支持跨项目锁版引用 |
| 通知 | 主要大版本，小版本不通知 | 本次原需求中的升版、失效、作废、替换均覆盖直接负责人；大小版本都通知 |
| 生命周期 | 当前有效、已替代等与审批状态共用显示 | 生命周期受控/失效/作废，审批进度独立显示 |
| 历史引用 | 待讨论 | 默认保留具体旧快照，有权限的人确认后才更新，不新建引用方文件 |

## 与仓库现有文档的适用关系

- `docs/product/dcc-windchill-version-phase1-prd.md` 中工作小版本不生效、轮次通过升小版本表达、独立发布、目录模板和例外替换不在范围等条款，与本次目标不一致；在M01—M30覆盖范围内由本方案替代。
- `docs/dcc-main-flow-no-training-distribution.md` 与 `docs/dcc-main-flow-20-issues-handoff.md` 中“人工上传盖章PDF”“大小版本均重审”“仅大版本通知”“名称从模板选择”等旧目标，在对应范围内由本方案替代。
- `docs/backend-development.md` 的固定矩阵完全一致、四阶段/独立发布相关旧门禁，需要在后续代码任务中按本方案同步对应条款及测试；本次不批量重写无关工程经验文档。
- `docs/frontend-development.md` 的项目模板名称选择、旧升版交互等合同，需要随新流程前端修改同步测试预期，不能同时要求两套相反行为。
- 原有鉴权、租户隔离、签名真实性、PDF不覆盖、旧数据不猜测和无fallback等约束继续适用。复用旧版本流程完成在途实例属于明确的流程版本管理，不是兼容兜底。

## 简化边界

仅建设一条普通PDF主流程、一个项目模板树、固定两阶段审批、页码文字批注、同页图像差异、直接关系通知。取消复杂通用流程设计、OCR/语义对比、自动关联、递归影响、批量历史修复、压测与罕见故障组合方案；不取消权限、必需签名、唯一有效版本和历史追溯。

产品缺口仍全部进入M01—M30及BDD验收，原P1条目不因分批交付自动延期。开发不允许把新表字段、前端按钮或静态字符串存在当作业务闭环完成。

## 实施授权边界

当前只授权形成开发文档。后续开发须遵守根AGENTS.md中的BDD/TDD和任务记录要求；E2E、真实数据库写入、Git提交推送、远程服务和发布仍按各自当轮授权处理。本记录不授权这些操作，也不要求为交付本轮文档启动服务或改库。
