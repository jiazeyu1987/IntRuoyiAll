# PQC 检验项目级首检与巡检任务

## Change Summary

- 来源：用户于 2026-08-17 明确要求，同一工序下不同检验项目的首检数量、巡检比例分别配置和执行，不得统一。
- 示例：组装Ⅰ的“外观”首检固定 13 件；“撤压”首检固定 5 件；巡检同样按各检验项目自己的比例计算。
- 决策：接受。该规则替代现有“同一 QA 工序同一检验类型只能有一个抽样值”的旧假设。

## Baseline And Classification

- 当前 QA 发布版本已经保存项目级首检数量和巡检比例，正式来源无歧义。
- 当前 PQC 任务只保存工序级计划检验数量，无法表达同工序不同项目的独立抽样值。
- 分类：业务行为、数据库任务身份、后端任务生成与校验、前端任务选择、历史数据修复的跨层变更。

## Accepted Behavior

- PQC 任务身份必须包含 QA 检验项目身份。
- 首检、巡检任务按“QA 工序 + 检验项目 + 检验规则”分别生成。
- 选择某个检验项目后，只展示并提交该项目；计划检验数量使用该项目自己的固定数量或巡检比例计算结果。
- 不同检验项目的数量或比例不同是合法配置，不得因不一致阻止任务生成。
- 旧任务保留审计轨迹并标记为 `CANCELLED`，不得物理删除，也不得直接篡改为新身份。
- 末检适用性仍为项目级统一开关；本次不改变该规则。

## Impact Matrix

| Area | Required Change |
| --- | --- |
| Database | PQC 任务增加 QA 检验项目身份，并纳入有效任务唯一身份；提供可回滚迁移。 |
| Backend | 按检验项目生成首检/巡检任务；按任务项目校验提交内容和生成逐件明细。 |
| Frontend | 任务选项显示检验项目，选择后使用该项目计划数量并只展示该项目。 |
| Historical data | 订单 30 的旧错误任务作废后，按锁定 QA 版本 60 重建项目级任务。 |
| Verification | 覆盖不同项目不同首检数量、不同巡检比例、提交项目隔离和历史修复。 |

## Approvals And Constraints

- 用户已明确批准项目级首检与巡检规则。
- 本次只操作本地 `int_main` 和活跃订单 `30`；不访问远端环境。
- 禁止 fallback、默认项目、按名称猜测或吞掉身份缺失错误。
- Git 提交、推送、发布和远端部署不在本次授权范围内。

## Downstream Delivery

- `database-schema-delivery`：任务项目身份字段、唯一性、迁移和数据修复。
- `backend-api-delivery`：项目级生成、读取、提交校验和结果明细。
- `frontend-feature-delivery`：项目级任务选择与数量展示。
- `bug-regression-fix-loop`：先复现失败，再修复并验证订单 30。
