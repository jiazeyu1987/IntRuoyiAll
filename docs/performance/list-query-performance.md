# 列表查询性能修复（本地验证及物料页面实测完成）

## 已确认原因与范围

物料及同类列表使用 `loadAllListPages` 依次拉取所有授权分页后在浏览器筛选。截图 261,718 条记录、每次 100 条意味着一次筛选最多 2,618 个串行分页请求。筛选必须保持跨页全范围、AND 多条件、导出范围、租户和业务权限。

当前工作分支 `codex/list-query-performance`，工作区由 Codex managed worktree 创建，基于 `int_main` / `ebad95af22684d4390ba64a930fd9c96824c68c1`。仅迁移本线程的性能改动；原主工作区保留只读，其他任务的混合修改未整体复制。

## 已确认实现约束

- 普通列表在原授权 SQL 上追加显式字段白名单和绑定参数，统计、分页、导出使用同一条件。
- 前端保留筛选草稿与已应用条件，成功后才提交；旧请求不能覆盖新结果；失败须明确显示。
- 物料选项使用远程分页查询，已选项按准确 ID 回显。
- 用户已明确选择保留签名、文件及 eDHR 进度的实时校验语义。外部证据条件经静态 SQL 预筛、固定批次沿原权威算法校验，只累计精确统计及所请求页，不能用持久化近似状态替代。
- 不绕过租户拦截，不通过缩小结果集、只筛当前页或全量实体内存分页掩盖问题。

## 已确认的验证边界

- 实时字段查询仍需遍历静态条件命中的候选并读取证据；优化重复校验、请求次数及内存，不承诺任意规模的实时过滤恒定耗时。普通字段则直接 SQL 统计及分页。
- 全类扩大回归存在历史失败：生成批记录旧导入夹具缺 `library_scope`，旧放行测试未满足最终校验/预览前提。分别独立编译 HEAD 服务运行相同失败方法，复现相同原因；本任务生成列表 11 项和放行分页 1 项独立通过。未改变导入、签署或放行业务规则来消除历史测试失败。
- DCC 工作浏览器测试继承的旧详情夹具仍按 `latest_controlled_file_id` 和旧权限 mock 断言，HEAD 实现已使用 `current_active_controlled_file_id` 及文件权限。受影响的工作浏览器本类 7 项单独通过，不能称继承类全部通过。
- 展厅另外两处自定义工作台（ApprovalTaskPanel、AssignmentWorkbench）保留原固定 50 条本地筛选边界，未计入原统一列表全量加载修复范围。没有扩大或修改其业务语义。
