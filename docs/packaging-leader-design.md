# 包装组长：业务设计与验证范围

## 用户可完成的操作

包装组长使用既有生产组长工作台。分配 `packaging_leader_permission` 后，标题显示“包装组长”，活跃工单展示当前租户所有生产组长的订单。订单原组长不变，跨租户访问不开放。

包装组长通过现有人员管理维护自己的正式工和临时工。其员工在一线生产中可选择本租户全部活跃工单，仍使用订单冻结的工序、表单、设备和本人签名。已完工、冻结、作废或处于放行锁定状态的工单仍按原规则拦截。

新报工的复核任务派给员工自己的组长。待审核列表限定自己的员工；报工审核、分配确认和退回均检查员工归属。原组长和包装组长之间不转移员工或代用对方签名。原有历史查询仍用于追溯。

包装组长可以办理整个活跃工单的完工。生产与PQC双100%、正式批记录和检验记录、版本冲突、幂等、异常冻结及签名证据条件均保留。完工回执记录实际操作者，订单归属保留原组长。资料准备与生产放行申请沿用既有链路，PQC和上市审批仍由各自冻结责任人办理；补正继续由原申请人办理。

## 实现范围

- 单一 `MesPackagingLeaderAccess` 服务判断明确角色、启用账号和当前租户；关闭租户隔离上下文时拒绝跨组权限。
- 活跃订单查询增加明确的全组范围参数，普通组长继续使用原查询。
- 一线报工以服务端解析的所属组长决定订单范围，人员选择仍限本组。
- 复核交接从正式员工绑定解析审核组长；包装员工报工不关闭原组生产接手通知。
- 完工、资料与放行相关入口统一检查订单归属或包装组长权限，保留状态和真实操作者审计。
- 不新增业务表，不批量更改员工、订单或用户角色绑定。

## 验收场景

1. 包装组长可见A、B两位生产组长的活跃工单；普通组长仍限定自己的订单；其他租户、停用账号或未获包装角色不可跨组。
2. 包装员工在A、B工单填写并签名，审核任务均交给包装组长；A、B组长不能审核这些员工，包装组长不能审核A、B自己的员工。
3. 普通组长原报工、审核和完工不回归；历史查询保持追溯能力。
4. 包装组长整单完工成功后，原订单归属不变，回执与审计为实际包装组长。
5. 生产或PQC不足100%、冻结、放行锁定、无正式来源、旧版本及越权审核均失败且不产生业务写入。
6. 生产放行与补正继续校验正式批次来源和原申请人，不能绕过PQC或上市审批。
