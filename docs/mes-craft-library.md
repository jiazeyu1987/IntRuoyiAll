# 工艺库与流程参数复用

## 使用规则

- 工艺库保存可复用参数方案，编号按租户从 `GY-0001` 单调递增，不回收已作废编号。
- 工艺不设版本；每个工艺归属一个基础工序，只保存参数，不保存设备身份。
- 路线版本的工序节点可选择所属工序的多项工艺，逐项指定执行设备；同一设备只属于一项工艺，设备身份仍保存在路线配置中。
- 已绑定节点的参数由工艺库维护；路线中的参数编辑入口、配置保存和识别导入均不能绕过工艺引用。
- 修改工艺先预览完整参数差异及全部受影响流程，只能全部升级或作废本次修改。
- 任一受影响流程已有未完成候选版本、缺少完整配置或不满足发布条件，整次修改不能提交。
- 每个受影响流程沿用既有版本及审批规则。全部审批通过后，在同一事务中统一发布所有流程并更新工艺。
- 任一审批拒绝或取消，整次修改及其他关联候选版本一同作废。审批中也可在工艺库作废整次修改。
- 变更记录保留修改前后内容、操作者、原因、时间及关联候选版本。工艺名称也参与并发修改校验。

## 初始化

1. 执行 `IntRuoyiBackend/sql/mysql/20261021_mes_craft_library.sql` 创建表、菜单和授权；使用现有 release-migration 依赖链。
2. 打开“工艺库 → 从现有流程初始化”，查看正式路线快照的来源和冲突。
3. 按工序及完整参数内容去重；同一节点不同设备的参数方案分别提取，不取并集，不把设备身份写入工艺。
4. 缺少正式生产或参数配置的历史来源明确列为未提取项，不推断旧数据；完成既有配置迁移后可再次提取。参数格式或工序无效仍阻止入库。
5. 确认仅向工艺库和初始化审计记录写入，立即生效；不创建候选版本、不绑定或升级流程，已有候选版本不阻止提取。
6. 预览展示来源、新增数量、已有数量及未提取原因；重复提取不重复新增工艺，也不生成空初始化记录。预览过期必须重新确认。
7. 流程后续在候选版本中手动选择工艺，沿用流程审批规则；修改已引用工艺仍要求全部升级或作废。初始化不会改变现有路线和订单参数快照、一线生产及 PQC 填写。

## 一线兼容边界

- 工艺参数仍展开为既有 `productionProcessConfigs[].parameterRules`，保留设备 ID、工序身份和全部参数字段。
- 生产组长新订单快照仍走既有路线版本参数解析；一线生产仍读取活跃订单冻结的设备与参数快照。
- 已有订单、已填写记录、PQC 检验规程和批记录绑定没有迁移写入；修改只影响新正式路线版本。
- 工序开始、逐工序批记录正式绑定、表单槽位仍为三条独立链路。
- 自动化验证不能代替真实页面验收。尚未完成真实生产提交和批记录回填验证时，不应宣布现场无影响已验收。

- 草稿版本的“设备参数”支持添加多项工艺，每项明确选择执行设备；主工艺沿用原字段，附加工艺保存为 `additionalCraftBindings`，每项都有独立工艺编号、参数指纹和设备集合。

- 参数维护、影响流程扫描、工艺升级和整批发布校验均覆盖主工艺及所有附加工艺；升级其中一项保留其他工艺的参数与设备。
- 已发布版本和已有订单冻结快照不直接改写；关联先保存到草稿版本，沿用现有审批发布流程。
