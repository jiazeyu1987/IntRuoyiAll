# 受控文件双版本上传开发文档

## 1. 需求概述

上传受控文件时支持两类文件：

- 不可编辑版本：必须上传，用于日常在线浏览。
- 可编辑版本：可以不上传，用于有权限用户下载和后续编辑。

本需求是独立功能，不依赖完整 DCC 主流程文档中的其他需求。

## 2. 业务规则

### 2.1 文件规则

| 文件 | 是否必填 | 建议格式 | 用途 |
|---|---:|---|---|
| 不可编辑版本 | 是 | PDF | 在线浏览、审批预览、签名和盖章 |
| 可编辑版本 | 否 | Word、Excel、DWG、SolidWorks 等源文件 | 授权下载和后续编辑 |

第一版不可编辑版本统一使用真实 PDF。系统不负责把可编辑文件自动转换成 PDF。

### 2.2 浏览规则

1. 普通详情页、目录页、审批页和历史版本默认打开不可编辑版本。
2. 不可编辑版本经过盖章后，在线浏览使用盖章后的不可编辑文件。
3. 可编辑版本不能作为普通在线浏览文件。
4. 不可编辑版本缺失时，返回明确错误，不能回退到可编辑版本。
5. 可编辑版本未上传时，页面显示“未上传可编辑版本”，不显示无效下载按钮。

### 2.3 权限规则

在线预览和文件下载是两类权限，下载权限再按文件版本拆分为两个独立权限：

| 权限 | 控制内容 |
|---|---|
| 在线浏览权限 | 在线打开不可编辑版本，不代表拥有下载权限 |
| 不可编辑版本下载权限 | 下载不可编辑PDF或其盖章后的PDF |
| 可编辑版本下载权限 | 下载可编辑源文件 |

规则如下：

1. 拥有不可编辑版本下载权限的用户，只能下载不可编辑版本。
2. 拥有可编辑版本下载权限的用户，只能下载可编辑版本。
3. 同时拥有两个权限的用户，才可以下载两个版本。
4. 只有在线浏览权限的用户可以在线查看，但不能下载任一版本。
5. 可编辑版本下载单独记录审计日志；不可编辑版本下载也单独记录审计日志。
6. 没有对应下载权限时，接口返回无权限错误，不泄露文件是否存在。
7. 没有可编辑版本时，即使用户拥有可编辑版本下载权限，也返回明确的文件不存在业务错误。

## 3. 上传流程

1. 用户选择不可编辑版本 PDF。
2. 用户按需选择可编辑版本。
3. 系统分别校验两个文件。
4. 没有不可编辑版本时，禁止提交。
5. 没有可编辑版本时，允许继续提交。
6. 提交后分别保存两个文件的文件ID、名称、大小和哈希。
7. 在线浏览只根据不可编辑版本文件ID解析文件。

## 4. 数据设计

在受控文件版本表增加明确的浏览文件字段：

| 字段 | 含义 | 是否允许为空 |
|---|---|---:|
| `readOnlyFileId` | 不可编辑浏览版本文件ID | 否 |
| `editableFileId` | 可编辑版本文件ID | 是 |

不要继续用一个字段同时表达两个文件角色。历史字段如果无法确认其角色，不在查询时自动猜测或补齐。

建议保存以下信息：

- 不可编辑版本文件名、大小、哈希。
- 可编辑版本文件名、大小、哈希。
- 当前浏览文件ID。
- 文件角色和上传时间。

## 5. 接口设计

### 5.1 上传预览

上传接口增加明确用途：

| 用途 | 规则 |
|---|---|
| `READ_ONLY_VIEW` | 必须是真实可读 PDF |
| `EDITABLE_SOURCE` | 可编辑文件白名单，不允许用 PDF 充当可编辑版本 |

两个上传槽位分别生成上传票据，不能共用同一个票据。

### 5.2 提交

提交请求使用以下字段：

```text
readOnlyUploadTicket   必填
editableUploadTicket   可选
```

提交时：

- 缺少 `readOnlyUploadTicket`，返回“不可编辑版本不能为空”。
- 只有 `readOnlyUploadTicket`，允许提交。
- 两个票据都存在时，分别保存，不互相覆盖。
- 不允许将旧的源文件票据自动当作不可编辑版本票据。

### 5.3 预览和下载

- 普通预览接口：只返回不可编辑版本或其盖章文件。
- 不可编辑版本下载接口：单独校验不可编辑版本下载权限。
- 可编辑版本下载接口：单独校验可编辑版本下载权限。
- 两个下载接口不能通过同一个通用权限互相放行。
- 浏览文件缺失：返回 `CONTROLLED_FILE_PREVIEW_ARTIFACT_MISSING`。
- 可编辑文件缺失：返回 `CONTROLLED_FILE_EDITABLE_FILE_NOT_FOUND`。

建议权限标识：

```text
dcc:controlled-file:download-read-only
dcc:controlled-file:download-editable
```

建议接口：

```text
GET /dcc/controlled-files/{id}/download/read-only
GET /dcc/controlled-files/{id}/download/editable
```

在线预览继续使用现有查看权限，不自动赋予上述任一下载权限。

## 6. 页面设计

上传页面提供两个独立上传区域：

```text
不可编辑版本（必填）
支持：PDF
说明：用于在线浏览

可编辑版本（可选）
支持：Word、Excel、DWG、SolidWorks 等源文件
说明：用于授权下载和后续编辑
```

交互要求：

- 不可编辑版本未上传时，提交按钮不可用。
- 可编辑版本未上传时，提交按钮仍可用。
- 不可编辑版本上传成功后，页面显示 PDF 预览。
- 可编辑版本只显示文件名、大小和上传状态，不作为主预览。
- 文件详情页默认显示不可编辑版本。
- 拥有不可编辑版本下载权限时，显示“下载不可编辑版本”。
- 拥有可编辑版本下载权限且存在可编辑版本时，显示“下载可编辑版本”。
- 用户只有在线浏览权限时，不显示任何下载按钮。

## 7. 错误处理

| 场景 | 返回结果 |
|---|---|
| 未上传不可编辑版本 | 阻止提交，返回必填错误 |
| 不可编辑版本不是有效 PDF | 上传失败，返回格式错误 |
| 可编辑版本格式不支持 | 可编辑文件上传失败，不影响用户删除后提交浏览版 |
| 在线浏览文件缺失 | 返回预览文件缺失错误，不显示可编辑文件 |
| 可编辑版本不存在 | 返回可编辑文件不存在错误 |
| 无源文件下载权限 | 返回无权限错误，不泄露文件信息 |

不允许通过自动转换、历史字段猜测或备用文件回退来掩盖必填浏览文件缺失。

## 8. 验收条件

### 场景一：只上传不可编辑版本

Given 用户上传有效 PDF，没有上传可编辑版本。\
When 用户提交文件。\
Then 提交成功，在线浏览正常，可编辑版本显示未上传。

### 场景二：同时上传两个版本

Given 用户上传一个可编辑源文件和一个 PDF。\
When 用户提交并打开文件详情。\
Then 两个文件分别保存，默认打开 PDF，授权用户可以下载可编辑源文件。

### 场景三：缺少不可编辑版本

Given 用户只上传可编辑源文件。\
When 用户提交文件。\
Then 提交失败，不创建正式文件记录，也不能进入审批。

### 场景四：浏览文件缺失

Given 文件存在可编辑版本，但不可编辑版本缺失。\
When 用户打开在线预览。\
Then 返回预览文件缺失错误，不能显示可编辑版本。

### 场景五：可编辑版本不存在

Given 文件只上传了不可编辑版本。\
When 用户查看详情或尝试下载可编辑版本。\
Then 页面显示未上传状态，下载接口返回可编辑文件不存在错误。

### 场景六：两个下载权限独立生效

Given 用户甲只有不可编辑版本下载权限，用户乙只有可编辑版本下载权限，用户丙只有在线浏览权限。\
When 三个用户分别打开详情并尝试下载两个版本。\
Then 用户甲只能下载不可编辑版本，用户乙只能下载可编辑版本，用户丙可以在线预览但不能下载任一版本。

## 9. Review结果

本需求文档 review 后保留以下最终结论：

- 两个版本必须使用两个独立字段和两个独立上传票据。
- 可编辑版本是可选数据，不应阻塞正常提交。
- 不可编辑版本是业务必填数据，不能用源文件替代。
- 普通浏览链路、不可编辑版本下载链路和可编辑文件下载链路必须分开。
- 不可编辑版本下载权限和可编辑版本下载权限必须是两个独立权限，不能使用一个通用下载权限代替。
- 不做自动格式转换，不做历史字段猜测，不做静默回退。
- 本需求只涉及上传、保存、预览、下载和权限，不扩展审批、版本、关联、通知等其他 DCC 功能。
