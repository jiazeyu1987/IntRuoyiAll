# 12 QMS 整合、培训与审批门禁

## 1. 目的

定义 CSV 活动如何纳入质量管理体系（QMS），并明确人员资质、培训、职责和验证报告审批要求。

## 2. QMS 文件清单

| 文件/SOP | 最低要求 | 当前状态 |
| --- | --- | --- |
| 计算机化系统验证 SOP | 范围、角色、风险评估、V 模型、IQ/OQ/PQ、RTM、报告和维护状态 | 待提供企业正式 SOP |
| 风险评估 SOP | S/O/D 或等效方法、接受准则、批准流程 | 本包有草案，SOP 待提供 |
| 变更控制 SOP | 软件、配置、数据、接口、环境变更和再验证 | 待提供 |
| 偏差/CAPA SOP | 偏差等级、根因、影响、CAPA、复测和关闭 | 本包有模板，SOP 待提供 |
| 电子签名 SOP | 账号、密码、签名含义、重新认证、共享账号禁止 | 电子签名周期审查 SOP 草案存在 |
| 审计追踪 SOP | 审计范围、审查、导出、留存、不可篡改 | 待提供正式 SOP |
| 备份恢复 SOP | 频率、链校验、恢复演练、证据包和职责 | 备份最小闭环设计存在，SOP 待提供 |
| 供应商管理 SOP | 评估、审计、质量协议、变更通知 | 待提供 |
| 周期回顾 SOP | 年度/季度回顾、输入、输出、批准 | 本包有方案，SOP 待提供 |
| 退役归档 SOP | 退役计划、数据归档、恢复检索、批准 | 本包有方案，SOP 待提供 |

## 3. 职责分工

| 角色 | 责任 | 不得替代 |
| --- | --- | --- |
| 业务负责人 | 批准预定用途、URS、PQ 场景和业务数据 | 不能替代 QA 批准 |
| QA/合规负责人 | 批准策略、风险、偏差、CAPA、验证报告 | 不能由开发自批准 |
| IT/系统负责人 | 环境、配置、权限、备份、接口、运行证据 | 不能替代业务适用性确认 |
| 开发负责人 | 设计、代码、工程测试、缺陷修复 | 不能单独宣称 CSV 完成 |
| 验证负责人 | 验证计划、执行协调、证据归档 | 不能省略测试偏差 |
| 测试执行人 | 执行脚本、记录实际结果和偏差 | 不能改写预期结果 |
| 审计/合规审查人 | 周期审查、抽样、发现项和关闭复核 | 不能忽略缺项 |

## 5. 验证报告审批门禁

验证总结报告必须包含：

- 系统名称、版本、环境和验证范围。
- URS、风险评估、GAMP 分类、IQ/OQ/PQ、RTM、偏差/CAPA 和培训清单。
- 供应商评估、接口验证、备份恢复、审计追踪和电子签名证据。
- 未关闭问题、限制、风险接受和后续 CAPA。
- 业务、IT、QA、验证负责人签名、日期和审批意见。

缺少任一授权审批，5.16 应判定为“发现问题”。

## 6. 当前 QMS 结论

当前仓库可以提供工程过程、任务记录、设计记录和部分 SOP 草案，但不能替代企业 QMS 的正式文件控制、人员培训、变更审批、偏差/CAPA 和验证报告签署。5.10、5.11、5.16 当前均应保持“发现问题”，直到正式 QMS 证据补齐。
