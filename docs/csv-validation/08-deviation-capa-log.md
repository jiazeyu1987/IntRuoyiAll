# 08 偏差与 CAPA 记录

## 1. 目的

定义 CSV 执行过程中的偏差识别、调查、影响评估、CAPA、复测和关闭规则，并登记当前最小包识别的合规差距。

## 2. 偏差分类

| 等级 | 定义 | 关闭要求 |
| --- | --- | --- |
| Critical | 影响产品质量、放行、电子签名、审计完整性、数据完整性或记录可恢复性 | 根因调查 + 影响评估 + CAPA + 复测 + QA 批准 |
| Major | 影响验证结论、测试覆盖、接口一致性或受控流程，但未直接导致错误放行 | 根因调查 + CAPA + 复测 + QA 复核 |
| Minor | 文档、格式或非关键配置偏差，不影响验证结论 | 更正记录 + QA 复核 |

## 3. 处理流程

1. 发现偏差后立即记录编号、测试项、实际结果和证据。
2. 判断是否需要暂停测试或阻止上线。
3. 调查根因，区分需求、设计、代码、配置、数据、环境、人员或供应商原因。
4. 评估对已执行测试、已生成记录、生产质量和患者安全的影响。
5. 制定纠正措施和预防措施，明确责任人和完成日期。
6. 执行复测或补充验证。
7. QA 审核关闭；关键偏差未关闭前不得批准验证总结。

## 6. 不允许的关闭方式

- 不得以“代码已实现”“工程测试已通过”“管理员确认可以用”直接关闭 CSV 偏差。
- 不得用 mock、默认成功、API-only 或手工数据库修改替代真实验证路径。
- 不得把未批准的草案标记为正式符合。
