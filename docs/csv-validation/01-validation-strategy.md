# 01 CSV 验证策略

## 1. 目的

建立 IntRuoyi GxP 功能的风险基础 CSV 策略，明确验证范围、生命周期模型、验证深度、首次上线确认、变更再验证、质量体系整合和放行门禁。

## 2. 系统和版本

| 项目 | 内容 |
| --- | --- |
| 系统名称 | IntRuoyi GxP 生产质量与文控系统 |
| 系统类型 | Web 应用 + 后端模块化单体 + 数据库/对象存储/外部接口 |
| 后端技术 | Java 17、Spring Boot、Maven 多模块 |
| 前端技术 | Vue 3、Vite、TypeScript、Element Plus |
| 主要模块 | MES/eDHR、DCC、BPM、System、Signature、Infra、ERP、MDM、Showroom |
| 当前验证包状态 | Draft，未 QA 批准 |

## 3. 验证范围

### 3.1 范围内

- MES/eDHR 批记录：工序报工、PQC、批记录执行、表单、放行、归档、打印、再打印和批记录追溯。
- DCC 文控：受控文件、注册证、版本、审批、发布、受控浏览、下载、旧证库和变更。
- 电子签名：签名密码、身份重新认证、签名含义、签名时间、签名内容绑定、签名证据和签名查询。
- GxP 审计追踪：只追加账本、before/after、原因、签名关联、hash、清单、归档和周期审查。
- 接口和外部依赖：ERP 同步、BPM 审批、对象存储、NAS/备份、Jimu/报表、Word 解析。
- 质量管理活动：CSV 包、变更评估、偏差/CAPA、培训、周期回顾、供应商评估、退役归档。

### 3.2 范围外

- 非 GxP 的普通后台管理、演示、营销或非质量决策功能。
- 未纳入当前 IntRuoyi 代码库的外部系统内部验证，例如金蝶 ERP 自身 CSV。
- 生产部署、正式数据库写入、正式服务器配置和远程 E2E；这些需要单独授权和运行证据。

## 4. 风险基础方法

### 4.1 影响性判定

功能符合任一条件即纳入 GxP CSV：

- 影响产品质量、患者安全或生产放行。
- 生成、修改、审批、归档或展示批记录、注册证、受控文件、检验记录或放行记录。
- 决定权限、电子签名、审计追踪、数据完整性或记录留存。
- 与 ERP、BPM、对象存储、备份或外部文档系统交换 GxP 数据。

### 4.2 风险等级

| 风险等级 | 判定条件 | 验证深度 |
| --- | --- | --- |
| 高 | 失败可能导致错误放行、记录缺失、签名无效、审计不可追溯、数据篡改无法发现 | URS + FS/DS + 风险评估 + IQ + OQ + PQ + 数据完整性 + 安全 + 恢复 + RTM |
| 中 | 失败影响流程效率、任务分配、查询展示或非最终质量结论，但有人工复核或上游控制 | URS + 设计评审 + OQ + 关键路径 PQ + RTM |
| 低 | 失败不影响 GxP 记录、质量结论或受控数据，只影响辅助展示 | 设计评审 + 受控变更 + 目标测试 |

### 4.3 GAMP 分类策略

| 类别 | 适用对象 | IntRuoyi 判定 | 验证要求 |
| --- | --- | --- | --- |
| Category 1 基础设施软件 | OS、数据库、中间件、运行环境 | Java、MySQL、Redis、MinIO、Nginx、Node、浏览器 | 基础设施确认、配置记录、供应商/版本评估 |
| Category 3 非配置标准软件 | 标准工具少量使用 | Office/文档查看器/通用工具如适用 | 安装确认、用途确认、供应商评估 |
| Category 4 配置型软件 | BPM、报表、规则、权限配置 | Flowable/BPM、Jimu 报表、菜单权限、策略配置 | 配置规范、配置测试、变更控制 |
| Category 5 定制软件 | 自研或深度定制业务逻辑 | MES/eDHR、DCC、电子签名、GxP 审计、注册证、备份证据闭环 | 完整生命周期验证和风险基础测试 |

总体结论：IntRuoyi 的 GxP 业务功能按 Category 5 定制软件管理；不能仅做简单 3Q 或只跑工程测试。

## 6. 首次使用前确认门禁

系统不得进入正式 GxP 使用，除非以下条件全部满足：

- CSV 包内 URS、FS/配置说明、风险评估、IQ/OQ/PQ、RTM 和验证总结均批准。
- 高风险测试全部通过；关键/重大偏差已关闭或由 QA 批准接受。
- 生产环境 IQ 通过，版本、配置、权限、备份、时间源、审计、对象存储和接口均确认。
- 培训记录覆盖所有实际角色，且系统 SOP 已生效。
- 电子签名和审计追踪在生产环境有正式运行证据。

## 7. 变更和再验证策略

### 7.1 触发再验证

- MES/eDHR、DCC、电子签名、审计追踪、权限、审批、备份恢复、接口、报表、模板解析或数据迁移发生变更。
- 生产环境配置、数据库 schema、菜单权限、外部接口、对象存储、时间源或安全策略发生变更。
- 缺陷修复影响 GxP 数据、记录、签名、审批或放行结论。

### 7.2 再验证深度

| 变更类型 | 最低动作 |
| --- | --- |
| 高风险功能或数据模型变更 | 风险评估更新 + OQ 回归 + PQ 场景 + RTM 更新 + QA 批准 |
| 中风险配置或流程变更 | 影响评估 + 配置确认 + OQ 定向测试 + 变更批准 |
| 低风险显示/文案变更 | 影响评估 + 静态/页面确认 + 变更记录 |

## 8. QMS 整合

CSV 活动必须纳入企业 QMS：

- 文件控制：所有 CSV 文档应有编号、版本、审批、状态和归档位置。
- 变更控制：软件、配置、数据迁移、接口和环境变更都需变更单。
- 偏差/CAPA：测试偏差和运行偏差必须调查根因、评估影响、制定 CAPA 并复核关闭。
- 培训：业务用户、QA、IT、验证人员需按 SOP 和角色完成培训。
- 供应商管理：外部系统、平台、基础软件、开源组件和服务商需评估。
- 周期回顾：至少年度回顾 CSV 状态；高风险审计/签名可按季度回顾。

## 9. 质量放行判定

| 判定 | 条件 |
| --- | --- |
| GO | 全部必需文档批准，IQ/OQ/PQ 通过，偏差关闭，培训完成，QA 签署。 |
| CONDITIONAL GO | 非关键项有经 QA 批准的限制、补偿措施和完成日期。 |
| NO-GO | 高风险测试失败、关键偏差未关闭、QA 未批准、培训缺失、生产证据缺失或接口/备份/审计不可验证。 |

当前包判定：NO-GO for production release，仅可作为差距关闭工作底稿。
