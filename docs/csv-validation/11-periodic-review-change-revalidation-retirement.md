# 11 周期回顾、变更再验证与退役归档方案

## 1. 目的

保证 IntRuoyi 在首次 CSV 后持续保持验证状态，覆盖软件变更、配置变更、接口变更、周期回顾和系统退役。

## 2. 周期回顾

### 2.1 频率

| 范围 | 最低频率 | 触发 |
| --- | --- | --- |
| 总体 CSV 状态 | 每年至少一次 | 年度质量回顾、重大变更、审计 |
| 电子签名和 GxP 审计 | 每季度至少一次 | 策略、密钥、时间、篡改、账户事件 |
| 备份恢复 | 每年至少一次真实恢复演练；重大变更后补演练 | 备份策略、存储、数据库、对象变更 |
| 供应商/接口 | 每年至少一次；外部升级后立即评估 | ERP/BPM/存储/报表/时间源变更 |

### 2.2 回顾输入

- 变更清单、发布记录、migration 清单、配置差异。
- 偏差、CAPA、问题单、失败测试、运行告警。
- 审计追踪完整性、电子签名抽样、权限和账户复核。
- 备份链、恢复演练、证据包、WORM/留存回执。
- 接口对账结果、失败重试、外部供应商变更通知。
- 培训记录、SOP 更新和用户权限调整。

### 2.3 回顾输出

| 输出 | 要求 |
| --- | --- |
| 周期回顾报告 | 范围、周期、输入证据、结论、发现项、责任人、QA 批准 |
| 风险再评估 | 新风险、风险等级变化、控制有效性 |
| CAPA | 对问题项创建 CAPA 并跟踪关闭 |
| 再验证计划 | 明确需要重测的 URS/OQ/PQ/接口/性能 |

## 3. 变更再验证流程

### 3.1 变更分类

| 变更类型 | 例子 | 风险 | 最低再验证 |
| --- | --- | --- | --- |
| 关键 GxP 功能变更 | 批记录提交、DCC 发布、电子签名、审计、放行、注册证生效 | 高 | 风险评估 + OQ/PQ + RTM + QA 批准 |
| 数据模型/迁移变更 | GxP 表、签名表、审计表、权限表、备份 manifest | 高 | migration 测试 + 数据对账 + 回归 + QA 批准 |
| 接口变更 | ERP/BPM/对象存储/时间源/报表接口 | 高 | 接口验证 + 对账 + 异常/重试 + 影响评估 |
| 配置/权限变更 | 菜单、角色、密码策略、审查周期、留存期限 | 中/高 | 配置确认 + 安全/OQ 验证 |
| 展示/文案变更 | 非关键标签、说明文案 | 低/中 | 影响评估 + 目标确认 |

### 3.2 变更记录模板

| 字段 | 要求 |
| --- | --- |
| Change ID | 唯一编号 |
| 变更原因 | 缺陷、需求、法规、供应商、环境、性能 |
| 影响范围 | URS、风险、设计、数据、接口、测试、培训、SOP |
| 风险评估 | S/O/D、风险等级、是否高风险 |
| 再验证范围 | IQ/OQ/PQ/SEC/DI/RT/接口/性能 |
| 偏差处理 | 开放偏差和 CAPA |
| 批准 | 业务、IT、QA、验证负责人 |

### 3.3 放行门禁

任一高风险变更缺少影响评估、定向测试或 QA 批准，不得发布为 GxP 可用版本。工程测试通过不能替代 QMS 变更批准。

## 4. 退役归档

### 4.1 触发条件

- IntRuoyi 被替换、模块停用或关键功能迁移到新系统。
- DCC、eDHR、注册证、签名、审计、备份或接口功能停止使用。
- 外部系统迁移导致历史记录需要冻结和独立保存。

### 4.2 退役步骤

1. 建立退役计划，明确范围、原因、责任人和时间。
2. 执行记录清单盘点：URS、风险评估、测试、验证报告、偏差、CAPA、培训、变更、周期回顾。
3. 执行数据和文件归档：数据库记录、对象存储、导出包、签名、审计、备份、接口日志。
4. 验证归档可读、可检索、hash 一致、权限受控。
5. 确认新系统或纸质流程接管边界。
6. QA 批准退役报告，保留退役期间所有审计证据。

### 4.3 退役记录模板

| 字段 | 要求 |
| --- | --- |
| Retirement ID | 唯一编号 |
| 系统/模块 | 退役范围 |
| 退役原因 | 替换、合并、停止使用 |
| 数据范围 | 记录类型、日期、租户、业务对象 |
| 归档位置 | 数据库导出、对象存储、受控文档库 |
| 校验结果 | hash、记录数、抽样检索、恢复测试 |
| 权限 | 谁可访问历史资料 |
| 批准 | 业务、QA、IT、验证负责人 |

## 5. 当前结论

当前未识别已退役的 IntRuoyi GxP 系统或模块，因此 5.15 可作为“不适用待确认”。但必须由业务负责人和 QA 在系统清单中确认“不存在已退役 GxP 系统”，否则不能勾选不适用。
