# 02 系统清单与 GxP 影响性评估

## 1. 目的

## 3. 影响性判定规则

| 判定问题 | 若答案为“是”的动作 |
| --- | --- |
| 是否影响产品质量、批记录、放行或检验结果？ | 纳入 GxP，高风险优先。 |
| 是否生成或修改受控电子记录？ | 纳入电子记录和数据完整性验证。 |
| 是否用于电子签名、审批或授权？ | 纳入安全、身份、签名和审计验证。 |
| 是否与外部系统交换 GxP 数据？ | 纳入接口验证和供应商评估。 |
| 是否用于备份、恢复、归档或长期留存？ | 纳入恢复、留存和审查证据验证。 |

## 4. 关键电子记录

| 记录类型 | 系统来源 | 数据完整性要求 | 验证重点 |
| --- | --- | --- | --- |
| 批记录执行记录 | MES/eDHR | 原始记录、修改留痕、签名、归档、可读 | 生产事实与签名、字段审计、归档完整性 |
| PQC 检验记录 | MES/PQC | 实际检验人、检验类型、数量、结果、复核 | 任务来源、电子签名、复核和回填 |
| 受控文件版本 | DCC | 版本身份、文件 hash、审批、发布、替代 | Revision/Iteration、发布原子切换、历史可追溯 |
| 注册证记录 | DCC/注册证 | 当前证、待生效、旧证、提醒、下载授权 | 生命周期、续证审批、旧证归档、权限 |
| 电子签名记录 | Signature/DCC/BPM/MES | 签名人、时间、含义、内容 hash、证据 hash | 重新认证、不可变证据、统一策略 |
| GxP 审计事件 | GxP Audit | before/after、原因、时间、hash、清单 | 只追加、同事务、完整性、归档恢复 |
| 备份恢复证据 | Infra/运维 | manifest、checksum、演练报告、证据包 hash | 全量/增量链、恢复演练、审计下载 |
| 变更和验证记录 | QMS/任务文档 | 需求、风险、测试、偏差、批准 | 追溯矩阵、QA 签署、再验证 |

## 5. 接口清单

| 接口 | 方向 | GxP 数据 | 风险 | 当前要求 |
| --- | --- | --- | --- | --- |
| ERP 生产订单/调拨/物料批次同步 | ERP -> IntRuoyi | 订单、调拨单、批次、数量 | 高 | 需验证完整性、准确性、失败处理和对账。 |
| BPM 审批 | IntRuoyi <-> BPM | 审批任务、意见、签名上下文 | 高 | 需验证任务身份、顺序、审批结果和签名绑定。 |
| 对象存储/MinIO/NAS | IntRuoyi -> 存储 | 文件、签名图片、导出包、备份对象 | 高 | 需验证 hash、权限、留存、恢复和缺失阻断。 |
| Jimu/报表 | IntRuoyi -> 报表 | 批记录报表、模板输出 | 中/高 | 需验证模板版本、输出内容和打印导出一致性。 |
| Word 解析 | 上传文件 -> IntRuoyi | 表单模板、批记录映射 | 中/高 | 需验证 `.doc/.docx` 解析一致、失败关闭和无写入 parse-only。 |
| 可信时间/系统时间 | 服务器/DB -> IntRuoyi | 签名时间、审计时间 | 高 | 需验证时间源、偏差、证据导出和不可手填。 |

## 6. 责任矩阵

| 角色 | CSV 职责 | 当前缺口 |
| --- | --- | --- |
| 业务负责人 | 批准预定用途、URS、PQ 场景和代表性数据 | 姓名和签署记录待补 |
| QA/合规负责人 | 批准风险评估、验证策略、偏差、验证报告 | 姓名、批准流程、培训记录待补 |
| IT/系统负责人 | 提供配置、部署、权限、备份和接口证据 | 生产环境 IQ 证据待补 |
| 开发负责人 | 提供设计、代码、单元/集成测试、变更影响分析 | 工程证据需纳入 RTM |
| 验证执行人 | 执行 IQ/OQ/PQ 并记录偏差 | 人员资质和培训待补 |
| 供应商/外部系统负责人 | 提供 ERP、BPM、对象存储、基础设施质量证据 | 供应商评估和质量协议待补 |

## 7. 影响性结论

IntRuoyi 当前范围包含多个直接影响产品质量、电子记录、电子签名、审计追踪、批记录和放行的功能，应作为高风险 GxP 计算机化系统验证。低风险功能不应过度验证，但凡进入批记录、文控、签名、审计、备份、放行和外部接口的链路，均不得仅用工程测试或页面截图替代 CSV 证据。
