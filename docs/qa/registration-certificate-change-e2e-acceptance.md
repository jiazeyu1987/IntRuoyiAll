# 注册证变更正确分支 E2E 验收流程

## Scope

本文档用于指导 Codex 在本机 `int_main` 环境，通过 Playwright 操作真实前端页面，验证“注册证变更”从申请人提交到注册经理审批，再到当前证字段更新和履历留痕的正确分支闭环。

不覆盖填错、缺字段、权限不足、网络失败等失败分支。

## Fixed Test Context

- 环境：本机 `int_main`。
- 前端入口：`http://127.0.0.1:8081` 或 `http://localhost:8081`。
- 后端健康检查：`http://127.0.0.1:48081/actuator/health`。
- 租户：芋道源码。
- 变更申请人 A：`wanglixuan`。
- 注册经理 B：`chudongqian`。
- 普通用户 C：优先使用 `wanglixuan` 执行普通用户下载授权分支，前提是该账号不是注册部经理且没有变更文件直接下载特权；若该账号已具备直接下载特权，执行前另选同租户内可查看注册证详情但无直接下载特权的普通用户账号，并记录账号名。
- 变更批件文件：`E:\IntRuoyi\e2e_test\registration\biangeng\biangeng.pdf`。
- 测试数据标识：注册证编号、产品名称、变更后字段和备注等必须包含本次任务唯一标识，例如 `E2E-CHANGE-YYYYMMDD-HHMMSS`。

密码由本次执行人按安全方式注入或手工输入，不写入文档、日志、截图、trace、脚本源码或提交记录。

## Required Preflight

1. 确认前端 `8081` 可访问，后端 `48081` health 为 `UP`。
2. 确认变更批件文件存在：`E:\IntRuoyi\e2e_test\registration\biangeng\biangeng.pdf`。
3. 用真实登录页确认租户为“芋道源码”。
4. 确认 `wanglixuan` 已具备注册证变更提交权限，并能在 CURRENT 注册证行看到“变更”入口。
5. 确认 `chudongqian` 已绑定注册部经理权限角色，并能进入审批中心待办。
6. 确认注册证变更审批候选不为空，候选来源为注册部经理角色及上传审批权限。
7. 确认普通用户 C 能进入注册证详情页，但不具备变更文件直接下载特权。
8. 确认普通用户下载申请的审批候选不为空，且注册部经理 B 能在审批中心处理该下载申请。
9. 准备至少两张任务自有 CURRENT 注册证：
   - 一张用于单项或少量字段变更审批。
   - 一张用于全结构化字段变更审批。
10. 确认目标 CURRENT 注册证没有待审批变更，行级“变更”入口可见。
11. 若上述任一项不满足，E2E 结论记为 `BLOCKED`，不得用 API-only、SQL 直改状态或切换账号替代真实页面路径。

## Test Data

每次执行创建或选取任务自有数据：

- 基准注册证：状态为 CURRENT，当前列表可见，且行级“变更”入口可见。
- 变更文件：`E:\IntRuoyi\e2e_test\registration\biangeng\biangeng.pdf`。
- 批准日期：选择不晚于当前真实日期的日期。
- 单项变更场景：至少选择“产品名称”或“型号规格”之一，并填写带唯一标识的新值。
- 生产地址变更场景：选择“生产地址”，填写新生产地址，并选择合法生产关系。
- 全结构化字段场景：选择产品名称、型号规格、结构组成、适用范围、产品技术要求、注册人名称、住所、生产地址，并逐项填写带唯一标识的新值。
- 其他内容场景：如需要覆盖“其他内容”正确分支，选择“其他内容”并填写带唯一标识的说明。
- 下载授权有效期：普通用户下载申请审批通过后的有效期为 24 小时，执行时记录具体授权通过时间、有效截止时间和验证时间。
- 缺少项目代码的注册证或变更批件文件也允许普通用户申请下载。
- 项目代码为空时审批摘要允许为空，下载文件名保留空项目代码段。

## E2E-1 申请人提交注册证变更审批

### Operation

1. 使用变更申请人 A `wanglixuan` 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”页。
3. 按任务自有基准注册证编号筛选当前列表。
4. 确认目标行状态为 CURRENT，且“变更”入口可见。
5. 点击“变更”。
6. 在变更弹框中核对证件编号、产品、当前版本和当前状态。
7. 填写批准日期。
8. 在“变更内容”中选择本次要变更的字段。
9. 核对所选字段输入框已回显当前证字段值。
10. 将所选字段改为带唯一标识的新值。
11. 若选择“生产地址”，同步选择合法的“是否委托生产”和“是否自行生产”；委托生产为是时填写正式受托企业。
12. 若选择“其他内容”，填写其他说明。
13. 上传 `E:\IntRuoyi\e2e_test\registration\biangeng\biangeng.pdf`。
14. 点击“确认”提交审批。

### Expected Result

- 页面显示注册证变更审批提交成功的中文结果。
- 变更弹框关闭或进入明确提交完成状态。
- 自然触发的变更提交请求返回业务成功。
- 生成一条“注册证变更审批”申请。
- 审批通过前，目标注册证的当前列表和详情仍展示原正式字段，不提前展示变更后字段。

### Evidence

- 记录登录身份标签：芋道源码 / `wanglixuan`。
- 记录基准注册证编号、当前版本号、所选变更字段和变更后值。
- 记录变更提交请求 URL、HTTP 状态、业务码和 requestId。
- 保存提交成功后的页面截图或 trace 步骤截图。

## E2E-2 提交后状态正确

### Operation

1. 仍使用变更申请人 A `wanglixuan`。
2. 返回“注册证管理 / 注册证”当前列表。
3. 按基准注册证编号查询目标行。
4. 打开目标注册证详情。
5. 进入审批中心待办。
6. 进入“我发起 / 已提交 / 流程记录”等发起人视角。

### Expected Result

- 审批通过前，当前列表仍展示基准注册证的原正式字段。
- 审批通过前，详情仍展示基准注册证的原正式字段。
- 目标行不再开放重复“变更”入口，或页面以正式待变更状态阻止重复变更。
- `wanglixuan` 的待办中不出现这条“注册证变更审批”。
- `wanglixuan` 的发起人视角能看到该申请处于审批中。
- 该申请标题或业务名称为“注册证变更审批”，不是上传、延续或通用英文码。

### Evidence

- 当前列表目标行截图，展示原正式字段。
- 详情页截图，展示原正式字段。
- 申请人待办查询截图，显示无该目标待办。
- 申请人发起记录截图，显示目标申请处理中。
- 记录目标页签、筛选关键词、自然触发分页请求的业务码和 total。

## E2E-3 注册经理待办审批

### Operation

1. 退出申请人 A。
2. 使用注册经理 B `chudongqian` 登录“芋道源码”租户。
3. 进入审批中心待办。
4. 按基准注册证编号或唯一标识筛选。
5. 打开“注册证变更审批”待办详情。
6. 核对审批标题、摘要和业务详情入口。
7. 打开或查看业务详情，核对变更字段、变更后值和变更批件文件。
8. 点击同意或通过，填写审批意见并提交。

### Expected Result

- 注册经理 B 的待办中出现目标“注册证变更审批”。
- 待办摘要展示注册证编号、分类、产品、所属公司。
- 审批详情中的审核对象体现注册部经理审批语义。
- 业务详情入口能打开或展示注册证变更申请详情。
- 业务详情展示本次选择的变更字段、变更后值、批准日期和变更批件文件。
- 注册经理 B 可处理原指派人为其他用户的变更审批待办。
- 审批提交成功后，该待办从 B 的待办中消失。

### Evidence

- 注册经理待办列表截图。
- 审批详情截图，包含标题、摘要和审核对象。
- 业务详情截图，包含变更字段和批件文件。
- 审批通过后的成功状态截图。
- 记录审批提交请求 URL、HTTP 状态、业务码、processInstanceId 或 taskId。

## E2E-4 审批后当前证正式字段更新

### Operation

1. 使用注册经理 B 或重新登录申请人 A。
2. 进入“注册证管理 / 注册证”当前列表。
3. 按基准注册证编号查询。
4. 打开该注册证详情。
5. 查看基础信息、生产信息、变更批件文件和操作审计信息。
6. 刷新当前列表并再次按注册证编号查询。

### Expected Result

- 当前列表出现且只出现一条目标注册证。
- 当前列表展示审批通过后的变更后字段。
- 当前列表状态仍为正式当前证状态，不因变更产生多条当前证。
- 详情基础信息与审批通过的变更后字段一致。
- 未选择变更的字段保持原正式值。
- 详情中可以查看本次变更批件文件，文件来源为本次上传材料。
- 变更申请人显示 `wanglixuan`，申请时间为真实提交时间。
- 变更审批人显示 `chudongqian`，审批时间为真实审批时间。
- 当前列表重复刷新仍成功，不出现读审计冲突。

### Evidence

- 当前列表目标行截图。
- 详情页基础信息截图。
- 详情页生产信息截图。
- 详情页变更批件文件查看区域截图。
- 详情页申请人/审批人/时间截图。
- 记录列表分页请求至少两次，均为 HTTP 成功、业务码成功。

## E2E-8 普通用户申请下载并在 24 小时内下载变更批件文件

### Operation

1. 使用普通用户 C 登录“芋道源码”租户。
2. 进入“注册证管理 / 注册证”当前列表。
3. 按已完成变更审批的目标注册证编号筛选。
4. 打开该注册证详情。
5. 定位本次变更批件文件区域。
6. 点击下载申请或等价入口。
7. 填写申请理由，理由包含本次唯一标识。
8. 提交下载申请。
9. 退出普通用户 C。
10. 使用注册经理 B `chudongqian` 登录。
11. 进入审批中心待办，按注册证编号或唯一标识筛选下载申请。
12. 打开下载申请审批详情，核对申请人、注册证编号、项目代码、文件名和申请理由；若项目代码为空，应显示为空或未填写，不得阻塞审批。
13. 点击同意或通过，填写审批意见并提交。
14. 记录下载授权通过时间和系统显示的有效截止时间。
15. 在授权通过后 24 小时内，重新使用普通用户 C 登录。
16. 打开目标注册证详情，点击下载本次变更批件文件。

### Expected Result

- 普通用户 C 在未获授权前通过页面发起下载申请。
- 下载申请标题或业务名称能明确体现注册证文件下载申请语义。
- 注册经理 B 的待办中出现该下载申请并可审批通过。
- 审批详情展示申请人、注册证编号、文件名和申请理由。
- 缺少项目代码时，普通用户 C 仍可提交申请，注册经理 B 仍可审批，下载文件名以空项目代码段开头。
- 审批通过后 24 小时内，普通用户 C 可以在详情中下载本次变更批件文件。
- 24 小时内下载不需要重复提交下载申请。
- 下载文件名或下载记录能对应本次变更批件文件 `biangeng.pdf`。

### Evidence

- 普通用户下载申请提交截图。
- 注册经理下载申请待办和审批详情截图。
- 下载授权通过后的成功状态截图。
- 授权通过时间、有效截止时间和 24 小时内下载验证时间。
- 普通用户 24 小时内下载触发前后截图或 Playwright download evidence。

## E2E-9 普通用户下载授权超过 24 小时后重新申请下载

### Operation

1. 使用已完成 E2E-8 的同一普通用户 C 和同一目标注册证。
2. 在下载授权超过 24 小时后登录普通用户 C。
3. 进入目标注册证详情。
4. 定位本次变更批件文件区域。
5. 点击下载入口。
6. 页面引导普通用户重新发起下载申请，或下载入口恢复为申请状态。
7. 再次填写申请理由，理由包含本次唯一标识和二次申请标记。
8. 提交第二次下载申请。
9. 使用注册经理 B 审批通过第二次下载申请。
10. 普通用户 C 在第二次授权通过后 24 小时内再次下载本次变更批件文件。

### Expected Result

- 超过第一次下载授权 24 小时后，普通用户 C 不能继续沿用第一次授权直接下载。
- 页面提供重新申请下载的正式入口。
- 第二次下载申请可由注册经理 B 审批通过。
- 第二次审批通过后，普通用户 C 在新的 24 小时有效期内可以下载本次变更批件文件。
- 第二次授权通过时间、有效截止时间与第一次授权分开记录。

### Evidence

- 超过 24 小时后的详情页文件区域截图，显示需要重新申请或等价状态。
- 第二次下载申请提交截图。
- 第二次审批详情和审批通过截图。
- 第二次授权通过时间、有效截止时间和下载验证时间。
- 第二次下载触发前后截图或 Playwright download evidence。
