# MES 统一版本升级重启用户前端操作流程

## Purpose and Scope

本文说明用户如何在活跃订单中点击“升级”按钮，确认系统自动解析的全部最新正式版本，提交独立审批、查看审批结果，以及如何从新订单追溯旧订单填写内容。

本流程适用于工艺路线、QA 检验规程、批记录模板、表单模板、设备参数标准、物料规范、放行规则等受控对象的版本变化。流程采用整单重启：审批通过后旧活跃订单和旧批次停止执行，新订单复制业务上下文但从头生成全部执行任务，不带入旧填写结果。

本流程不是不合格处理流程。因质量不合格、偏差、CAPA、召回或报废产生的问题，仍从各自的质量或合规入口处理。

## Evidence Reviewed

- `docs/product/mes-unified-version-upgrade-restart-prd.md`：统一版本升版重启产品需求。
- `docs/product/frontline-process-material-batch-record-mvp-user-operation.md`：一线批记录物料、历史快照和批号展示规则。
- `docs/acceptance/production-execution-main-loop/traceability-matrix.md`：生产、QA、复核、批记录和放行的追溯要求。
- `docs/backend-development.md`：版本快照、批记录来源边界、冻结门禁和只读追溯约束。
- 用户确认：活跃订单提供升级按钮；点击后不进入复杂版本选择，系统按所有受控对象的最新正式版本生成升级快照并走升级审批；审批通过后作废老版本批次，创建相同业务内容的新订单重新加入活跃订单；旧填写内容必须在追溯中可查看。

## Primary User Flows

### Flow 1：查看当前订单版本基线

1. 进入“活跃订单”列表。
2. 打开目标订单详情。
3. 进入“版本基线”区域。
4. 查看当前订单实际锁定的版本集合。
5. 确认每行的对象名称、当前版本、版本状态和锁定时间。
6. 点击“升级”。

页面应明确显示：

```text
当前执行版本基线
工艺路线：V1
QA 检验规程：5.0
批记录模板：3.0
表单模板：2.0
```

操作重点：

- 当前版本来自订单锁定快照，不是页面临时查询的最新版本。
- 已放行、已归档、已终止或存在不可绕过的合规冻结时，不显示可用的升版提交动作。
- 版本基线页只展示版本事实，不允许直接编辑当前版本。

### Flow 2：确认系统解析的全部最新版本

1. 在升级页面查看来源订单和当前版本基线。
2. 等待系统读取所有受控对象的最新正式版本。
3. 查看系统生成的“当前版本 → 最新版本”清单。
4. 确认本次为全部最新版本整单重启。
5. 不需要也不能逐项选择、删除或替换目标版本。

示例：当前 QA 为 5.0，系统最新正式版本为 7.0：

```text
QA 检验规程：5.0 → 7.0
工艺路线：V1 → V2
批记录模板：3.0 → 4.0
表单模板：2.0 → 3.0
```

界面规则：

- 最新版本必须显示真实版本号及正式版本状态。
- 草稿、已撤销、已作废或不适用版本不能进入升级快照；出现此情况时页面显示阻塞原因。
- 页面不提供逐项版本选择器，也不提供只升级部分对象的操作。
- 系统在用户确认并提交审批前保存完整升级快照；审批通过按该快照应用。

### Flow 3：查看差异预览

1. 系统生成全部最新版本快照后点击“查看差异”。
2. 查看每个受控对象的当前版本与最新版本差异。
3. 查看差异是否改变执行数据结构。
4. 查看系统提示的版本依赖和阻塞项。
5. 确认“整单从头重启，不继承旧填写内容”。

差异示例：

```text
工艺路线 V1 → V2
粗洗工序：清洗物料 2 项 → 3 项

QA 规程 5.0 → 6.0
新增检验项目：1 项

批记录模板：未变更
表单模板：未变更
```

如果最新版本集合存在依赖冲突，页面必须显示：

```text
无法提交：QA 7.0 依赖表单模板 4.0，但最新版本快照中的表单模板不满足依赖。
请修复正式版本依赖后重新点击“升级”。
```

用户不能在前端补选或拼接依赖版本。

### Flow 4：提交版本升版审批

1. 填写升版原因。
2. 确认来源订单、旧批次和全部最新版本快照。
3. 阅读并确认影响提示：旧执行将终止，新订单从头执行，历史填写只读保留。
4. 使用当前用户电子签名完成提交。
5. 点击“提交升版审批”。
6. 系统显示审批编号和状态 `版本升级审批中`。

提交确认文案至少应表达：

```text
旧活跃订单将停止生产和放行操作。
旧批次将因版本升版重启而终止，不会删除历史填写、签名、附件和审计。
审批通过后将创建一个业务内容相同的新活跃订单。
新订单不继承旧订单任何填写结果，所有工序和检验从头开始。
本申请属于版本升版，不属于不合格审批。
```

### Flow 5：审批期间查看冻结状态

1. 用户返回活跃订单详情。
2. 页面顶部显示“版本升版审批中”。
3. 页面显示审批编号、申请人、提交时间和全部最新版本摘要。
4. 生产、PQC、批记录、放行和再次升版按钮均显示为不可用。
5. 用户可以打开历史只读页面，但不能新增或修改执行数据。

审批拒绝或撤回时：

1. 页面显示拒绝/撤回原因。
2. 旧订单解除版本升版冻结。
3. 旧订单继续按原版本执行。
4. 不创建新活跃订单。

### Flow 6：审批通过后查看新活跃订单

1. 打开版本升版申请详情。
2. 查看审批结果为“已通过”。
3. 查看旧订单状态为“因版本升版终止”。
4. 查看新订单编号和新批次编号。
5. 点击“打开新活跃订单”。
6. 在新订单详情确认全部最新版本基线。
7. 从第一道工序开始重新执行。

新订单必须显示：

```text
来源订单：AO-001-R1
升版申请：VU-2026-001
当前修订：AO-001-R2
工艺路线：V2
QA 检验规程：7.0
执行状态：从头开始
```

当旧路线有两个物料、新路线有三个物料时，新订单应直接显示三个空白物料执行项，不显示旧订单的已填写数量。

### Flow 7：从新订单查看旧版本填写内容

1. 在新订单详情点击“版本历史”。
2. 在历史列表选择旧订单修订版。
3. 点击“查看旧版本填写记录”。
4. 系统打开旧订单只读详情。
5. 选择“我的填写”或“完整审计”视图。
6. 查看原工序、物料、QA、批记录、设备参数、签名和附件内容。
7. 通过“返回新订单”回到当前活跃订单。

历史列表示例：

| 修订版 | 路线版本 | QA 版本 | 状态 | 终止原因 | 操作 |
| --- | --- | --- | --- | --- | --- |
| R1 | V1 | 5.0 | 版本升版终止 | 升版重启 | 查看 |
| R2 | V2 | 6.0 | 当前活跃 | - | 进入 |

旧版本详情应显示：

- 当时使用的路线、QA、批记录和表单版本。
- 用户填写的完成数量、损耗、不良明细和设备参数。
- QA 检验值、结果和签名。
- 批记录表单原始布局和字段值。
- 附件、字段审计、提交时间和操作人。
- 版本升版申请、审批结果、作废原因和替代订单。

历史页面只读，不提供编辑、重新提交、审批、放行或“一键复制到新订单”。

## Alternate Flows

### Alternate Flow 1：QA 版本随全部最新版本一起升级

1. 在活跃订单点击“升级”。
2. 系统自动解析 QA、路线、批记录、表单和其他受控对象的最新正式版本。
3. 用户查看完整版本变化摘要，不单独选择 QA 版本。
4. 提交版本升版审批。
5. 审批通过后创建新活跃订单。
6. 新订单按全部最新版本从头执行所有工序和检验。

如果 QA 7.0 是点击升级时的最新正式版本，系统就按 QA 7.0 创建升级快照。

### Alternate Flow 2：路线物料数量变化

1. 在活跃订单点击“升级”。
2. 差异预览显示“物料 2 项变为 3 项”。
3. 用户确认整单重启。
4. 审批通过后进入新订单。
5. 新订单按三项物料生成空白执行数据。
6. 用户从头填写三个物料，旧订单两项物料数据仅在历史页面查看。

### Alternate Flow 3：多个对象同时变更

1. 在活跃订单点击“升级”。
2. 系统将路线、QA、批记录、表单和其他受控对象的最新正式版本一起写入升级快照。
3. 用户确认完整差异和整单重启后提交审批。
4. 新订单使用这组完整的最新版本快照。

### Alternate Flow 4：审批期间目标版本继续发布新版本

1. 用户已提交升级申请，申请快照中记录 QA 7.0。
2. 系统后来发布 QA 8.0。
3. 原申请仍显示并使用已记录的 QA 7.0 快照。
4. 如果用户要改用 8.0，应撤回原申请后重新点击“升级”。

### Alternate Flow 5：无旧填写数据的订单升版

1. 用户仍可发起升版申请。
2. 系统照常记录旧订单和升版审批关系。
3. 审批通过后创建新订单并从头执行。
4. 旧订单历史页面显示“无执行填写记录”。

## Error Flows

### Error Flow 1：没有升版权限

- 页面不显示可用的升版按钮，或点击后提示无权操作。
- 用户仍可以按权限查看订单和历史记录。

### Error Flow 2：订单存在不合格或合规冻结

- 页面显示冻结原因。
- 升版提交按钮不可用。
- 用户必须先按不合格/合规流程处理，版本升版不能解除该冻结。

### Error Flow 3：最新版本快照不可用

- 任一对象没有可用的正式最新版本，提交被阻止。
- 页面明确指出具体对象和阻塞原因。
- 系统不自动替换为其他版本，也不允许用户手工选择旧版本继续。

### Error Flow 4：最新版本依赖不满足

- 页面显示缺少或冲突的依赖版本。
- 用户必须修复正式版本依赖后重新点击“升级”。
- 页面不得静默拼接或替换依赖版本。

### Error Flow 5：审批通过但新订单创建失败

- 页面显示“版本升版应用失败”。
- 旧订单保持冻结，不恢复为可生产状态，也不删除历史。
- 不显示一个未完成的新订单作为可生产订单。
- 授权用户进入失败处理入口重新校验或重试。

### Error Flow 6：重复提交或重复点击

- 页面返回已有的升版申请或已创建的新订单。
- 不创建第二个升版申请或第二个有效活跃订单。

### Error Flow 7：旧历史数据无法加载

- 页面显示历史快照或审计证据缺失。
- 不使用当前最新模板或当前路线补齐旧页面。
- 该问题应进入数据修复/审计处理，不得标记历史查看成功。

### Error Flow 8：订单已经放行或归档

- 普通升版按钮不可用。
- 页面引导用户进入放行后变更、CAPA、召回或其他正式流程。

## Out-of-Scope Flows

- 在旧订单上直接修改路线或 QA 版本。
- 让用户逐项选择目标版本或只升级部分对象。
- 只修改版本号而不创建新订单。
- 把旧填写值复制到新订单。
- 通过升版按钮处理生产不合格、偏差、CAPA、召回或报废。
- 删除旧订单、旧批次或旧表单历史。
- 用当前最新模板解释旧版本表单。
- 在前端自动创建新的外部 ERP 生产工单。
- 设计跨版本字段映射或部分工序继承。

## Open Questions

- 升版审批中具体需要哪些角色和电子签名，需由审批配置确定。
- “一模一样订单”在外部 ERP 中是否需要新工单编号，需由 ERP 集成规则确定。
- 旧订单的领料、库存和 FIFO 分配如何释放或冲销，需由生产和仓储规则确定。
- 旧版本历史的保留期限、普通用户可见范围和脱敏规则，需由合规策略确定。
- 升版应用失败的重试和人工修复页面，需在系统设计阶段确定。
