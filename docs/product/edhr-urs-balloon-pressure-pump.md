## 4. 目的

本文件仅描述用户需求，不描述数据库结构、页面样式、接口报文、算法细节或实现方案。

## 5. 范围

本 URS 覆盖产品主数据、工艺与批记录绑定、生产填写、过程检验、偏差、复核、放行、追溯、归档、权限、电子签名、审计追踪以及备份恢复。

## 6. 预定用途

系统用于车间、一线PQC、组长和QA在已批准版本下完成电子批记录填写、检验、复核、偏差处置、放行和追溯归档。

## 8. 术语和角色

### 8.1 术语

| 术语 | 定义 |
| --- | --- |
| eDHR | 某批或某生产订单产品在生产、检验、复核、放行和归档过程中形成的电子质量记录集合 |
| 正式批记录表单 | 对应工序的正式生产批记录载体 |
| 辅助表单 | 用于工艺执行补充记录的独立表单，不得替代正式批记录表单 |
| 工序开始配置 | 用于特殊开始节点责任人或上传人的配置，不生成批记录内容 |
| 偏差 | 对生产、检验、附件、设备、数量、状态或结果的受控异常处理记录 |
| 放行 | 经授权人员确认记录齐套并批准产品进入下一质量状态 |

### 8.2 角色

| 角色 | 主要职责 |
| --- | --- |
| 一线生产 | 填写生产记录并提交 |
| 一线 PQC | 填写过程检验记录并提交 |
| 组长 | 复核、驳回或要求补正 |
| QA/放行人 | 审核偏差并执行放行 |
| 系统管理员 | 维护账号、权限和基础字典 |
| 审计只读 | 查询、导出和留痕查看 |

## 9. 运行约束

- 系统应在受控账号、受控时间和已批准版本下运行。
- 系统不得允许未授权账户执行填写、复核、签名或放行。
- 系统应对创建、修改、作废、复核、放行、导出和打印保留审计追踪。
- 系统应支持受控备份和恢复。

## 11. 状态与转换

| 对象 | 状态 | 允许转换 |
| --- | --- | --- |
| 生产记录 | 草稿 -> 已提交 -> 已复核 -> 已放行 / 已归档 |
| 检验记录 | 草稿 -> 已提交 -> 已复核 |
| 批记录 | 待齐套 -> 待放行 -> 已放行 -> 已归档 |
| 偏差 | 新建 -> 调查中 -> 待批准 -> 已关闭 |
| 更正记录 | 新建 -> 已提交 -> 已生效 |

## 12. 边界情况

- 订单剩余数量不足时，系统不得提交。
- 某工序无独立设备参数时，相关字段应可按配置不适用。
- 记录已放行或已归档时，系统不得允许普通用户直接修改。
- 恢复期间形成的记录应在恢复后按受控流程补录和签名。

## 13. 验收原则

- 每条需求应可追踪到设计、测试和验证证据。
- 高风险需求在投入使用前应完成 OQ/PQ 并关闭相关偏差。
- 未在本 URS 中定义的实现细节不得作为需求自动补入。
