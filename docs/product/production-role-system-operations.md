# 生产全流程角色系统操作文档

## Purpose and Scope

本文整理从生产订单确认到生产结束放行的角色边界、系统界面入口和操作要求。本文只定义未来在本系统中的业务操作口径，不替代金蝶 ERP、纸质单据或仓库发料流程。

## Evidence Reviewed

- 用户确认的生产流程：生产订单确认、调拨申请、仓库调拨发料、物料员核对解包、线边仓、按 SOP 生产、员工报工、班组长确认分配、PQC 首检/巡检/末检、PQC 组长确认、批记录汇总、负责人放行。
- 用户补充的订单口径：班组长与计划排产员可每周或每两周确认生产订单，紧急订单可当天确认；已确认且未异常终止的订单都要执行。
- 用户补充的数量口径：工序应完成数量等于生产订单数量乘以工艺路线中该工序的生产系数。
- 用户补充的系统边界：计划排产员、仓库、物料员不使用本系统，使用纸质单据或金蝶 ERP；ERP 数据可由本系统直连获取；其他角色未来需要使用本系统。
- 用户裁定：ERP 每晚同步到本地生产订单列表和本地调拨单列表；班组长按纸质订单编号加入活跃订单池，按纸质调拨单号关联调拨单；FIFO 按活跃订单加入时间；设备从设备台账选择并绑定到工序；上下限不覆盖员工原始提交。
- 项目约束：批记录表单、表单槽位 `formBindings`、工序开始配置是三条独立链路，不得互相替代。

## Product Summary

未来系统应以“活跃订单”为主线。系统每天晚上从金蝶 ERP 同步生产订单、调拨申请、调拨单和物料批次到本地列表；生产班组长根据纸质订单编号和纸质调拨单号，在本系统本地列表中过滤搜索后，将生产订单加入活跃订单池并关联调拨单。生产现场角色在本系统中完成订单异常、工序报工、报工确认、PQC 检验、检验复核、批记录汇总和放行。

系统内核心原则：

- 外部角色不登录本系统操作，系统通过夜间 ERP 同步把生产订单和调拨单写入本地列表，班组长再按纸质单据选择加入或关联。
- 生产一线员工在本系统记录生产事实。
- PQC 检验员在本系统记录检验事实。
- 生产班组长确认生产事实并分配到订单。
- PQC 组长确认检验事实并汇集到过程检验记录。
- QA 在本系统维护检验规程。
- 系统按正式规则计算工序应完成数量、更新订单进度、生成批记录完整性判断并推送放行。

## Target Users

| 角色 | 是否登录本系统 | 主要系统关系 |
| --- | --- | --- |
| 计划排产员 | 否 | 用纸质订单与班组长同步；班组长按纸质订单编号在本系统本地生产订单列表中过滤搜索。 |
| 仓库 | 否 | 在金蝶 ERP 中生成调拨单并发货；系统夜间同步到本地调拨单列表，班组长按纸质调拨单号关联。 |
| 物料员 | 否 | 根据调拨单核对、解包和交接物料；本系统读取 ERP 物料批次作为追溯依据。 |
| 生产班组长 | 是 | 确认订单执行、上报异常、复核报工、分配工序数量、维护班组级基础数据。 |
| 生产一线员工 | 是 | 在设备端或一线报工入口提交工序生产事实。 |
| PQC 检验员 | 是 | 按检验规程提交首检、巡检、末检记录。 |
| PQC 组长 | 是 | 复核 PQC 检验单，确认后汇集到过程检验记录。 |
| QA | 是 | 维护各产品、各工序的检验规程和检验规则。 |
| 放行负责人 | 是 | 审核完整批记录和过程检验记录，执行订单放行。 |
| 系统 | 是 | 执行 ERP 同步、数量计算、状态流转、批记录汇总、待办推送和完整性校验。 |

## First Version Scope

- 覆盖生产订单、工序、报工、PQC、批记录和放行的角色操作说明。
- 覆盖计划排产员、仓库、物料员“不使用本系统”的边界。
- 覆盖 ERP 夜间同步数据进入本地生产订单列表和本地调拨单列表后的系统内使用方式。
- 覆盖生产系数、异常订单、报工分配、PQC 组长确认和放行触发规则。
- 覆盖未来系统应提供的界面名称、操作动作和产出数据。

## Non-Goals

- 不要求计划排产员、仓库、物料员在本系统补录纸质单据。
- 不在本文设计金蝶 ERP 的调拨申请、调拨单或仓库发货页面。
- 不把表单槽位 `formBindings` 当作批记录表单来源。
- 不把工序开始配置当作批记录表单或表单槽位。
- 不用默认订单、默认物料批次、默认设备或默认成功状态掩盖数据缺失。

## Primary User Flows

### Flow 1: ERP 数据进入本系统

1. 计划排产员与生产班组长在纸质单据或金蝶 ERP 中确认生产订单。
2. 生产班组长在金蝶 ERP 中填写调拨申请单。
3. 仓库在金蝶 ERP 中生成调拨单并发货。
4. 物料员按调拨单核对并解包物料。
5. 系统夜间同步 ERP 生产订单、调拨申请、调拨单、发货物料、数量和批次到本地列表。
6. 班组长根据纸质订单编号在本地生产订单列表中过滤搜索并加入活跃订单池；根据纸质调拨单号在本地调拨单列表中过滤搜索并关联调拨单。

### Flow 2: 班组长执行订单和异常上报

1. 生产班组长进入 `生产班组长工作台`。
2. 班组长查看已加入的活跃订单、本地同步订单数据和已关联调拨单物料状态。
3. 如果订单可执行，班组长保持订单为待生产或生产中。
4. 如果出现原材料异常、客户取消或现场无法生产，班组长进入 `异常订单上报`。
5. 班组长填写异常原因、说明、影响范围并提交。
6. 系统将订单标记为异常，不再生成后续报工、PQC、批记录和放行待办。

### Flow 3: 一线员工报工

1. 一线员工进入 `一线报工/记录本提交`。
2. 员工选择工艺路线、工序、实际员工、设备和对应生产上下文。
3. 员工按 SOP 完成生产。
4. 员工填写完成数量、损耗数量、损耗原因、设备参数。
5. 员工电子签名并提交。
6. 系统保存生产事实，形成可追溯报工记录，等待班组长复核。

### Flow 4: 班组长复核并分配订单

1. 生产班组长进入 `报工复核与订单分配`。
2. 班组长查看员工提交的工序报工、设备参数和损耗信息。
3. 班组长确认报工数据合理。
4. 班组长将工序完成数量分配给对应生产订单。
5. 系统按生产系数计算目标数量并累计进度。
6. 当工序累计合格完成数量达到应完成数量，系统更新该工序完成状态并写入批记录表单。

### Flow 5: PQC 检验

1. PQC 检验员进入 `PQC 过程检验工作台`。
2. 系统按已确认生产订单和 QA 检验规程生成首检、巡检、末检任务。
3. PQC 检验员执行检验并填写检验记录。
4. PQC 检验员电子签名提交。
5. 系统保存检验事实，等待 PQC 组长确认。

### Flow 6: PQC 组长确认

1. PQC 组长进入 `PQC 检验单复核工作台`。
2. PQC 组长查看检验员提交的检验单。
3. 内容正确时确认检验单。
4. 内容不完整或关联错误时退回补正。
5. 系统在确认后将检验数据汇集到对应批记录的过程检验记录。

### Flow 7: 批记录完成和订单放行

1. 系统持续检查每个生产订单的工序批记录表单完成情况。
2. 系统持续检查对应过程检验记录是否已由 PQC 组长确认。
3. 当订单所有批记录表单和过程检验记录都完整后，系统推送放行待办。
4. 放行负责人进入 `批记录放行工作台`。
5. 放行负责人审核生产事实、检验事实、物料批次、设备参数、损耗记录和完整性检查。
6. 放行负责人通过或退回。
7. 系统记录放行结果并更新生产订单最终状态。

## Business Rules

- 已由班组长从本地生产订单列表加入活跃订单池且未异常终止的生产订单都要执行；纸质确认时间可以是当天、几天前、上周或两周前。
- 紧急订单可以当天由计划排产员与生产班组长确认。
- 活跃订单加入时间是 FIFO 默认分配的第一排序依据。
- 班组长只能从设备台账选择设备并绑定到工序，不随意创建主设备。
- 设备参数上下限用于提示、复核、异常判断和审核副本，不覆盖员工原始提交。
- 异常上报第一版暂时只在活跃订单里发起；异常订单不进入后续生产、报工、PQC、批记录和放行流程。
- 工序应完成数量按生产订单数量和工艺路线生产系数计算。
- 生产系数为 `1.0` 时，订单 300 个产品对应工序目标数量为 300。
- 生产系数为 `3.0` 时，订单 300 个产品对应工序目标数量为 900。
- 员工报工记录生产事实；PQC 检验记录检验事实；两类事实来源不同，但都归集到订单和批记录。
- 损耗数量不能替代合格完成数量。
- 班组长确认和分配报工后，系统才能把工序数量计入订单进度。
- PQC 组长确认检验单后，系统才能把检验数据汇集到过程检验记录。
- QA 检验规程是 PQC 检验项目、数量、频次和接受标准的正式来源。
- 批记录表单必须来自工序设置中的正式逐工序绑定关系。
- 表单槽位 `formBindings` 只用于补充性动态表单，不得替代批记录表单。
- 工序开始配置只用于开始节点职责，不得替代批记录表单或表单槽位。

## States and Transitions

| 对象 | 状态 | 触发 |
| --- | --- | --- |
| 生产订单 | 本地已同步 | ERP 夜间同步到本地生产订单列表。 |
| 生产订单 | 活跃 | 班组长按纸质订单编号过滤搜索后加入活跃订单池。 |
| 生产订单 | 异常终止 | 班组长上报异常并被系统记录。 |
| 生产订单 | 生产中 | 有有效工序报工被班组长确认并分配。 |
| 工序 | 未开始 | 订单已确认但无有效报工分配。 |
| 工序 | 进行中 | 工序累计完成数量小于应完成数量。 |
| 工序 | 已完成 | 工序累计合格完成数量达到订单数量乘以生产系数。 |
| 检验单 | 待提交 | 系统按订单和检验规程生成任务。 |
| 检验单 | 待复核 | PQC 检验员签名提交。 |
| 检验单 | 已确认 | PQC 组长确认。 |
| 批记录 | 待完整 | 仍有工序批记录表单或过程检验记录未完成。 |
| 批记录 | 待放行 | 所有批记录表单和过程检验记录完整。 |
| 生产订单 | 已放行 | 放行负责人审核通过。 |

## Edge Cases

- 如果纸质订单在本地生产订单列表中查不到对应 ERP 同步数据，本系统不能自动创建订单，必须补正式同步来源或处理纸质单据差异。
- 如果 ERP 调拨单缺少物料批次，本系统不能生成完整物料追溯。
- 如果工艺路线缺少某工序生产系数，系统不能用 `1.0` 默认值掩盖缺失，必须阻塞该工序完成判断。
- 如果工序缺少正式批记录表单绑定，系统不能用表单槽位或工序开始配置替代。
- 如果检验规程缺少首检、巡检或末检规则，系统不能自动生成对应检验数量。
- 如果 PQC 组长未确认检验单，过程检验记录不能视为完成。
- 如果班组长未复核并分配报工，生产员工提交不能直接推动订单完成。
- 如果订单异常发生在部分工序完成后，系统必须保留已提交生产事实和检验事实，同时停止后续待办。

## Acceptance Criteria

- 计划排产员、仓库、物料员在文档中明确为不登录本系统操作。
- ERP 夜间同步数据在文档中明确覆盖本地生产订单列表、本地调拨单列表、物料数量和物料批次。
- 每个使用本系统的角色都有明确界面入口、操作动作和系统产出。
- 生产班组长操作覆盖本地订单列表加入活跃订单、调拨单关联、异常上报、报工复核和工序数量分配。
- 生产一线员工操作覆盖设备、设备参数、完成数量、损耗数量和损耗原因提交。
- PQC 检验员操作覆盖首检、巡检、末检及按 QA 规程执行。
- PQC 组长操作覆盖检验单确认和退回补正。
- QA 操作覆盖检验规程维护、检验项目、数量、频次和接受标准。
- 放行负责人操作覆盖批记录完整性审核、放行通过和退回。
- 系统规则覆盖生产系数计算、异常订单停止、批记录汇总和放行推送。
- 文档明确批记录表单、表单槽位、工序开始三类配置不得混用。

## Open Questions

- 计划排产员与班组长确认生产订单的最终正式数据来源是否全部进入金蝶 ERP；如果仍有纸质确认，需要确定由谁、在哪个正式系统中转为结构化数据。
- 物料员解包和线边仓交接是否需要在未来形成结构化追溯数据；当前口径是物料员不使用本系统。
- 放行负责人来源应按工艺路线、产品、订单类型、角色还是固定人员配置，需要后续确认。
- 班组长上报异常后的审批、关闭和恢复规则需要后续确认。
- 工序生产系数缺失时是否允许路线发布阶段阻塞，需要在工艺路线配置规则中确认。

## Product Blockers

- 没有 ERP 夜间同步到本地生产订单列表的正式数据来源时，班组长不能加入活跃订单。
- ERP 调拨数据无法直连或缺少物料批次时，批记录物料追溯不完整。
- 工艺路线缺少生产系数、工序 SOP 或正式批记录表单绑定时，不能完成工序进度和批记录汇总。
- QA 未维护检验规程时，系统不能生成首检、巡检和末检任务。
- PQC 组长未确认检验单时，过程检验记录不能自动汇集为完成。
