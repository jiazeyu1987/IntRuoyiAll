# 注册证业务时间模拟与九点任务测试验收标准

## Purpose and Scope

本文将“注册测试”页签 MVP 转换为可执行的验收条件，覆盖环境隔离、单证件测试场景、场景业务日期、续证生效、旧证归档、九点任务模拟和幂等。

## Acceptance Criteria

### AC-01 测试入口隔离

Given 当前环境、租户或用户权限不满足测试条件，When 用户打开注册证管理，Then 不显示“注册测试”页签；直接请求接口也必须拒绝且无数据写入。

### AC-02 模拟日期显示

Given 用户进入芋道源码租户内的合法测试页签，When 页面加载完成，Then 同时显示真实当前时间、芋道源码租户和可创建的测试场景，且不改变正式业务日期。

### AC-03 保存日期不自动执行

Given 用户选择一张任务自有测试证件并输入合法场景日期，When 点击“保存场景”，Then 页面显示场景编号和保存结果，但正式注册证列表、其他证件、提醒数量和通知数量不因保存动作改变。

### AC-04 生效日边界

Given 场景测试证件待生效续证的 `effectiveDate` 等于场景日期，When 点击“执行续证生效扫描”，Then 续证必须生效，原证必须进入旧证库，其他证件不受影响。

### AC-05 未来日期不生效

Given 场景测试证件待生效续证的 `effectiveDate` 晚于场景日期，When 点击“执行续证生效扫描”，Then 当前证保持不变，续证保持待生效，旧证库不新增该版本。

### AC-06 旧证失效日期

Given 某续证已生效并归档原证，When 用户查看旧证列表或详情，Then 必须显示“已失效，失效日期 YYYY-MM-DD”，且日期等于原证自身有效期至。

### AC-07 生效扫描不发通知

Given 用户点击“执行续证生效扫描”，When 任务结束，Then 只产生生效/归档结果，不生成提醒或站内信发送记录；单证件失败时不影响其他证件。

### AC-08 完整九点任务分阶段结果

Given 用户点击“执行完整九点任务模拟”，When 生效、提醒计算或通知预览任一阶段失败，Then 页面分别展示各阶段状态和正式错误，不能以总成功覆盖失败，也不发送真实站内信。

### AC-09 幂等执行

Given 同一场景、测试证件、场景日期和任务类型已经成功执行，When 用户再次执行相同任务，Then 不重复切换版本、生命周期事件或提醒事实，并返回幂等重放结果。

### AC-10 日期回退不可逆

Given 新证已经生效且旧证已经归档，When 用户把场景日期调回生效日前并再次执行任务，Then 新证不得恢复为待生效，旧证不得从旧证库移出。

### AC-11 真实时间审计

Given 用户保存场景或执行任务，When 用户查看任务和审计记录，Then 操作时间、任务开始/结束时间和审计时间为真实时间，同时记录当时的场景业务日期和场景编号。

### AC-12 关闭场景

Given 一个测试场景已经完成，When 用户确认“关闭场景”，Then 场景变为只读且不可再次执行；正式注册证查询和正式任务始终使用真实上海业务日期。

### AC-13 数据范围

Given 用户选择测试注册证，When 页面加载证件状态，Then 只能返回芋道源码租户内任务自有、未删除且与当前场景绑定的证件；其他租户、其他证件或正式证件必须不可见。

### AC-14 生效数据完整性

Given 待生效证件缺少正式版本、快照、文件或生命周期关系，When 用户执行生效扫描，Then 该证件失败且不发生部分切换，页面显示具体缺失来源。

## Rejection Criteria

- 修改了操作系统、数据库、Redis 或其他模块的系统时间。
- 正式环境可以看到或调用测试页签。
- 保存场景日期后自动修改证件状态、影响其他证件或发送通知。
- 生效后旧证未进入旧证库，或失效日期使用了切换日/模拟日期。
- 重复执行产生第二个当前证、第二条生效事件、重复提醒事实或真实通知。
- 提醒/通知失败时页面隐藏失败，或把完整九点任务显示为无条件成功。
- 使用前端隐藏、默认值、空列表或 API-only 结果绕过后端环境、租户和权限校验。
- 调用全租户正式九点任务、修改正式任务记录或发送真实站内信。

## Product Blockers

- 测试环境、芋道源码租户内测试证件和专用权限未确认。
- 场景内完整九点任务模拟只验证通知预览；真实任务调度和真实通知发送不在 MVP 验收范围。
