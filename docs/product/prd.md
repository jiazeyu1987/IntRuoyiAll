# 注册证业务时间模拟与九点任务测试 MVP PRD

## Purpose and Scope

本 PRD 定义注册证管理中的“注册测试”页签。它只在隔离的本机/测试环境、且仅在芋道源码租户内创建测试场景；每个场景保存一张测试注册证和一个场景业务日期，用于验证续证生效、旧证归档、提醒计算和任务幂等。

场景业务日期只用于该场景的执行请求和结果预览，不改变租户级注册证查询、正式九点任务、Windows 系统时间、数据库服务器时间、Redis 时间、文件时间、审批平台时间或其他业务模块的时间。

## Product Summary

注册测试页签提供一条受限、可审计的测试路径：用户创建测试场景，选择一张测试注册证并设定场景业务日期，点击“执行续证生效扫描”或“执行完整九点任务模拟”，再查看新证、旧证、提醒和通知预览结果。所有状态判断和版本切换复用正式业务规则；场景不调用全租户正式任务，也不发送真实站内信。

## Target Users

- 注册证测试人员：验证续证审批、生效、旧证归档和提醒结果。
- 注册业务负责人：核对版本状态和失效日期是否符合业务规则。
- 系统管理员：配置芋道源码租户内的测试权限，查看失败原因和任务记录。

普通注册证维护人员、生产用户和正式环境用户不应看到或调用此页签。

## First Version Scope

1. 在注册证管理中增加“注册测试”页签；仅在允许的本机/测试环境、芋道源码租户和指定测试权限同时满足时显示。
2. 创建并显示测试场景编号、真实当前时间、场景业务日期和已选择的测试注册证。
3. 支持输入并保存一个合法场景业务日期；关闭场景不会改变任何全局或租户级业务时间。
4. 每个场景只支持选择一张任务自有测试注册证，显示其当前证、待生效证和预计受影响的旧证。
5. 提供“执行续证生效扫描”按钮，只处理该场景选择的证件；不发送提醒或通知。
6. 提供“执行完整九点任务模拟”按钮，按正式业务顺序处理该证件的生效、提醒计算和通知预览，不发送真实站内信。
7. 展示本次执行的开始/结束真实时间、场景编号、场景业务日期、测试证件、归档数量、提醒数量、通知预览数量、失败原因和幂等结果。
8. 同一场景、测试证件、场景业务日期和任务类型重复执行时保持幂等，不重复切换版本、归档或生成提醒事实。
9. 测试入口、场景日期变更、任务执行和关闭操作均记录操作人、芋道源码租户、真实时间、场景业务日期和结果。

## Non-Goals

- 不修改 Windows、Docker、数据库或 Redis 的系统时间。
- 不模拟审批平台的真实处理时间、登录令牌过期时间、下载授权时间或其他模块时间。
- 不允许选择生产证件、正式租户或非任务自有测试数据。
- 不提供直接批准、驳回、撤回审批的快捷按钮，不绕过现有审批流程。
- 不允许手工把任意版本标记为当前证或旧证。
- 不复制新的生效、归档或提醒算法；测试入口只调用正式状态判断和版本切换能力。
- 不在第一版提供批量生成测试证件、其他租户测试、远程服务器测试或自动清理生产数据。
- 不改变提醒阈值、通知接收规则、旧证查看申请和下载授权规则。
- 不触发全租户正式 Quartz 九点任务，不发送真实站内信，不改变正式任务的执行记录或幂等键。

## Functional Requirements

### FR-1 测试入口与环境隔离

- 页签名称为“注册测试”，位于注册证管理内部，不新增独立业务模块。
- 只有明确的测试权限、芋道源码租户和允许环境同时满足时才显示入口。
- 页面首屏必须显示“测试模式”、环境、芋道源码租户和“不会修改系统时间”的提示。
- 后端对每个读写请求再次校验环境、芋道源码租户正式身份、权限和测试证件范围；前端隐藏不是安全边界，且不得按租户展示名称匹配放行。
- 正式环境、非芋道源码租户或测试权限缺失时，接口必须直接拒绝并记录失败审计。

### FR-2 测试场景与场景业务日期

- 用户先创建一个测试场景；场景必须属于芋道源码租户、记录创建人，并保存唯一场景编号。
- 用户在场景内保存业务日期；页面同时显示真实当前时间和场景业务日期，避免用户误认为系统时间已被修改。
- 场景日期只影响该场景执行时的续证生效判断、提醒阈值计算和场景结果展示；正式注册证列表、详情和正式九点任务继续使用真实上海业务日期。
- 用户可关闭场景；关闭只禁止后续执行并保留审计结果，不存在“恢复租户真实业务时间”的操作。
- 操作时间、审批记录时间、审计时间、任务开始/结束时间和数据库创建时间使用真实时间，不跟随模拟日期跳变。

### FR-3 测试证件选择

- 每个场景只能选择一张任务自有、已标记为测试用途且属于芋道源码租户的注册证。
- 选择后显示证件编号、当前版本、生效日期、有效期至、待生效续证状态和预计会进入旧证库的版本。
- 没有待生效续证时，生效扫描仍可执行，但结果必须明确显示“无可生效候选”，不得伪造成功归档。
- 选择器不得返回其他租户、正式业务证件、已删除证件或无法解析版本身份的记录。

### FR-4 保存场景日期

- 用户在已创建场景内输入合法日期后点击“保存场景”，页面显示保存成功、场景日期和真实保存时间。
- 场景日期保存后不自动执行生效或提醒；用户必须显式点击任务按钮。
- 日期格式非法、缺失或超出产品允许范围时，保存被拒绝并显示明确原因。
- 场景日期保存失败时保留用户输入，不显示默认日期或伪造成功。

### FR-5 执行续证生效扫描

- 点击后只处理场景选择的测试证件；仅当其待生效续证的生效日期小于或等于场景业务日期且版本关系完整时才执行。
- 执行成功后，新证成为唯一当前证，原当前证进入旧证库，旧证失效日期取旧证自身有效期至。
- 同一证件重复执行不会重复生成生命周期事件或重复改变版本状态。
- 版本、主档、快照、文件和生命周期事件的正式校验继续生效；校验失败时该测试证件的事务失败并显示原因，不影响场景外证件。
- 该按钮不创建提醒、不发送站内信，也不改变提醒配置。

### FR-6 执行完整九点任务模拟

- 点击后使用场景业务日期，按正式业务顺序处理该场景测试证件的续证生效、提醒计算和通知预览。
- 页面分别显示生效阶段、提醒计算阶段、通知预览阶段的状态，不以一个总成功覆盖阶段失败。
- 不调用全租户正式九点任务，不创建真实站内信；通知预览仍按正式规则解析接收范围，解析失败只标记预览阶段失败，不阻断已完成的单证件生效。
- 同一场景、测试证件、场景日期和任务类型重复执行遵循场景幂等规则，不重复生效、归档或生成提醒事实。
- 任务执行记录使用真实开始/结束时间，并保存场景编号、场景业务日期和单证件影响统计。

### FR-7 结果与审计

- 结果至少包括：场景编号、任务类型、芋道源码租户、场景业务日期、真实执行时间、单证件扫描结果、生效数、旧证归档数、提醒计算结果、通知预览数量、跳过数、失败数和失败原因。
- 对每个受影响证件显示执行前状态、执行后状态、新旧版本号和旧证失效日期。
- 失败结果可重试；重试必须复用同一正式幂等键，不能通过更换键制造第二次业务结果。
- 页面提供最近任务记录查询，但不提供删除或篡改审计记录的入口。

### FR-8 正式业务边界

- 测试模拟不会改变正式续证上传、审批、访问申请、下载授权或旧证查看权限规则。
- 任何测试请求都必须经过租户、公司范围、版本身份和状态校验。
- 场景任务只显示通知预览，不发送真实站内信；真实九点任务触发、真实通知发送和 Quartz 注册验证属于后续范围。

## Business Rules

1. 模拟的是测试场景内一张注册证的“场景业务日期”，不是租户级或全局系统时间。
2. 生效判断使用 `effectiveDate <= scenarioBusinessDate`；等于场景日期视为已到生效日。
3. 旧证失效日期始终等于旧版本的原 `expiryDate`，不使用模拟日期或任务执行日期替代。
4. 一个注册证主档最多一个当前版本；生效切换必须原子完成。
5. 待审批或待生效续证仍然遵守重复提交冲突规则；测试页签不能绕过冲突保护。
6. 场景日期变更不会自动执行任务；任务必须由用户显式触发。
7. 同一场景、测试证件、场景日期和任务类型重复触发必须幂等。
8. 完整九点任务模拟只计算正式通知规则的命中范围，不发送通知、不写入正式通知去重事实。
9. 所有异常、权限拒绝、数据缺失和阶段失败都必须显式返回并记录，不能返回空成功。
10. 测试证件必须可追踪；测试结束后的数据清理由既有正式作废流程处理，本 MVP 不提供自动清理。

## States and Transitions

### Test scenario state

- `CONFIGURING`：已创建场景，尚未完成测试证件和场景日期配置。
- `READY`：一张测试证件和场景日期均已保存，可以执行任务。
- `RUNNING`：场景任务正在执行，禁止同一场景并发执行。
- `COMPLETED`：当前配置的任务已完成或已返回幂等结果。
- `CLOSED`：场景已关闭，只读保留审计和结果，不再执行。

### Test run state

- `NOT_STARTED`：尚未执行任务。
- `RUNNING`：正在执行，按钮锁定，禁止并发执行同一场景/证件/日期/任务。
- `SUCCEEDED`：全部阶段完成。
- `PARTIAL_FAILED`：生效阶段完成但提醒或通知阶段失败，必须显示分阶段结果。
- `FAILED`：场景测试证件的前置校验或版本切换失败；该证件本次事务按规则回滚，不影响其他证件。
- `IDEMPOTENT_REPLAY`：重复请求返回原任务结果，不产生新增业务事实。

### Certificate transition

`CURRENT + PENDING_EFFECTIVE` --(scenario date reaches effective date, run activation)--> `NEW CURRENT + OLD`

`CURRENT + future PENDING_EFFECTIVE` --(run activation before effective date)--> `CURRENT + PENDING_EFFECTIVE`

`CURRENT + no pending version` --(run activation)--> `CURRENT`, result is `NO_DUE_CANDIDATE`

## Edge Cases

- 场景日期早于当前真实日期：允许使用，但页面必须明确显示日期回退，不改变真实创建时间或其他证件展示。
- 场景日期回退后再次执行：不得把已完成的生效切换回旧证；不得反向生成生命周期事件。
- 生效日期恰好等于场景日期：必须生效。
- 多次点击按钮或网络重试：只返回同一幂等结果。
- 同一证件存在两个待生效候选：正式唯一性校验失败，不能任选其一。
- 续证文件缺失、快照缺失、租户不一致或版本关系不完整：该证件失败并显示正式错误。
- 通知接收范围无法解析：通知预览阶段显示失败原因，不影响已完成的单证件生效结果。
- 测试权限在执行中被撤销：后端拒绝后续请求，已完成的正式事务不回滚为旧状态。
- 页面刷新或重新登录：按场景编号重新加载场景日期、测试证件和最近任务记录。

## Acceptance Criteria

- AC-01：仅允许环境、芋道源码租户、测试权限和测试证件全部满足时进入页签。
- AC-02：页面同时显示真实当前时间、场景编号和场景业务日期，且明确说明不会修改系统时间或芋道源码租户的全局业务日期。
- AC-03：保存场景日期后，正式注册证列表、详情和正式九点任务不受影响；保存动作本身不执行生效或提醒。
- AC-04：场景测试证件的待生效续证生效日期小于或等于场景日期时，执行生效扫描后新证成为当前证，原证进入旧证库；其他证件不受影响。
- AC-05：旧证展示的失效日期等于旧证原有效期至，不等于场景日期或执行日期。
- AC-06：生效扫描不会发送提醒或通知；结果显示生效数和归档数。
- AC-07：完整九点任务模拟显示生效、提醒计算、通知预览三个阶段的独立结果，不发送真实站内信；预览失败不能隐藏生效结果。
- AC-08：同一场景、测试证件、场景日期和任务重复执行不重复归档、不重复生命周期事件或提醒事实。
- AC-09：任务记录包含场景编号、真实执行时间、场景业务日期、单一影响证件和失败原因。
- AC-10：关闭场景后，场景不可再执行；正式注册证查询和任务始终使用真实上海日期。
- AC-11：正式环境或非芋道源码租户直接拒绝页签和接口请求，且无注册证数据变化。
- AC-12：场景日期回退不会反向恢复旧证，也不会删除或修改既有生命周期审计。
