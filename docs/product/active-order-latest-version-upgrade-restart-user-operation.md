# MES 活跃订单按最新版本升级重启用户前端操作流程

## Purpose and Scope

本文说明前端用户如何从“活跃订单”发起版本升级，确认系统自动解析的全部最新正式版本，提交独立升级审批，并在审批通过后从新订单重新开始执行，同时通过追溯查看旧订单填写内容。

本流程只保留一个用户路径：进入活跃订单，点击“升级”，系统按所有适用受控对象的最新正式版本生成升级快照，审批通过后作废旧执行批次并创建新活跃订单。用户不再进入复杂版本选择流程，也不能只选择某一个版本对象升级。

本流程适用于工艺路线、QA 检验规程、批记录模板、表单模板、表单槽位、工序开始配置、设备参数、物料规范、放行规则和未来同类受控版本对象。

## Primary User Flows

### Flow 1：从活跃订单进入升级

1. 用户进入“生产执行 > 活跃订单”。
2. 用户搜索或筛选目标订单。
3. 用户打开订单详情。
4. 页面展示当前执行进度、当前锁定版本基线和追溯入口。
5. 用户点击右上角或主操作区的“升级”按钮。

页面要点：

- “升级”只出现在活跃订单中。
- 按钮文案建议使用“升级”，确认页标题使用“版本升级重启”。
- 已进入升级审批、已终止、已归档、已放行或存在不可绕过冻结时，按钮不可提交并显示原因。

### Flow 2：查看当前版本和自动解析的最新版本

1. 用户进入“版本升级重启”确认页。
2. 页面顶部展示来源活跃订单、生产工单、产品、批号和计划数量。
3. 页面展示当前订单锁定的版本基线。
4. 系统自动解析所有适用受控对象的最新正式版本。
5. 页面展示“当前版本 -> 最新正式版本”的清单。

示例展示：

| 对象 | 当前锁定版本 | 本次升级目标 |
| --- | --- | --- |
| 工艺路线 | V1 | V2 |
| QA 检验规程 | 5.0 | 7.0 |
| 批记录模板 | 3.0 | 4.0 |
| 表单槽位 | 2.0 | 3.0 |

前端规则：

- 用户不需要选择版本。
- 页面不提供版本下拉框、版本多选框或“只升级此项”操作。
- 最新版本由后端返回，前端只展示结果。
- 若点击升级后系统发现没有版本变化，仍可展示“全部对象已是最新正式版本”，并阻止无意义提交或要求用户关闭页面。

### Flow 3：查看差异和重启影响

1. 用户点击或展开“差异与影响”。
2. 页面按对象展示版本变化。
3. 页面突出展示会影响重新填写的结构变化。
4. 用户阅读“审批通过后整单从头执行”的提示。

示例提示：

| 变化类型 | 影响 |
| --- | --- |
| 工艺路线 V1 -> V2 | 粗洗工序清洗物料由 2 项变为 3 项 |
| QA 5.0 -> 7.0 | 新增检验项目和判定标准 |
| 批记录模板 3.0 -> 4.0 | 新增必填字段 |

页面必须明确：

- 旧订单已经填写的内容会保留在追溯里。
- 新订单不带入旧填写值、旧检验结果、旧签名或旧放行状态。
- 审批通过后旧活跃执行停止，新活跃订单从头开始。

### Flow 4：提交升级审批

1. 用户填写升级原因。
2. 用户确认当前版本、目标最新版本和差异影响。
3. 用户勾选确认项：我理解审批通过后将作废旧执行批次并创建新订单从头执行。
4. 用户完成电子签名或身份确认。
5. 用户点击“提交升级审批”。
6. 系统显示审批编号和状态“版本升级审批中”。

确认文案建议：

```text
审批通过后，旧活跃订单和旧批次将停止继续执行。
系统将创建一个业务上下文相同的新活跃订单，并按全部最新正式版本从头生成任务。
旧订单的填写内容、签名、附件和审计不会删除，可在追溯中查看。
本申请属于版本升级重启，不属于不合格审批。
```

### Flow 5：审批期间查看冻结状态

1. 用户返回旧活跃订单详情。
2. 页面顶部显示“版本升级审批中，当前执行已冻结”。
3. 页面显示审批编号、申请人、申请时间和目标版本摘要。
4. 报工、PQC、批记录填写、批记录审批、上市放行和再次升级按钮均不可用。
5. 用户仍可打开只读追溯和审批详情。

审批拒绝或撤回时：

1. 页面显示审批拒绝或撤回原因。
2. 旧订单解除版本升级冻结。
3. 用户继续按原锁定版本执行旧订单。
4. 系统不创建新活跃订单。

### Flow 6：审批通过后进入新活跃订单

1. 审批通过后，系统展示“升级已应用”。
2. 页面显示旧订单状态“因版本升级终止”。
3. 页面显示新订单编号、新批次编号和“打开新活跃订单”按钮。
4. 用户打开新活跃订单。
5. 新订单页面展示来源旧订单、升级申请编号和全部最新版本基线。
6. 用户从第一道工序或系统指定的起始执行入口重新开始填写。

示例展示：

```text
来源订单：AO-20260902-001-R1
升级申请：VU-20260902-001
当前订单：AO-20260902-001-R2
执行状态：从头开始
工艺路线：V2
QA 检验规程：7.0
```

如果新路线从两个清洗物料变为三个清洗物料，新订单页面应直接显示三个空白物料项。旧订单的两个物料填写结果只能在旧订单追溯中查看。

### Flow 7：查看旧订单填写内容

1. 用户在新订单详情点击“版本历史”。
2. 页面显示旧订单、新订单和升级申请的关系。
3. 用户选择旧订单修订版。
4. 用户点击“查看旧版本填写记录”。
5. 系统打开旧订单只读详情。
6. 用户查看旧版本下的工序、物料、QA、批记录、设备参数、签名、附件和字段审计。
7. 用户点击“返回当前订单”回到新活跃订单。

历史列表建议：

| 修订 | 状态 | 版本集合 | 终止原因 | 操作 |
| --- | --- | --- | --- | --- |
| R1 | 因版本升级终止 | 路线 V1 / QA 5.0 | 版本升级重启 | 查看 |
| R2 | 当前活跃 | 路线 V2 / QA 7.0 | - | 进入 |

旧订单详情规则：

- 只读展示旧版本表单和旧填写内容。
- 不显示编辑、重新提交、审批、放行或复制到新订单按钮。
- 不用当前最新模板补齐旧订单缺失字段。

## Alternate Flows

### Alternate Flow 1：订单卡在上市放行前

1. 用户发现最后上市放行前需要按新版本执行。
2. 用户仍从活跃订单点击“升级”。
3. 系统冻结旧放行操作并提交版本升级审批。
4. 审批通过后旧放行任务终止，新订单按全部最新版本从头执行。
5. 若卡住原因是真实质量问题，用户不能用升级按钮绕过质量流程。

### Alternate Flow 2：QA 或路线变化导致需要重填

1. 用户点击“升级”。
2. 差异预览显示 QA 新增检验项目、路线新增物料或表单新增必填字段。
3. 用户确认重启影响并提交审批。
4. 审批通过后，新订单生成新的空白检验项、物料项和表单字段。
5. 旧填写内容只在追溯中查看。

### Alternate Flow 3：审批期间又发布新版本

1. 用户提交审批时，系统快照中 QA 最新正式版本为 7.0。
2. 审批期间 QA 发布 8.0。
3. 当前申请仍显示并应用 QA 7.0。
4. 若用户需要 QA 8.0，应撤回或让审批拒绝后重新从活跃订单点击升级。

### Alternate Flow 4：多人同时操作

1. 第一个用户已提交升级审批。
2. 第二个用户打开同一旧订单并点击升级。
3. 系统显示已有进行中升级申请。
4. 第二个用户只能查看申请，不能创建第二个进行中申请。

### Alternate Flow 5：无旧填写数据

1. 旧订单尚未开始填写。
2. 用户仍可点击升级并提交审批。
3. 审批通过后系统创建新订单。
4. 旧订单追溯显示无执行填写记录，但仍保留升级申请和替代关系。

## Error Flows

### Error Flow 1：用户无权限

- 页面不显示可点击的“升级”按钮，或点击后提示无权发起版本升级。
- 用户可按自身权限继续查看订单。

### Error Flow 2：订单不可升级

- 订单已放行、已归档、已终止或已处于升级审批中时，页面阻止发起。
- 页面展示当前状态和不能升级的原因。

### Error Flow 3：存在真实不合格或合规冻结

- 页面显示冻结原因。
- “提交升级审批”不可用。
- 用户需要先处理质量或合规流程，升级审批不能解除该冻结。

### Error Flow 4：最新版本集合不可用

- 任一受控对象没有适用的最新正式版本时，页面阻止提交。
- 页面明确显示对象名称、缺失版本或适用范围冲突。
- 系统不自动改用旧版本、草稿版本或人工选择版本。

### Error Flow 5：最新版本依赖冲突

- 页面显示冲突对象和依赖关系。
- 用户需要联系对应管理员修复正式版本依赖后重新点击升级。
- 前端不提供手工拼接版本组合的入口。

### Error Flow 6：审批通过但应用失败

- 页面显示“版本升级应用失败”。
- 旧订单保持冻结和只读处理状态。
- 系统不展示一个可生产但未完整创建的新订单。
- 授权人员进入失败处理入口查看原因并执行受控重试。

### Error Flow 7：旧历史无法加载

- 页面显示旧快照、旧表单或审计证据缺失。
- 系统不得用当前最新模板补旧历史。
- 该问题进入数据修复或审计处理。

### Error Flow 8：重复点击或网络重试

- 系统返回已有申请、已有新订单或明确冲突信息。
- 页面不产生第二个有效申请或第二个新活跃订单。

## Out-of-Scope Flows

- 从订单外部的版本管理页面直接给活跃订单换版。
- 用户逐项选择目标版本。
- 只升级 QA、只升级路线或只升级某个模板。
- 指定低于最新正式版本的目标版本。
- 在旧订单上直接修改版本号继续执行。
- 把旧填写值自动带入新订单。
- 通过升级按钮处理不合格、偏差、CAPA、召回或报废。
- 删除旧订单、旧批次、旧表单、旧签名、旧附件或旧审计。
- 用当前 ACTIVE 配置或最新模板重新解释旧订单历史。
- 前端自动创建外部 ERP 新生产工单。

## Open Questions

- 升级审批详情页是否需要按受控对象动态展示审批节点，需由审批配置确认。
- 新订单编号和旧订单编号的修订号规则需由生产执行编号规则确认。
- 旧订单相关库存、领料、FIFO 分配和 WIP 占用如何显示，需由生产与仓储流程确认。
- 应用失败后的受控重试入口放在审批详情页还是订单详情页，需由系统设计确认。
- 普通员工、组长、QA 和审计角色在旧版本追溯中的可见字段范围需由权限规则确认。
