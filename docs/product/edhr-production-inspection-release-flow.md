# eDHR电子批记录业务流程（90步）

整理日期：2026-09-14。依据：用户提供的90步流程及本次领料时机更正。

**领料时机：一线生产、一线PQC可以先填写记录，领料单可能在填写完成后才进入系统。执行订单完成动作时，再获取正式领料单，将物料批次号及来源回填到对应工序的输入物料。**

文中的“完成”指订单完成及回填动作；按照本流程，当前“申请放行”入口包含这一动作。

1. **建立产品资料。** 先维护产品编码、名称、型号规格等信息，让订单、工艺路线和检验规程指向同一个产品。
2. **建立物料资料。** 为原材料、半成品和成品维护正式编码，后续依靠编码关联领料、生产和补料记录。
3. **关联产品项目。** 工艺路线需要关联正确的DCC项目代码，用来找到该产品对应的专用检验规程。
4. **建立生产工艺路线。** 配置产品需要经过哪些生产工序，以及工序之间的先后关系。
5. **设置工序生产系数。** 工序目标数量由订单数量乘以生产系数计算，各工序的目标数量可以不同。
6. **设置工序输入物料。** 明确该工序需要投入或承接哪些物料，作为批号展示和物料追溯的依据。
7. **设置工序输出物料。** 明确该工序生产哪些物料，一线人员后续按这些物料填写完成数量。
8. **配置生产设备。** 为工序设置可选设备、需要记录的设备参数及相应标准。
9. **配置损耗原因。** 提前维护工序允许使用的损耗原因，现场人员按实际情况选择并填写数量。
10. **绑定批记录表单。** 每个工序需要正式关联对应记录表，系统后续才能把生产数据写入正确位置。
11. **区分三类配置。** 工序开始关系、批记录表单、表单槽位分别维护，配置其中一项不会自动补齐另外两项。
12. **配置责任人员。** 明确生产组长、现场人员、检验人员及相关表单处理人员的职责范围。
13. **配置报告上传责任人。** 四类放行资料分别需要有效的负责人员，系统据此派发上传任务。
14. **配置归档责任人。** 提前指定谁负责该路线的最终归档，否则后续归档待办无法正常派发。
15. **发布工艺路线。** 草稿需要按发布流程生效，新加入的订单才能使用正式版本。
16. **维护专用检验规程。** QA设置该产品的检验工序、检验项目、检验要求和判断标准。
17. **维护通用检验规程。** 可复用的检验内容单独维护，也可以组成通用规程套供多个产品引用。
18. **绑定通用规程版本。** 产品按正式绑定引用通用规程；当前代码并不强制每个产品都必须绑定通用规程。
19. **设置检验类型。** 配置首检、上午巡检、下午巡检，以及该产品是否需要末检。
20. **设置抽样数量。** 首检和末检采用固定数量；巡检支持固定数量或按订单数量计算比例，比例结果向上取整。
21. **发布QA规程。** 系统生成检验任务时使用正式发布版本，尚未发布的编辑内容不能直接用于订单执行。
22. **准备账号权限。** 生产提交、生产复核、PQC提交、PQC复核、生产放行和最终放行分别需要相应授权。
23. **同步ERP业务数据。** 生产订单、领料单和补料单分别进入系统；领料单可能在一线生产、PQC填写完成后才同步，不作为开始填写的前提。
24. **生产组长选择订单。** 在本地生产订单列表找到准备执行的订单，将其加入活跃订单。
25. **系统检查加入条件。** 产品路线、正式路线版本、DCC项目和专用QA规程等必要信息缺失时，加入失败。
26. **系统锁定订单版本。** 加入成功后，保存该订单采用的工艺路线、QA规程及工序配置，作为本次生产依据。
27. **历史订单保留原版本。** 后续发布新路线或新规程，不会自动替换已经加入的订单；升级需要走明确的升级流程。
28. **生成生产和检验任务。** 系统计算各生产工序目标数量，并按锁定的QA规则生成对应PQC任务。
29. **现场人员进入一线生产。** 选择活跃订单、生产工序和实际操作人员，避免把记录提交到其他订单或工序。
30. **页面加载工序配置。** 显示当前订单锁定的物料、设备、参数和损耗原因，供现场填写。
31. **一线填写时领料单可能未到。** 一线生产和PQC先填写各自现场记录，输入物料批号不要求在开始填写时就取得。
32. **领料批号留待完成回填。** 正式批号在完成阶段按领料单取得，不得用其他订单、库存批号或人工猜测的数据提前补齐。
33. **填写输出物料数量。** 现场人员按实际生产情况填写本次完成数量和损耗数量。
34. **填写损耗明细。** 有损耗时选择具体原因并填写数量，各原因数量之和必须等于本次损耗数量。
35. **填写设备和参数。** 记录实际使用的设备及生产参数，让后续能追溯当时的生产条件。
36. **多物料数量分别保存。** 当前实现对本次提交的多个输出物料，以最小完成数量计算本次工序进度数量。
37. **生产人员签名提交。** 实际操作人员输入本人签名密码，系统保存生产记录、物料明细、人员和提交时间。
38. **系统建立初始数量归属。** 一线已选择活跃订单时，本次生产数量会先自动归入该订单，仍需后续正式复核。
39. **生产组长检查原始记录。** 查看人员、工序、数量、损耗、设备参数和签名，确认现场提交是否正确。
40. **生产组长复核并确认分配。** 通过正式复核及数量分配流程，形成可用于工序完成和批记录回填的依据。
41. **错误记录需要纠正。** 生产组长可按权限调整数量归属或驳回记录，系统保留处理记录并重新计算相关数量。
42. **PQC在生产过程中检验。** 检验员进入一线PQC页面，选择订单、工序、检验任务和实际检验人员。
43. **按任务执行检验。** 首检、上午巡检、下午巡检和末检分别处理，不能把一种检验的提交当成其他检验完成。
44. **填写实际检验数量。** 按页面任务和现场实际填写数量，并逐件、逐项记录检验结果。
45. **记录检验设备。** 检验项目配置了设备时，记录实际使用的检验设备，供后续核查。
46. **如实记录不合格情况。** 填写检测值、结果和报废数量，系统据提交内容形成检验判定。
47. **检验人员签名提交。** 输入实际检验人员的签名密码，保存检验明细、签名及提交时间。
48. **提交后进入待复核。** 一线PQC提交成功，仅表示记录已提交，不代表检验任务已经确认完成。
49. **PQC组长审核检验记录。** 检查检验项目、数量、结果、人员签名，以及订单和工序关联是否正确。
50. **PQC组长签名确认。** 确认通过后，检验任务计入已完成，并形成正式过程检验记录的回填来源。
51. **区分检验复核和生产放行。** PQC组长确认某次检验记录，与后面审核整批生产资料，是两个不同操作。
52. **生产期间即可查看详细信息。** 订单详情持续汇总生产和检验记录，并不是等订单完成后才出现数据。
53. **详情展示已形成的生产事实。** 可查看工序提交、完成数量、损耗、设备参数和相关签名；输入物料批号在完成回填后补齐。
54. **补料单补充物料追溯。** 补料单进入系统后，按生产订单及工序输入物料匹配，展示补料数量、批号和来源单据。
55. **正式损耗来源于生产记录。** 完工回填使用生产报工中的损耗明细及复核依据，不能直接把补料数量当作生产损耗。
56. **详情损耗表另有来源。** 页面中的“生产过程损耗报告单”读取PQC报废记录，与补料明细、生产报工损耗需要分别理解。
57. **检查生产进度。** 各工序按订单锁定的目标数量检查完成情况，不能只看最后一道工序或总提交数量。
58. **检查检验进度。** 检验任务需要经过PQC组长确认，所有任务确认完成后，检验进度才达到100%。
59. **两项进度都要完成。** 生产进度100%、检验进度100%，才具备申请放行的进度条件。
60. **进度完成仍要检查异常。** 数量冲突、订单异常、正式来源或签名缺失，仍可能阻止申请放行。
61. **生产组长执行完成动作。** 当前“申请放行”入口先完成订单；完成时获取领料单并回填输入物料，再提交PQC生产放行申请。
62. **完成时核查正式领料来源。** 按生产订单和输入物料编码匹配正式领料单，同时检查出库、工序完成、检验确认、签名及表单绑定。
63. **回填输入物料并固化完工记录。** 将领料批号及单据来源写入对应输入物料；多张匹配单据保留各自来源，同时保存批记录、检验及适用损耗资料。
64. **无损耗也需要依据。** 系统保存明确的无损耗确认信息，而不是因为找不到损耗数据就认定没有损耗。
65. **生成PQC放行待办。** 申请成功后进入待PQC放行，此时尚未进入四类报告上传阶段。
66. **授权人员执行生产放行。** 需要具备专门的PQC生产放行授权，普通检验权限不等于放行权限。
67. **PQC审核整批资料并签名。** 检查生产、检验、损耗和来源完整性，确认后输入签名密码执行生产放行。
68. **生产放行后创建批次执行。** 系统建立对应批次，将生产、过程检验及适用的损耗资料写入批次表单。
69. **系统派发四类上传任务。** 各任务交给路线中配置的负责人员处理，上传人员不是随意指定的。
70. **上传来料检验报告。** 将本批生产所需的来料检验资料上传到对应报告任务。
71. **上传灭菌报告。** 除上传文件外，还需要填写灭菌批号，建立生产批次与灭菌批次的关联。
72. **上传成品检验报告。** 将成品检验结论文件上传到对应任务，作为最终放行审核资料。
73. **上传成品检验记录。** 成品检验记录与成品检验报告是两个独立资料类别，需要分别完成。
74. **上传后完成对应任务。** 仅选择文件或上传其中一类不算全部完成，四类任务都完成后才进入最终放行。
75. **系统保存四类资料证据。** 记录附件、所属批次及文件校验信息，后续最终放行还会检查资料是否发生变化。
76. **生成管理者代表待办。** 四类资料齐全后，系统把最终放行任务交给具备管理者代表授权的候选人员。
77. **管理者代表审核并签名。** 审核整批生产、检验和报告资料，完成本人身份确认后执行最终放行。
78. **生产负责人需要相应授权。** 如果由生产负责人执行所说的“上市放行”，该人员必须同时具备管理者代表放行资格。
79. **最终放行后关闭批次。** 系统记录放行人员、时间、意见和签名，并生成最终归档待办。
80. **归档责任人执行归档。** 系统汇集批记录和相关证据，生成最终归档文件；归档生成或保存失败时，不算归档成功。
81. **归档成功后进入历史追溯。** 历史追溯列表只展示已归档批次，最终放行成功并不等于已经完成归档。
82. **按业务信息查找历史。** 可以通过工单号、批次号、产品、路线及日期查找对应电子批记录。
83. **查看全过程时间线。** 历史页面展示批次事件、任务事件、电子签名、审批记录和归档版本。
84. **查看或打印归档资料。** 有相应权限的人员可以查看归档内容并打印，核查当时由谁生产、检验、放行。
85. **发现不合格时进入审查。** 放行环节可发起不合格审查，相关订单或批次会受到冻结限制，等待QA处置。
86. **QA记录处置依据。** 提交评审材料、处理意见和签名信息，并选择让步放行、返工或作废。
87. **让步处置不替代最终放行。** 满足处置条件后继续相应主流程，仍需完成后续资料和放行要求。
88. **返工不能理解成自动重做生产。** 当前处置代码记录返工结果并处理流程状态，不能据此认定已自动完成重新生产和检验。
89. **作废后停止正常流转。** 作废对象保留历史及处置记录，用于只读追溯，不能继续按正常批次放行。
90. **关键记录保留处理痕迹。** 生产提交、复核、数量调整、检验确认、放行和归档分别留痕，便于追查问题发生在哪一步。
