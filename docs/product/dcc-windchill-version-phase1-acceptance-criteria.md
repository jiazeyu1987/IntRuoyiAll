# Acceptance Criteria：DCC 第一阶段 Windchill 版本机制

## Purpose and Scope

本文给出第一阶段可执行的产品验收标准。验收对象包括逻辑文件身份、自动版本编号、检出检入、撤销检出、大版本来源选择、送审锁定、发布切换、可见性、审计和迁移预检。

## Evidence Reviewed

- `docs/product/dcc-windchill-version-phase1-prd.md`。
- `docs/product/dcc-windchill-version-phase1-user-flows.md`。
- 用户确认的 DCC Windchill 式版本规则。
- 当前 DCC 文件版本、审批、发布、受控浏览和检出检入实现。

## Acceptance Criteria

### AC-P1-01 逻辑文件身份唯一

Given 同一租户内已有项目 P、分类叶子 T、文件编码 F 对应的逻辑文件，When 另一个请求再次使用 P、T、F 创建文件，Then 系统拒绝重复创建并返回明确身份冲突，原逻辑文件不变。

### AC-P1-02 文件编码允许跨边界重复

Given 两个请求使用相同文件编码 F，When 两个请求的项目不同或分类叶子不同，Then 系统允许分别创建两个逻辑文件，且版本历史互不混合。

### AC-P1-03 并发创建不可重复

Given 逻辑文件 P+T+F 尚不存在，When 两个请求同时创建该身份，Then 只能有一个请求创建成功，数据库中只能存在一个逻辑文件。

### AC-P1-04 初始版本自动生成

Given 用户具有项目访问权和创建权限，When 用户创建新逻辑文件，Then 系统自动创建 A/1，页面和请求均不能手工指定版本号。

### AC-P1-05 检出不产生小版本

Given A/1 处于工作中且无人检出，When 授权用户检出 A/1，Then 系统记录检出人、时间和原因，但版本历史中仍只有 A/1。

### AC-P1-06 同时只能一人检出

Given A/1 已由用户甲检出，When 用户乙尝试检出，Then 系统拒绝用户乙并显示当前检出人为用户甲，不改变原锁。

### AC-P1-07 非本人不能检入

Given A/1 已由用户甲检出，When 用户乙尝试检入，Then 系统拒绝操作，不创建 A/2，也不释放用户甲的锁。

### AC-P1-08 检入生成下一小版本

Given 用户甲已检出 A/1，When 用户甲提交有效内容变化或允许元数据变化并填写修改说明后检入，Then 系统生成 A/2、记录来源 A/1、变更范围、前后哈希和字段差异、保留 A/1 并释放检出锁。

### AC-P1-09 检入失败保持原状态

Given 用户甲已检出 A/1，When 文件存储、哈希计算或版本保存失败，Then 系统不创建 A/2，A/1 仍由用户甲检出，并返回具体失败原因。

### AC-P1-10 重复检入不产生重复版本

Given A/1 的同一次检入请求已经成功生成 A/2，When 相同请求再次到达，Then 系统不得再生成另一个 A/2 或 A/3，并返回第一次请求的明确结果或重复请求错误。

### AC-P1-11 撤销检出不增加版本

Given 用户甲已检出 A/2，When 用户甲填写原因并撤销检出，Then 系统释放锁、不生成 A/3，并记录撤销检出审计。

### AC-P1-12 正式版本不能直接检出

Given A/3 已正式发布且不存在开放大版本，When 用户尝试直接检出 A/3，Then 系统拒绝并提示应先创建下一大版本。

### AC-P1-13 选择历史小版本创建下一大版本

Given 当前大版本 A 下存在 A/1、A/2、A/3，且 A/3 是当前正式版本，When 用户选择 A/2 并填写理由创建下一大版本，Then 系统创建 B/1、记录来源 A/2 和创建时正式版本 A/3，不复制 A/3 替代用户选择。

### AC-P1-14 非当前来源必须说明理由

Given A/3 是当前正式版本，When 用户选择 A/2 创建 B/1 但未填写理由，Then 系统拒绝创建且不产生开放大版本。

### AC-P1-15 只能存在一个开放大版本

Given B 大版本已经开放且存在 B/1，When 用户再次尝试从 A 系列创建下一大版本，Then 系统拒绝创建第二个 B 大版本并返回现有开放大版本信息。

### AC-P1-16 小版本不自动审批或生效

Given B/1 处于工作中，When 用户检入形成 B/2，Then B/2 仍处于工作中，不自动生成审批流程，也不替代普通用户看到的 A/3。

### AC-P1-17 送审锁定具体小版本

Given B/1、B/2、B/3 均存在且 B/3 是最新工作小版本，When 文件责任人提交审批，Then 系统只允许提交 B/3，并锁定 B/3 的文件哈希、元数据、关联快照和路线快照；提交 B/1 或 B/2 必须被拒绝。

### AC-P1-18 送审版本不可修改

Given B/3 正在审批，When 任意用户尝试检出、检入或替换 B/3 内容，Then 系统拒绝并保持审批快照不变。

### AC-P1-19 驳回后形成新小版本

Given B/3 被驳回，When 编制人员基于 B/3 检出修改并检入，Then 系统生成 B/4，B/3 及其审批、签名和驳回原因继续可查。

### AC-P1-20 重新送审不得复用旧审批

Given B/4 由被驳回的 B/3 修改形成，When 文件责任人提交 B/4，Then 系统生成新的审批快照，不能沿用 B/3 的审核、批准或签名结果。

### AC-P1-21 批准不等于发布

Given B/4 审批通过但尚未文控发布，When 普通用户查询该文件，Then 普通入口仍返回 A/3，B/4 显示为已批准/待发布。

### AC-P1-22 发布成功原子切换

Given A/3 是当前正式版本且 B/4 已批准，When 文控成功发布 B/4，Then B/4 成为唯一当前正式版本，A/3 同时标记为已替代。

### AC-P1-23 发布失败保留旧正式版本

Given A/3 是当前正式版本且 B/4 已批准，When B/4 发布失败，Then A/3 继续为当前正式版本，B/4 不得进入普通阅读入口。

### AC-P1-24 普通用户只能看到正式版本

Given A/3 正式有效且 B/1、B/2 处于工作中，When 普通阅读用户查询、预览或下载文件，Then 默认只看到 A/3，不能访问 B/1 或 B/2 正文。

### AC-P1-25 历史完整可追溯

Given 文件存在 A/1、A/2、A/3、B/1、B/2、B/3、B/4，When 授权用户打开版本历史，Then 每个版本均显示状态、直接来源、修订来源、操作者、时间、修改说明、哈希及审批发布结果。

### AC-P1-26 项目停用阻止新动作

Given 文件所属 DCC 项目已停用，When 用户尝试创建、检出、检入或新建大版本，Then 系统拒绝动作，但已授权历史查询仍可执行。

### AC-P1-27 迁移预检失败关闭

Given 现有文件缺少项目、分类叶子或唯一版本映射，When 执行迁移预检，Then 系统列出文件编号、主档和具体阻塞原因，不写入默认值，也不执行正式迁移。

### AC-P1-28 发布衔接快照

Given 新大版本发布成功，When 审计人员查看发布记录，Then 能看到发布时关联方范围及关联文件版本快照，同时状态明确表示通知和影响评估尚未由第一阶段完成。

### AC-P1-29 Z 后使用 AA

Given 当前正式大版本为 Z，When 项目 OWNER 创建下一大版本，Then 系统自动创建 AA/1，不能循环回 A 或要求用户输入版本号。

### AC-P1-30 AZ 后使用 BA

Given 当前正式大版本为 AZ，When 项目 OWNER 创建下一大版本，Then 系统自动创建 BA/1。

### AC-P1-31 仅元数据检入

Given 用户已检出 A/1 且只修改允许的业务元数据，When 用户填写修改说明并检入，Then 系统创建 A/2、生成独立受控源文件记录、保持源文件哈希一致并保存字段差异。

### AC-P1-32 空操作检入被拒绝

Given 用户已检出 A/1，When 用户没有上传新文件且没有任何允许元数据差异，Then 系统拒绝检入、不创建 A/2 并保留检出锁。

### AC-P1-33 项目访问级别控制动作

Given 用户只有项目 VIEW，When 用户尝试检出、检入或创建 Revision，Then 系统拒绝；Given 用户具有项目 EDIT，Then 可以检出和检入但不能创建 Revision；Given 用户具有项目 OWNER，Then 可以创建 Revision 和提交最新工作小版本。

### AC-P1-34 确定性迁移旧测试链

Given 一个旧 Master 身份唯一、版本号唯一可排序、没有未完成审批且正式指针唯一，When 执行批准的测试环境迁移，Then 单旧版本映射为 A/1，多个旧版本按顺序映射为 A/1、B/1、C/1；不满足任一条件时必须阻塞且不删除数据。

## Rejection Criteria

- 仍使用“类别 + 目录 + 文件名”或全局文件编码作为逻辑文件身份。
- 允许用户手工输入 `A/2`、`B/1` 等版本号。
- 检出时直接生成下一小版本，或撤销检出仍增加版本号。
- 检入覆盖原文件内容而不保留上一小版本。
- 没有内容或元数据差异仍允许检入并增加小版本。
- 元数据检入可以修改项目、分类叶子或文件编码。
- 小版本检入后自动成为普通用户使用的正式版本。
- 用户选择 A/2 作为 B/1 来源时，系统静默改用 A/3。
- 已送审版本仍能修改，或审批页面未显示具体小版本。
- 审批通过后直接替代旧正式版本，未经过文控发布。
- 新版本发布失败后旧正式版本被提前替代。
- 普通用户能够通过列表、直链或下载接口访问未发布工作版本。
- 历史迁移通过默认项目、默认分类叶子、文件名猜测或自动重新编号掩盖数据问题。
- 大版本发布未保存关联方范围和关联文件版本快照，却被标记为已经完成后续通知或影响评估。

## Product Blockers

- 必须先完成现有 DCC 数据只读盘点并确认每个主档的目标项目、分类叶子和版本映射。
- 同一目标身份对应多个现有主档或同一主档存在多个当前有效版本时，必须由业务人员逐项决策。
- 任何迁移前置缺失都必须阻止正式迁移，不允许以兼容路径继续上线。
