# User Flows：DCC 第一阶段 Windchill 版本机制

## Purpose and Scope

本文描述第一阶段可观察的用户流程，覆盖逻辑文件创建、小版本迭代、大版本创建、送审发布、历史查看和迁移阻塞。流程中的版本号均由系统生成。

## Evidence Reviewed

- `docs/product/dcc-windchill-version-phase1-prd.md`。
- 用户确认的 Windchill 式 `Revision / Iteration` 规则。
- 当前 DCC 上传、审批、发布、受控浏览、检出检入和版本历史实现。
- `Windchill公开课_第1至16讲播放器文字记录.docx` 中相关课程记录。

## Primary User Flows

### Flow P1-01 创建新逻辑文件和 A/1

1. 具有项目 OWNER 或 EDIT 访问级别的文件编制人员进入 DCC 项目。
2. 用户选择一个有效分类叶子并填写文件编码、名称和初始文件。
3. 系统按项目、分类叶子和规范化文件编码检查逻辑文件身份。
4. 身份不存在时，系统创建逻辑文件并自动生成 A/1。
5. A/1 进入工作中状态，不自动发起审批，也不出现在普通阅读入口。

### Flow P1-02 检出并检入形成下一小版本

1. 编制人员打开当前最新工作小版本 A/1。
2. 用户点击检出并填写修改原因。
3. 系统取得独占编辑锁，显示检出人和检出时间。
4. 用户修改源文件、允许修改的业务元数据，或同时修改两者。
5. 用户点击检入，提交修改内容和修改说明。
6. 系统校验检出人、内容/元数据真实差异、文件完整性和版本序列。
7. 系统保存 A/2、变更范围、前后文件哈希、字段差异和来源 A/1，并释放检出锁。
8. A/1 留在历史中，A/2 成为当前最新工作小版本。

### Flow P1-03 撤销检出

1. 编制人员已经检出 A/2，但决定放弃本次修改。
2. 用户点击撤销检出并填写原因。
3. 系统丢弃未检入的工作副本，释放检出锁。
4. 系统不生成 A/3，A/2 保持当前最新工作小版本。
5. 审计历史显示本次检出和撤销检出。

### Flow P1-04 提交最新工作小版本

1. 当前工作大版本 A 已形成 A/1、A/2、A/3，A/3 是最新工作小版本。
2. 文件责任人打开 A/3，系统展示该版本的文件、哈希、修改说明和来源 A/2。
3. 用户提交审批。
4. 系统确认不存在更新的小版本后，锁定 A/3 及审批快照。
5. 审核和批准人员处理的始终是 A/3。
6. 审批期间普通用户仍使用原正式版本；新文件首次审批时普通入口仍不显示该文件。

### Flow P1-05 驳回后形成新小版本

1. 审批人员驳回送审版本 A/3 并填写理由。
2. A/3 标记为已驳回，原审批记录保留。
3. 编制人员以 A/3 为基础检出修改。
4. 编制人员检入后，系统生成 A/4。
5. 文件责任人提交最新小版本 A/4，系统创建新的审批快照。

### Flow P1-06 发布首个正式大版本

1. A/3 审批通过后进入已批准/待发布。
2. 文控核对审批对象和受控文件一致。
3. 文控执行发布。
4. 发布成功后 A/3 成为逻辑文件的当前正式版本。
5. 普通用户第一次可以在正式阅读入口看到该文件。
6. A/1、A/2 保留为大版本 A 的历史小版本。

### Flow P1-07 从选定小版本创建下一大版本

1. 当前正式版本为 A/3，项目 OWNER 点击新建修订版。
2. 系统列出大版本 A 的可选历史小版本。
3. 用户明确选择 A/2 作为来源。
4. 因 A/2 不是当前正式版本，用户填写选择理由。
5. 系统创建 B/1，记录来源 A/2和创建时当前正式版本 A/3。
6. B/1 进入工作中，A/3 继续作为普通用户的当前正式版本。
7. 编制人员可以继续检出、检入，形成 B/2、B/3。

### Flow P1-08 新大版本发布并替代旧版本

1. 文件责任人选择 B/3 送审。
2. B/3 审批通过并等待文控发布。
3. 文控发布 B/3。
4. 系统将 B/3 设为当前正式版本，同时将 A/3 标记为已替代。
5. 系统保存发布时关联方范围和关联文件版本快照。
6. 普通用户后续只从默认入口看到 B/3。

### Flow P1-09 查看版本历史

1. 授权用户打开逻辑文件历史。
2. 系统按大版本和小版本展示 A/1、A/2、A/3、B/1、B/2、B/3。
3. 用户可以看到每个版本的状态、来源、修改人、修改说明、哈希和审批发布结果。
4. 系统明确标记当前正式版本 B/3、当前最新工作版本以及 B/1 的来源 A/2。

## Alternate Flows

- 用户选择当前正式版本作为下一大版本来源时，不需要填写“选择历史小版本”的额外理由，但仍需填写大版本变更原因。
- 同一大版本可进行多次检出检入，系统按顺序生成 `/2、/3、/4`。
- 仅修改允许的元数据时，用户可以不上传新文件；系统复制形成独立受控源文件记录，内容哈希保持不变并记录字段差异。
- 同时修改内容和元数据时，两类变化归入同一个新小版本，不拆成两个版本。
- 大版本序列在 Z 后继续为 AA、AB；AZ 后继续为 BA。
- 审批前发现错误时，用户撤回送审版本；原送审记录保留，后续修改形成下一小版本后重新送审。
- 新大版本创建后尚未送审时，普通用户继续使用旧正式版本，编制人员可继续生成小版本。
- 新大版本发布记录生成关联快照，但通知和影响评估任务由后续阶段处理。

## Error Flows

- 同一逻辑文件身份已存在：系统阻止重复创建并引导用户打开现有逻辑文件。
- 所选文件类型不是分类叶子或项目已停用：创建、检出、检入或新建大版本失败。
- 文件已被他人检出：系统显示检出人和检出时间，不覆盖现有锁。
- 非检出人尝试检入或撤销检出：系统拒绝并保持原锁。
- 检入文件存储或哈希失败：不创建新小版本，原锁保留。
- 未上传新文件且没有允许元数据差异：系统拒绝空操作检入，不创建新小版本。
- 用户尝试通过元数据检入修改项目、分类叶子或文件编码：系统拒绝身份变更。
- 项目 VIEW 用户尝试检出、检入或创建 Revision：系统拒绝并保持版本不变。
- 存在更新工作小版本时尝试提交旧小版本：系统拒绝并提示应提交最新小版本。
- 已送审版本被尝试修改：系统拒绝，审批快照不变。
- 选择非当前正式来源但未填写理由：不创建下一大版本。
- 已存在开放大版本：不创建第二个开放大版本。
- 发布失败：新版本不生效，旧正式版本继续有效。
- 迁移数据身份或版本映射不唯一：预检列出阻塞项，不执行正式迁移。

## Out-of-Scope Flows

- 目录模板选择、项目目录生成和完整性统计。
- 文档内容模板选择及模板附件校验。
- 大版本发布后的实际消息发送、催办和送达确认。
- 关联文件“需要升级/无需升级”的影响评估处理页面。
- 跨项目引用审批、同版本例外替换、人员代理交接和强制解锁。
- 培训完成后生效及纸质/电子分发流程调整。

## Open Questions
