00

需求总览

以本次最新确认的业务顺序为准

已确认上传、升版的主流程统一为：

会签→批准→培训（如需）→文控审核→受控→下发

部门负责人指派属于会签阶段。受控日期与生效日期分别记录，生效日期可以晚于受控日期；文控按生效日期先后处置下发。下发不设置失败或驳回业务分支。

作废流程会签 → 批准。批准通过即完成文件作废并结束流程，后面不再增加培训、文控审核、受控或下发节点。作废文件保留期内继续占用原编号和完整文件名称。

既有确认继续保留：统一“受控版本”术语；产品创建审核人由后台配置，提交时带出；模板编辑仅校验权限；跨项目禁止同名新上传；所有升版版本展示实际变更类型；引用与取消仅限当前项目负责人；作废从文件选择器中所选文件的操作面板发起。

新版生效，旧版自动作废

检入、送审和提前受控不使旧版失效。新版生效时，旧版自动作废，无需另发申请；生效日前旧版继续用于执行。

关联跟随最新受控版

关联当前展示始终解析到最新受控版本。未受控的小版本不替换目标，历史审批证据保持原样。

项目默认，申请可修改

上传、升版、作废均带出所属项目的三组属性。用户修改只保存到本次申请，不反向修改项目。

01

上传操作流程

操作人：具备项目文件上传权限的用户

进入上传文档页签 → 选择项目 → 自动带出该项目的三组属性默认值 → 选择存储文件夹 → 选择文件类型 → 带出审批矩阵的会签部门及批准人 → 按需要增加、删除本次会签部门 → 选择需要上传的文件 → 校验全部项目范围内是否已有同名文件 → 预设生效日期 → 填写文件编号 → 填写初始版本号 → 核对并按需要修改三组属性 → 点击关联按钮 → 在关联窗口选择文件并确认 → 通过培训 CheckBox选择是否培训，默认不选择 → 点击确认 → 弹出提交确认框 → 再次确认 → 进入会签流程。

a. 自动带出的项目属性

显示“目标市场”“是否为注册人”“是否为生产方”“文件转移及转移至”。带出的是项目默认值，用户可修改本次上传申请的实际值；字段选项与校验见第13项。

b. 提交确认框

汇总项目、存储文件夹、文件类型、完整文件名称（含后缀）、文件编号、初始版本号、预设生效日期、三组属性、关联文件、会签部门、批准人和是否培训。提示“受控日期由系统记录，生效日期可晚于受控日期”。用户取消时保留已填写内容；确认后才提交审批。

c. 提交与异常处理

  • 项目、文件夹、文件类型、主文件、文件编号、初始版本、预设生效日期及三组属性必须完整；条件必填项按选择结果校验。受控日期由系统记录，不能用它覆盖编制时设置的生效日期。
  • 新建上传仅用于新文件；同一逻辑文件已存在时，提示走检出、检入及升版入口，不能重复创建版本链。
  • 不同项目中不允许上传同名文件。同名按含后缀的完整文件名称区分大小写精确比较；只有大小写和后缀全部一致才算同名。换项目、文件夹、文件类型或编号不能绕过；无查看权限时不泄露另一项目的内容。
  • 作废文件在保留期限内继续占用原编号和文件名称。作废不能使原名称或编号立即可用于另一条新文件链；同一逻辑文件自身升版可以沿用原编号与名称。保留期满后的释放和归档需明确处理，不自动删除历史证据。
  • 其他项目需要使用该文件时，由该项目负责人引用已有文件；同一文件自身检入、升版仍属于原版本链，不按跨项目新建同名文件处理。
  • 当前项目支持的源文件范围沿用已有上传能力；工程图纸需要配套PDF时，在同一申请中上传对应PDF。
  • 文件尚未上传完成、上传失败、项目默认属性未配置或审批人员不可解析时，准确提示原因并阻止提交。
  • 切换项目后重新加载文件夹、类型、审批条件和三组默认值；已有手动修改或关联选择时提示确认，不把上一项目的选择静默带入。

浏览流程

从项目目录和搜索结果进入统一浏览页面

a. 按目录浏览

进入项目目录 → 选择项目 → 选择存储文件夹 → 显示文件列表 → 点击文件的浏览按钮 → 打开该文件的最新受控版本。

b. 搜索浏览

进入项目目录 → 输入文件名称、编号等条件 → 选择当前项目或全部有权限项目的搜索范围 → 点击搜索 → 在结果中查看所属项目、文件夹和版本 → 点击浏览 → 打开对应文件。

c. 浏览页签显示内容

区域展示内容
文件正文当前查看版本的正文预览；明确显示受控、审批中、小版本或已作废状态，不能混淆正文版本。
基础信息名称、编号、查看版本、最新受控版本、项目、文件夹、文件类型、文件负责人；分别显示受控日期、生效日期、下发日期；检出人及检出时间。
本版本属性本版本申请实际保存的目标市场、注册人/生产方、文件转移及目标；不使用项目当前默认值覆盖。
版本与关系版本历史、实际变更类型（局部变更／换版变更）、来源受控版本、选用小版本及变更说明；当前关联文件、引用项目和数量。历史流程内的关联证据展示当时审阅版本。
过程记录会签指派、会签意见与签名、批准意见与签名、培训记录、文控审核及签名、受控记录、文控下发和接收记录。作废申请只显示会签与批准，不显示未适用节点。
点击版本历史 → 选择历史版本 → 查看对应正文、属性及审批记录 → 页面显示“已作废／历史版本”提示 → 返回当前版本。

列表默认展示最新受控版本；受控但生效日期尚未到达时，明确显示“已受控、待生效”和生效日期，不因受控章而允许提前作为正式执行文件使用。未受控文件通过对应状态筛选或任务入口查看，不伪装成受控文件。有名称查看权限但无内容权限时，可以按授权搜索和定位，不得显示正文；操作按钮按实际权限和状态显示。

2026年10月4日确认批准创建项目时，在创建项目、产品及存储目录的同一事务中，为申请中选定的正式启用项目负责人建立一条 USER/OWNER 项目权限。负责人据此进入项目目录及办理授权范围内的文件操作；申请人、审核人、批准人和管理员不自动获得该项目权限，其他人员以后通过正式权限配置加入。初始化失败不得出现部分创建成功，已完成申请再次办理不得覆写现有权限。

任一环节驳回 → 申请人收到通知 → 打开原申请查看原因 → 修改后重新提交。创建失败时显示失败原因，不显示创建成功或留下可正常使用的残缺项目。

b. 维护项目默认属性

进入项目详情 → 点击编辑项目属性 → 修改三组默认值 → 保存 → 后续新发起的上传、升版、作废申请带出新的默认值。

既有文件版本、已提交申请及已保存草稿的实际值保持不变。项目属性编辑权限需与项目管理权限一致，并保留修改前后记录。

D02 建议项目负责人使用系统账号选择。产品创建审核人已确认由后台配置并在提交时带出；批准人配置与本人兼任限制也未在本稿中确定。当前负责人文本输入和固定admin审核批准仅作为现状记录。
04

存储文件夹创建、修改、删除

模板库提供可复用目录，项目拥有自己的文件夹结构

a. 新建和使用模板

进入文件夹模板管理 → 点击新增模板 → 填写模板名称、说明 → 新增文件夹及子文件夹 → 设置名称、层级和排序 → 保存并启用。
新建项目 → 选择一套已启用模板 → 预览文件夹结构 → 提交项目申请 → 批准后按模板生成项目文件夹。

b. 修改、停用模板

进入文件夹模板管理 → 选择模板 → 点击编辑 → 系统确认当前用户具有模板编辑权限 → 新增、修改、删除模板内文件夹或调整排序 → 点击保存 → 模板修改完成。

已确认编辑文件夹模板只需权限确认，不进入审核或批准流程。有权限即可编辑保存，无权限禁止编辑；保存修改人、时间及修改内容。是否有权限由系统校验，不另增人工授权审批节点。

模板后续变化默认只影响新建项目；已有项目不自动同步。需要调整已有项目时，在项目内显式修改并查看影响。未使用模板可删除，已使用模板保留历史并停用。

c. 项目内维护文件夹

进入项目目录 → 选择项目 → 点击新增文件夹，或选中文件夹点击修改 → 填写名称、上级文件夹等信息 → 确认保存。
选中文件夹 → 点击删除 → 系统检查文件、引用及子文件夹 → 存在内容时提示先处理 → 空文件夹弹出二次确认 → 确认删除。
D10 建议目录模板与项目目录独立维护，禁止删除文件夹时连带删除正式文件。当前目录删除存在对子树及文件的处理能力，新项目目录入口不能直接照搬该语义。

文件类型创建、修改、删除

文件类型决定适用规则，文件夹决定存放位置

进入文件类型管理 → 点击新增 → 填写类型名称、编码及说明 → 配置与现有分类、审批规则的对应关系 → 保存。
选择文件类型 → 点击修改 → 修改信息 → 保存 → 后续文件申请使用新的配置。
选择文件类型 → 点击删除 → 检查是否被文件、模板或审批矩阵使用 → 未使用时二次确认删除；已使用时提示停用，保留历史对应关系。

上传时先选择存储文件夹，再选择文件类型。当前“阶段、文件类型、文件分类、文件类别”有多层配置；实施时应明确映射，不能把存储文件夹与文件类型混成同一个选项，也不能仅改显示名称而保留错误取值。

06

审批矩阵创建、修改、删除

管理员维护默认路线，申请保存本次执行名单

进入审批矩阵管理 → 选择文件类型及适用动作，上传／升版／作废 → 点击新增 → 选择默认会签部门 → 显示部门负责人 → 配置批准人 → 保存并启用。
选择矩阵 → 点击修改 → 调整部门或批准人 → 保存 → 新提交申请使用新配置。
选择矩阵 → 点击删除或停用 → 检查使用情况 → 二次确认 → 后续申请不能再选用，历史记录继续可追溯。
  • 部门负责人须是有效系统账号；缺失或失效时明确报错，不自动改派管理员、不跳过该部门。
  • 会签要求全部通过；批准人来源于本动作适用的矩阵，不由上传人随意替换。
  • 提交时保存本次会签部门及批准规则；部门负责人创建任务时确定，后续配置变更不静默改变已创建任务。
  • 申请人增删部门形成当前申请的执行名单；不反向改写全局矩阵。
  • 上传、升版、作废可以复用管理界面，但各自流程、状态和结果必须清晰，不能缺少某动作配置时借用其他动作。
D02 批准建议配置一名明确批准人；若保留多人候选，是否一人通过即可需明确配置和展示。不能把当前代码的ANY规则直接写成业务已确认规则。
07

关联文件操作流程

建立文件之间的关系，统一解析最新受控版本

进入项目目录 → 选择项目 → 选择存储文件夹 → 显示文件列表 → 点击文件的关联按钮 → 弹出关联窗口 → 查看已有关系 → 按目录或全局搜索选择文件 → 按需要增加、取消关联 → 点击确认 → 保存关联关系。

上传时和文件列表中的关联操作使用同一个选择窗口。上传未正式提交时，关联选择暂存于本次申请；文件列表上的关联修改保存后即时生效，并保留操作记录。

已确认关联始终取最新受控版本。例如A关联B，B从A/1升版到A/2并受控后，A的当前关联入口自动显示B的A/2，无需手动重新关联。若A/2尚未到生效日期，关联处同时标识“待生效”，不能把它当作已经生效的正文使用。

  • 关联依据文件的稳定身份建立；展示和打开当前关联时查找最新受控版本，不能固定在最初选中的旧版。
  • 新版本未受控时，关联继续指向原受控版本；不存在任何当前受控版本时，明确显示“无可用受控版本”，不能悄悄打开已作废版。
  • 历史审批记录保存当时审核的关联版本；自动更新当前关联不能覆盖历史证据，也不能把新的关联正文伪装成当时已审内容。
  • 不能重复关联同一文件，也不能关联自己；跨项目候选限定为当前租户内有权限的文件。
  • 关联关系更新不等于关联文件必须升版。只有本次会签阶段明确指定整改负责人和期限的文件，才产生联动升版任务。

09

上传、升版、作废审批流程

上传／升版：会签 → 批准 → 培训（如需）→ 文控审核 → 受控 → 下发；作废：会签 → 批准后结束

a. 部门负责人指派会签人

申请提交 → 各会签部门负责人收到待办 → 打开会签指派弹框 → 查看文件正文、基础信息、三组属性、关联文件及变更说明 → 指派本部门的会签负责人，可以选择自己 → 部门负责人电子签名确认 → 被指派人收到会签任务。

部门负责人和会签负责人是两种职责；同一人兼任时，指派确认和正式会签仍分别留痕。每个部门的会签义务独立存在，不能因为同一人负责多个部门就省略某个部门的意见。

b. 升版时选择关联文件整改责任人

部门负责人打开升版指派弹框 → 查看关联文件清单 → 对需要联动升版的文件选择负责人及整改期限 → 对不要求升版的文件保留“不需要升版” → 核对后电子签名确认。

没有指定升版责任人的关联文件，本次不要求升版。已指定的任务先保存为待触发安排；主文件正式受控成功后才通知负责人。会签、批准、文控审核驳回，流程撤回或受控处理失败时，不发送该整改通知。通知触发点仍为受控，不擅自改成未来生效日。

D08 建议期限填写“主文件受控后N天内完成”，从实际受控时间起计算。同一关联文件在同一次申请中只有一位有效负责人和一个期限；多个部门的指派冲突需协调解决，不能后写覆盖。任务完成以关联文件新版受控为准。

c. 会签负责人办理

会签负责人进入待办 → 打开会签弹框 → 查看正文、版本、三组属性及相关说明 → 填写会签意见 → 选择通过或不通过 → 电子签名确认。

所有部门的会签任务全部通过后才进入批准。通过和不通过都需要有效电子签名；签名绑定办理人、本次申请、所审版本、操作结果和时间。

d. 批准

矩阵配置的批准人收到待办 → 打开批准弹框 → 查看文件正文、基础信息、三组属性及全部会签意见 → 确认文件负责人 → 填写批准意见 → 选择通过或不通过 → 电子签名确认。

已确认上传、升版由批准人在批准弹框中选择文件负责人，与本次批准及电子签名一并保存，不新增审批节点。所选负责人使用正式启用账号，历史保留本次人选；不默认指定申请人。独立作废流程不增加负责人选择。

e. 培训，如需要

批准通过 → 判断本次申请的培训CheckBox → 未勾选则跳过培训并进入文控审核 → 已勾选则进入培训节点 → 文控上传该文件本次申请的线下培训文件 → 确认上传 → 进入文控审核。

培训使用本次已批准、内容冻结的正文，标识“待受控”。不能为了培训预览提前盖受控章或提前作废旧版；未勾选时不创建培训待办和培训通知。

D06 已确认：文控上传线下培训文件即可完成本次培训节点，不要求系统逐人学习确认、全员完成核验或另一个培训批准节点。上传文件须绑定当前文件、版本及真实申请轮次，上传或绑定失败不能报告完成。

f. 文控审核

批准及必要培训完成 → 文控收到审核任务 → 打开审核弹框 → 查看本次冻结正文、名称、编号、版本、生效日期、三组属性、关联、会签指派和签名、批准记录及培训证据 → 核对生效日期是否合理 → 选择通过或驳回 → 电子签名确认。

文控审核通过才进入受控。若正文或信息有误、必需证据不足、生效日期不合理，文控填写原因并签名驳回到申请人修正。文控审核和受控之后的下发是两个不同节点，不能合并。

g. 受控日期与生效日期

文控审核通过 → 系统对冻结正文生成受控文件、加盖受控章 → 受控成功 → 自动记录受控日期 → 保留编制时预设的生效日期 → 显示“已受控、待生效”或“已受控、已生效” → 进入文控下发待办。

日期规则已确认生效日期可在受控日期之后，文件编制时可预设生效日期。不能用受控日期覆盖用户预设日期，也不能因完成受控就把尚未到期的文件标记为已生效。

受控成功时，最新受控版本和当前关联展示更新，并触发已指定的关联升版通知；历史记录保留。受控处理失败时，不变更旧版状态、不切换关联、不通知整改负责人。

D04 已确认等新版本生效，旧版本才自动作废。新版提前受控而尚未到生效日期时，旧版继续用于执行；到新版生效日期，系统完成新版生效和旧版自动作废，不另发作废申请。新旧版分别显示生效状态，关联仍显示最新受控版并标识待生效。

新版生效与旧版作废应作为同一次版本切换完成，保留切换时间、作废原因及历史证据；未完成切换时不能先作废旧版，避免执行空档。

h. 按生效日期提醒文控处置

文控进入待处置／下发列表 → 系统按生效日期从早到晚排序 → 查看到期、临期及后续文件提醒 → 打开目标文件 → 核对生效日期与处置事项 → 办理下发和相关记录 → 该事项显示已处置。
  • 列表同时显示预设生效日期、受控日期、文件版本、负责人、当前节点、下发及处置情况。
  • 到期及逾期未处置事项优先提示；已办理事项不继续作为未处理提醒。提醒不能自动完成文控审核或伪造下发。
  • 日期检查在编制提交和文控审核时进行；建议生效日期不得早于实际受控日期。如果审批拖延导致日期已过，提示调整申请并重新审核，不能静默改为今天或追溯生效。
  • 提前提醒多少天、是否每日提醒及具体提醒渠道尚未指定，本稿不编造固定天数。明确为可配置项并供业务核对。

i. 文控下发

文件受控 → 文控按生效日期排序接收下发提醒 → 打开下发弹框 → 查看受控正文、名称、编号、版本、受控日期、生效日期、三组属性和前序审核证据 → 确认接收部门、人员和方式 → 点击下发 → 二次确认 → 接收人收到通知 → 记录电子接收或纸质签收。

已确认下发不会失败：业务流程按文控确认下发后完成下发设计，不设置失败、驳回或回退分支。提前下发时明确显示生效日期和“生效前不得执行”；下发不改变预设生效日期，也不省略前面的文控审核。

升版下发时提示旧版处置安排，纸质副本登记回收或处置记录。若文控在受控后发现内容错误，应发起正式升版或作废处理，不直接回改已受控正文。

j. 驳回、修正与重新提交

会签、批准或文控审核选择不通过并签名 → 申请人收到修正通知 → 查看原因 → 修改文件、申请信息或生效日期 → 核对三组属性、关联和会签部门 → 重新确认提交 → 重新进入指派及完整审批流程。
D03 会签、批准、文控审核驳回建议均回到申请人；取消本轮未完成任务，保留已完成签名，不沿用上一轮通过结果。正文变化后重新办理必要培训。文控审核驳回回到申请节点符合原始需求；文控下发不使用审批驳回。

k. 独立作废申请

进入受控文件 → 打开文件选择器 → 选择一个受控文件 → 打开该文件的操作面板 → 点击作废按钮 → 弹框显示文件基础信息及所属项目 → 从项目重新带出三组属性默认值 → 用户核对并可修改本次值 → 填写作废原因 → 核对会签部门和批准人 → 点击确认 → 二次确认 → 会签 → 批准通过 → 文件标记已作废 → 流程结束。

入口已确认作废按钮属于文件选择器选中文件后的操作面板；先定位具体文件，再发起作废，不作为脱离所选文件的独立新建入口。

作废申请中的三组实际值单独保存，不能覆盖原受控版本的历史属性。审批期间原版本保持受控；作废成功后停止受控使用，引用和关联入口显示明确作废状态，不删除追溯记录。

D05 已确认作废流程在批准节点结束。批准通过即完成作废，不增加培训、文控审核、受控或下发。作废后的消息、纸件回收如需执行属于独立后续处置记录，不成为本申请继续流转的节点，也不推迟作废结果。

l. 保留期内占用编号和名称

批准完成作废，或旧版按规则自动作废 → 保留正文、版本和签核记录 → 记录作废日期与保留期限 → 保留期内继续占用原编号及完整名称 → 新建上传校验占用 → 保留期到期后按确认的归档和释放规则处置。

已确认独立作废文件和自动作废的旧版均保存20年；保留期限内，不允许另一条新文件链冒用被占用编号或相同完整名称。原文件链的新受控版本仍可沿用自身编号与名称，不被自己的历史版本阻断。本轮实施口径从实际作废日期起算；期满处置权限仍待明确，期满不等于自动删除证据或释放仍由当前受控版本占用的名称与编号。

检出、检入与升版

检入保存小版本；正式变更经过审批、文控审核、受控及下发，按预设日期生效

a. 检出文件

打开文件选择器 → 按项目目录或搜索选择文件 → 点击检出 → 填写修改原因 → 确认 → 锁定文件编辑权 → 页面显示检出人及检出时间。

其他人不能再次检出同一文件；有权限的人仍可查看当前受控版本。检出人可以撤销检出，填写原因后释放锁，不产生新版本。

b. 检入小版本

检出人完成修改 → 选择该文件 → 点击检入 → 选择修改后的文件及必要配套PDF → 填写修改说明 → 确认 → 生成新的小版本 → 释放检出锁。

c. 局部变更

打开文件选择器 → 选择文件 → 进入文件详情 → 打开版本历史 → 选择一个小版本 → 点击局部变更 → 展示原受控版本、选中小版本正文和目标正式版本 → 带出所属项目三组属性默认值 → 用户核对并可修改 → 填写变更说明并预设生效日期 → 核对关联、会签部门、批准人和培训选择 → 点击确认 → 二次确认 → 进入升版审批流程。

引用流程

项目文件夹使用已有文件，不复制源文件正文

项目负责人进入项目目录 → 选择项目 → 选择存储文件夹 → 点击引用 → 打开文件选择器 → 按目录或全局搜索选择已有受控文件 → 核对来源项目、名称、编号及版本 → 点击确认引用 → 文件显示在当前项目文件夹中。

权限已确认引用操作者只能是当前目标项目的项目负责人。普通成员、其他项目负责人及未担任该项目负责人的管理员，不能仅凭其他权限执行引用。页面入口和服务端操作均须校验负责人身份。

  • 引用入口使用橙色字体，并明确标注“引用”和来源项目，不能仅用颜色传达状态。
  • 展示引用项目数，例如被10个项目引用时显示“引用项目：10”；可以打开明细查看项目、文件夹和所用版本。
  • 按不同项目去重计数；同一项目在两个文件夹引用同一文件，项目数仍为1。同一文件夹不能重复引用同一文件。
  • 引用不改变源文件归属、文件编号或内容，不自动复制源项目的默认属性到当前项目。浏览时展示该文件版本自身的实际属性。
  • 引用成功不自动获得源文件编辑、升版或作废权限；这些动作仍校验文件所属项目和正式授权。
D10 建议源文件被引用时也显示橙色及计数；建议项目引用跟随最新受控版本，并通知项目负责人。用户已确认“关联始终最新”，但“引用是否跟随”尚未单独确认，两者不能混同。

如果源文件独立作废且没有可用受控版本，引用入口显示“源文件已作废”，保留追溯入口，禁止把历史正文当作当前受控文件使用。

取消引用流程

移除本项目文件夹入口，保留源文件和其他使用关系

项目负责人进入项目目录 → 选择项目 → 选择存储文件夹 → 选中橙色且带“引用”标识的文件 → 点击控制栏取消引用 → 弹框展示文件名称、来源项目及当前文件夹 → 二次确认 → 当前文件夹中的引用入口消失。

权限已确认取消引用操作者只能是该引用所在项目的项目负责人。权限规则与引用一致；源文件负责人或其他项目负责人不能代替当前项目负责人取消引用。

  • 本项目其他文件夹仍引用同一文件时，引用项目数不变；解除本项目最后一个引用时，引用项目数减1。
  • 所有项目均取消引用后，源文件引用项目数为0，源文件因被引用而产生的橙色标识恢复。
  • 取消引用不删除源文件，不删除版本、签名、审批或下发记录，也不取消文件之间的关联。
  • 取消确认框时不保存任何变化；操作失败时保留原引用并提示原因。

橙色来源区分“此行是引用入口”和“源文件被其他项目引用”。其他项目的引用取消，不会让仍存在的引用入口失去“引用”标识。

AC-01在后台配置项目及产品审核人，创建项目、填写模板及三组属性并审核批准；提交后再修改审核配置。提交时带出并保存当时审核账号；后续改配置不改变旧申请审核身份。项目产品可用，文件夹按模板生成，三组默认值准确回显；批准创建同事务为选定负责人建立一条正式 USER/OWNER 权限，负责人能进入新项目及目录，其他人员不被自动授权，初始化失败整体回滚。缺配置或账号不可用时明确拒绝提交。
AC-02上传时选择项目并修改带出的属性，提交。申请保存修改值；项目默认值、其他文件不变；会签与批准看到相同申请值。
AC-03文件原属性与项目默认不同，分别发起升版、作废。两种新申请都先带出项目默认值，允许修改；作废申请不覆盖旧版历史属性。
AC-04修改项目默认值，再查看草稿、在途流程和历史版本。已保存值不被覆盖；新申请带出新的项目默认值。
AC-05选择“其他”、N/A及文件转移是/否。按确认的D01互斥与条件必填规则校验；不能提交矛盾组合或空转移目标。
AC-06填写上传信息、关联和培训选择，点击确认。出现二次确认；取消保留输入；再次确认后才创建审批。
AC-07部门负责人指定自己及其他人为会签人。被指定人收到正式会签任务，指派和会签签名分别留痕。
AC-08会签、批准及文控审核分别驳回；文控审核尝试未签名提交。均不提前受控，按规则修正重提；文控审核驳回回到申请节点，签名必需，新轮次重新会签。
AC-09上传、升版分别提交需要培训和不需要培训的申请。顺序为会签→批准→可选培训→文控审核→受控→下发；跳过培训也不能跳过文控审核，受控日期与预设生效日期分别保留。
AC-10多人尝试检出同一文件，由检出人检入。只有一人持有编辑锁，其他人看到检出人；检入生成横杠小版本并释放锁。
AC-11选择小版本局部变更、A/9局部变更、换版变更。分别得到A/2、B/1及下一字母/1；以实际选定正文审批；未受控前旧版仍保持受控。
AC-12新版提前受控及受控失败各一次，观察关联、旧版和新版生效日。提前受控后关联切换并显示待生效，旧版继续执行；新版生效时旧版自动作废。受控失败时旧版、关联保持不变，不发整改通知。
AC-13会签中选择部分关联文件的责任人和期限。只在主文件受控后通知所选人员；未选择的不产生本次整改任务；审批中断不通知。
AC-14跨项目关联文件，目标产生新受控版后打开关联。当前关联显示最新受控版；原审批记录仍展示当时审阅版本。
AC-15从目录和搜索分别浏览同一文件及其历史版。正文、版本、状态与属性一致；历史已作废标识明确；无内容权限不能看正文。
AC-16各目标项目负责人分别引用同一文件到自己的项目及文件夹，并由非负责人尝试引用。仅目标项目负责人可成功；非负责人前后端均不可操作；引用入口橙色且有文字标识，按项目去重计数。
AC-17当前项目负责人取消单个、项目最后一个及全局最后一个引用，并由非负责人尝试取消。只有当前项目负责人能取消；只移除相应入口，计数正确；最后一个引用解除后源文件颜色恢复。
AC-18有权限和无权限用户分别编辑文件夹模板；删除非空文件夹、停用已使用文件类型。模板编辑仅校验权限，有权限保存后完成、不创建审批任务，无权限禁止；目录与类型按确认规则保护文件及历史记录。
AC-19文控从按生效日期排序的列表办理已受控文件下发，并记录接收及纸件处置。下发业务没有失败或驳回分支，不改变预设生效日期；提前下发标识生效前不得执行，签收与下发分别记录。
AC-20进入受控文件，通过选择器选中文件，在操作面板发起作废并通过会签、批准。批准通过即作废且流程结束，不创建培训、文控审核、受控或下发节点；三组属性独立保存，关联与引用标示作废。
AC-21另一项目上传SOP.pdf、sop.pdf、SOP.PDF和SOP.docx；已有文件为SOP.pdf。仅完整名称SOP.pdf为同名且新建被阻止；其他三者按大小写或后缀差异视为不同文件。改变目录或编号不能绕过完全同名判定。
AC-22查看由局部变更形成的A/2、由局部变更进位形成的B/1、由换版变更形成的B/1，并切换历史版本。无论版本号是什么，详情均展示本次实际操作的“局部变更”或“换版变更”、来源版本和说明；切换历史版显示对应历史事实。
AC-23查看列表、文件选择器、详情、版本历史和审批展示。关于文件版本的业务术语统一使用“受控版本”，且与审批中、小版本、已作废版本明确区分。
AC-24文件作废后，在其保留期限内用原编号、原完整名称发起另一条文件链上传。编号和名称都仍被占用，不能因作废绕过；同一逻辑文件自己的后续版本不受历史占用阻断。
AC-25编制时预设晚于受控日期的生效日期，完成文控审核和受控，随后到达生效日。两日期分别保存；受控后待生效，旧版继续执行；到预设日期新版生效并自动作废旧版，切换和历史记录一致。日期已过时不能静默改期或追溯生效。
AC-26存在不同生效日期、已到期、临期及已处置文件，文控打开待处置列表。按生效日期升序排列并优先提醒到期事项；已处置不重复作为未办理提醒；提前天数按明确配置，不凭空补值。
AC-27A/1申请升到A/2被驳回，修改正文后连续重新提交，并逐次打开失败申请与新申请。正式目标仍为A/2；各次申请拥有独立文件身份、正文来源、BPM、默认来源、实际属性及签名历史。失败历史不删除、不改号、不被新申请覆盖；新版生效之前A/1仍为当前执行受控版本。

实现时需分别覆盖上传、升版、作废三种属性继承路径，以及关联和引用两种独立关系。真实业务E2E仅在用户明确要求的当轮执行，并按仓库规则通过真实前端页面办理。
