# 电子签名定期合规审查 SOP

## 1. 目的

建立电子签名定期合规审查机制，确保电子签名制作数据持续满足“专属于签名人一人、仅由签名人控制、签名后任何改动能够被发现”的审查要求。

## 2. 适用范围

适用于 IntRuoyi 中所有被标记为正式电子签名的业务链路，包括统一电子签名记录、eDHR 批记录签名、BPM 审批签名、签名证据查询与导出。

非正式草稿、模拟、预览、登录会话保存记录不得作为正式电子签名合规证据。

## 3. 角色与职责

| 角色 | 职责 | 最低频率 |
|---|---|---|
| 电子签名合规负责人 | 发起审查、确认范围、关闭整改项 | 每季度一次 |
| 系统管理员 | 导出账号、密码策略、锁定策略和权限证据 | 每季度一次 |
| 业务流程负责人 | 确认多级审批路径、签名顺序和业务内容绑定 | 每季度一次 |
| QA/合规审查人 | 复核证据、抽样验证签名记录、批准审查结论 | 每季度一次 |
| 安全负责人 | 复核认证、账号唯一性、审计追踪和异常事件 | 每季度一次 |

## 4. 审查触发

必须在以下任一场景发起审查：

- 固定周期：每季度至少一次。
- 变更触发：电子签名、账号认证、密码策略、BPM 审批、eDHR 批记录签名或审计导出逻辑发生生产变更。
- 事件触发：发现共享账号、密码泄露、异常登录、签名记录缺失、签名内容 hash 不一致、审批顺序异常。
- 审计触发：内外部审计要求补充电子签名可靠性验证。

## 5. 审查输入证据

每次审查必须收集并归档以下证据，缺一项不得关闭审查：

| 证据类型 | 必填内容 | 对应审查项 |
|---|---|---|
| 账号唯一性证据 | 用户清单、租户、用户名、规范化用户名、重复账号检查结果 | 4.1 |
| 密码策略证据 | 最小长度、复杂度、有效期、历史密码限制、首次/重置改密状态 | 4.2、4.3、4.4、4.5 |
| 账户锁定证据 | 失败次数阈值、锁定状态、锁定时间、解锁记录 | 4.6 |
| 正式签名抽样 | 签名人、业务对象、签名原因、签名时间、认证方式、内容 hash、证据 hash | 4.7、4.8、4.9、4.12 |
| 审计追踪证据 | 签名操作、变更前后内容、字段 diff、算法、key/policy 版本 | 4.9 |
| 多级审批证据 | 流程实例、任务 ID、节点编码、节点顺序、审批结果 | 4.11 |
| 整改记录 | 问题描述、责任人、修复计划、验证证据、关闭批准 | 4.10 |

## 6. 审查步骤

1. 创建审查批次，记录审查周期、范围、负责人、计划开始时间、计划完成时间。
2. 导出本周期正式电子签名记录和账号安全策略证据。
3. 对 4.1 至 4.12 逐项执行审查，不允许以“系统默认正常”代替证据。
4. 对正式签名记录进行抽样复算：确认签名内容 hash、证据 hash、签名时间和审批上下文一致。
5. 对异常项建立整改记录；高风险项必须在批准上线或审计提交前关闭。
6. QA/合规审查人复核证据包，形成“未发现 / 发现问题 / 不适用”结论。
7. 归档审查包，至少包含审查表、导出证据、抽样记录、整改闭环和批准记录。

## 7. 判定规则

| 结论 | 判定条件 |
|---|---|
| 未发现 | 有完整证据证明该项控制存在、有效且抽样未发现异常。 |
| 发现问题 | 缺少控制、控制无效、证据缺失、抽样发现异常，或整改未关闭。 |
| 不适用 | 当前系统没有该类业务场景，且业务负责人和合规负责人均确认不适用原因。 |

## 8. 记录留存

- 审查记录、导出证据和整改闭环记录保留不少于企业电子记录保存期限。
- 记录必须包含创建人、复核人、批准人、时间戳和版本。
- 不得修改已批准审查记录；更正必须生成新版本并保留更正原因。

## 9. 最低审查表模板

每次审查至少使用以下字段：

| 字段 | 要求 |
|---|---|
| Review ID | 唯一编号，例如 `ESIGN-YYYY-QN` |
| Review Period | 审查覆盖周期 |
| Scope | 涉及模块、环境、租户和业务链路 |
| Owner | 电子签名合规负责人 |
| Reviewer | QA/合规审查人 |
| Planned Start / Due Date | 计划开始与截止日期 |
| Evidence Package | 账号、密码、锁定、签名、审计、审批顺序证据清单 |
| Checklist Result | 4.1 至 4.12 每项结论和证据引用 |
| Findings | 问题、等级、责任人、计划完成日期 |
| Approval | 复核结论、批准人、批准时间 |

## 10. 发布门禁

电子签名相关功能上线前必须满足：

- 4.1 至 4.9、4.11、4.12 均有代码或配置证据支撑。
- 4.10 至少具备本 SOP、审查表模板和首期审查计划。
- 若是生产审计交付，必须额外具备已执行并批准的审查记录；只有 SOP 或模板不得标记为已完成运营审查。
