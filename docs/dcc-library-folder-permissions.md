# QMS、通用文件库目录维护与权限分配

## 页面操作

进入文件浏览页，切换「QMS文件夹」或「通用文件夹」。具备当前库编辑权时，左侧目录树上方显示「新增文件夹」「编辑文件夹」「删除文件夹」。

- 新增：选中目录后新增，默认以上述目录为父级；可在弹窗选择其他上级或文件库根目录。
- 编辑：选中目录后修改名称、上级和排序；填写修改原因后保存。
- 删除：仅允许删除没有子目录、文件位置、引用和存储映射的目录；填写原因并再次确认。
- 保存、删除后刷新当前文件库。目录维护沿用现有变更审计，不移动 NAS 实际文件。

## 权限清单

| 权限 | 标识 | 作用 |
| --- | --- | --- |
| 文件浏览入口 | `dcc:controlled-file:query` | 进入浏览页、读取目录，调用本页目录维护接口的基础入口资格 |
| QMS文件夹浏览 | `dcc:library:qms:view` | 浏览 QMS 目录与允许查看的正文，不可维护目录 |
| QMS文件夹编辑 | `dcc:library:qms:edit` | 包含 QMS 浏览权，并允许新增、修改、删除 QMS 目录 |
| 通用文件夹浏览 | `dcc:library:general:view` | 浏览通用目录与允许查看的正文，不可维护目录 |
| 通用文件夹编辑 | `dcc:library:general:edit` | 包含通用浏览权，并允许新增、修改、删除通用目录 |

编辑权包含同库浏览权，无需重复勾选浏览。QMS 与通用库分别授权，授权覆盖该库全部目录，不按子目录单独分配。具有一个库的编辑权不能维护另一个库。同租户启用的超级管理员沿用现有全库访问能力。

本功能不要求 `dcc:project-code:update`，不新增 `dcc:library-folder:update`，也不以全局 `dcc:controlled-file:edit` 替代具体文件库编辑权。普通项目文件夹继续使用原项目权限规则。上传、文件修改及下载继续按各自既有接口权限执行，本次目录维护不扩大这些动作的授权。

## 分配步骤

1. 管理员进入「系统管理 → 权限角色」，选择现有角色或建立职责明确的角色。
2. 点击该角色的「菜单权限」，勾选 DCC 文件浏览入口，以及需要的 QMS/通用浏览或编辑权限，保存。
3. 进入「系统管理 → 用户管理」，通过「分配角色」把该角色分给对应人员。
4. 用户重新登录，打开对应文件库。编辑用户可见维护按钮，只有浏览权的用户不能维护。

例如：QMS 文控人员勾选文件浏览入口和 QMS文件夹编辑；若其只需查阅通用文件，再加通用文件夹浏览。需要维护两个库的人员，勾选两个库的编辑权限。

授权管理采用当前系统权限角色机制：查看角色需要 `system:role:query`，分配角色菜单需要 `system:permission:assign-role-menu`，给人员分配角色需要 `system:permission:assign-user-role`；页面查询和新增角色还需对应系统管理权限。文件库编辑权本身不包含授权管理能力。
