# DCC 上传流程的候选部署资料

这里保存与当前生产 `DccWorkflowDefinitionCatalog` 完整图摘要一致的三份模型和本批迁移依赖清单。模型从已验证的任务源逐字节复制，保留原说明注释。它们不在 Spring 自动部署资源目录；生成本目录不会部署模型、执行迁移或改变运行服务。

| 模型 | 流程键 | 业务顺序 |
| --- | --- | --- |
| upload.bpmn20.xml | dcc-controlled-file-upload | 主管 → 部门指派及实际会签 → 批准/文件负责人 → 文控 → 可选培训 → 结束受控 |
| revision.bpmn20.xml | dcc-controlled-file-revision | 同上传审批，保留升版来源与旧版替换约束 |
| obsolete.bpmn20.xml | dcc-controlled-file-obsolete | 主管 → 部门指派及实际会签 → 批准结束 |

`deployment-inputs.json` 记录原始XML及解析后的完整图摘要、13份本批前向SQL加1份既有到期启用任务注册SQL的声明依赖闭包、当前审计政策文件与待批准状态。该闭包供核对，不能作为把旧种子迁移全部重放到现有库的授权或执行清单。实际待执行SQL必须以运行库结构、账本及备份核对后确定。

后续经授权部署时，通过既有模型维护/部署服务读取并保留当前租户模型的表单、管理人和节点设置，用这里的完整XML产生新定义；记录实际返回的 `processDefinitionId` 和完整图摘要。已有实例保持原定义和签名证据；不得覆写历史XML、伪造ID或直接用流程键/最新版本补历史。跨申请类型继承还必须登记实际来源定义与目标定义的精确过渡映射。

运行前需要明确业务时区、主管关系、项目/类别权限、下发部门人员及正式审计策略。未设置的值不得以示例账号、部门负责人或虚假批准记录代替。预设日期已过的处理遵守用户最新规则：提交时合法，后续满足审批、培训和受控条件后立即实际生效下发；保留原预设日期。

未来日期的自动生效还需要正式启用 `dccControlledFileActivationJob`。既有注册SQL要求明确的 cron/重试/监控参数，并只创建暂停状态；实际启用必须走现有任务控制并核对 Quartz 注册。只有一行暂停的 infra_job 记录不能证明将自动生效。已到期而后完成受控的申请由受控事务立即启用，不等待此定时扫描。

当前仅完成静态材料与真实模型解析验证，`runtimeReady=false`。没有执行真实数据库写入、BPM部署、服务操作、远程发布或网页E2E。正式发布包仍须遵循仓库的来源冻结、备份、目标环境与授权规则。
