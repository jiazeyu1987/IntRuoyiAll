# DCC 截图需求 BDD 场景

## Purpose and Scope

本文将 DCC 截图中的 14 条需求转为可验收的 BDD 场景。范围只覆盖截图可见需求，后续实现必须复用当前系统的 `yudao-module-dcc`、BPM 流程、系统用户密码、现有 DCC 前端页面和既有审计/发放/培训能力，不允许独立另起一套 DCC 系统，不允许以 mock、默认成功或 fallback 掩盖缺失前置条件。

## Feature Scenarios

### R01 文件受控审批上传可编辑源文件和图纸 PDF

Given 申请人已登录测试租户，并进入 DCC 受控文件上传页面  
When 申请人上传 `doc`、`docx`、`xls`、`xlsx`、`dwg`、`sldprt`、`sldasm` 或 `slddrw` 等可编辑源文件  
Then 系统应接受源文件并在提交前保留该源文件引用  

Given 申请人上传的源文件为 `dwg`、`sldprt`、`sldasm` 或 `slddrw` 图纸类文件  
When 申请人未同时上传 PDF 格式文件并提交文件受控审批  
Then 系统应拒绝提交，并提示缺少图纸 PDF 伴随文件  

Given 申请人上传图纸类源文件，并同时上传对应 PDF 格式文件  
When 其他必填字段完整且审批路线可解析  
Then 系统应允许提交受控文件审批，并在后端记录源文件和 PDF 伴随文件关系  

### R02 账户密码强度和定期强制更新

Given 管理员创建用户、重置用户密码，或用户在个人中心修改密码  
When 输入密码少于 8 位，或未同时包含英文和数字  
Then 系统应拒绝保存，并提示密码必须至少 8 位且包含英文和数字  

Given 密码强制更新周期已由业务确认并配置  
When 用户账号的密码更新时间超过该周期后登录或继续访问后台  
Then 系统应强制进入密码更新流程，在完成合规密码更新前不得继续正常业务操作  

### R03 下载非受控提醒和下载留痕

Given 用户在受控文件详情或预览页面点击下载  
When 下载动作发起前  
Then 前端应显示“下载后文件为非受控文件”提醒，并要求用户确认  

Given 用户确认下载，并且后端成功读取文件内容  
When 下载接口返回文件内容  
Then 系统应写入下载留痕，至少包含下载人 id 和下载时间  

Given 后端无法写入下载留痕  
When 用户尝试下载文件  
Then 下载不得静默成功，应失败并提示下载留痕写入失败或下载失败  

### R04 文件视图显示修改中标识

Given 文件处于修改中或审批修订中的状态  
When 用户进入 DCC 文件列表、目录浏览或文件详情视图  
Then 界面应在该文件上显示 `修改中` 标识  

Given 文件不处于修改中状态  
When 用户查看文件视图  
Then 界面不应显示 `修改中` 标识  

### R05 节点负责人回退、转交、加签和申请人撤回后处理

Given 节点负责人拥有当前审批任务权限  
When 节点负责人打开审批任务详情  
Then 界面应按权限展示回退、转交、加签操作入口  

Given 节点负责人选择回退流程  
When 回退目标为前一节点处理人  
Then 流程应回到前一节点处理人的待办，当前流程实例不变  

Given 节点负责人选择回退流程  
When 回退目标为申请人  
Then 流程应进入申请人待办，并显示 `有流程回退，需处理`  

Given 申请人在待办中处理被退回的流程  
When 申请人修改后再次提交  
Then 系统应继续原流程实例，不得重新发起新的流程实例  

Given 申请人主动撤回未完成的流程  
When 撤回成功后申请人选择删除流程  
Then 系统应删除或作废该流程对应的待办和业务草稿，并记录撤回原因  

Given 申请人主动撤回未完成的流程  
When 撤回成功后申请人选择重新提交  
Then 系统应基于原业务记录重新提交，不得丢失原表单和文件信息  

### R06 文件受控审批新增字段

Given 申请人进入文件受控审批表单  
When 填写文件类别、查看现行有效版本、录入产品编号  
Then 文件类别候选值至少包含 `体系文件`、`技术文件-DHF`、`技术文件-DMR`，现行有效版本应从当前受控文件版本链读取，产品编号必须按统一 14 位编码记录  

Given 申请人未填写文件类别或产品编号，或产品编号不是 14 位  
When 提交文件受控审批  
Then 系统应拒绝提交，并提示具体缺失或格式错误字段  

Given 当前文件存在现行有效版本  
When 申请人选择同一文件名称或编号发起新版审批  
Then 表单应显示现行有效版本，后端应校验新版本高于现行有效版本  

### R07 外来文件评审流程

Given 外来文件评审流程的字段、节点、参与人、结论和输出物尚未确认  
When 后续 worker 评估实现该需求  
Then 应将该项标记为阻塞，不得创建空流程、默认审批通过流程或独立临时流程  

Given 业务补充完整外来文件评审流程定义  
When 用户发起外来文件评审  
Then 系统应复用当前 BPM 和 DCC 流程能力，按确认后的字段、节点、参与人和输出物流转  

### R08 体系记录所有人可下载

Given 文件编码满足经业务确认的体系记录识别规则，且截图当前规则为编码前六位可识别 `INT/RE`  
When 任意已登录用户在 DCC 文件视图点击下载  
Then 系统应允许下载，并仍然显示非受控提醒、记录下载人 id 和下载时间  

Given 文件编码不满足体系记录规则，且用户没有该文件下载权限  
When 用户尝试下载  
Then 系统应拒绝下载，并记录拒绝原因，不得因模糊匹配放开权限  

### R09 根据是否需要培训触发申请人上传培训记录

Given 申请人在文件受控审批表单选择 `是否需要培训 = 是`  
When 流程准备进入第四节点受控上传签核版本文件前  
Then 系统应要求申请人上传培训记录，培训记录缺失时不得进入第四节点  

Given 申请人在文件受控审批表单选择 `是否需要培训 = 否`  
When 流程准备进入第四节点  
Then 系统不应强制申请人上传培训记录，但仍应执行后续文控受控章 PDF 校验  

### R10 电子发放回收接收人加签

Given 文控在电子发放回收中选择接收人  
When 接收人进入自己的电子发放任务  
Then 接收人应可按权限选择加签人员，并提交加签  

Given 用户不是该电子发放任务接收人或无加签权限  
When 用户尝试加签  
Then 系统应拒绝操作，并保持原发放任务状态不变  

### R11 纸质发放回收记录导出和打印

Given 文控维护纸质发放回收记录  
When 新增或编辑记录  
Then 记录应包含文件编号、版本、名称、发放人、接收人、发放日期、回收人、回收日期  

Given 纸质发放回收记录存在  
When 用户执行导出或打印  
Then 输出内容应包含上述全部字段，且与页面记录一致  

### R12 文件受控审批导出、打印和 Word 模板配置

Given 文件受控审批流程存在  
When 用户在有权限的流程详情或文件详情中执行导出或打印  
Then 系统应输出当前流程表单、审批节点、签核信息和文件基础信息  

Given 打印模板配置为上传 Word 模板  
When 模板缺少确认后的必需占位符或模板文件不可读取  
Then 系统应失败并提示模板问题，不得使用默认空模板静默成功  

### R13 会签节点由申请人自行选择

Given 审批路线包含会签节点且该节点允许申请人选择  
When 申请人提交文件受控审批前选择会签人员  
Then 系统应把申请人选择的会签人员写入流程变量和路线快照，并由 BPM 按选择人员生成会签任务  

Given 申请人未选择必需会签人员或选择无权限人员  
When 提交文件受控审批  
Then 系统应拒绝提交，并提示会签人员缺失或不合法  

### R14 第四节点文控上传加盖受控章 PDF

Given 流程到达第四节点，且当前处理人为文控  
When 文控未上传加盖受控章后的 PDF 文件就尝试完成节点  
Then 系统应拒绝完成第四节点，并提示必须上传加盖受控章后的 PDF  

Given 文控上传加盖受控章后的 PDF 文件  
When 文控完成第四节点审批  
Then 系统应保存受控章 PDF，并继续后续发布、发放或归档逻辑  

## Failure Scenarios

- Given 必需文件、培训记录、受控章 PDF、审批路线、会签人员、密码策略配置或模板占位符缺失，When 用户执行相关动作，Then 系统必须失败并返回明确错误，不得默认成功。
- Given 下载留痕写入失败，When 文件内容已可读取，Then 仍不得放行下载，因为下载和审计是同一验收行为。
- Given `INT/RE` 编码完整规则未确认，When 后续实现体系记录所有人下载，Then 只能按确认规则实现，不得用模糊字符串包含判断扩大权限。
- Given 外来文件评审需求仍只有流程名称，When 进入开发，Then 必须阻塞该项而不是补造业务规则。

## Boundary Scenarios

- 多个图纸源文件是否要求逐文件 PDF 伴随件未确认，验收计划按“每个图纸源文件必须有对应 PDF”作为更严格边界，需业务确认后实现。
- 历史文件缺少新增字段时，列表和详情展示不得报错；但新增提交必须校验字段完整。
- 申请人、文控、节点负责人、接收人、会签人员离职或禁用时，不得自动改派，需按业务确认规则处理。
- Word 模板、流程导出和纸质记录打印的目标格式未完全确认，未确认前只允许做验证计划，不允许实现默认模板 fallback。

## Subagent-Driven Verification Responsibilities

- Worker-A 后端契约与单元测试：负责 DCC 后端服务、VO、Mapper、BPM 动作、系统密码策略相关 RED/GREEN/REGRESSION。
- Worker-B 前端契约与交互测试：负责 DCC Vue 页面、表单校验、下载提醒、加签/回退/转交入口、打印导出入口的 RED/GREEN/REGRESSION。
- Worker-C 验收计划：负责维护本文档及 TDD、E2E、测试数据计划，不改生产代码。
- Worker-D 真实路径 E2E：负责用 Playwright 在 `http://localhost:8081` 和真实测试租户中执行端到端验证，不使用 mock。
- Reviewer 主 agent：只在文档可实现图片目标且无副作用、满足 BDD/TDD/subagent-driven、逻辑自洽接口清晰、复用当前系统基础四项均满足后放行。

## Open Questions

1. `H`、`I`、`L` 的实际排期含义是什么？
2. 当前文件受控审批第四节点在 BPM 中的节点 key、节点名和文控角色映射是什么？
3. 图纸 PDF 伴随件是逐文件绑定还是审批包级绑定？
4. 14 位产品编号是否需要调用外部系统校验？
5. 密码强制更新周期、历史账号处理和强制更新入口是什么？
6. `INT/RE` 体系记录完整编码格式是什么？
7. 导出和打印的目标格式、模板占位符和模板权限是什么？
8. 外来文件评审完整流程是什么？

## Test Blockers

- 未确认第四节点 key、节点名和文控角色时，R09、R12、R14 的实现和 E2E 不可放行。
- 未确认密码强制更新周期和历史账号处理策略时，R02 的定期强制更新不可实现，只能先实现密码强度。
- 未确认 `INT/RE` 完整编码规则时，R08 不可放开所有人下载。
- 未确认外来文件评审字段、节点、参与人、结论和输出物时，R07 不可开发。
