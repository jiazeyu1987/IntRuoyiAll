# DCC 截图需求 E2E 计划

## Purpose and Scope

本文定义 DCC 截图 14 条需求的真实用户路径 E2E 计划。E2E 必须使用测试租户真实账号、真实菜单、真实后端服务、真实数据库和 Playwright 操作前端 `http://localhost:8081`；API 只用于最终状态核验，不得用 mock 数据、接口直塞或新增测试专用前端控件绕过用户路径。

## User Paths

### Path R01 文件受控审批上传

1. 使用测试租户申请人登录 `http://localhost:8081`。
2. 进入 DCC 受控文件上传页面。
3. 上传 `dcc-r01-source.docx` 并提交，确认源文件被接受。
4. 上传 `dcc-r01-drawing.dwg`，不上传 PDF，点击提交。
5. 验证页面提示缺少 PDF，后端没有创建新流程实例。
6. 上传 `dcc-r01-drawing.dwg` 和 `dcc-r01-drawing.pdf`，补齐字段后提交。
7. 验证提交成功，详情页可看到源文件和 PDF 伴随件。

### Path R02 密码策略

1. 管理员登录测试租户。
2. 进入系统用户管理，创建或重置测试用户密码为 `abc123`。
3. 验证页面和后端均拒绝保存。
4. 修改为 `abc12345`，验证保存成功。
5. 若强制更新周期已确认并配置，将测试账号密码更新时间调整为过期状态。
6. 用该账号登录，验证被引导到密码更新路径，更新前不能进入 DCC 页面。

### Path R03 下载提醒和留痕

1. 普通用户登录测试租户。
2. 进入 DCC 文件详情或预览页面，点击下载。
3. 验证弹窗显示“下载后文件为非受控文件”。
4. 取消下载，验证浏览器未下载文件且后端无成功下载记录。
5. 再次点击并确认下载，验证文件下载开始。
6. 使用 API 或数据库只做最终核验：下载记录包含当前用户 id 和下载时间。

### Path R04 修改中标识

1. 申请人提交一个新版审批，使文件进入修改中或审批修订状态。
2. 普通用户进入 DCC 文件列表、目录浏览和详情页。
3. 验证该文件显示 `修改中` 标识。
4. 完成或取消修订后再次查看，验证标识消失或随状态变化。

### Path R05 回退、转交、加签和撤回

1. 申请人提交受控文件审批。
2. 节点负责人登录审批任务页面。
3. 验证当前任务显示回退、转交、加签入口。
4. 选择回退至前一节点处理人，验证前一节点处理人待办出现该任务。
5. 再次流转到节点负责人，选择回退至申请人。
6. 申请人登录待办，验证 `有流程回退，需处理`。
7. 申请人处理后提交，验证流程实例 id 未变化。
8. 新建流程后由申请人主动撤回，分别验证删除流程和重新提交两条路径。

### Path R06 新增字段

1. 申请人进入上传页。
2. 验证文件类别候选值包含 `体系文件`、`技术文件-DHF`、`技术文件-DMR`。
3. 选择已有文件名称或编号，验证页面显示现行有效版本。
4. 输入非 14 位产品编号并提交，验证失败。
5. 输入 14 位产品编号并提交，验证详情页和后端记录一致。

### Path R07 外来文件评审

1. 在业务未补充完整定义前，不执行生产路径 E2E。
2. Reviewer 验证计划和任务文档中该项为 blocker。
3. 业务补充流程后，按确认入口执行发起、审批、结论、输出物全路径。

### Path R08 体系记录所有人下载

1. 管理员或文控准备编码满足确认后 `INT/RE` 体系记录规则的文件。
2. 无该文件类别下载权限的普通用户登录。
3. 进入可见体系记录路径并点击下载。
4. 验证出现非受控提醒，确认后下载成功。
5. 准备不满足规则且无权限文件，普通用户尝试下载。
6. 验证下载失败，并有拒绝访问记录。

### Path R09 培训记录节点

1. 申请人发起受控文件审批，选择 `是否需要培训 = 是`。
2. 流程流转至第四节点前。
3. 验证系统要求申请人上传培训记录，缺少记录时无法进入第四节点。
4. 申请人上传培训记录后提交。
5. 验证流程进入第四节点。
6. 再发起一条 `是否需要培训 = 否` 的流程，验证第四节点前不强制培训记录。

### Path R10 电子发放回收接收人加签

1. 文控在电子发放回收中选择接收人。
2. 接收人登录自己的发放任务。
3. 点击加签，选择加签人员并提交。
4. 验证加签人员收到任务或参与记录。
5. 非接收人登录尝试访问同一任务加签，验证失败。

### Path R11 纸质发放回收记录导出和打印

1. 文控进入纸质发放回收记录页面。
2. 新增记录，填写文件编号、版本、名称、发放人、接收人、发放日期、回收人、回收日期。
3. 保存后在列表和详情中核对字段。
4. 点击导出，验证下载文件包含全部字段。
5. 点击打印，验证打印预览或生成内容包含全部字段。

### Path R12 流程导出、打印和 Word 模板

1. 进入一条受控文件审批详情。
2. 点击导出，验证导出内容包含表单、节点、签核和文件信息。
3. 点击打印，验证打印内容与详情一致。
4. 上传缺少必需占位符的 Word 模板。
5. 执行打印或导出，验证失败并提示模板问题。

### Path R13 申请人选择会签人员

1. 申请人进入上传页，选择包含会签节点的审批路线。
2. 在会签节点选择合法会签人员。
3. 提交后查看流程详情或审批任务。
4. 验证 BPM 任务分配给申请人选择的会签人员。
5. 不选择必需会签人员或选择无权限人员提交，验证失败。

### Path R14 第四节点上传受控章 PDF

1. 将受控文件审批流转到第四节点文控处理。
2. 文控不上传加盖受控章 PDF，尝试完成节点。
3. 验证系统拒绝完成并提示必须上传 PDF。
4. 文控上传 `dcc-r14-stamped.pdf` 后完成节点。
5. 验证详情页显示受控章 PDF，流程继续发布、发放或归档。

## Browser or Client Steps

- 所有 E2E 使用 Playwright 操作浏览器，不通过 API 发起主流程。
- 登录、菜单导航、文件上传、表单填写、审批动作、下载确认、导出、打印和加签必须通过前端真实控件完成。
- 文件下载通过浏览器 download 事件验证，下载产物保存到测试临时目录，仅用于断言后清理。
- 打印验证优先检查浏览器打印预览触发或后端打印文件下载；不新增测试专用按钮。

## API Verification

API 只用于最终核验：

- 查询受控文件详情，核验流程实例 id、状态、字段、附件、路线快照、签核摘要。
- 查询下载留痕，核验下载人 id、下载时间、成功/拒绝结果。
- 查询纸质发放记录，核验字段与导出/打印一致。
- 查询 BPM 待办，核验回退、转交、加签、会签人员和第四节点流转。
- 查询系统用户，核验密码更新时间和强制更新状态。

## Console and Log Checks

- Playwright 每条路径结束后检查浏览器 console，不允许出现未处理异常、资源 404、接口 500 或权限静默失败。
- 后端日志不得出现被吞掉的异常；下载留痕失败、模板缺失、节点缺失必须有明确错误。
- 网络请求不得命中 mock endpoint、fixture endpoint 或测试专用后门。

## Subagent-Driven Verification Responsibilities

- Worker-B 负责把必要的前端静态测试和页面交互测试补齐到 `scripts/*.test.mjs`。
- Worker-D 负责创建 Playwright E2E 脚本并运行真实路径。
- Worker-A 负责提供后端最终核验 API 或数据库查询口径，但不得替代浏览器主流程。
- Reviewer 负责核查 E2E 是否真实走前端、是否使用测试租户真实数据、是否覆盖 14 条需求。

## Test Blockers

- 测试服前后端未启动或无法通过 `http://localhost:8081` 登录：阻塞全部 E2E。
- 测试租户缺少申请人、文控、节点负责人、接收人、普通用户、会签人员账号和权限：阻塞 R01、R03、R05、R08、R09、R10、R13、R14。
- 第四节点和文控角色未确认：阻塞 R09、R12、R14。
- 密码强制更新周期未确认：阻塞 R02 周期更新 E2E。
- `INT/RE` 完整编码规则未确认：阻塞 R08 放行路径。
- 外来文件评审流程未确认：阻塞 R07 E2E。
- 导出/打印格式和 Word 模板占位符未确认：阻塞 R11、R12 的最终格式验收。
