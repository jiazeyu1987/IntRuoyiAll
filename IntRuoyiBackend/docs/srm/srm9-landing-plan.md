# SRM srm9 落地计划

## 1. 使用目的

本文件把 `SRM系统需求.xlsx`、当前系统符合性结论、W0 冻结包和依赖阻塞清单合并成一份按“可落地程度”排序的执行计划。它回答三个问题：

- 现在能做什么。
- 拿到哪些输入后才能开生产代码。
- 哪些已完成能力只做回归，不得重复开发。

本文件不替代 `docs/srm/srm9-w0-freeze-pack.md`。生产代码任务启动前，仍必须先运行 W0 冻结门禁。

```powershell
python -X utf8 script/srm/check_srm_w0_freeze_gate.py --freeze-pack docs/srm/srm9-w0-freeze-pack.md --wave W1
```

机器可校验的 blocker 清单见 `docs/dependencies/srm9-blocker-manifest.json`。文档变更后应同步运行：

```powershell
python -X utf8 script/srm/check_srm_blocker_manifest.py --manifest docs/dependencies/srm9-blocker-manifest.json --freeze-pack docs/srm/srm9-w0-freeze-pack.md --landing-plan docs/srm/srm9-landing-plan.md
```

## 2. 落地程度分级

| 等级 | 含义 | 是否允许写生产代码 | 下一步 |
| --- | --- | --- | --- |
| `L4` | 输入、边界、验证和阻塞出口已经清楚 | 仅当任务类型本身需要代码时允许 | 创建任务、写 BDD/RED、实现、GREEN、回归 |
| `L3` | 业务和接口已冻结，但还未建立任务上下文 | 允许，但必须先建任务和 worktree | 补任务文档、样本台账、RED 命令 |
| `L2` | 方向明确，但关键规则、样本或字段未冻结 | 不允许 | 继续收集冻结输入，不写生产代码 |
| `L1` | 关键外部依赖或业务口径缺失 | 不允许 | 指定 owner，补合同、字段、样本和失败策略 |
| `L0` | 当前不具备启动条件，依赖前序波次完成 | 不允许 | 等前序实现和 merged-result 验证完成 |

## 8. 禁止重复开发和错误需求

- 不得重复开发 `5/6`；采购申请和订单变更只进入回归保护。
- 不得重复开发供应商门户、准入审批、公开/邀请询价主链、采购订单主链、现有 ERP 金蝶基础配置/读同步和 Phase45 受控模拟基线。
- 不得把受控模拟改名为真实联通。
- 不得用 mock、默认成功、静态数据、截图看板、空 `catch` 或静默跳过替代真实外部前置。
- 不得在 K3、签章、财务、PDA、仓储、质检凭据缺失时写“成功路径优先”的代码。
- 不得为测试额外增加前端控件或绕过真实用户路径。

## 9. 业务输入移交清单

任一 W0 子包准备从 `BLOCKED` 改为 `FROZEN` 前，必须同时提供：

| 输入 | 最低要求 |
| --- | --- |
| owner | 业务 owner、接口 owner、测试 owner 均明确 |
| 契约 | 字段、枚举、状态、错误码、幂等、重试和人工处理清楚 |
| 样本 | 测试租户、账号、样本编号、可复用/已占用规则清楚 |
| 凭据 | 只记录凭据保管方式，不把密码、token、AppSecret 写入文档 |
| 验收 | RED 命令、GREEN 命令、Playwright 路径和 admin 只读复验路径清楚 |
| 失败出口 | 缺输入时必须记录 `BLOCKER`，不得继续编码 |

## 10. 后续执行顺序

1. 业务/接口方先补齐一个 W0 子包。
2. 开发者更新 `docs/srm/srm9-w0-freeze-pack.md` 对应状态为 `FROZEN`，并同步 `docs/dependencies/*`。
3. 运行 `check_srm_w0_freeze_gate.py --wave <W1-W5>`，确认目标波次允许启动。
4. 在 `doc/tasks/<task-id>/` 建立独立任务，写 BDD、RED、样本台账和运行态边界。
5. 先跑 RED，再最小实现，最后跑 GREEN、REGRESSION、Playwright 真实路径和 admin 只读复验。
6. 只提交当前任务直接产生的改动，不提交 `.runtime/`、临时文件或无关脏改。
