# MES 排产模块阶段性改写控制方案

本文档用于控制 MES 排产模块阶段 1~5 的改写风险。它不是普通重构说明，而是后续改写前必须遵守的业务保护、测试门禁、停止条件和回退边界。

本方案必须与 `mes-scheduling-domain-contracts.md` 联动维护；任何阶段发现本文与排产域词典、身份优先级或身份口径判定矩阵冲突时，以域契约为准，并先更新契约与测试后再继续改写。

## 总控原则

1. 禁止一次性大重构：阶段 1~5 必须串行推进，每个阶段独立 RED -> GREEN -> REGRESSION，上一阶段未验收不得进入下一阶段。
2. 业务结果优先于代码形态：服务拆分、组件拆分和 Key 对象化不得改变排产结果、报工归属、日历产能阻断和受保护任务行为。
3. 缺前置即阻塞：缺路线、缺快照、缺日历、缺产能、缺任务扩展、缺报工链路或缺测试租户真实数据时，必须停止并记录 blocker。
4. 不引入 fallback：不得新增默认成功、空 catch、mock 数据、静默降级、自动补默认路线、自动补默认产能或绕过应用前重算。
5. 先保护再替换：任何阶段改写前，先补能证明现有业务行为的保护性测试，再做最小改写。
6. 真实 E2E 只在阶段门禁要求时执行，且必须走真实用户路径；接口只用于最终核验，不替代页面行为。

## 不改范围

- 不改变生产工单转排产工单入口，不直接 SQL 拼排产工单主表、工序快照或任务。
- 不改变 `routeProcessId`、`processId`、`scheduleOrderId`、`taskId` 的业务含义。
- 不改变应用重排必须重新计算、校验 `calendarContextToken` 和阻断 issue 的门禁。
- 不改变受保护任务的保护事实；已报工、锁定、手工调整任务不得被重排覆盖。
- 不改变报工必须沿任务扩展链归属的要求：`taskId -> scheduleOrderProcessId -> scheduleOrderId -> workOrderId`。
- 不把前端拆分扩大为接口语义、权限、菜单、分页或排序规则变更。

## 业务不变量

| 不变量 | 业务含义 | 验证要求 |
| --- | --- | --- |
| 路线工序隔离 | `routeVersionId + routeProcessId` 是路线内工序主身份。 | 禁止用 processId 跨路线合并；配置保存、工作台在制、路线工序设置必须按路线工序隔离。 |
| 排产工序快照优先 | 排产工单内计算使用 `scheduleOrderId + routeProcessId`。 | 当前路线漂移时，仍有剩余量的历史快照工序不能被静默丢弃。 |
| 前置拓扑不破坏 | 后工序不得早于直接前置结束。 | 依赖必须保留 `predecessorRouteProcessId` 和 FS link，缺前置快照必须 fail fast。 |
| 应用前重算 | 预览成功不等于可应用。 | 应用前必须重跑 preflight、preview、token 校验和阻断 issue 校验。 |
| 日历产能主身份 | 产能主身份是 `lineId + date + shift`。 | 缺日历、缺夜班、缺容量、token 过期不得默认白班或默认成功。 |
| 报工链路可追 | 报工必须绑定真实任务、排产工序、排产工单和生产工单。 | 禁止只凭产品号、工序名或 Excel 行文本归属报工。 |
| 受保护任务不覆盖 | 已报工、锁定、手工调整任务事实必须保留。 | 重排不得覆盖受保护任务时间、工作站和反馈上下文。 |
| 错误显性化 | 缺配置、缺资源、缺归属、超量报工必须可见。 | 后端返回明确错误，前端页面或导入行级结果必须展示原因。 |

## 阶段入口门禁

进入任一阶段前必须完成以下检查：

1. 当前任务文档已建立，记录 BDD、RED、GREEN、REGRESSION 证据模板。
2. 读取并确认 `mes-scheduling-domain-contracts.md` 中的排产域词典、身份优先级、身份口径判定矩阵。
3. 明确本阶段是否涉及后端、前端、数据库、真实 E2E、发布链路；未授权范围不得顺手扩大。
4. 检查混合工作区，确认本阶段目标文件与其他任务脏改无文件级或 hunk 级冲突。
5. 准备阶段回退方式：代码可回退、测试可证明回退后业务仍成立、文档记录本阶段未完成项。

## 阶段 1：身份 Key 固化

### 改写目标

- 引入清晰命名的身份对象或 Key 构造出口，例如 `RouteProcessIdentity`、`ScheduleOrderProcessIdentity`、`TaskAttributionIdentity`。
- 将散落的字符串拼接、Map Key 拼接和隐式组合键收敛到可读、可测的身份口径。
- 保持业务行为不变，只降低理解成本和误用概率。

### 禁止变更

- 禁止改变查询结果、分组粒度、排序和页面展示数据。
- 禁止把 `processId` 升级成路线工序身份。
- 禁止在同一阶段顺手改排产算法、日历产能、报工归属或前端交互。

### 主要风险

- 将 `processId` 能力匹配误替换成 `routeProcessId`，导致工作站能力匹配失败。
- 将 `routeVersionId + routeProcessId` 与 `scheduleOrderId + routeProcessId` 混成同一个 Key。
- 改 Map Key 后影响受保护任务、在制统计或路线配置唯一性。

### BDD 场景

BDD: 路线工序身份保持隔离 -> Given 同一个 `processId` 存在于两条路线, When 工作台统计和路线排产配置保存, Then 系统按 `routeVersionId + routeProcessId` 分行和保存，不跨路线合并。

BDD: 排产工单快照身份保持稳定 -> Given 排产工单存在历史快照工序且当前路线已漂移, When 执行重排预览, Then 系统按 `scheduleOrderId + routeProcessId` 纳入仍有剩余量的快照工序。

### RED

- 新增身份 Key 单元或静态契约测试，先断言散落 Key 使用点必须通过统一构造出口。
- 新增跨路线同基础工序测试，先证明直接使用 `processId` 合并会失败。

### GREEN

- 最小实现身份对象或 Key 构造方法。
- 替换最小高风险路径：路线配置、工作台在制、重排快照、报工归属校验。
- 保持现有排产结果和统计结果不变。

### REGRESSION

- 跑排产域契约测试。
- 跑身份 Key 目标单测。
- 对比改写前后同一真实样本的预览工序数、工序顺序、资源池 Key、受保护任务数。

### 停止条件

- 无法判断某个 Key 的业务主身份。
- 发现同一字段在不同路径语义冲突且缺业务确认。
- 改写后排产预览、在制统计或报工归属结果不一致。

### 回退策略

- 回退本阶段身份对象替换。
- 保留新增测试和文档问题记录。
- 将冲突 Key 追加到身份口径判定矩阵后再重新进入阶段 1。

### 验收通过口径

- 所有新增身份对象测试通过。
- 高风险路径不再出现未命名的字符串 Key 拼接。
- `routeProcessId` 与 `processId` 的使用边界在代码命名中可直接识别。

## 阶段 2：自动排产服务拆分

### 改写目标

- 将 `MesProAutoScheduleServiceImpl` 的大服务拆成职责清晰的内部协作组件。
- 推荐边界：`ScheduleScopeResolver`、`ScheduleTopologyResolver`、`ScheduleResourcePoolBuilder`、`ScheduleCalendarWindowPlanner`、`ScheduleTaskAllocator`、`ScheduleApplyWriter`、`ReplanExplanationBuilder`。
- 拆分只移动逻辑和命名边界，不改变算法结果。

### 禁止变更

- 禁止同时调整排序算法、资源分配策略、日历窗口选择或任务切段规则。
- 禁止删除 preflight、preview、apply、replanPreview、replanApply 任一路径的现有校验。
- 禁止把应用前重算改成复用旧预览。

### 主要风险

- 拆分时漏传 `calendarContextToken` 或 issue severity。
- 拆分拓扑时破坏 `predecessorRouteProcessId` 和 `dependencyAvailableFrom`。
- 拆分应用写入时丢失 FS link、保护任务、任务扩展或重排说明。

### BDD 场景

BDD: 拆分后排产预览结果一致 -> Given 同一组待排产工单、路线快照、资源池和日历产能, When 使用拆分后的服务执行预览, Then 任务数量、开始结束时间、前置依赖、issue 列表与拆分前一致。

BDD: 应用重排仍必须重新计算 -> Given 用户拿到一次预览结果后日历规则发生变化, When 用户执行应用重排, Then 系统必须校验 `calendarContextToken` 并重新计算，不能沿用旧预览。

### RED

- 新增服务拆分一致性测试，先用当前服务输出作为合同快照。
- 新增应用前重算测试，断言缺 token 或 token 漂移必须失败。

### GREEN

- 逐组件抽取，只移动一个职责后跑目标测试。
- 每次抽取保持公共入口、请求 VO、响应 VO 和异常口径不变。
- 抽取完成后再整理私有方法命名。

### REGRESSION

- 跑自动排产目标测试。
- 跑排产域契约测试。
- 用真实样本只读对比预览 JSON 的任务数、依赖数、BLOCKING issue、受保护任务数。

### 停止条件

- 拆分后任一预览样本结果不一致且无法解释为已批准业务变更。
- 应用前重算、token 校验或阻断 issue 校验缺失。
- 拆分后组件之间出现循环依赖或共享可变状态导致结果不稳定。

### 回退策略

- 回退最近一次组件抽取，保留已通过的更小组件。
- 若无法局部回退，回退阶段 2 全部生产代码，仅保留一致性测试。

### 验收通过口径

- 拆分后的组件职责边界可读。
- 预览、应用、重排预览、重排应用核心结果与拆分前一致。
- 新组件均有对应测试或被服务级合同测试覆盖。

## 阶段 3：默认值与历史兼容治理

### 改写目标

- 清点 `10.5h`、默认排产配置 warning、默认资源快照 warning、`TenantUtils.executeIgnore`、`catch ignored` 等历史口径。
- 将默认值分成正式业务默认、历史兼容读取、必须失败三类。
- 把历史兼容隔离到命名清晰的边界，避免继续扩散。

### 禁止变更

- 禁止把缺配置、缺路线、缺日历、缺产能变成默认成功。
- 禁止删除仍被历史快照依赖的兼容读取。
- 禁止在未确认业务规则前修改班时、夜班、默认资源或默认配置 warning 口径。

### 主要风险

- 把历史兼容当成新业务默认，继续制造隐性错误。
- 删除旧快照兼容后，存量排产工单无法重排或查看。
- 把 warning 改成 blocking 或 blocking 改成 warning，导致业务节奏变化。

### BDD 场景

BDD: 缺正式配置时显式失败 -> Given 新建排产工单缺少必须的路线排产配置, When 执行自动排产预览, Then 系统返回明确配置缺失 issue，不能用默认成功掩盖。

BDD: 历史快照仍可只读展示 -> Given 存量排产工单带有旧快照字段, When 用户查看详情或执行允许的历史读取, Then 系统在兼容边界内展示历史事实，不把缺失伪装成新配置。

### RED

- 新增默认值分类静态测试，断言每个历史默认必须有命名边界。
- 新增缺配置失败测试，先证明缺正式前置不能成功。

### GREEN

- 为每个默认值补命名方法、注释或配置来源。
- 将历史兼容读取集中到少数方法。
- 对写入、预览、应用、报工归属路径保持 fail fast。

### REGRESSION

- 跑排产域契约测试。
- 跑涉及默认配置、日历规则、容量计划的目标测试。
- 只读核对存量历史排产工单仍可查看。

### 停止条件

- 无法判断某默认值是业务规则还是历史兼容。
- 改动会导致存量历史快照不可读取。
- 缺前置场景被测试发现仍返回成功。

### 回退策略

- 回退默认值行为变更，保留分类文档和失败测试。
- 将未确认默认值登记为业务确认 blocker。

### 验收通过口径

- 所有默认值都有分类：业务默认、历史兼容、必须失败。
- 写入和计算路径不再新增隐式 fallback。
- 历史兼容边界清晰且有测试保护。

## 阶段 4：报工联动治理

### 改写目标

- 固化报工归属链：`taskId -> scheduleOrderProcessId -> scheduleOrderId -> workOrderId`。
- 治理导入报工、手动归属、正式报工、进度同步、剩余量、重排保护之间的联动。
- 让正向、超量负向、缺任务、缺审批人、重复指纹等错误都可见且可追。

### 禁止变更

- 禁止只凭产品号、工序名或 Excel 行文本归属报工。
- 禁止用接口直调代替真实前端导入路径作为最终验收。
- 禁止把报工保护通过等同于剩余量算法正确。

### 主要风险

- 报工记录归属到错误生产工单或排产工序。
- 进度同步把完成、取消或不可归属工单继续统计为有效排产。
- 重排只保护已报工任务，但生成任务数量仍按旧总量口径，造成剩余量偏差。

### BDD 场景

BDD: 第三方报工正向归属 -> Given Excel 行能唯一定位真实任务、排产工序、排产工单和生产工单, When 用户通过生产报工页面上传并手动归属, Then 系统生成正式报工、更新排产工序进度，并记录任务保护事实。

BDD: 超量报工必须失败可见 -> Given Excel 行报工数量大于排产工序剩余数量, When 用户确认归属, Then 系统拒绝归属，导入记录保持待处理，页面显示明确错误，不能生成正式报工。

### RED

- 新增报工链路归属测试，先断言缺任务扩展链不能归属。
- 新增超量负向测试，先断言超剩余量不能生成正式报工。

### GREEN

- 收敛报工归属链查询和校验出口。
- 明确进度同步与剩余量更新边界。
- 保留行级错误和页面可见错误。

### REGRESSION

- 跑报工导入与归属目标测试。
- 跑排产重排保护目标测试。
- 必要时跑真实 E2E：第三方报工导入 -> 手动归属 -> 正式报工 -> 进度回写 -> 重排保护。

### 停止条件

- 当前库没有可归属真实任务样本且用户未授权创建测试租户样本。
- 任务扩展链缺失，无法证明归属对象。
- 正向归属成功但进度、正式报工或重排保护任一环节不一致。

### 回退策略

- 回退报工归属生产代码，保留新增负向测试和样本构造脚本。
- 将无法验证的真实 E2E 标记为 blocker，不用 mock 或接口绕过。

### 验收通过口径

- 正向和超量负向均被测试覆盖。
- 报工链路、进度回写、正式业务单、重排保护都有证据。
- 页面能暴露后端真实错误。

## 阶段 5：前端页面拆分

### 改写目标

- 拆分 `scheduleorder/index.vue` 和 `scheduler-workbench/index.vue` 的大页面。
- 推荐边界：列表、预检、重排弹窗、工序详情、报工历史、导出配置、工作台在制表。
- 保持接口、权限、菜单、分页、排序、筛选、按钮行为不变。

### 禁止变更

- 禁止在页面拆分时顺手改后端接口语义。
- 禁止隐藏后端错误、吞 toast、空 catch 或用前端默认值补后端缺字段。
- 禁止为 E2E 增加临时控件或测试专用入口。

### 主要风险

- 拆分组件后查询条件、分页、行 key、展开行或弹窗状态丢失。
- 错误提示被子组件吞掉，用户只看到无反馈。
- 权限按钮、动态菜单、导出列或详情统计与原页面不一致。

### BDD 场景

BDD: 排产工单页面拆分后行为保持 -> Given 用户拥有排产工单查询、预检、重排和详情权限, When 用户在拆分后的页面执行列表查询、打开工序详情、触发预检和重排预览, Then 数据、按钮可见性、错误提示和弹窗结果与拆分前一致。

BDD: 工作台在制表拆分后身份不漂 -> Given 同一基础工序存在于多条路线, When 用户查看工作台在制统计, Then 页面仍按 `routeVersionId + routeProcessId` 分行，不按 `processId` 合并。

### RED

- 新增前端静态契约测试，断言拆分组件保留目标 API、权限、table key、行 key 和错误处理。
- 新增或复用真实 E2E 脚本，先锁定现有用户路径。

### GREEN

- 每次只抽一个子组件。
- 抽取后立即跑类型检查、静态契约和目标页面测试。
- 保持原页面 props、emit、API 参数和权限判断口径。

### REGRESSION

- 跑前端类型检查。
- 跑目标静态契约测试。
- 必要时跑真实 E2E：登录测试租户 -> 打开智能排产 -> 排产工单/工作台 -> 预检/重排/详情/报工历史。

### 停止条件

- 页面缺真实入口、菜单权限不完整或测试租户无法访问。
- 拆分后真实页面出现 404、按钮无反馈、接口错误不可见。
- 组件抽取导致分页、筛选、权限或弹窗状态与原页面不一致。

### 回退策略

- 回退最近一个组件抽取。
- 保留测试和拆分边界文档。
- 待确认组件状态契约后再继续。

### 验收通过口径

- 页面行为与拆分前一致。
- 类型检查和目标契约测试通过。
- 真实 E2E 覆盖的用户路径可操作，错误可见。

## 阶段验收总矩阵

| 阶段 | 主交付 | 必跑测试 | 真实 E2E 要求 | 验收结论 |
| --- | --- | --- | --- | --- |
| 阶段 1 | 身份 Key 对象化和统一构造出口 | 身份 Key 单测、排产域契约测试 | 通常不需要；若影响工作台或重排显示则补真实只读路径 | 身份不漂、结果不变 |
| 阶段 2 | 自动排产服务拆分 | 自动排产合同测试、应用前重算测试、排产域契约测试 | 对高风险重排应用路径执行真实页面预览/应用前置验证 | 算法结果不变、链路更清晰 |
| 阶段 3 | 默认值和历史兼容隔离 | 默认值分类测试、缺前置失败测试、历史快照读取测试 | 只读核存量历史记录；不造 mock | 默认有归属、缺前置失败 |
| 阶段 4 | 报工联动链路治理 | 报工归属测试、超量负向测试、进度同步测试 | 必须覆盖真实导入归属闭环 | 报工可追、错误可见 |
| 阶段 5 | 前端页面拆分 | 类型检查、静态契约测试、目标页面测试 | 必须覆盖关键用户路径 | 页面行为不变、组件边界清晰 |

## 停止条件

任一阶段出现以下情况必须停止：

- 身份口径无法判断或与 `mes-scheduling-domain-contracts.md` 冲突。
- 真实样本无法证明业务结果与改写前一致。
- 缺路线、缺快照、缺日历、缺产能、缺任务扩展或缺报工链路。
- 测试失败原因不是当前阶段可解释的预期 RED。
- 混合工作区存在同文件或同 hunk 冲突，无法隔离本阶段改动。
- 用户未授权的数据库、服务器、发布链路或真实写入前置被触发。

## 回退策略

- 每阶段单独提交或至少保持可隔离 diff；不得把 1~5 混成一个不可回退改动。
- 优先局部回退最近一次职责抽取、组件抽取或 Key 替换。
- 回退后必须重跑本阶段已通过测试，证明恢复到可用业务状态。
- 回退不删除失败测试和 blocker 记录；失败测试用于证明下一轮重新进入的原因。
- 如果业务口径本身不清，回退代码并把问题补充到排产域契约或本控制方案。

## 执行记录要求

每个阶段任务目录必须记录：

- BDD: 至少一个正向场景和一个失败/边界场景。
- RED: 失败命令、失败原因、为何是预期失败。
- GREEN: 通过命令、覆盖范围。
- REGRESSION: 回归命令、真实数据或真实页面证据。
- Blocker: 缺前置、口径冲突、无法验证或环境问题。
- Closeout: 任务状态、保留证据、是否进入下一阶段。
