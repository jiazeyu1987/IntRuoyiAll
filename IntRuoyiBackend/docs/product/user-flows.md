# User Flows: IntRuoyi 自动排产

## Purpose and Scope

本文定义 IntRuoyi 自动排产第一版本的用户流程。流程遵循当前系统优先原则：用户在现有生产排产入口操作，系统复用当前 MES 数据，只维护一个当前有效排产结果。

## Primary User Flows

### Flow 1: 自动生成并应用当前排产

1. 生产计划员进入生产排产页面。
2. 用户选择排产范围、开始日期、产能模式和重排策略。
3. 用户点击自动排产。
4. 系统校验工单、路线、BOM、库存、产能、日历和权限。
5. 系统生成排产结果摘要，展示任务数量、影响工单、预计开始/结束、缺料风险和冲突数量。
6. 用户确认应用。
7. 系统写入当前生产任务并同步工单 `quantityScheduled`。
8. 页面刷新 Gantt，展示任务、工序依赖线和风险标记。

### Flow 2: 查看缺料风险

1. 用户在排产结果或 Gantt 中看到缺料风险标记。
2. 用户打开缺料明细。
3. 系统展示缺料物料、缺口数量、影响工单、影响工序、预计影响日期。
4. 用户根据缺料信息协调库存或调整排产参数。

### Flow 3: 重排当前任务

1. 用户进入生产排产页面并选择重排范围。
2. 用户选择是否保留锁定任务、手工任务和已开始任务。
3. 用户点击重排。
4. 系统校验重排范围和保护规则。
5. 系统展示重排影响摘要。
6. 用户确认应用。
7. 系统更新允许变更的生产任务，保留不可覆盖任务，并同步 `quantityScheduled`。

### Flow 4: 处理冲突

1. 用户发起自动排产或重排。
2. 系统发现阻塞性冲突。
3. 系统停止应用并展示冲突列表。
4. 用户打开冲突详情，查看原因和定位对象。
5. 用户修正基础数据、库存、产能或排产范围后重新发起排产。

## Alternate Flows

### Alternate Flow 1: 仅预览不应用

1. 用户发起自动排产。
2. 系统返回非持久化预览结果。
3. 用户关闭预览。
4. 系统不写入生产任务，不改变 `quantityScheduled`。

### Alternate Flow 2: 有缺料但允许风险排产

1. 系统发现缺料但规则允许风险排产。
2. 系统展示风险排产提示。
3. 用户确认应用。
4. 系统写入生产任务，并在结果中保留缺料风险标记。

### Alternate Flow 3: 用户无应用权限

1. 用户可以查看排产页面。
2. 用户尝试应用自动排产。
3. 系统拒绝操作并提示权限不足。
4. 当前生产任务不变化。

## Error Flows

### Error Flow 1: 缺少工艺路线

1. 用户发起自动排产。
2. 系统发现工单缺少可用工艺路线。
3. 系统失败并提示具体工单。
4. 当前生产任务不变化。

### Error Flow 2: 缺少产能数据

1. 用户选择计划产能或实际产能模式。
2. 系统发现排产日期、班次、工序或资源缺少必需产能数据。
3. 系统失败并提示缺失维度。
4. 当前生产任务不变化。

### Error Flow 3: 重排范围包含已完工任务

1. 用户选择重排范围。
2. 系统发现范围内存在已完工任务。
3. 系统保留已完工任务，并提示不可覆盖。
4. 如果剩余任务可重排，用户可继续确认；否则系统失败。

### Error Flow 4: 已排产数量超出工单数量

1. 系统准备应用排产结果。
2. 系统发现写入后 `quantityScheduled` 会超过工单数量。
3. 系统失败并提示对应工单和数量差异。
4. 当前生产任务不变化。

## Out-of-Scope Flows

- 保存排产草稿。
- 查看排产版本列表。
- 对比多个排产版本。
- 加载历史快照。
- 发布某个排产版本。
- 使用 IntPP 表结构直接替换 IntRuoyi 工单、任务、路线、BOM、库存或资源模型。

## Open Questions

- 自动排产是否默认先展示非持久化预览，再由用户确认应用？
- 缺料风险是否允许普通计划员确认应用，还是需要主管权限？
- 重排影响摘要需要展示到任务级、工单级，还是工序级？
- 手工任务锁定入口放在 Gantt 上还是任务详情中？
