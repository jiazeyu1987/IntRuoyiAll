# User Flows: DCC 截图需求分析草稿

## Purpose and Scope

本文记录用户提供的 DCC 截图需求所对应的用户流程草稿。范围仅限截图可见需求，用于后续系统设计、BDD/TDD 计划和前后端实现拆分。

## Primary User Flows

### Flow 1: 文件受控审批提交

1. 申请人进入文件受控审批表单。
2. 申请人上传可编辑源文件。
3. 若源文件为图纸类文件，申请人上传 PDF 伴随文件。
4. 申请人填写文件类别、确认现行有效版本、录入 14 位产品编号。
5. 申请人选择是否需要培训。
6. 申请人提交审批流程。
7. 若需要培训，流程在第四节点前要求申请人上传培训记录。
8. 文控在第四节点上传加盖受控章后的 PDF。
9. 流程继续后续审批、会签、导出或打印。

### Flow 2: 流程回退至申请人并重提

1. 节点负责人在待办中选择回退。
2. 节点负责人选择回退至申请人。
3. 系统将流程放入申请人待办，并显示 `有流程回退，需处理`。
4. 申请人处理退回意见。
5. 申请人提交原流程。
6. 原流程继续推进，不创建新流程。

### Flow 3: 节点转交和加签

1. 节点负责人进入当前处理节点。
2. 节点负责人选择转交或加签。
3. 系统按权限校验可选人员。
4. 节点负责人确认后，流程参与人更新。

### Flow 4: 文档下载

1. 用户点击下载文档。
2. 系统提示下载后文件为非受控文件。
3. 用户确认下载。
4. 系统记录下载人 id 和下载时间。
5. 文件下载完成。

### Flow 5: 纸质发放回收记录

1. 文控进入纸质发放回收记录。
2. 文控录入文件编号、版本、名称、发放人、接收人、发放日期、回收人、回收日期。
3. 用户按权限导出或打印记录。
4. 输出包含全部必需字段。

## Alternate Flows

- 申请人主动撤回流程后选择删除流程。
- 申请人主动撤回流程后选择重新提交。
- 申请人在会签节点自行选择会签人员。
- 电子发放回收中，接收人对发放任务进行加签。
- 编码符合 `INT/RE` 规则的体系记录由任意用户下载。

## Error Flows

- 图纸类文件缺少 PDF 伴随文件，提交失败。
- 需要培训但培训记录缺失，流程不得进入第四节点受控上传。
- 第四节点缺少加盖受控章后的 PDF，节点不得完成。
- 下载留痕写入失败时，下载不得静默成功。
- 密码不满足 8 位、英文和数字组合要求时，保存失败。
- Word 模板缺少必需占位符时，导出或打印失败并提示。

## Out-of-Scope Flows

- 外来文件评审完整流程，需业务补充字段、节点、参与人和结论。
- 14 位产品编号外部系统校验流程，需确认系统边界和接口。
- 密码定期强制更新的上线迁移流程，需确认周期和历史账号规则。

## Open Questions

1. 文件受控审批当前菜单入口和流程定义在哪里？
2. 第四节点在当前流程配置中是否固定，还是按文件类别变化？
3. 回退、转交、加签是否有角色、节点或文件类别限制？
4. 下载提示是否需要二次确认，还是 toast/弹窗提示即可？
5. 导出和打印是否需要套用公司模板？
