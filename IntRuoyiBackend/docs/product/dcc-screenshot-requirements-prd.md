# PRD: DCC 截图需求分析草稿

## Purpose and Scope

本文将用户提供的 DCC 需求截图整理为 IntRuoyi 后续开发可复用的产品需求草稿。范围仅限截图中可见的 14 条需求，不补充未确认业务规则，不覆盖仓库中既有的自动排产产品文档。

## Evidence Reviewed

- 用户提供的 DCC 需求截图。
- 截图列：`优先级`、`需求模块`、`需求内容`。
- 后端任务分析：`doc/tasks/20260525-dcc-requirements-analysis/requirements-analysis.md`。
- 优先级原样保留为 `H`、`I`、`L`，实际含义和排期规则待业务确认。

## Product Summary

DCC 需要围绕文件受控审批、流程回退/转交/加签、培训记录、受控章 PDF、下载提醒与留痕、电子/纸质发放回收、账户密码策略、文件视图状态和外来文件评审进行增强。高优先级需求主要集中在文件受控审批主流程和流程动作权限上。

## Target Users

- 申请人：发起文件受控审批，处理退回流程，选择会签节点人员，上传培训记录。
- 文控：处理受控文件、上传加盖受控章后的 PDF，选择电子发放接收人，维护发放回收记录。
- 节点负责人：在流程节点中执行回退、转交和加签。
- 接收人：接收电子发放回收任务，并在允许时加签。
- 普通用户：下载文档或体系记录，查看文件状态。
- 系统管理员：配置账号密码策略、权限和可能的打印模板。

## First Version Scope

- 文件受控审批上传规则：可编辑源文件和图纸类 PDF 伴随上传。
- 文件受控审批新增字段：文件类别、现行有效版本、14 位产品编号。
- 下载非受控文件提醒和下载留痕。
- 编码前六位识别为 `INT/RE` 的体系记录支持所有人下载。
- 纸质发放回收记录及导出、打印。
- 第四节点文控上传加盖受控章后的 PDF。
- 回退至申请人后的待办提醒和原流程重提。

## Non-Goals

- 不在需求未确认前实现外来文件评审完整流程。
- 不猜测密码强制更新周期、历史账号处理方式或密码历史规则。
- 不猜测文件受控审批第四节点名称和角色绑定。
- 不实现缺少文件、缺少节点、缺少审计记录时的 fallback 成功路径。
- 不覆盖现有自动排产产品文档。

## Functional Requirements

1. 文件受控审批应要求申请人上传可编辑源文件，支持截图列出的 `doc`、`docx`、`xls`、`xlsx`、`dwg`、`sldprt`、`sldasm`、`slddrw` 等类型。
2. 当源文件为图纸类文件 `dwg`、`sldprt`、`sldasm`、`slddrw` 时，应同时要求上传 PDF 格式文件。
3. 文件受控审批表单应增加文件类别字段，候选值至少包含体系文件、技术文件-DHF、技术文件-DMR。
4. 文件受控审批表单应显示或读取现行有效版本。
5. 文件受控审批表单应记录统一 14 位产品编号，作为后续其他系统接口信息。
6. 节点负责人应在权限允许时具备回退、转交、加签能力。
7. 回退目标应支持前一节点处理人或申请人。
8. 流程回退至申请人后，应进入申请人待办，并显示 `有流程回退，需处理`。
9. 申请人处理退回流程后，应对原流程再次提交，不重新发起流程。
10. 申请人主动撤回流程后，应可选择删除流程或重新提交。
11. 当表单选择 `是否需要培训` 时，文件受控审批流程应在第四个节点受控上传签核版本文件前要求申请人上传培训记录。
12. 第四节点应由文控上传加盖受控章后的 PDF 格式文件。
13. 文件受控审批流程应支持导出与打印。
14. 打印模板可考虑支持上传 Word 模板配置，具体占位符待确认。
15. 会签节点应可由申请人自行选择。
16. 下载文档前应提示下载后文件为非受控文件。
17. 下载成功后应记录下载人 id 和下载时间。
18. 体系记录应支持所有人下载，识别规则以编码前六位 `INT/RE` 为基础，完整格式待确认。
19. 文件电子发放回收中，文控选择接收人后，接收人应可进行加签。
20. 纸质发放回收记录应包含文件编号、版本、名称、发放人、接收人、发放日期、回收人、回收日期。
21. 纸质发放回收记录应支持导出和打印。
22. 账户密码强度应至少满足 8 位，并由英文和数字组成。
23. 账户应定期强制更新密码，周期待确认。
24. 文件视图应显示 `修改中` 标识。
25. 系统应支持外来文件评审流程，完整流程待补充。

## Business Rules

- 缺少必需源文件、图纸类 PDF 伴随文件、培训记录或第四节点受控章 PDF 时，应失败并提示具体缺失项。
- 下载成功时必须生成下载留痕，不允许静默跳过。
- 退回至申请人的流程重提必须沿用原流程实例。
- 体系记录是否可被所有人下载必须基于确认后的编码规则，不得只凭模糊匹配放开权限。
- 密码策略配置缺失时不得静默使用默认成功策略。

## States and Transitions

- 文件受控审批草稿 -> 已提交：必填文件和字段完成后提交。
- 已提交 -> 退回前一节点处理人：节点负责人选择退回前一节点。
- 已提交 -> 退回申请人：节点负责人选择直接退回申请人。
- 退回申请人 -> 申请人待处理：待办显示 `有流程回退，需处理`。
- 申请人待处理 -> 原流程再次提交：申请人处理后继续原流程。
- 申请人主动撤回 -> 删除流程或重新提交：申请人选择后续动作。
- 需要培训 -> 培训记录待上传：第四节点前要求上传培训记录。
- 第四节点待处理 -> 第四节点完成：文控上传加盖受控章后的 PDF 后完成。
- 文件修改中 -> 视图展示：文件处于修改状态时展示 `修改中`。

## Edge Cases

- 一个审批包含多个图纸文件时，PDF 伴随文件是逐文件要求还是审批包级要求待确认。
- 历史文件可能缺少文件类别、现行有效版本或产品编号。
- 原节点处理人、申请人或接收人离职/禁用时，流程动作规则待确认。
- 接收人加签可能产生重复参与人或循环节点，需要权限和去重规则。
- Word 模板缺少必需占位符时应失败并提示。
- 历史账号密码不满足新规则时的上线处理待确认。

## Acceptance Criteria

- Given 申请人上传图纸类源文件，When 未上传 PDF 伴随文件并提交，Then 系统拒绝提交并提示缺少 PDF。
- Given 流程被退回至申请人，When 申请人打开待办，Then 可看到 `有流程回退，需处理`。
- Given 申请人处理退回流程，When 再次提交，Then 原流程继续推进且不产生新流程。
- Given 表单选择需要培训，When 流程到达第四节点前，Then 申请人必须上传培训记录。
- Given 文控处理第四节点，When 未上传加盖受控章后的 PDF，Then 节点不可完成。
- Given 用户下载文档，When 下载成功，Then 系统已提示非受控文件并记录下载人 id 和下载时间。
- Given 纸质发放回收记录存在，When 用户导出或打印，Then 输出包含截图要求的全部字段。
- Given 用户设置密码，When 密码少于 8 位或未同时包含英文和数字，Then 系统拒绝保存。

## Open Questions

1. `H`、`I`、`L` 的实际优先级含义和排期规则是什么？
2. 当前系统中哪个流程是 `文件受控审批流程`，第四节点名称和责任角色是什么？
3. `申请人`、`文控`、`节点负责人`、`接收人`、`会签节点` 的角色和权限映射是什么？
4. 图纸类 PDF 是每个图纸文件各传一份，还是每个审批包传一份？
5. `文件类别` 是否只有截图中的三类，历史数据是否需要补齐？
6. `现行有效版本` 从哪个业务对象读取？
7. 14 位产品编号由哪个系统维护，DCC 是否需要本地校验或调用外部接口？
8. 退回提醒通过待办、站内信、邮件、钉钉还是多渠道发送？
9. 密码强制更新周期、历史账号处理、密码历史和锁定规则是什么？
10. `INT/RE` 编码前六位识别规则的完整格式是什么？
11. 流程导出、发放记录导出的目标格式是什么？
12. Word 模板占位符、模板权限和模板版本规则是什么？
13. 外来文件评审流程的字段、节点、参与人、结论和输出物是什么？

## Product Blockers

- 文件受控审批实现前必须确认当前流程和第四节点。
- 密码定期强制更新实现前必须确认周期和历史账号处理规则。
- 外来文件评审流程信息不足，需单独补充需求。
