# PRD: IntRuoyi 自动排产

## Purpose and Scope

本 PRD 定义在 IntRuoyi MES 中实现自动排产的产品需求。目标是最大化复用当前 IntRuoyi 的工单、工艺路线、BOM、库存、资源、日历和生产任务体系，将 IntPP 的自动排产能力作为调度逻辑适配到当前系统。

第一版本只保留一个当前有效排产结果。自动排产结果写回 IntRuoyi 生产任务，不引入 IntPP 的排产草稿、排产版本、快照、版本对比、加载历史版本等体系。

## Product Summary

生产计划员在当前生产排产页面选择待排工单和排产参数后，系统基于现有工单、路线、BOM、库存、工作站、日历和产能数据生成当前有效排产任务。系统需要在生成或重排前检查产能、物料、路线、日历和数量约束；有阻塞性问题时失败并说明原因；有物料风险但允许排产时标记风险并展示明细。排产应用成功后，当前生产任务和工单已排产数量保持一致。

## Target Users

- 生产计划员：发起自动排产、查看排产结果、处理缺料和冲突、执行重排。
- 生产主管：确认排产结果是否可执行，关注产能、缺料和延期风险。
- 仓储/物料人员：根据缺料提示处理备料或库存调整。
- 工艺/制造工程人员：维护路线、工序、工作站和标准产能相关数据。
- 系统管理员：维护权限、菜单和基础配置。

## First Version Scope

- 在现有生产排产入口增加自动排产能力。
- 使用当前 IntRuoyi 工单作为排产对象。
- 使用当前 IntRuoyi 生产任务作为唯一有效排产结果。
- 复用当前工艺路线、工序、BOM、库存、工作站、人员、设备、日历等基础数据。
- 新增排产适配层，把 IntRuoyi 数据转换成排产引擎可计算的数据。
- 新增产能模型，支持日期、班次、工序、工作站或产线维度的计划产能和必要的实际产能。
- 新增物料齐套和缺料判断。
- 新增工序依赖解析，供排产引擎和 Gantt 依赖线使用。
- 移植或改造 IntPP 自动排产逻辑，使其读取和写回 IntRuoyi 数据。
- 支持当前任务重排，并保护已锁定、已手工确认、已完工或不可覆盖的任务。
- 支持冲突检测和失败提示。
- 自动排产、应用、重排、查看缺料和冲突的 API。
- 前端支持自动排产、产能模式、缺料/冲突查看、重排和 Gantt 依赖展示。
- 排产结果应用后同步工单 `quantityScheduled`。
- 后端单测、API 测试、前端真实数据 E2E。

## Non-Goals

- 不迁移 IntPP 的排产版本表、草稿表、快照表。
- 不提供多版本排产对比。
- 不提供加载历史排产版本。
- 不要求 IntRuoyi 的工单、任务、路线、BOM、库存、资源或日历模型改造成 IntPP 命名和表结构。
- 第一版本不做跨工厂、多组织、多租户全局优化规则扩展，除非当前系统已有明确数据口径。
- 第一版本不使用 mock 数据完成验收。

## Functional Requirements

### FR1 自动排产入口

生产计划员可以在生产排产页面发起自动排产。系统应允许用户选择排产范围、开始日期、产能模式和重排策略。

### FR2 当前系统数据复用

系统必须以 IntRuoyi 现有工单、工艺路线、BOM、库存、工作站、日历和生产任务为主数据来源。缺少必要数据时，系统必须失败并提示具体缺失项。

### FR3 单版本当前排产

系统只保留一个当前有效排产结果。自动排产应用成功后，结果写入当前生产任务；旧的可替换任务按重排策略更新或删除，不生成持久化草稿、版本或快照。

### FR4 产能约束

系统应按日期、班次、工序和资源维度计算可用产能。排产不得静默超过硬性产能约束。选择实际产能模式时，如果缺少必需的实际产能数据，系统必须失败。

### FR5 物料齐套与缺料风险

系统应根据 BOM 和库存判断物料是否满足排产需要。阻塞性缺料必须阻止应用排产；允许带风险排产的缺料必须标记风险并展示缺料物料、缺口数量、影响工单和影响工序。

### FR6 工序依赖

系统应从当前工艺路线解析工序前后关系。排产结果必须遵守工序依赖，Gantt 应展示任务依赖线。

### FR7 重排保护

系统重排时不得覆盖已完工任务。对锁定任务、手工调整任务和已开始任务，系统必须按用户选择的重排策略处理，并在应用前说明影响范围。

### FR8 冲突检测

系统必须检查超产能、重复占用、缺路线、缺工序、缺 BOM、缺库存、无效日历、超工单数量、无可用工作站等问题，并给出可操作错误信息。

### FR9 数量同步

自动排产应用、手工修改、删除和重排后，系统必须同步更新工单 `quantityScheduled`，并防止已排产数量超过工单数量。

### FR10 权限控制

自动排产、应用排产、重排、查看缺料/冲突应受权限控制。无权限用户不能执行对应动作。

### FR11 可观测结果

排产完成后，用户应能在当前页面看到任务时间、工作站、工序、数量、依赖、缺料风险、冲突状态和排产结果摘要。

## Business Rules

- IntRuoyi 是数据主系统；IntPP 排产逻辑必须通过适配层读取和写回 IntRuoyi 数据。
- 当前有效排产结果以 IntRuoyi 生产任务为准。
- 缺少必要前置数据必须失败，不允许静默降级或默认成功。
- 已完工任务不可被自动排产覆盖。
- 已排产数量不能超过工单数量。
- 生产任务的工序顺序必须遵守工艺路线。
- 产能模式必须显式选择或使用系统配置的默认值。
- 实际产能模式缺少实际产能数据时必须失败。
- 缺料处理规则必须明确区分“阻塞排产”和“允许风险排产”。
- 所有自动生成或重排导致的任务变化必须可被用户识别。

## States and Transitions

- 未排产工单 -> 自动排产应用成功 -> 已排产工单。
- 已排产工单 -> 重排应用成功 -> 已更新排产工单。
- 已排产工单 -> 任务删除或数量减少 -> 部分排产或未排产。
- 自动排产请求 -> 校验失败 -> 未改变当前任务。
- 自动排产请求 -> 有风险但允许应用 -> 风险排产结果。
- 自动排产请求 -> 应用成功 -> 当前生产任务更新。
- 生产任务 -> 锁定 -> 重排时保留或提示不可覆盖。
- 生产任务 -> 已完工 -> 重排时必须保留。

## Edge Cases

- 工单没有工艺路线。
- 工艺路线存在循环或缺少工序。
- 工序没有可用工作站。
- 工作站日历不可用或当天无班次。
- 计划产能为 0。
- 实际产能模式缺少实际产能。
- BOM 缺失或 BOM 中存在循环。
- 库存数量不足、冻结库存不可用、单位换算缺失。
- 多个工单争用同一工作站同一班次。
- 已有手工任务与自动排产结果冲突。
- 重排范围包含已完工任务。
- 工单数量小于已排产数量。
- 用户无自动排产或重排权限。

## Acceptance Criteria

- 用户可以从当前生产排产页面发起自动排产并看到结果摘要。
- 系统只写入当前生产任务，不生成持久化排产版本、草稿或快照。
- 缺少路线、BOM、产能、日历或库存必要数据时，系统失败并提示具体原因。
- 排产结果遵守工序依赖和产能约束。
- 缺料风险可见，并能定位到物料、数量、工单和工序。
- 重排不会覆盖已完工任务。
- 自动排产应用后，工单 `quantityScheduled` 与生产任务数量一致。
- Gantt 能显示自动生成任务和工序依赖线。
- 后端单测/API 测试和真实数据 Playwright E2E 覆盖主流程和失败流程。

## Open Questions

- 产能维度最终以工作站、产线，还是工序+工作站组合为准？
- 计划产能和实际产能的数据来源由谁维护？
- 缺料是否默认阻塞排产，还是允许生成风险排产？
- 手工调整任务如何标记为锁定？
- 当前任务被自动重排覆盖前是否需要二次确认？
- 是否需要保留自动排产操作审计日志？
- 物料库存口径是否包含在途、冻结、已分配和待检库存？

## Product Blockers

- 未确定产能维度和产能数据来源。
- 未确定缺料阻塞/风险排产规则。
- 未确定锁定任务和手工任务识别规则。
- 未确定库存可用量口径。
- 未确定自动排产应用时是否允许覆盖当前未开始任务。
