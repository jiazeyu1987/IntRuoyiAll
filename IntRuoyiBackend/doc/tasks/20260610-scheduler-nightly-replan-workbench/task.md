# 20260610 排产夜间重排与工作台增强

## 任务目标

在独立 worktree `codex/scheduler-replan-workbench` 中完成目标 5 + 目标 6：

- 目标 5：每天晚上自动重排，已经报工/已执行/已锁定任务不动，未开始部分可以按最新订单、资源和报工进度重排。
- 目标 6：增强排产员工作台，让排产员能看到今天能生产多少、瓶颈在哪、产能为什么变化、报工为什么与预设不同，并能按顺序跳转到现有页面处理。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。缺少排程范围、日历规则、资源配置、测试环境或真实数据时直接暴露错误。
- 是否从根因和长期维护角度解决：是。复用现有自动排程、重排保护、排产工单、任务扩展、报工归属和工作台汇总能力，仅补齐夜间触发与解释视图。
- 是否存在临时补丁或绕过：否。不新增与现有生产订单、排产工单、报工、任务、维修重复的业务主表。

## 里程碑

1. 现状审计：确认现有重排引擎、保护规则、工作台统计与菜单入口。
2. 后端夜间重排：新增定时 Job 服务入口，按排产工单池选择需要重排的范围，调用现有重排 apply，并记录可验证结果。
3. 后端工作台解释增强：扩展 summary 返回今天可生产、瓶颈建议、报工偏差、重排状态/说明等字段。
4. 前端工作台增强：在排产员页签展示快捷入口、统计卡、瓶颈/异常、重排与偏差说明，所有办理仍跳转现有页面。
5. 验证与融合：单元测试、前端静态契约、测试租户真实 E2E 通过后合并进 `int_main`。

## 预期验证

- 后端 RED/GREEN 覆盖夜间重排选择未完成排产工单，并保护已报工任务。
- 后端 RED/GREEN 覆盖工作台产能、阻塞、报工偏差、瓶颈建议字段。
- 前端 RED/GREEN 覆盖工作台固定步骤、快捷入口、夜间重排说明、偏差复盘说明。
- Playwright 使用测试租户 `aoteman` 真实登录验证工作台导航与统计展示；不修改 `芋道源码/admin` 数据。
