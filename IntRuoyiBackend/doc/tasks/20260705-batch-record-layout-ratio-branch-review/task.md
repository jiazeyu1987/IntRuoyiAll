# 批记录复杂表布局比例分支评审任务

## 任务目标

针对 `RE-PP-ID-01（A 1）球囊扩张压力泵生产记录(1).doc` 在批记录表单识别与渲染中的复杂表整体宽高比例、大合并说明区行高模型问题，创建多个隔离分支，由不同子agent采用不同通用算法思路修改，再由主agent评审哪一组改动最符合 Word 原表。

本任务只解决通用表格布局算法问题，不允许针对工序名、表格标题、字段文本、页码、文件名或单个表格写特殊判断。

## 已知问题范围

- 光固Ⅰ记录区右侧 `生产数量 /pcs`、`自检合格数量 /pcs`、`不合格数量 /pcs`、`操作人` 等列出现局部窄列线、区域压缩和比例异常。
- 组装Ⅰ、检测、光固Ⅱ、单包装、大包装等复杂合并表存在类似整体宽高比例或大合并说明区行高偏差。
- 当前算法主体已基本可用，本轮禁止通过新增可见文字、隐藏列线、裁剪、过滤空列、跳过失败表或 CSS 遮挡制造通过。

## 里程碑

1. 建立任务文档与经验门禁。
2. 创建三个隔离 worktree/分支，分别承载不同修复思路。
3. 启动多个子agent并行修改，要求各自补测试与证据。
4. 主agent review 三个分支的代码、测试结果和截图对比。
5. 选择最安全且最接近 Word 原表的通用算法方案，记录结论。

## BDD 场景

BDD: 复杂工序表保持 Word 行高比例 -> Given 真实批记录 Word 文档中的复杂工序表，When 系统识别并渲染表格，Then 大合并说明区、生产记录区和右侧统计签名区应保持与 Word 原表一致的整体宽高比例，不新增可见文字或幽灵列。

BDD: 正常对照表不被破坏 -> Given 当前已基本正确的简单表、中等复杂表和正常右侧布局表，When 应用通用行高/比例算法修改，Then 行列结构、rowSpan/colSpan、文本落位、边框和视觉比例不得退化。

BDD: 禁止特例通过 -> Given 任一工序名、表格标题、字段文本或页码变化，When 系统执行表格识别和渲染，Then 算法仍应基于 Word 原始结构、合并关系、列宽和行高推导结果工作，而不是依赖文本特征。

## 预期验证

- 后端单元/集成测试覆盖布局行高、复杂合并表、正常对照表。
- 对比真实 Word 渲染图与 admin 渲染截图，重点查看光固Ⅰ红框区域和同类复杂表。
- 结构验证不得只比较 HTML 单元格数量，必须检查行列位置、rowSpan/colSpan、文本落位、边框、行高列宽比例。
- 子agent 输出必须包含 PASS / FAIL / BLOCKED 判定和证据。

## 经验门禁

- PowerShell 命令必须显式设置 UTF-8 输入输出，不使用 `&&`。
- 本任务不得引入 fallback、静默降级、异常吞噬、mock 成功或临时绕过。
- 表格修复必须走通用算法层：Word 结构读取、逻辑网格、视觉网格、列宽推导、行高推导、合并单元格、边框模型或渲染比例。
- 涉及 E2E 或真实页面验证时必须走真实登录路径和真实数据，不得额外增加测试控件或页面内容。
- worktree 分支必须隔离，不得用主工作区脏改作为最终融合依据。
