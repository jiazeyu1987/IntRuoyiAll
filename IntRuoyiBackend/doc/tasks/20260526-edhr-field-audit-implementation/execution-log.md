# 后端执行日志：eDHR 字段级不可篡改审计

- BDD: 字段变更留痕 -> Given DRAFT eDHR 字段被修改, When FIELD_CHANGE 签名保存, Then 后端先写审计链再更新 JSON。
- BDD: 旧保存入口不得绕过审计 -> Given 旧 save-draft 带字段值变更, When 保存, Then fail-fast 或委托同一审计事务。
- BDD: typed JSON 值精确保留 -> Given 字段值包含 null、0、false、空字符串和 JSON 对象, When 保存字段变更, Then 审计链不混淆 old/new 值。
- BDD: 字段路径进入审计链 -> Given 用户修改带 fieldPath 的 eDHR 字段, When 保存字段变更, Then audit item 持久化 field_path 且 item hash 覆盖 fieldPath。
- BDD: expected old 只做冲突检测 -> Given 前端携带 expectedOldValueJson 或 expectedOldValueHash, When 后端保存字段变更, Then old value 仍由当前 JSON/base hash 计算，expected old 不写为审计事实。
- BDD: 字段审计 REST 闭环 -> Given 后端已有字段审计 core service, When 授权用户调用 save/page/detail/verify/export, Then REST 路径、权限、字段名与 hashVerification=VALID 响应符合冻结契约。
- BDD: 字段审计查询与导出不降级 -> Given eDHR 已有字段审计 batch/item, When 查询分页、详情、校验或导出, Then 返回 fieldPath、old/new、原因、actor、changedAt、signatureId、previousHash/auditHash 与 VALID 校验；链断裂时详情和导出 fail-fast。
- BDD: 旧草稿保存不得绕过审计 -> Given 旧 save-draft 请求携带 cellValues, When 后端无法委托完整字段审计事务, Then fail-fast 且 cellValuesJson/remark 不变化。
- BDD: 提交审批归档绑定字段审计证据 -> Given eDHR 有持久化 cellValuesHash、fieldAuditRevision 和 fieldAuditHeadHash, When 提交、审批或归档, Then 业务变量、快照、签名和归档记录绑定这些证据，提交后证据不一致时审批 fail-fast。
- BDD: 缺租户拒绝字段审计保存 -> Given 字段审计保存事务没有 TenantContext, When 保存字段变更, Then 后端按租户上下文 fail-fast，不得把 tenantId 默认为 0。
- BDD: 字段审计详情合同一致性 -> Given 查询参数包含 executionId 且 auditBatchId/auditItemId 至少一个, When 同时提供 batch 与 item, Then item 必须属于该 batch；响应 items[] 使用 id 作为审计 item ID 并包含 page Row 全字段。
- BDD: 签名绑定参与审计链校验 -> Given 字段审计 batch/item 链正常但签名行绑定证据被篡改, When 后端执行 verify-chain, Then 返回 SIGNATURE_MISMATCH 而不是 VALID。
- BDD: typed JSON null 保存闭环 -> Given 字段旧值为空字符串且用户提交 valueType=NULL/newValueJson=null, When 调用字段审计 save-changes, Then REST 校验允许该请求且审计 item 写入 oldValueJson="\"\""、newValueJson=null、对应 hash；若 STRING/NUMBER 缺失 newValueJson 则 fail-fast 且不更新 JSON。
