# 任务：给芋道源码 admin 绑定运维工程师角色

## 任务目标

- 在测试服务器真实数据库中确认 `芋道源码/admin` 当前角色与运行控制台菜单权限。
- 在 `芋道源码` 租户下新增或复用“运维工程师”角色。
- 将运行控制台查询、重启、运维操作权限授权给“运维工程师”角色。
- 将 `admin` 账号绑定到“运维工程师”角色，使前端能看到运维按钮。
- 只补充缺失的角色、角色-菜单和用户-角色关系，不修改密码、用户资料或其他租户数据。

## 非目标

- 不执行备份、恢复、回滚、发布或重启操作。
- 不修改生产服务器。
- 不调整前端代码或后端代码。

## BDD 场景

- BDD: admin 通过运维工程师角色看到运行控制台运维按钮 -> Given 测试服 `芋道源码/admin` 已登录, When 账号绑定“运维工程师”角色且角色拥有 `infra:runtime-control:operate`, Then 前端运行控制台顶部显示发布、备份、回滚和恢复按钮。
- BDD: 权限变更最小化 -> Given 运行控制台菜单权限已存在, When 新增或复用“运维工程师”角色并绑定 admin, Then 只插入缺失的 `system_role`、`system_role_menu`、`system_user_role` 关系，不改动用户基础资料。

## 预期验证

- RED：授权前 SQL 查询显示 admin 未绑定“运维工程师”角色，或该角色缺少 `infra:runtime-control:operate`。
- GREEN：授权后 SQL 查询显示 admin 绑定“运维工程师”角色，且该角色拥有 `infra:runtime-control:query`、`infra:runtime-control:restart`、`infra:runtime-control:operate`。
- GREEN：不执行任何高风险运维动作。
- BLOCKED：若真实前端仍是旧包，不包含运行控制台运维按钮区域，则数据库权限已完成但页面仍需发布最新前端后才能看到按钮。
