# 偏差管理权限、安全与部署设计

## Purpose and Scope

沿用租户、角色权限、统一电子签名、不合格评审和迁移制度；本次不新增认证方式或外部服务。

## Evidence Reviewed

- docs/database-rules.md、docs/login-access.md、docs/backend-development.md。
- 审核要求表 C5–C10、C25–C27、C30、C34–C38；用户确认角色可由同一账号兼任。
- 当前 NCR create/dispose、MES 签名服务和动作适配器。

## Configuration

编号用 Asia/Shanghai 服务器年月，签署时间用受控服务器时间。权限菜单迁移检查固定ID、路径、权限码冲突，绝不自动给全员授予新写权限。

## Secrets

复用既有身份再验证和签名授权。密码、令牌、签名密钥不进入正文、审计载荷、请求幂等摘要或日志；返回前端只含可展示证据。

## Permissions

| 权限后缀建议（前缀 mes:pro-edhr-deviation:） | 角色语义/动作 |
| --- | --- |
| query | 看当前租户全部偏差；不是仅看本人创建。管理员按角色授予。 |
| create | 发起偏差并签署发起编制；有处理权不自动获得发起权。 |
| handle | 保存/修改唯一处理记录并签署处理编制。 |
| verify | 签署整改验证结论。 |
| department-confirm | 偏差部门负责人签署处理结论。 |
| qa-close | QA关闭确认。 |
| quality-approve | 质量负责人批准。 |
| critical-management-approve | 仅关键偏差常规路径的管理者代表批准。 |
| ncr-create | QA从关键偏差发起统一NCR；同时校验现有NCR创建权限。不能只凭前端QA标签或角色名称。 |

NCR处置复用正式 dispose 权限，管理员可配置给QA或PQC生产放行处置角色；仅有查询/发起/普通PQC列表访问权不能处置。一人可获多个节点权限，但每个节点独立签署，不允许一签自动填充全表。

读取偏差内容必须有 query 权限；批记录详情能打开不意味着可以越过偏差权限。无权显示“无权查看偏差”，不能显示“没有偏差”。没有部门过滤的新要求，沿用租户隔离，不新增“只能看本人”的限制。

## Security Controls

- API检查租户、当前角色权限、正式来源、对象状态、内容版本和签名授权。
- 编制/验证/批准/QA确认都记录真实签署人、时间、时区、意图及内容哈希；签署图样来自现有签名证据。
- 常规关闭包含部门负责人，QA与质量负责人互不依赖先后；关键路径增加管理者代表。
- 转NCR替代偏差表验证与批准，仍保留发起事实和已有签名，不制造“验证合格”或模拟缺失签名。
- 处理正文修改需原因和before/after，旧签名保留但对新版本无效。新增同版签名不改变正文摘要。
- 四项写门禁必须在最终事务执行；处理/验证/签名/发起评审/处置不被自身阻断。
- 上市放行与偏差创建共享串行边界，防止已放行批次新增偏差；历史追溯只读。
- 审计默认开启，不能清空。仅本模块正式业务数据和任务自有测试数据在授权边界内操作。

## Deployment

本轮只编写文档。后续先验证正式schema、migration dependsOn闭包、幂等DDL、菜单权限和签名动作注册，再根据当轮授权执行数据库及运行环境操作。缺表/缺签名动作是明确失败，不能增加兼容兜底或默认成功。

未推送PQC的批记录发起、关键偏差转审及四项阻断必须作为上线门禁；如果正式来源当前不支持，应在P1解决，不能用已推送后的场景替换验收。

## Observability

审计可按 deviationId、batchExecutionId、reviewId、actionCode、contentVersion关联。记录创建、修订、重签、关闭原因、转审及处置、阻断动作和原因。失败零业务写入但正式认证/安全失败审计可以保留；不记录密码。
