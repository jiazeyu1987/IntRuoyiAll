# eDHR 偏差管理用户流程

## Purpose and Scope

描述偏差发起、常规单次处理、关键偏差转不合格审批、列表查看、批记录追溯及失败流程。

## Evidence Reviewed

- 用户确认的批记录级关联和偏差状态规则。
- 偏差处理记录表的两段内容。
- 电子批记录审核要求表 C15、C18、C34–C36 及签名/审计要求。
- 当前 eDHR 批记录详情、不合格评审详情、UnifiedListTemplate 与批记录追溯入口。

## Primary User Flows

### UF-01 发起普通偏差

Given 当前用户在系统中拥有偏差发起权限，且目标批记录属于当前租户、尚未上市放行
When 用户在偏差发起页选择批记录，填写发起内容并完成编制人电子签名后提交
Then 系统原子分配 PC-YYYYMM-流水号，保存唯一批记录关联和发起人/签名证据，并将偏差列入未处理列表

### UF-02 常规处理、验证与关闭

Given 一条未关闭偏差已发起，且当前用户拥有相应处理权限
When 处理编制人、验证人（合格）和部门负责人已签署，QA 与质量负责人分别完成关闭确认和批准
Then 满足 PRD FR-06 全部签署条件后才关闭并列入已处理；QA 与质量负责人不要求先后顺序

### UF-03 关键偏差管理者代表签署

Given 一条重大（关键）偏差走常规处理流程，且管理者代表拥有相应签署权限
When 常规处理编制、验证合格和部门负责人均已签署，QA、质量负责人和管理者代表完成其签署
Then 系统只在全部必需签署完成后关闭偏差

### UF-04 QA 将多条关键偏差转入一个评审

Given 同一批记录关联一条或多条未关闭的重大（关键）偏差，且当前 QA 拥有发起不合格审批权限
When QA 在批记录上下文选择一条或多条偏差并完成不合格审批发起签名
Then 系统不等待偏差表验证或批准，创建一张批记录级不合格审批，关联全部选中偏差并自动关闭这些偏差；批记录继续冻结直至评审处置完成

### UF-05 解除评审后按处置结果推进

Given 批记录存在待处置不合格评审，且 QA 或 PQC 生产放行授权人员已进入正式评审详情
When 用户完成授权签名并提交让步放行、返工或作废处置
Then 评审记录关闭，偏差与评审关系仍可追溯，批次按处置结果及其他现存门禁决定后续可执行操作

### UF-06 从偏差列表追溯处理

Given 用户拥有 query 权限并打开偏差管理，且列表数据可正常读取
When 用户切换全部、未处理或已处理 Tab 并打开一条偏差
Then 页面展示偏差编号、关联批记录、发起内容、唯一处理记录、签名、关闭状态和关联不合格审批

### UF-07 从正式批记录详情及追溯查看

Given 用户从正式顶层活跃表单详情或只读批记录追溯进入“偏差”Tab
When 宿主携带明确的 batchExecutionId 查询关联偏差
Then 有记录时展示其发起和处理内容；无记录时显示“没有偏差”；只读追溯中同样可见历史签名和评审结果

### UF-08 正常入口补齐正式身份，异常来源明确失败

Given 正式批记录详情入口只有 activeOrderId，后端有可核对的正式批记录来源关系
When 用户打开该详情的偏差区
Then 后端返回准确 batchExecutionId 后查询偏差；不让用户手填ID，也不把正常入口永久显示为错误

Given 正式来源真实缺失或歧义，或者共享面板只是在历史追溯内嵌显示某工序表单
When 详情渲染
Then 来源异常明确报错而非空态；内嵌表单不重复显示主偏差Tab，外层只读追溯仍保留偏差区

## Alternate Flows

- 一份批记录下多条偏差分别走各自常规处理流程。
- 多条重大（关键）偏差在发起评审时一次选择，并由同一评审关联。
- 同一用户被管理员授予多个角色时，可在授权范围内完成多个不同签署节点；每个签署动作单独记录意图和身份验证。
- 处理内容被修改时继续编辑原处理记录；记录审计变化，并要求受影响签名重新签署。
- 一条偏差完成普通流程后进入已处理列表；若通过评审发起自动关闭但评审仍待处置，也进入已处理列表并显示批次受限提示。

## Error Flows

- 无偏差发起权限：服务端拒绝，不生成编号或业务记录。
- 批记录不存在、跨租户或已上市放行：拒绝发起并返回可读原因。
- 当前用户没有对应处理/批准/QA评审权限或签名验证失败：拒绝动作，不写入成功状态。
- 普通偏差尝试关联不合格审批：拒绝。
- 评审选择中包含不同批次、已关闭或非关键偏差：整笔拒绝，不做部分链接或部分关闭。
- 关键偏差评审创建的任一写入步骤失败：签名、审批、关联、自动关闭、冻结均回滚。
- 活跃表单详情偏差请求失败：呈现错误和重试入口，不显示空数据状态。
- 四类生产/放行动作遇到未关闭偏差或待处置评审：后端拒绝并指出阻断偏差或评审编号。

## Out-of-Scope Flows

- 已上市放行批记录补挂新偏差。
- 一条偏差连接多个批记录。
- 同一偏差建立第二份独立处理单；对原处理记录修改和重新验证属于范围内。
- 未经 QA 发起关键偏差不合格审批的自动审批。
- 用订单号代替批记录号发起或关联偏差。

## Open Questions

主流程已经确认。首版不事后追加已签NCR，不支持关闭后重开；已有待审评审时明确返回其编号，当前评审可继续处置，其他偏差保持开放。真实入口如仅有activeOrderId，由后端正式来源解析批记录身份后再使用偏差功能，不能将这类入口永久降为不可用。
