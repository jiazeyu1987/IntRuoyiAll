# E2E Plan

## Purpose and Scope

本计划定义用户真实路径验证，目标是证明“模板规则经用户确认并保存后，批次执行打开填写不再误报未确认规则”。E2E 只验证现有页面和 API 链路，不通过直接 SQL 造成功能成功，不新增仅为测试服务的前端控件。

## Evidence Reviewed

- 用户真实入口为批次执行详情中的“打开填写”。
- 后端执行入口最终调用 `openOrCreateByContext` 并构建执行快照。
- 模板规则配置入口最终调用 `saveCellRules` 并写回 Jimu 报表 JSON。
- 自动识别规则在确认前仍是建议态，E2E 不应把自动识别视为可执行确认。
- 现有 E2E 政策要求使用真实前端路径；API 只能作为最终验证或只读辅助检查。

## User Paths

Path: 规则确认后打开填写

Given 测试租户内存在一个任务专用批记录模板，模板包含可填单元格，且这些单元格已通过规则配置页保存确认

When 测试用户进入批次执行详情并点击“打开填写”

Then 页面应进入填写状态或展示可填写表单

And 不应出现“批记录模板存在未确认填写规则的可填单元格”提示

Path: 自动建议或未确认规则仍拦截

Given 测试租户内存在一个任务专用模板，模板包含自动识别但未确认的可填单元格

When 测试用户点击“打开填写”

Then 页面应展示未确认规则提示

And 提示中应包含具体坐标

And 不应创建新的执行快照记录

## Browser or Client Steps

1. 使用 Playwright 登录已确认的本地测试账号。
2. 进入批记录模板或批次执行菜单，定位任务专用模板和工序。
3. 在规则配置入口确认可填单元格规则并保存。
4. 进入批次执行详情，点击“打开填写”。
5. 捕获页面 toast、dialog、网络请求结果和控制台错误。

## API Verification

- 通过只读 API 或数据库只读查询确认执行记录存在，并且 `executionSnapshotJson` 中包含对应 `edhrCellRule`。
- 对未确认规则场景，确认执行记录数未增加。
- 历史修复不属于当前 E2E 必跑范围；若后续授权 apply，先保存 dry run 输出，再验证 apply 后 Jimu JSON 中候选单元格为 `source=MANUAL && reviewed=true`。

## Console and Log Checks

- 浏览器控制台不得出现未处理异常。
- 网络请求不得返回 `PRO_BATCH_RECORD_EXECUTION_CELL_RULE_UNREVIEWED`，除非当前场景是未确认规则失败路径。
- 后端日志不得出现 JSON 解析失败、规则校验失败或快照来源缺失错误。

## Test Blockers

- 本地 `http://127.0.0.1:8081` 前端和 `http://127.0.0.1:48081` 后端均已监听。
- 当前浏览器会话提示登录超时，且未提供任务专用测试账号、测试租户和任务专用模板数据；因此不能执行写型真实 E2E。
- 获得任务专用账号后，必须使用 Playwright 走规则确认、批次执行详情、打开填写的真实路径，并确认不会触碰生产或共享业务数据。
