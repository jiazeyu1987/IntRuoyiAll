# 一线生产设备参数范围中点默认值

## Task Goal

修复一线生产设备参数没有显式目标值时被前端显示为 `0` 的问题；数值参数存在完整上下限且未配置显式默认值时，统一使用上下限中点作为默认值，其他同类范围参数遵循相同规则。缺少任一边界时保持未配置状态，不生成 `0` 或其它猜测值。

- [x] M1：定位默认值来源、空值转零根因和现有范围参数配置契约
- [x] M2：先补后端中点默认值与前端空值保护的失败回归测试
- [x] M3：实现后端统一中点解析和前端 `null` 空值保护
- [x] M4：完成定向回归、证据校验和差异检查
- [x] M5：完成经验沉淀与任务收尾

## Expected Verification

- 后端回归证明：显式默认值优先；无显式默认值且上下限完整时返回精确中点；文本标准或边界不完整时不生成数值默认值。
- 前端静态合同证明：`null` / `undefined` 不进入数值归一化，不再通过 `Number(null)` 生成 `0`。
- 相关一线生产设备参数范围展示和正式提交静态回归通过。
- `git diff --check` 通过；不改动或覆盖工作区已有并发修改。

## Experience Gate

- `docs/experience-index.md` 存在并已检索设备参数、默认值、目标值、上下限和一线生产关键词。
- 适用 `docs/backend-development.md#一线生产正式提交必须单事务落链并按唯一组长归属可见`：设备参数继续来自正式运行态规则，不使用前端猜测、默认成功或其它数据源替代。
- 适用 `docs/frontend-development.md` 的前端静态合同与错误可见性门禁：先 RED 后 GREEN，空值不得静默转换成业务数值。
- 用户本轮明确变更旧口径：数值范围无显式目标值时，默认值应为上下限中点，且所有同类范围参数统一处理。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否；中点是用户明确指定的正式默认值规则，不是缺失前置条件时的降级。
- `是否从根因和长期维护角度解决`：是；由后端运行态统一解析范围默认值，前端只消费正式默认值并正确保留空值。
- `是否存在临时补丁或绕过`：否。
