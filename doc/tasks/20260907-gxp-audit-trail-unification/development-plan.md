# 统一 GxP 审计追踪开发计划

## Delivery Principle

按风险从基础设施到业务接入逐阶段实施。每个阶段必须先完成 BDD 和 RED，再写生产代码；阶段验证未通过不得进入下一阶段。禁止长期双写和审计失败后的业务成功 fallback。

## M0：范围与政策基线

- 建立 `config/gxp-audit-policy.yaml` 及版本化 schema，盘点全部写 Controller、领域服务、Job、消息消费者、导入、外部同步、Migration 和发布/运维脚本。
- 为每项操作确定动作、原因、签名、前后值、保存类别和负责人。
- 每项登记包含 `operationId/sourceType/sourceLocator/domain/subject/action/reasonPolicy/signaturePolicy/statePolicy/retentionClass/testIds/owner/applicabilityDecision`；不适用决定包含批准人、依据和有效期。
- 使用编译期注解处理/ArchUnit 和脚本扫描生成实际写入口清单；禁止 Controller、Job 或消费者绕过已登记领域服务直接调用变更 Mapper。
- 批准审查周期、保存期限、NTP 和 WORM 参数。
- Gate：登记表 schema 校验通过，实际入口与登记表双向一致，所有 GxP 对象均有 owner，任何不适用项有有效批准依据，覆盖报告 hash 已冻结。

## M1：统一审计内核和数据库

- 新增公共审计契约、领域服务、规范化哈希器和错误码。
- 新增只追加事件、证据关联、每日清单、归档回执和策略版本表。
- 建立数据库 INSERT/SELECT 权限，应用无 UPDATE/DELETE 权限。
- 完成事务回滚、幂等、并发顺序和篡改检测测试。
- Gate：内核测试、真实事务测试和 schema 约束全部通过。

## M2：高风险领域接入

- 接入 eDHR 字段变更、提交、复核、批准、附件和归档。
- 接入 DCC 修订、检出/检入、批准、发布、替代、作废、下载和打印。
- 接入 BPM、Showroom 和统一电子签名证据。
- 现有专业审计表通过证据引用和 hash 接入，不复制或猜测历史事实。
- Gate：每个动作均覆盖成功、审计失败回滚、并发和签名缺失测试。

## M3：权限、配置和基础数据接入

- 接入用户、角色、菜单、数据范围、临时授权和签名授权。
- 接入系统配置、通知配置、调度配置。
- 接入 MES 工艺路线、工序、表单绑定、物料、设备和质量标准等已批准范围。
- Gate：新增、修改、删除/作废、启停和导入路径均有事件及前后值。

## M4：查询中心和周期审查

- 建设统一只读事件列表、详情、证据跳转、完整性状态和导出。
- 建设持久化周期审查批次、冻结快照、发现项、整改、签名和关闭。
- 建设持久化审查计划和运行账本；调度按 `periodCode` 唯一创建批次，停机恢复后补扫所有漏期且不重复，保存计划/开始/完成/失败/逾期/告警证据。
- 审查策略明确关键事件全量审查与风险抽样规则，抽样总体、算法、样本和排除依据冻结保存；审查动作本身进入统一审计账本。
- Gate：权限隔离、冻结快照、连续周期自动执行、停机补扫、逾期升级、未关闭整改阻断和导出重算 hash 测试通过。

## M5：可信时间、WORM、备份和恢复

- 对接已批准 NTP/chrony，采集服务器、数据库、偏差和时间源证据。
- 按批准的最大未封存时长生成增量密封水位，生成每日最终不可变清单；水位超期时治理状态和发布门禁失败。
- 生成自包含法规归档包，固定包含 `events.ndjson`、`evidence-links.ndjson`、签名证据、必需领域证据、可信时间证据、`manifest.json` 和 `SHA256SUMS`，整包写入正式 WORM/Object Lock 存储。
- 对象存储回执必须绑定归档包 ID、对象 `versionId`、包 hash、retainUntil 和 legal hold；只归档清单或 hash 不得标记法规归档完成。
- 建立独立故障域副本、保存截止时间、legal hold 和恢复演练。
- Gate：清空独立演练环境数据库后仅从归档包恢复完整审查范围，真实目标存储、时间偏差、主副本和长期可读性验证全部通过。

## M6：系统变更和持续覆盖门禁

- 发布脚本生成版本化系统变更清单：前后 commit、产物/镜像 digest、OpenAPI 前后 hash 与结构化 diff、Migration 有序列表和逐文件 hash、关键配置脱敏快照与 diff、批准、原因、操作者、时间、结果和回滚事件。
- CI 比对实际写入口、GxP 登记表、批准不适用项和测试清单；新增未登记入口、过期例外或实际入口缺失直接失败。
- 接入数据库/schema 特权审计；审计表 DML/DDL、授权和关闭审计等事件必须实时或在批准时限内外送到独立保护存储，且不受业务应用账号控制。
- 移除被统一账本替代的自由文本合规声明；技术访问日志继续独立保留。
- Gate：覆盖报告无未解释缺口，特权篡改与关闭审计测试、系统变更清单重算和独立验证通过后才进入发布评审。

## Migration Strategy

- 不回写或改造既有不可变专业证据。
- 对历史 eDHR、DCC 和签名记录生成一次性只追加 `LEGACY_EVIDENCE_REGISTERED` 索引事件，保存来源表、主键和原始 hash；无法证明唯一关联的历史记录进入 blocker 清单。
- 每个模块在维护窗口一次切换到统一写入，不进行长期新旧双写。
- 模块切换后的任何成功 GxP 写入都必须具有统一事件；缺失即回滚并报警。

## Stop Conditions

- 保存策略、NTP、WORM 或 GxP 范围缺少批准。
- 业务事务和审计事务无法证明原子性。
- 生产应用账号仍具备审计表 UPDATE/DELETE 权限。
- 历史证据身份或签名关联无法唯一解析。
- 关键写入口无法取得真实 before/after 或必须依赖客户端自报。
