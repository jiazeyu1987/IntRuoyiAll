# DCC 主流程静态逻辑审查

## Goal

用 gpt-5.5 high 子线程静态检查 4 个 DCC 主流程代码逻辑；主线程复核子线程反馈，确认真实问题后修复，非问题跳过，并循环到子线程确认无静态逻辑问题。

## Scope

- 受控浏览流程：名称查看权限、内容查看权限、关联候选、目录/文件/版本切换重新校验。
- 升版流程：检出独占、检入说明、大小版本判定、审批/盖章 PDF 生效、关联不自动切换。
- 文件生命周期：配置、新建、审批锁定、驳回重传、盖章 PDF、默认目录受控保存、生效替代。
- 上传到受控保存流程：源文件上传、模板文件夹、初始版本、关联版本、审批、盖章 PDF、默认目录受控保存闭环。

## Milestones

- [ ] 读取仓库规则和 DCC 主流程文档。
- [ ] 建立 gpt-5.5 high 子线程并收集静态审查结论。
- [ ] 主线程逐项复核反馈，确认真实逻辑问题。
- [ ] 对真实问题执行 RED / GREEN 修复；对误报记录跳过原因。
- [ ] 复跑子线程静态复核，直到无静态逻辑问题。
- [ ] 记录验证报告和收尾状态。

## BDD

- BDD: 配套 PDF 删除替换清理 -> Given 外来评审已有源文件和未绑定图纸 PDF, When 删除或替换 PDF, Then 先按该 PDF 的正式会话和 ticket 清理；清理失败时保留旧凭证并停止删除或新上传。

- BDD: 受控浏览权限分层 -> Given 用户只有名称查看权限, When 浏览、搜索、选择关联候选或切换目录/版本, Then 只能发现名称级候选，不能获取正文、详情、预览或串用旧上下文数据。
- BDD: 升版受控生效 -> Given 已有受控文件需要修改, When 授权人员检出检入并产生新版本, Then 检入保留旧版本并进入审批，新版本只有审批通过且盖章 PDF 保存到默认目录后才生效，关联不自动切换。
- BDD: 生命周期闭环 -> Given 版本进入审批或被驳回, When 审批处理、驳回重传、盖章 PDF 上传和最终批准发生, Then 审批对象锁定，驳回保留原因并要求重新上传，最终批准失败必须暴露真实原因。
- BDD: 上传到受控保存 -> Given 上传人员选择项目和模板文件夹, When 首次上传源文件并提交审批, Then 上传入口只新建逻辑文件和初始版本，不通过上传创建新版，最终批准即受控保存。

## Expected Verification

- BDD: 预上传模板前置校验 -> Given 首次上传缺少有效项目模板或类别不匹配, When 请求上传源文件或配套 PDF, Then 在读取和保存文件之前拒绝；有效模板允许上传；检入必须匹配当前检出人和具体版本；外来评审使用明确的独立场景。

- 子线程静态审查结论：四个流程均覆盖，问题需带文件和行号。
- RED：对确认的真实逻辑问题补最小静态或单元测试，先失败并记录原因。
- GREEN：生产代码修复后定向验证通过。
- REGRESSION：复跑相关静态合同或单元测试；不执行 E2E、数据库写入、服务重启、Git 提交或推送，除非用户另行明确授权。

## Design Constraints Check

- 遵守 `AGENTS.md`、`docs/task-closeout-rules.md`、后端/前端/数据库/PowerShell 规则。
- 不做 fallback、降级、吞异常、模拟成功或兼容补丁。
- 不用 API 或数据库写入代替业务验收；本轮未获 E2E 授权，不执行 E2E。
- 未获 Git 提交/推送授权，不执行提交或推送；完成性按任务规则记录实际阻塞边界。
- DCC 最新业务口径以用户本轮 4 个主流程和 `docs/dcc-main-flow-no-training-distribution.md` 为准；旧 Windchill PRD 中“批准后另行发布”“系统自动初始版本”等与本轮口径冲突处不作为当前验收目标。
