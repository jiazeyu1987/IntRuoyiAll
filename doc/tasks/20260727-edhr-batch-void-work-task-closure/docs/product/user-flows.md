# User Flows

## Purpose and Scope

描述批次作废后负责人工作台任务闭环的主要用户流程、替代流程和错误流程，确保 6 项能力可从真实用户路径验证。

## Primary User Flows

### Flow 1: 作废批次并关闭活动任务

1. 发起人或审批人进入批次作废流程。
2. 用户填写作废原因并完成签名、审批或平台作废确认。
3. 系统将批次置为 `VOIDED`。
4. 系统取消同批次待处理、处理中、逾期工作任务。
5. 系统记录作废事件、归档失效和任务取消原因。
6. 负责人刷新工作台后不再看到该批次可操作待办。

### Flow 2: 负责人刷新工作台

1. 负责人打开个人控制台或 eDHR 工作任务列表。
2. 系统读取本人可操作任务和统计。
3. 系统排除作废批次对应的任务。
4. 页面只展示仍可处理的真实任务。

### Flow 3: 审计人员追溯作废历史

1. 审计人员进入批次详情、变更事件或历史记录页面。
2. 系统展示批次作废状态、作废原因、签名或审批信息。
3. 系统展示归档失效信息和任务取消记录。
4. 审计人员可确认原负责人、原任务类型、取消原因和时间。

## Alternate Flows

- 批次无活动任务：系统只完成批次终态、归档失效和审计记录，不额外创建任务。
- 批次含已完成任务：系统保留已完成任务历史，只取消仍活动的任务。
- 直接平台作废：如果流程绕过 BPM，也必须执行同样的批次终态和任务取消规则。
- 金手指批量作废：每个生效作废批次都必须独立执行活动任务取消。

## Error Flows

- 作废原因缺失：系统按现有作废校验失败，不更新批次和任务状态。
- 任务取消失败：作废流程失败或回滚，不允许出现“批次已作废但活动任务仍可处理”的新数据。
- 旧链接打开：用户通过旧 `workTaskId` 打开作废批次任务，系统返回终态阻断错误。
- 工作台刷新失败：页面展示真实请求失败，不把任务列表清空伪装成已处理成功。

## Out-of-Scope Flows

- 历史脏数据批量修复。
- 新增只读任务处理页。
- 新增重开、补录、重执行流程本身的完整产品设计。
- 绕过审批或签名的快捷作废入口。

## Open Questions

- 产品是否需要在工作台历史页突出展示“因批次作废自动取消”的任务标签。
- 产品是否需要给审计人员增加独立的作废任务取消报表。
