# Acceptance Criteria

## Purpose and Scope

把 6 项能力拆成可验收条件，作为后续代码实现、RED/GREEN、真实 E2E 和回归验证的准入标准。

## Evidence Reviewed

- PRD：`docs/product/prd.md`。
- 用户流程：`docs/product/user-flows.md`。
- BDD 场景：`docs/acceptance/bdd-scenarios.md`。
- TDD 计划：`docs/acceptance/tdd-plan.md`。
- E2E 计划：`docs/acceptance/e2e-plan.md`。

## Acceptance Criteria

- AC1 作废终态：给定可作废批次，当作废审批或平台作废生效后，批次状态必须为 `VOIDED`，正常处理动作被终态校验阻断。
- AC2 工作台移除：给定负责人已有该批次待办，当批次作废生效并刷新工作台后，该批次任务不得出现在待办、逾期或统计数量中。
- AC3 活动任务取消：给定同批次存在待处理、处理中、逾期任务，当作废生效后，这些任务必须变为已取消并写入取消原因和完成时间。
- AC4 历史任务保留：给定同批次存在已完成或已取消任务，当作废生效后，已完成任务仍为已完成，已取消任务仍为已取消。
- AC5 旧入口阻断：给定用户持有旧 `workTaskId` 或旧页面缓存，当批次已作废后继续打开或提交，后端必须返回终态错误，前端不得显示处理成功。
- AC6 审计可追溯：给定批次作废后，审计路径必须能追溯作废原因、作废事件、签名或审批、归档失效、任务取消原因、原负责人和时间。
- AC7 后续受控：给定业务需要继续处理已作废批次关联事项，用户不能复用原取消任务，只能走受控重开、补录、重执行或新建批次流程。

## Rejection Criteria

- 仅前端隐藏任务、未取消活动任务。
- 作废成功但活动任务仍为待处理、处理中或逾期。
- 作废后旧链接仍能打开可编辑或可提交页面。
- 任务取消失败被吞掉，接口仍返回作废成功。
- 已完成任务被错误改成已取消。
- 审计数据被物理删除或无法追溯作废原因。
- 用 API-only 或 mock 数据替代要求的真实工作台 E2E。

## Product Blockers

- 没有真实工作台入口、测试账号、租户或测试批次数据时，不能声明真实 E2E 通过。
- 没有任务取消原因、完成时间或状态字段时，不能声明活动任务取消能力完成。
- 未确认旧入口仍被后端终态校验阻断时，不能声明 6 项能力全部完成。
