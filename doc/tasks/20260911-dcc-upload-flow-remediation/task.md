# DCC 上传审批流逻辑修复

## Task Goal

修复 DCC 受控文件上传、审批、发布及影响关联链路中经静态审查确认的逻辑缺陷，使代码实现与项目既定的 Windchill 版本、权限、发布边界、关联文件和幂等规则一致。

## Design Constraints

- 正式受控文件仅保留一条上传入口，不允许表单中心旁路绕过模板、权限和发布治理。
- 新建版本与大版本均须在审批通过后进入待发布，发布动作独立于内容审批。
- 文件逻辑身份由租户、项目、文件类型叶子节点和规范化文件编号共同确定。
- 后端必须独立校验项目访问、类别上传权限、类别与文件类型绑定、会签矩阵和关联文件候选资格。
- 所有写操作必须显式幂等；不得以异常吞噬、默认成功或兼容分支代替。
- 本轮不执行真实 E2E、数据库写入、服务启停、Git 提交或推送。

## Milestones

- [x] M1 建立缺陷回归场景与 RED 证据。
- [x] M2 修复上传提交、当前版本定位、权限、类别绑定和会签矩阵约束。
- [x] M3 修复审批后待发布边界和旧版本存储副作用。
- [x] M4 修复关联文件候选和后端关联资格校验。
- [x] M5 完成任务自有前端合同、幂等键持久化和定向验证；全量类型检查保留并行改动诊断。

- 前端 DCC 上传合同测试与 TypeScript 检查通过。
- 数据库迁移静态契约及 H2 兼容测试通过（如项目已有对应入口）。
- 不运行 Playwright；本轮用户未明确授权 E2E。
