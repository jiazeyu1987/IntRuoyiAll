# G32 authenticated one-time legacy registration entry proposal

## Scope and decision
prepared_for_root_review — Architecture proposal only; no production changes, final41 edits, Maven, UI-script edits, actual DB/OAuth/login/browser/service/object operation or new permission question by this reviewer. Existing `activateVerifiedScope` is an internal transactional method and its package-private sealed artifact factory has no execution caller. A concrete caller is necessary for future authorized configuration registration, but actual source remains35 MATCH/4 missing, QA/26 policy and legacy registration permission are not ready; no caller may activate now.

Preferred future path is one **explicit one-time local maintenance command** invoking the existing Spring-proxied registration service. It adds no REST/product UI/job/new approval node and never becomes an always-on startup write. Reuse an already authenticated formal servlet SecurityContext when a legitimate protected existing maintenance invocation provides one; when a separate local process is necessary, derive the narrowly scoped maintenance identity only from a freshly verified **actual access token**, then revalidate the formal current account/roles/permissions in the existing service. Never construct admin/LoginUser from a requested actorId/username or quality signer field. Production implementation remains unassigned and needs Root review of this concrete plan/tests.

## Minimal proposed components and defaults
1. `DccLegacyNameRegistrationMaintenanceCommand` in the DCC module accepts only mode `inspect` or `activate`, exact protected artifact ID/rawSHA plus exact Root operation authorization reference and source environment comparison. No caller actor, QA actor/time, allowLegacy, or bytesVerified boolean decides trusted facts. `inspect` is read-only preparation, never returns activation success.
2. Optional task-owned `DccLegacyNameRegistrationMaintenanceRunner` exists **only** under explicit local maintenance profile and opt-in property (`enabled=true`, matchIfMissing=false); when absent/false no bean, stdin read or writes. No default mode/environment/tenant/actor or new HTTP mapping. Run once and exit. It must not run on ordinary int_qms/int_main startup, replay on scheduler or attach itself to background jobs.
3. Protected manifest loader is the current strict `fromProtectedArtifact`, fed a Root-rebuilt complete39 receipt/facts/results/actual historical decision and live row preimages, with exact raw hashes and sourceUUID. The caller's nonsecret operation config carries exact approved artifact descriptors; token remains stdin in memory only, never artifact/env argv/log/result. The proposed entry has no authentication fallback or API-only business seed.
4. Use the **same** actual DataSource/PlatformTransactionManager, Spring proxy and existing runtime source23306/tenant1/UUID. Do not open a new datasource3306, direct JDBC write lane or call a new instance that bypasses the proxy. External caller auth/approval checks occur before artifact/body/write flow; service authorizes again, ensuring missing context cannot reach Gxp SYSTEM_ACTOR.
5. Existing mode-specific Root service/startup controls must suppress or fence unrelated writers before one-time process startup. A new local CLI loading Spring can trigger unrelated ApplicationRunner listeners, scheduled jobs and cache changes; verify the actual runtime startup set rather than claiming WebApplicationType.NONE alone disables everything. Use existing reviewed slot/runtime plan and no shared-service restart. If required beans cannot initialize in a non-web dedicated context, report it; do not silently add servlet mocks or relax auth to boot.

## Authentication route and token handling
When legitimate current formal authenticated servlet context is available, prefer calling the internal maintenance command inside it; preserve the existing Authentication/request/tenant, recheck expiry and account/role immediately, then call the real registration proxy. No frontend REST endpoint is proposed here. The review did not discover an existing protected generic action already authorized to invoke this DCC method; do not add activation to an unrelated config-import endpoint as a hidden side effect.

For a separate explicit local process, the maintenance token must be a **fresh real session access token** obtained through the actual authenticated operator mechanism and passed privately by Root in stdin. No password login API, token createAccessToken(userId), refreshAccessToken or fakeMockPrefix is called by this command. It is not used to bootstrap E2E browser contexts; all E2E uses fresh real frontend login.

Strict check sequence for that process:

- read bounded credential stdin exactly once; reject empty/overlength, never print it or persist stdin/raw exception;
- call formal OAuth2TokenCommonApi.checkAccessToken with errors propagating, not development filter which can return null+mock fallback;
- require actual exact access-token mapper row exists and matches returned userId/type/tenant/expiry/client authorization facts. Reject refresh-only compatibility, expired/revoked/missing token and foreign/nonADMIN tenant. Cache stale result is insufficient if actual record is revoked;
- require real actual same-tenant enabled account and token info username/nickname match current formal account, then actual doc_control and update permission. Token scopes are retained and must not be broadened or assigned manually;
- only after these checks may a dedicated maintenance security adapter bind a LoginUser **derived exclusively from verified formal token/account data**, not a supplied operator ID, to current Spring authentication. Use the actual current request/context if present. In a non-web process, an explicit narrowly tested adapter must establish formal Authentication from the verified principal without forging a servlet request; this detail requires Root implementation review and must not invoke the private buildAuthentication with null request or a production MockHttpServletRequest;
- save previous SecurityContext/tenant before binding, reject inherited ignore/visited tenant bypass, and restore/clear in finally after success or any exception. No asynchronous context leakage, thread-local reuse or token written to audit payload. Authentication refresh/relogin is external formal operator work if stale user info fails, not a fallback.

The token mapper read is a configuration-authorization check. It may legitimately fill existing auth caches through the formal API, but must not create business rows/tokens or claim a fully read-only DB transaction around cache behavior. Because token lifecycle/expiry may change between verification and commit, actual short operation/writer registry and immediate service recheck are required; don't make a long-lived fake authenticated session.
