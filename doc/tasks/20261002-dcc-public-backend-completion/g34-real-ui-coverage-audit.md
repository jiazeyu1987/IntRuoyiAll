## BDD for bounded new scripts

- Given a real task-owned original file and a specific exact-name/retained-number refusal path, When the UI attempts the new upload, Then only the expected concrete error plus unchanged original identity/status/history and no accepted new candidate after reload qualifies as scoped expected refusal. Generic errors, timeouts, missing controls or actual success never qualify.
- Given actor A holds the actual Master, When actor B opens the same version, Then displayed holder A and absent/disabled B checkout/checkin before/after reload qualify as refused action availability; no forced click/API race injection. This does not claim a true simultaneous race or backend rejection from a hidden button.
- Given an actual stage task, When submitting without password or with explicitly provided wrong password, Then exact required-password/wrong-password text, unchanged task/round/signatures/status after reload and continuing actual task qualify; traces/screenshot are stopped before any password fill and kept off on cleanup failure.
- Given named UI-created old/new versions and natural current Shanghai date, When readonly observer opens exact rows/details/rounds, Then its mandatory expected facts, frozen signature/attribute tables and named date-list membership are compared; it never invokes an application/signature/checkout/distribution/activation control.
- RED/GREEN must include pure decision contracts rejecting arbitrary exception/business-success/mutated snapshot as expected refusal, invalid config before browser and AST forbidden-action boundaries. Offline tests do not mock a business success and do not launch Playwright.

Only five negative scenarios and detail/history/reminder observation are assigned now. Additional gaps above stay explicit; these two increments do not replace full 27-case orchestration, source viewer, basic-data maintenance or recipient actions.
