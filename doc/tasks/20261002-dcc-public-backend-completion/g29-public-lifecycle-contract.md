## Common nonsecret contract
Mode, taskMarker matching 20261001-dcc-integration plus unique suffix, frontendUrl exactly http loopback:8067/, tenant, actual actorDisplayLabel, real menuLabels array and nonempty postconditions are mandatory. Supported postcondition scopes are body/detail/history/training/project-records; mode-specific core identity/status requirements prevent an arbitrary body “项目” text from making acceptance succeed. Unknown task identity/actual menu/actor/candidate labels must be supplied from real UI facts; no ID/role/default inference.

Nested credentials/token/secret/cookie/storageState/pageHandle/browserHandle/runtime-byte fields reject before launch. Real source/training files are existing absolute task-owned paths with task marker basenames; no synthetic signer images. Form actual attributes contain explicit markets/registrant/manufacturer/transfer and required conditional otherMarket/transferTo. Source-supported markets exactly follow Vue labels.

project-product requires action/create-or-review-or-approve, task projectCode/productCode/reason, expectedSavedStatus=PENDING_REVIEW/PENDING_APPROVAL/COMPLETED respectively, and an exact project-records status postcondition. Create additionally requires projectName/productName/leaderOptionLabel/folderTemplateLabel/reviewerOptionLabel/classification/attributes.

upload-submit additionally requires projectName/projectOptionLabel/folderName/registrationReason/stageLabel/typeLabel/templateFileName/approverText/fileNumber/versionNo/effectiveDate/needTraining/departments/filePath/defaultAttributes/actual attributes/expectedSavedStatus. Initial version is explicitly [A-Z]/1; no A/1 default. Date must be a real ISO calendar date. Nonempty department labels and actual boolean training are explicit. No source input `.first()` or `visible` restriction on hidden upload input; exact 受控文件 form-item anchors one real file input.

native-task requires explicit assign/sign, task fileNumber/versionNo/reason/stageLabel/expectedTaskId/expectedBpmId/historyRoundLabel plus actual department/assignee option for assign, or exact openActionButton/dialogTitle/approve-or-reject/ownerRequired boolean and ownerOptionLabel when needed. Input IDs are comparison facts observed from UI navigation, not business URL construction. Actual route is read only for equality after clicking real row View. Missing owner requirement never silently defaults false. Current history dropdown intentionally locked by the processing route is read only if its already selected visible label exactly matches historyRoundLabel and its real evidence matches BPM; otherwise the runner blocks, never forces another round or alters hidden state.

training requires actual projectName/folderName/versionView/fileNumber/versionNo/expectedBpmId/existing filePath and a training-scope postcondition containing actual filename. Wrong tenant/actor/node button missing/disabled or an explicit page error fails without API/role workaround.

## Evidence and credential capture
Login happens before tracing starts. In a fresh context there is no remembered credential bootstrap. At each signed step, **tracing itself is stopped** before password fill/action; screenshots are disabled. Input removed count0 is safe; remaining input must be uniquely empty, otherwise capture stays off. Only after every page password field is verified empty does fresh tracing resume. This avoids retaining sensitive actions while merely closing a trace chunk. No raw Playwright exception or password text is printed; failures are whitelisted fixed error codes, with no output of failed input/path values.

Trace segments after login contain protected real authenticated browser activity and must remain task evidence; a segment is not a claim of one uninterrupted trace. Root should review trace privacy/credential content before sharing. No video/storageState saved. Natural mutation request records retain method and pathname only (no headers/query/cookies/bodies/response JSON). Temporary source/training/stamp upload attempts are reported separately from formal mutationAttempted, so failed preview upload is not described as zero write. After any action failure the result states STOPPED_AFTER_ACTION_VERIFY_REAL_STATE_NO_RETRY; it never resubmits automatically.

PASS_SCOPED_REAL_UI_DOM_AND_RELOAD is only emitted after each implemented mode's mandatory form/identity/saved state visible assertions and reload. actualGoalComplete remains false. Click acceptance alone, HTTP200, natural request method, offline tests and validate-only never qualify as runtime PASS.
