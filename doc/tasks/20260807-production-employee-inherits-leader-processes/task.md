# 生产员工继承生产组长工序范围

## Task Goal

取消生产员工与工序的直接绑定。生产员工登录一线生产后，只通过启用的生产人员档案归属找到其生产组长，并看到该组长在正式“工序开始”配置中负责路线下的全部工序；生产组长班组配置页不再提供员工—工序绑定入口。

## Milestones

- [ ] M0：建立任务合同，保存共享脏工作区基线并确认既有数据链路。
- [ ] M1：以 BDD/TDD 取得后端与前端 RED，覆盖员工继承组长工序及绑定入口移除。
- [ ] M2：移除员工—工序写入接口与前端配置入口，统一一线工序和员工候选来源。
- [ ] M3：完成目标测试、相邻回归、类型检查与技能证据校验。
- [ ] M4：完成经验沉淀、cleanup、提交和推送。

## Expected Verification

- 后端目标测试：启用生产员工账号按人员档案 `leaderUserId` 获取生产组长正式负责路线的全部工序，不读取员工—工序绑定；禁用档案、多组长归属或组长无正式负责工序时明确失败。
- 后端目标测试：一线运行配置和提交身份校验使用该生产组长的启用人员档案，不再按当前工序筛选员工。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否；员工档案存在时必须使用其唯一生产组长归属，缺失、禁用或多归属均显式失败。
- `是否从根因和长期维护角度解决`：是；移除员工—工序写入面，并将工序权限收口到“人员档案归属组长 -> 组长正式负责路线工序”。
- `是否存在临时补丁或绕过`：否。
