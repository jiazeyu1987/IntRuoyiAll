# 一线 PQC 显示全部 QA 工序修复

## Task Goal

修复一线 PQC 选工序列表只显示单个工序的问题，确保按当前活跃订单产品定位对应工艺路线，再由工艺路线项目代码匹配 QA 检验项目，并展示 QA 检验项目中不重复的全部工序。

## Milestones

- [x] M1 源码定位：确认当前一线 PQC 工序列表的数据来源与错误截断点。
- [x] M2 回归用例：确认已有“同一 QA 产品多工序应全部显示”的目标回归覆盖。
- [ ] M3 正式修复：按活跃订单 → 工艺路线 → 项目代码 → QA 检验项目 → 去重工序链路修复。
- [x] M4 验证：运行目标后端/前端验证，并执行真实路径 E2E 或记录阻塞原因。

## Expected Verification

- 后端目标测试覆盖同一项目代码下多个 QA 检验项目/工序的返回。
- 前端选工序列表显示 QA 检验项目中所有不重复工序，不只显示第一个。
- E2E 通过真实一线 PQC 页面验证列表展示。

## Current Status

blocked

阻塞原因：当前本机运行数据在目标订单路线版本下只存在 1 条 `MES_QA / PUBLISHED` QA 逐工序规程，因此一线 PQC 接口只能返回 1 个工序。源码单测已验证多条已发布 QA 规程时会返回全部工序；要让页面显示截图里的全部 QA 工序，需要先通过正式 QA 保存/发布链路为当前路线版本发布多工序规程，或确认截图对应的是另一个产品/项目/路线版本。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否。
- `是否从根因和长期维护角度解决`：是，目标是修正正式取数链路和回归测试。
- `是否存在临时补丁或绕过`：否。

## Applicable Experience Gates

- `docs/backend-development.md#PQC 待检准入与工序选择必须分离`：订单产品只用于定位路线，路线绑定代码解析唯一 DCC 项目和 QA 产品；候选工序只从 QA 检验项目规程中提取，并按 `routeProcessId + processId` 去重。
- `docs/backend-development.md#零排产活跃订单必须使用发布态正式路线`：工单产品与 QA 产品 ID 不同时，必须通过正式路线绑定和 DCC 项目代码解析 QA 上下文，不得任取第一条。
- `docs/frontend-development.md#前端选择弹框即时反馈门禁`：一线 PQC picker 必须由正式候选数组驱动，并区分 loading / empty / error。
- `docs/e2e-rules.md#E2E 脚本入口存在性门禁`：真实 E2E 必须操作真实前端页面，不能用 API-only 或静态合同冒充。
