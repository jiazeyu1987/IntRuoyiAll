# 受控文件详情页布局修改说明

适用页面为「受控浏览 → 受控文件详情」。下文列出已确认的布局和验收要求。本次范围为页面布局、字段展示和入口位置，业务流程、权限、下载校验和原始记录沿用现有实现。

**预览说明**　配套预览图用于示意页面布局、字段位置和操作入口。图中的文件名、编号、版本、人员、时间、记录条数、业务状态和权限状态均为示例。开发时应按当前用户、文件和版本读取并展示系统实际数据、权限及业务状态。

## 一、页头与操作

**现状**　文件状态与生效信息分散在页头和下方大表中。「更多」菜单和正文、分发等区域存在重复入口。

**目标**

- 所有页签共用文件头。第一行显示完整文件名和受控状态，第二行显示文件编号、查看版本及实际生效时间。查看版本就是当前受控版本时，只展示一次版本号并标注「当前受控版本」。两者不同时分别标明，正文预览打开的版本沿用现有规则。
- 页头右侧依次显示「返回」「更多」「更多操作」。「更多」保留为下拉菜单，按原有顺序显示「发送与签收」「预览受控文件」「下载正文」「BPM 详情」「修改基础信息」「流程导出 Word」。这些操作统一从「更多」进入。「更多操作」继续使用原有独立入口和菜单内容。
- 下载权限按当前用户、文件和查看版本判断。C/4 示例中，「下载正文」在菜单内显示不可用及原因，预览入口可用。本次详情页范围移除「受控打印」「流程打印」以及相关状态、说明和打印记录区域。
- 文件头下方依次显示「概览」「版本与生效」「审批与追溯」「分发与培训」。各页签共用内容边距、分区标题位置、卡片内边距和表头对齐方式。同一行的并排区域顶部对齐，字段标签和值使用统一的列宽和间距。较长的文件名、分类和审批意见可换行。

## 二、概览

**现状**　页面模式、责任面、空白阶段和权限术语占据首屏。附件、关联文件和文件资料散落在页面下方。

**目标**

- 主区左侧展示「文件附件」，表格显示附件名称、用途、大小和当前可用操作。关联文件紧接附件，有记录时显示可识别的名称、编号及对应版本，无记录时用一行「暂无关联文件」。
- 右侧展示「文件归属」，保留所属项目、文件分类、产品名称、可读的目录名称及「关联文档入口」。下方集中展示「文件与申请资料」，包括编制人、申请时间、目标市场、注册人身份、生产方身份、文件转移和申请生效方式等有记录的业务信息。
- 存在版本变更信息时，展示「本次变更」，包括变更类型、来源受控版本和变更说明。文件及归属信息按实际资料填写。
- 去掉「详情查看态」、空白的当前阶段和阻塞原因，以及机器权限术语。影响查阅的权限说明随对应操作展示。

## 三、版本与生效

**现状**　版本信息、受控生效结果、关键时间线和签核表重复展示生效与发布信息。发布件和盖章件入口在多条签核记录内反复出现。

**目标**

- 左侧「受控与下发」展示受控、启用、发布和下发时间。同一时间发生的事项可以在一行列出，各时间不同则分别展示。实际生效时间由公共页头展示。
- 旧版作废情况以实际记录为准。有待核验事项时，在「受控与下发」内简短说明。区分「已作废」和「未查到由本次生效产生的作废记录」。
- 右侧「发布件与盖章件」统一显示两类文件的可用状态和查看入口。下方「版本历史」每个版本一行，显示版本、变更类型、变更说明、提交人。「发起局部变更」「发起换版变更」沿用既有可用条件，放在版本历史标题右侧。

## 四、审批与追溯

**现状**　审批记录、关键记录时间线、审批路线快照、签核摘要和签名留痕重复展示办理人、时间和签名。用户查看一次审批时需要对照多个区域。

**目标**

- C/1 和 C/4 共用同一套「审批记录」表格和「审批规则」入口。表头固定为「办理事项」「办理人」「记录时间」「处理结果」「审批意见」「电子签名」。一次办理在一行集中展示，指派对象、确认的文件负责人等信息随对应事项展示。人员优先展示姓名，只有账号名称时展示业务账号名称。
- 用现有业务关联识别同一次办理，将对应签名状态带入该行。仅有相同办理人或时间的记录仍按独立事项处理。提交、指派、正式会签及无法归入具体事项但独立存在的签名应各自保留。关联到审批的记录以办理时间为主，独立签名使用签名时间。
- 「处理结果」和「电子签名」分别取实际记录。C/4 示例里只确认「已校验」的行在签名列显示该状态，处理结果显示「—」。C/1 示例有审批结果和签名状态时分别显示。
- 「审批规则」默认收起，展开后展示实际环节及通过要求。办理结果、人员和签名以审批记录为主。生效、受控、启用和发布事件归入「版本与生效」，下发、阅读及签收在对应业务区域查看。
- 用户端移除内容哈希、BPM 实例标识、内部 ID、快照编号及签名校验实现细节。原始签名与审计数据继续用于现有业务和授权追溯。

## 五、分发与培训

**现状**　分发节点结果、分发摘要、接收人签收和培训材料分别出现在状态表、时间线与附件表中。分发摘要中的「待签收」与后续签收记录容易被误读为同时生效的状态。

**目标**

- 「分发与签收」简明展示分发节点结果及部门回执有无。列表按接收对象显示部门、接收人、下发渠道、阅读时间和实际签收状态及时间。存在已确认的后续签收记录时，在签收列展示该记录，原分发摘要通过「查看原分发记录」查阅。
- 「培训」展示培训要求、对象和可取得的培训记录。已上传线下培训记录时，提供「在附件中查看培训记录单」，定位到概览的对应附件。附件文件名、大小及下载操作由附件列表展示。发送与签收入口使用页头「更多」菜单。

## 验收重点

| 场景 | 核对结果 |
| --- | --- |
| 切换四个页签 | 文件信息和页头操作位置稳定，同一行的卡片、标签、表头与单元格对齐。 |
| 展开「更多」 | 六项操作位于下拉内，「更多操作」独立可用。C/4 无下载权限时，菜单说明原因。 |
| 对比 C/1 与 C/4 | 审批表列顺序和规则入口一致，同一次办理只展示一次，审批结果与签名状态分别取实际记录。 |
| 核对追溯来源 | 关联失败或存在多次办理时，各条独立记录可查。用户界面仅呈现业务可读字段。 |
| 核对版本与分发 | 发布件、盖章件只展示一组查看入口。C/1 原分发摘要与后续实际签收可分别查阅，培训记录能定位到附件。 |
| 核对权限和打印范围 | 正文、下载、发送、修改与流程操作遵守原有权限，详情页本次范围内没有打印入口或打印区域。 |

C/4 的完整审批结果、审批规则与「更多操作」菜单内容以现有系统数据为准，运行效果在开发后按上述场景验证。
