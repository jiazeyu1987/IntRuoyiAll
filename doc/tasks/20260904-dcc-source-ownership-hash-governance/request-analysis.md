# DCC 源文件独占与 SHA-256 证据治理需求分析

## User Goal

在当前测试环境中，先治理历史 DCC 受控文件的源文件归属和内容哈希证据，再重新判断哪些旧版本可以确定性迁移到 Windchill 风格的 Master / Revision / Iteration 模型。治理结果必须可追溯、可重复核验；系统不能根据文件名、版本号、最新记录或共享引用猜测历史关系。

本任务处理的是版本迁移的前置证据，不代表 Revision / Iteration 改造已经开始，也不以把全部历史记录强行变成可迁移为目标。无法证明的记录应保持 `BLOCKED`。

## Current System

### 已有数据结构

- `dcc_controlled_file.source_file_id` 指向当前受控记录使用的源文件记录；同一 `source_file_id` 在历史数据中可能被多个受控记录引用。
- `infra_file`（代码实体为 `FileDO`）是全局文件表，没有 `tenant_id`；它保存文件配置、路径、名称、类型和大小等文件记录，正文由 `FileService` 根据 `config_id + path` 读取。文件本身不能用业务租户字段判断归属。
- `dcc_controlled_file_source_ownership` 已定义受控记录、当前独占源文件、原始源文件、`source_sha256`、归属类型、认领人和认领时间。现有唯一约束是租户范围内的约束；由于 `infra_file` 全局且同一 source_file_id 可能被不同租户的受控记录引用，治理必须额外做全局引用核验，不能按租户分别认领。
- `dcc_controlled_file_source_migration` 已定义受控记录、旧源文件、隔离后的源文件、SHA-256、迁移状态、错误、执行人和执行时间，可作为可恢复迁移的基础证据。
- 正式迁移 `20260811_dcc_source_ownership.sql` 和测试 schema 已包含上述两张表；测试库只读盘点也确认这些表存在。

### 已有服务能力

- `DccControlledFileSourceOwnershipService` 可以读取源文件正文、计算 SHA-256、复制文件并核对副本哈希，以及写入独占 ownership。
- 新提交文件如已被引用、已被认领或来自原始文件引用路径，会创建字节一致的独立副本；未被引用的上传文件可直接成为独占源文件。
- `DccControlledFileSourceMigrationService` 可以按租户选择未认领记录，以最多 200 条为一批执行历史迁移；当前服务按租户读取共享关系，尚未证明同一全局 source_file_id 在冻结范围外没有其它租户有效引用，不能直接用于本治理。
- `DccControlledFileSourceMigrationCommitService` 在提交前检查 `source_file_id` 是否漂移，并以事务完成受控记录指针更新、ownership 认领和迁移状态更新。
- 管理接口已经提供租户级 readiness 查询和有界批次执行入口，权限要求文控角色及受控文件更新权限。

### 当前能力与本次治理目标的差距

- 现有 readiness 只有总数、已归属数、未归属数、共享组/记录数和失败数，不能逐条解释源文件缺失、软删除、正文不可读、哈希异常、ownership 冲突等原因。
- 当前候选查询没有冻结边界，也没有显式限定 `dcc_controlled_file.deleted = 0`；不能直接等同于本次只读盘点使用的“有效受控文件”口径。
- 当前“存在 ownership 行”即被统计为已归属，未证明 ownership 的受控记录、源文件指针、全局文件记录、正文和 SHA-256 仍一致。盘点中的 7 条已有 ownership 均指向软删除源文件，不能视为有效证据。
- 当前批次接口会直接处理所有选中的未归属记录，没有独立的 `READY / BLOCKED` 决策清单、快照哈希和确认门禁。
- 当前迁移状态主要为 `PENDING / COPY_VERIFIED / COMPLETED / FAILED`；业务上不可判定的历史事实尚未与技术执行失败分开表示。
- 共享源文件当前由排序靠前的一条保留原记录、其他记录复制，且查询按租户过滤。若冻结范围外存在其它租户有效引用，现有逻辑可能把全局共享源误当成当前租户可认领源；本任务必须先以受控数据库读取权限完成全局引用核验，再决定复制或整体阻塞。
- 当前提交检查会防止源文件 ID 漂移，但正式治理仍需确认执行前后正文哈希、文件记录状态和冻结边界没有漂移。

### 测试库只读基线

2026-09-04 的测试库只读盘点，在当次快照边界内报告：

- 18,072 条有效受控文件；其中 18,065 条没有 ownership/hash 行。
- 已存在的 7 条 ownership 引用同一个已经软删除的 infra 文件记录，因此不构成有效证据。
- 43 组源文件被当前盘点冻结范围内的多个有效受控记录共享，共影响 289 条记录；该数字不包含未纳入本次冻结范围的引用，必须由受控数据库读取权限补做全局核验。
- Windchill 迁移 `AUTO_MAP` 候选为 0；38 个近候选全部缺 ownership/hash，其中部分还缺可用源文件记录。
- 版本身份、平台 ACTIVE、空 Master、重复版本、正式指针和检出异常是后续独立 blocker；完成源文件治理不会自动消除这些问题。

这些数字是一次已完成只读盘点的快照结果，不是实施完成量，也不能代表执行治理时仍未变化。任何写入前必须重新冻结边界并复核。

## Constraints

- 当前范围仅限测试环境；不执行生产发布、安全加固、灾备或容量建设，但业务权限、租户隔离、审计、唯一性、幂等和数据完整性仍是必要约束。
- 本规划阶段只读检查仓库和文档，不执行数据库写入、DDL、服务重启、E2E 或 Git 操作。
- 后续任何数据库写入、文件复制或运行态变更都必须获得主任务当轮明确授权，并遵守项目数据库规则。
- 受控文件盘点以授权业务租户、冻结的 `snapshotMaxControlledFileId` 及有效记录口径为边界；对于全局 `infra_file` 的引用关系，只有受控数据库读取权限可以跨租户核验，不能因此扩大业务用户或普通租户的文件可见性。报告不得泄露凭据或文件正文。
- 源文件归属必须绑定明确的 `controlled_file_id`。文件名、文件路径相似、版本文本、创建时间接近、当前最新版本或任一弱字段都不能用来反推归属。
- `source_file_id` 非空或 ownership 行存在，只是引用存在，不代表正文可读、哈希可信或独占关系有效。
- 每条完成治理的记录必须能从受控记录追溯到治理前源文件、治理后独占源文件、文件存储定位、SHA-256、执行人、执行时间、规则版本和执行结果。
- 共享源文件、冻结范围外全局引用、缺失引用、软删除文件、正文不可读、哈希不一致、指针漂移或已存在冲突 ownership 必须失败关闭；不能返回模拟成功、默认值或静默跳过。`infra_file` 没有 `tenant_id`，不把“源文件租户不一致”作为直接校验条件。
- 本任务不能改写既有签名的版本标签、签名哈希、签署信息或证据载荷，也不能改变 original/published/stamped 等非源文件指针。
- 源文件证据治理完成后必须重新执行完整 Windchill 迁移只读盘点；不能只看 ownership 数量宣布可迁移。

## Unknowns

- 再次冻结测试库时，有效受控文件总数和上述 18,065、43、7、38 等快照数字是否发生变化。
- 43 个共享源文件组的正文当前是否全部可读，以及复制全部有效引用所需的实际文件大小和存储空间。
- 缺 ownership 的记录中，除已知 7 条软删除引用外，还有多少属于空引用、物理正文缺失、存储配置不可用、冻结范围外全局引用或内容读取失败。
- 已软删除的 7 个源文件是否存在可验证的对象存储正文、发布副本、备份或经业务批准的替代证据。未获得正式证据前不能恢复或重建。
- 既有 7 条无效 ownership 应采用状态化保留、软删除后重建还是另建更正证据；该处需要数据模型设计评审，不能在 PRD 阶段假设已经解决。
- 历史共享源治理究竟允许一条记录保留共享源文件，还是所有有效引用都复制为独立记录。为避免任意选择，本 PRD 推荐“共享组内全部有效受控记录均生成独立副本”，仍需设计评审确认存储成本。
- 测试环境正式治理的执行维护窗口、执行账号、数据/对象存储恢复点和治理结果确认人尚未确定。
- 是否需要专门的文控管理页面；当前已有管理 API，可先以受控治理包和服务/API 完成第一阶段，页面不是本任务默认范围。

## Risks

- 若直接调用现有批次接口，软删除、正文不可读、已失效 ownership 或冻结范围外全局引用会在写入期间才暴露，无法形成执行前完整 blocker 清单。
- 候选查询未统一有效记录口径时，可能处理已软删除受控记录；未做全局 source_file_id 引用核验时，还可能跨租户拆分一个实际共享组，导致治理总数与 Windchill 盘点总数不一致。
- 共享源文件只让第一条记录保留原文件会把排序顺序变成业务决定，虽不改变正文，却难以解释历史归属。
- 文件复制成功但证据事务失败会留下未绑定文件；重试若没有稳定任务键和副本证据，可能重复复制。
- 读取和计算大量文件哈希可能对对象存储和运行服务产生负载；未完成规模与空间预检前不能直接全量执行。
- 仅保存 SHA-256 而不保存原/新文件关系、位置快照和执行规则，会形成无法解释的“孤立哈希”。
- 治理期间源文件引用或正文发生变化，会让只读快照与最终证据不一致；必须以漂移检查阻塞提交。
- ownership 全部补齐也不代表 Revision / Iteration 可迁移；身份、平台 ACTIVE、指针、重复版本和检出 blocker 仍可能使 `AUTO_MAP` 保持为 0。

## Validation Surface

- 数据结构：ownership 和 migration 唯一约束、受控记录租户字段、全局原/新源文件字段、64 位 SHA-256、执行状态和审计字段；同时核对现有唯一约束是否足以防止跨租户复用全局 source_file_id。
- 只读盘点：按授权业务租户和冻结边界统计有效受控记录、有效/无效/缺失 ownership、按全局 source_file_id 聚合的共享组、冻结范围外其它租户引用、缺失或软删除文件、正文不可读、哈希不一致和漂移。
- 服务行为：独占可读源的直接认领；共享源的逐记录独立复制；原/副本字节哈希相等；失败副本清理；重复执行幂等；并发漂移失败关闭。
- 状态行为：`READY` 只表示满足执行前置；`BLOCKED` 保存稳定原因且不写业务指针；`COMPLETED` 必须具备完整证据；技术失败不得伪装为 blocker 已解决。
- 数据后置：每个有效受控记录至多一个有效 ownership，每个有效独占 source_file_id 至多归属一个受控记录，ownership 与当前 source_file_id 一致，正文重算 SHA-256 与证据一致。
- 影响隔离：original/published/stamped 指针、审批、签名、分发、培训、打印和访问历史保持不变。
- 迁移门禁：完成后重跑完整 Windchill 只读盘点，报告 `AUTO_MAP` 数量和每类剩余 blocker；任何剩余项均可逐条解释。

## Blocking Prerequisites

- 未生成基于最新冻结边界的逐条源文件证据盘点和稳定 blocker 原因码前，不得运行治理写批次。
- 未核对运行态实际数据源、现有正式 schema、对象存储读取能力以及执行账号租户范围前，不得实施；全局 source_file_id 引用核验还必须确认受控数据库读取权限，不能用普通业务租户权限代替。
- 未确认按冻结任务范围全局聚合共享组、冻结范围外其它租户引用的处理方式、共享组“全部复制”规则和预估新增文件体积前，不得处理共享源文件。
- 未为软删除、物理缺失、正文不可读和无 source_file_id 的记录取得可验证来源及人工确认前，这些记录必须保持 `BLOCKED`。
- 未明确维护窗口、恢复点、执行批次大小、任务幂等键、暂停/续跑方式和结果确认人前，不得开始写入。
- 未通过 BDD/TDD、schema 合同、文件字节哈希、只读数据 postflight 和完整 Windchill 盘点重跑，不得宣布本前置完成或进入 Revision / Iteration 回填。
