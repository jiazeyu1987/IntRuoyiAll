# 辅助模式角色责任主体改造

## Task Goal

将批记录表单辅助模式从“一个辅助表格绑定一个固定人员”调整为支持“权限角色作为责任主体”：业务可把辅助行分配给角色，拥有角色的任意人员可填写；最终责任仍由实际填写和签字用户承担。

## Milestones

- [x] 核对现有辅助模式 API、前端填写配置、批次任务生成和执行打开链路。
- [x] 记录 BDD 场景与 RED 证据，覆盖角色辅助主体展示、保存和运行态候选展开。
- [x] 实现最小后端与前端变更，不引入 fallback 或旧数据静默降级。
- [x] 运行定向后端、前端静态合同和必要回归验证。
- [x] 更新验证报告、经验沉淀与收尾状态。

## Expected Verification

- 批记录表单列表能显示辅助模式角色/人员汇总，不再只看旧 `fillRule`。
- 辅助映射编辑可选择人员或角色，保存时以 `fillAssignments` 明确记录责任主体，不再从 `rowKey` 反推人员。
- 后端执行任务生成能把角色型辅助责任主体展开为有效用户候选，保持 `ANY_ONE` 完成策略。
- 旧的单一填写人保存入口不会覆盖已有辅助行分配。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否。
- `是否从根因和长期维护角度解决`：是；将辅助模式责任主体从 `rowKey` 解析转为正式 `fillAssignments` 契约。
- `是否存在临时补丁或绕过`：否。

## Applicable Gates

- 批记录表单、表单槽位、工序开始三类配置不得混用；本任务只改批记录表单辅助模式的责任主体契约。
- 前端静态契约隔离门禁：若宽回归存在无关历史失败，使用任务专用最小静态合同记录 RED/GREEN。
- 前端延迟辅助加载错误归属门禁：填写人规则加载失败必须落到行级，不得污染主列表或吞异常。
- eDHR 详情回填门禁：页面展示必须来自正式配置/API 字段，不得把角色 ID 当用户 ID 或用当前登录人推断。
- 切换填写人快照读取边界：运行态候选应来自执行任务/工作任务快照，不能在弹窗打开时重算全量详情。
- Element Plus 选择框显示门禁：人员/角色选择控件必须有稳定布局，不能只依赖 tooltip 看完整选项。
