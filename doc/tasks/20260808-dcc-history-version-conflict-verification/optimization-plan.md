# DCC 文件上传问题优化建议

## 1. 背景结论

本次优化建议基于账号“赵海辰”在 `/dcc/controlled-file/upload` 的复核结果，以及用户补充确认的业务规则：**文控文件允许发布到“未分类”**。

因此，“技术调研报告没有绑定提交目录，系统自动落到未分类”不再按缺陷处理。它可以保留，但页面表达要更清楚，避免用户误以为系统走了异常兜底。

## 2. 本次不作为缺陷处理的项

1. **技术调研报告落位到“未分类”**
   - 当前表现：类别没有绑定提交目录时，系统把提交目录设为“未分类”，预检显示“可落位”。
   - 处理建议：保留该规则。
   - 优化建议：把提示从“未分类/可落位”改得更明确，例如“该类别未配置专属目录，按规则发布到未分类”。
   - 验收标准：用户能一眼看出这是允许的业务规则，不是系统没查到目录后的异常兜底。

2. **附件入口、培训要求开关、取消会签不保留人员**
   - 当前表现与预期一致。
   - 处理建议：不需要修复，只保留在回归测试范围内。

## 3. 必须优先修复的问题

1. **历史文件升版状态互相矛盾**
   - 当前风险：页面同时提示“将按升版提交”、又提示“未查询到同编号现行版本，将创建新的 master 主档”，最后后端又报编号冲突。
   - 用户影响：用户无法判断这是升版还是新建，严重时可能破坏版本链或误导提交。
   - 修复建议：把“升版”和“新建 master”做成互斥状态。只要选择了历史文件，就必须先定位它对应的现行主档；定位不到时直接阻断，不允许继续显示“新建 master”。
   - 验收标准：选择历史文件后，页面只能出现一种明确状态：可升版、不可升版并说明原因，或需修复数据；不能同时出现“升版”和“新建 master”。

2. **编号冲突时前端仍显示“可提交”**
   - 当前风险：后端已经能识别 `Controlled file number conflicts with the existing logical document chain`，但前端预检仍显示“文件编号/版本 可提交”。
   - 用户影响：用户按页面提示继续操作，最后才被英文错误打断。
   - 修复建议：前端预检必须接入同一套编号链路校验结果；只要后端会判定冲突，前端就要同步显示“不可提交”。
   - 验收标准：编号冲突时，顶部、字段校验、预检列表三处状态一致，统一显示中文错误，不再显示“可提交”。

3. **英文错误需要中文化并定位到字段**
   - 当前风险：页面弹出英文错误 `Controlled file number conflicts with the existing logical document chain`。
   - 用户影响：业务用户难以理解冲突原因，也不知道该改编号、改版本，还是找数据管理员处理版本链。
   - 修复建议：后端错误码保留，但前端展示中文文案，例如“该文件编号已存在版本链冲突，请选择正确历史文件或联系管理员修复主档版本链”。
   - 验收标准：用户看到中文错误、错误挂到“文件编号/版本”区域，并且提交按钮进入阻断状态。

4. **版本号格式校验前后端不一致**
   - 当前风险：新文件版本号填写 `abc` 时，前端预检仍显示“可提交”，实际后端提交阶段才会报版本非法。
   - 用户影响：用户在前端得到错误的可提交信号，浪费操作时间。
   - 修复建议：前端版本规则与后端一致。若系统只允许 `V1.0`、`V2.0` 这类格式，前端输入时就必须拦截。
   - 验收标准：输入 `abc` 后，文件编号/版本立即显示不可提交，并提示正确格式示例。

5. **过去生效日期规则不明确**
   - 当前风险：生效日期选择过去日期 `2026-08-07` 后，前端仍显示“可提交”。
   - 用户影响：如果业务不允许历史生效日期，当前页面会误导用户；如果允许，则需要明确说明。
   - 修复建议：先明确规则。若不允许过去日期，前端预检和提交按钮都要阻断；若允许，页面应显示“允许补录历史生效日期”的说明。
   - 验收标准：过去日期不再处于模糊状态，要么明确可提交，要么明确不可提交。

## 4. 配置类问题建议修复

1. **DHF文件清单没有可上传的正式 DCC 类别**
   - 当前表现：`技术文档 / 清单 / DHF文件清单` 没有关联有效正式 DCC 类别，无法进入正常提交流程。
   - 修复建议：如果该分类应该允许上传，就补齐正式类别绑定；如果该分类仅用于清单展示，就从上传分类入口隐藏或提示“该分类不支持上传”。
   - 验收标准：用户选择该分类后不会卡在半流程；要么能提交，要么明确知道不能提交。

2. **市场调研报告绑定多个正式 DCC 类别**
   - 当前表现：`技术文档 / 设计和开发策划阶段 / 市场调研报告` 同时绑定多个正式 DCC 类别。
   - 修复建议：一个上传分类原则上只绑定一个正式类别；如确实需要多个类别，页面必须让用户选择具体类别，不能后台自动猜。
   - 验收标准：同一个分类不会因为多类别映射导致提交阻断或错误落类。

3. **版本链数据需要巡检**
   - 当前风险：历史文件升版依赖“历史文件、当前主档、现行版本、编号链”一致。如果存在同编号多 master、没有当前 active 版本、历史文件断链，就会触发冲突。
   - 修复建议：增加数据巡检脚本或管理页检查项，定期找出同编号多主档、无现行版本、历史文件找不到主档等异常。
   - 验收标准：上线前能列出并修复异常编号链，避免用户在上传页才遇到冲突。

## 5. 数据质量问题建议处理

1. **`smokeplan1` 昵称显示为 `???????`**
   - 当前表现：会签人员第 2 页存在用户 `smokeplan1`，昵称乱码。
   - 修复建议：先确认源数据是否已经损坏。如果数据库里就是问号，需要按正式源重新修复；如果只是页面显示乱码，需要排查接口、导入、编码链路。
   - 验收标准：昵称字段能正常显示中文或正确原文，不再出现问号替代字符。

2. **会签人员总数存在环境漂移**
   - 当前表现：用户记录为 2148 条、108 页；本机复核为 2125 条、107 页。
   - 处理建议：不直接按缺陷处理，作为环境或数据版本差异记录。
   - 验收标准：如果要做严格回归，先固定测试环境、租户、账号和用户数据快照。

## 6. 推荐实施顺序

1. 先修复历史文件升版状态互斥，避免“升版”和“新建 master”同时出现。
2. 再统一编号冲突的前端预检、提交阻断和中文错误展示。
3. 然后补齐版本格式和生效日期的前端校验规则。
4. 接着治理 DHF文件清单无类别、市场调研报告多类别这两类配置问题。
5. 最后处理 `smokeplan1` 昵称乱码和会签人员数据漂移核对。

## 7. 验收清单

1. 选择历史文件时，系统能准确找到现行 V1.0 主档并按升版生成 V2.0。
2. 找不到历史文件对应主档时，页面明确阻断，不显示“新建 master”。
3. 编号冲突时，页面不显示“可提交”，并使用中文错误。
4. 版本号输入 `abc` 时，前端立即提示格式错误。
5. 生效日期选择过去日期时，页面按最终业务规则明确允许或阻断。
6. DHF文件清单和市场调研报告的类别映射结果清晰，不再让用户进入不确定流程。
7. “未分类”发布作为允许规则保留，但页面说明清楚。
8. 会签人员昵称不再出现 `???????`。

## 8. 建议的最终用户提示文案

1. 历史文件可升版：`已匹配现行版本 V1.0，本次将按升版提交并生成 V2.0。`
2. 历史文件找不到主档：`未找到该历史文件对应的现行主档，不能升版提交，请联系管理员修复版本链。`
3. 编号冲突：`该文件编号存在版本链冲突，当前不可提交，请选择正确历史文件或联系管理员处理。`
4. 未分类允许发布：`该类别未配置专属目录，按规则发布到“未分类”。`
5. 多类别配置：`该分类绑定了多个正式文件类别，暂不可提交，请先修正分类配置。`
6. 无类别配置：`该分类未配置正式文件类别，暂不支持上传。`
