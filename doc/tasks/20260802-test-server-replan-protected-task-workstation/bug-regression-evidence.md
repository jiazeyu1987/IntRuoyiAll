# Bug Regression Evidence

## Bug

测试服务器手动重排时，已报工的受保护任务阻塞为 `受保护任务未绑定工作站`，导致排产工单无法重排。

追加现象：测试服务器排产员工作台工序列表中 `Z2772/Z2510/Z2775/Z2971` 班次产能显示为 0。

再次追加现象：同一工作台截图中剩余 8 个工序仍使用 `TPFB-WS-20260802-*` 临时工作站，班次产能低于本机。

全量追加现象：继续检查测试服当前 WIP 工序后，仍有 14 个工序的工作站编码、班次小时、设备绑定数或班次产能与本机对应工序不一致。

## Expected

第三方报工导入创建正式报工后，手动重排应能保护已报工任务，并从任务工作站解析到工作站产线；不应再出现 `受保护任务未绑定工作站` 或 `受保护任务未绑定产线`。

工作台当前路线工序如果本地有正式同 `process_id` 工作站资源链路，测试服同步后应按排产配置和工作站 `shift_hours` 计算出非 0 班次产能。

临时工作站若已被正式报工/任务引用，修复时必须保留测试服主键，只调整编码、名称、班次小时、产线/车间、设备绑定和设备工序产能，使工作台计算结果与本机一致。

测试服当前 WIP 工序应与本机同工序正式工作站资源口径一致；本机存在但测试服当前 WIP 不存在的额外工序不应被扩大同步。

## Root Cause

第三方导入修复只创建了正式报工和测试工作站，但没有把正式报工的单一工作站反填到受保护任务，也没有给这些测试工作站绑定正式产线。重排保护逻辑先校验任务工作站，再校验工作站产线，因此测试服报错。

工作台班次产能为 0 的直接原因是测试服缺本地正式 `WS-XLSX-00002-*` 工作站资源链路；后端按当前路线工序 `process_id` 查询启用工作站并读取 `shift_hours`，缺工作站时无法把有限小时产能换算为班次产能。

剩余 8 个工序班次产能不一致的原因是测试服使用临时工作站 `shift_hours=7.00`，本机同工序正式工作站为 `shift_hours=10.50` 并有设备绑定。

全量剩余差异的原因是测试服还有 10 个临时工作站未对齐，以及 4 个工序完全缺失启用工作站；这些工序在本机均有正式 `WS-XLSX-00002-*` 工作站和资源链路。
