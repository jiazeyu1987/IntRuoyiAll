## Task Goal

在不执行 E2E、不启动服务、不改数据库、不提交或推送 Git 的前提下，静态检查并修复以下 DCC 主流程的真实代码逻辑问题：

1. 受控浏览：名称权限、内容权限、关联候选、目录/文件/版本切换与租户/上下文隔离。
2. 升版：检出、检入、修改说明、大小版本判定、审批锁定、旧版保留和大版本关联通知。
3. 文件生命周期：配置、新建、审批、驳回、盖章 PDF、默认目录、生效和历史版本。
4. 上传到受控保存：模板文件夹、初始上传、附件一致性、提交审批、盖章 PDF、默认目录和失败真实反馈。

子线程使用 GPT-5.5 high 做只读静态审查；主线程逐条复核反馈，仅修复确认存在的逻辑问题。修复后继续让同一子线程复查，直到其反馈无静态逻辑问题或明确记录剩余阻塞。

## BDD

- BDD: 受控浏览权限隔离 -> Given 用户只有名称查看权限且目标存在多个目录/版本；When 用户浏览、搜索、切换目录、文件或版本；Then 只能得到允许索引的名称元数据，不能得到正文、详情、预览或其他上下文的数据。
- BDD: 受控浏览关联候选 -> Given 用户具备名称查看和关联操作权限但不具备内容查看权限；When 用户搜索并选择关联文件版本；Then 候选按名称权限和业务范围返回，建立关联再次校验关联权限、目标版本和范围，且不泄漏正文。
- BDD: 升版检出检入 -> Given 文件存在正式版本且用户具备编辑权限；When 用户检出、上传新内容并填写修改说明后检入；Then 检出互斥，版本号按统一策略生成，旧版本保留，新版本进入审批且审批期间不可再次检出。
- BDD: 大小版本通知 -> Given 关联指向旧版本；When 检入或生效形成小版本或大版本；Then 小版本不触发大版本通知，大版本只通知有权限的处理人员，关联不自动切换。
- BDD: 文件生命周期 -> Given 新文件已按模板和正式路线提交；When 审批通过或驳回、上传盖章 PDF并进入默认目录；Then 驳回保留原因并要求新文件重传，只有最终批准且盖章 PDF和默认目录保存成功才生效，失败不伪装成成功。
- BDD: 上传到受控保存 -> Given 用户选择有效项目、模板文件夹、模板名称和源文件；When 用户提交、审批并完成盖章 PDF上传；Then 源文件、送审版本、配套 PDF、盖章 PDF和默认目录归属一致，上传入口不创建已有逻辑文件的新版本。

## Design Constraints

- 遵守 `AGENTS.md`、`docs/task-closeout-rules.md`、`docs/backend-development.md` 和前端规则。
- 默认禁止 fallback、降级、吞异常、模拟成功和兼容分支；缺失权限、数据、依赖或服务必须真实失败。
- 不改变与本任务无关的并行改动；当前工作区基线已确认干净。
- 升版与上传新建必须分离；权限必须区分名称查看、内容查看、编辑/审批/关联操作。
- 版本规则必须统一使用正式策略，禁止按局部字符串或通知层硬编码推导。
- 关联、目录、版本、附件和来源都必须按明确业务身份处理，禁止猜测或跨上下文复用。
- 只修复主线程确认属实的子线程问题；子线程提出但经复核不成立的问题不改代码，并记录原因。
