# 活跃订单放行资料用户流程 V2

## Purpose and Scope

本文描述第一版从真实生产/PQC 历史数据形成双 100%，到生产组长申请，再到生产负责人放行的用户流程。重点是用户怎么走、系统怎么显示、失败时怎么提示。

## Evidence Reviewed

- 用户确认：双 100% 必须由生产组长/PQC 组长历史数据支撑。
- 用户确认：测试数据必须符合产品 QA 文件和批记录表单设计。
- 当前系统已有生产组长活跃订单、PQC 组长复核、eDHR 待办和放行入口。

## Primary User Flows

### Flow-01 准备真实业务来源

1. 一线生产人员按产品工序要求提交生产数据。
2. 生产数据进入生产组长报工历史和生产历史表单列表。
3. 生产组长按正式流程确认或审核生产数据。
4. 一线 PQC 按该产品 QA 文件提交过程检验数据。
5. PQC 数据进入 PQC 组长检验历史和历史表单列表。
6. PQC 组长复核通过，系统形成过程检验汇集明细。
7. 系统按这些历史数据汇总活跃订单生产进度和检验进度。
8. 活跃订单达到生产进度 100%、检验进度 100%。

### Flow-02 生产组长申请放行

1. 生产组长登录系统。
2. 进入生产组长工作台的活跃订单列表。
3. 定位目标活跃订单。
4. 页面显示生产进度 100%、检验进度 100% 和“申请放行”按钮。
5. 生产组长点击“申请放行”。
6. 系统弹出确认框，提示将基于历史生产/PQC 数据生成正式批记录、过程检验单和损耗单，并发送生产负责人放行。
7. 生产组长确认。
8. 后端执行正式来源预检、映射、填表和待办创建。
9. 页面显示“待负责人放行”或展示 blocker。

### Flow-03 生产负责人放行

1. 生产负责人登录系统。
2. 进入个人待办或 eDHR 放行待办。
3. 打开该订单的最终放行任务。
4. 查看正式批记录、过程检验单、损耗单和来源摘要。
5. 如资料完整，生产负责人电子签名放行。
6. 系统记录放行签名和放行时间，更新批次状态。

## Alternate Flows

- AF-01 重复申请：若已经生成资料和待办，系统返回既有结果。
- AF-02 资料生成阻塞后重试：用户补齐来源数据或映射后，再次从活跃订单点击申请。
- AF-03 已有批次执行：系统复用已有正式批次执行，只补齐缺失资料或待办。
- AF-04 无损耗订单：若模板支持无损耗确认，系统生成无损耗记录；否则提示模板缺少无损耗口径。
- AF-05 负责人驳回：生产组长看到驳回状态和意见，修复后重新申请。

## Error Flows

- EF-01 双 100% 缺来源：页面显示进度 100%，但后端发现没有对应历史数据，申请失败并提示“进度来源不完整”。
- EF-02 生产表单不完整：缺设备、设备参数、生产数量、损耗原因或生产组长确认，申请失败。
- EF-03 PQC 表单不完整：缺 QA 项目、检验值、设备编号、判定或 PQC 组长复核，申请失败。
- EF-04 映射缺失：历史字段无法映射到批记录/过程检验单/损耗单目标字段，申请失败。
- EF-05 签名缺失：填写人、审核人或签名时间没有正式来源，申请失败。
- EF-06 负责人缺失：资料可生成但无法推送放行待办，申请失败并提示负责人配置。

## Out-of-Scope Flows

- 自动后台触发申请。
- API-only 直接生成资料并跳过页面。
- 直接修改活跃订单进度制造双 100%。
- 跳过生产组长/PQC 组长历史列表和历史表单。
- 跳过生产负责人签名放行。

## Open Questions

- OQ-01 生产负责人待办展示在 eDHR 工作任务还是统一审批中心，第一版可优先复用现有 eDHR 工作任务。
- OQ-02 blocker 展示是行内摘要加详情抽屉，还是直接弹窗展示，第一版可先摘要加详情。
- OQ-03 负责人驳回后是否自动回到 `READY_TO_APPLY`，还是保留 `REJECTED` 等待用户手动重试。
