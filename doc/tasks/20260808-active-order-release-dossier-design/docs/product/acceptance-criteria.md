# 活跃订单放行资料验收标准 V2

## Purpose and Scope

本文定义 V2 需求的可测试验收标准。验收重点不是单纯出现双 100%，而是双 100% 背后是否存在符合产品、QA 文件、批记录表单和人员签名要求的真实历史数据。

## Evidence Reviewed

- PRD V2。
- 用户关于测试数据、历史报工、历史表单、QA 文件、批记录表单和签名来源的澄清。
- 项目 no-fallback 规则和 MES 三类配置术语契约。

## Acceptance Criteria

- AC-01 测试环境存在任务自有活跃订单，且生产进度 100% 来自生产组长报工历史和生产历史表单。
- AC-02 检验进度 100% 来自 PQC 组长检验历史、PQC 历史表单和复核汇集明细。
- AC-03 生产历史数据符合目标产品对应工序的批记录表单约束，包括设备、设备参数、数量、损耗和必填字段。
- AC-04 PQC 历史数据符合目标产品对应工序的 QA 文件约束，包括检验项目、方法、标准、上下限、设备要求、实测值和判定。
- AC-05 点击“申请放行”后，后端重新校验双 100% 来源，而不是只信任活跃订单显示字段。
- AC-06 系统创建或复用正式批次执行，并能按订单、产品、路线、工序和批号追溯。
- AC-07 正式批记录表单已填字段能逐项追溯到一线生产提交、生产组长确认、设备参数和签名时间。
- AC-08 正式过程检验单已填字段能逐项追溯到一线 PQC 提交、PQC 组长复核、QA 文件约束和签名时间。
- AC-09 正式损耗单已填字段能追溯到生产损耗数量、损耗原因、工序和报工来源。
- AC-10 表单填写人等于实际一线提交人，审核人等于对应生产组长/PQC 组长，签名时间等于对应提交/审核签名时间。
- AC-11 资料完成后生产负责人收到放行待办，不直接变成已放行。
- AC-12 生产负责人能打开待办查看资料，并完成放行或驳回。
- AC-13 缺少 QA 文件、批记录表单、设备参数、历史表单、签名、损耗映射或负责人时，系统返回 blocker，不生成假资料。
- AC-14 重复申请不重复创建批次执行、正式表单、字段审计或负责人待办。
- AC-15 审计记录包含来源快照、映射结果、申请人、生成时间和负责人待办。

## Rejection Criteria

- RC-01 通过直接改活跃订单进度字段制造双 100%。
- RC-02 测试数据不进入生产组长/PQC 组长历史列表和历史表单。
- RC-03 PQC 数据不符合 QA 文件仍能生成过程检验单。
- RC-04 生产数据不符合批记录表单仍能生成批记录。
- RC-05 用当前登录人或当前时间默认填填写人、审核人或签名时间。
- RC-06 用 `formBindings`、默认 `MAIN`、工序开始配置或空值替代正式批记录表单。
- RC-07 用 raw payload、状态字段或前端文案替代过程检验结构化数据。
- RC-08 用空损耗单或默认无损耗替代真实损耗口径。
- RC-09 生产组长申请后直接完成放行，绕过生产负责人。

## Product Blockers

- PB-01 没有符合目标产品的 QA 文件和批记录表单，不能验证成功路径。
- PB-02 没有可创建历史生产/PQC 数据的测试入口或 fixture，不能验证真实双 100%。
- PB-03 没有生产组长、PQC 组长、生产负责人和一线人员签名配置，不能验证人员和时间映射。
- PB-04 损耗单或过程检验单正式承载未确认，不能宣称完整资料包生成成功。
