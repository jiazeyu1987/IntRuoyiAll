# 活跃订单放行资料配置、安全与部署设计

## Purpose and Scope

本文定义申请放行资料生成能力涉及的配置、权限、安全控制、部署注意事项和观测要求。第一版不引入外部服务和新密钥。

## Evidence Reviewed

- eDHR 现有权限包括批次执行、批记录执行、工作任务、放行预检、放行提交、放行审批和操作审计。
- 项目规则要求写操作必须有权限码、对象范围、审计事件和失败原因。
- 生产组长、PQC 组长和生产负责人是不同职责，申请与放行不能混用权限。
- 当前系统使用 Spring Security 权限注解和前端路由/按钮权限控制。

## Configuration

- 放行负责人规则：
  - 推荐优先复用 eDHR 工作任务分配规则 `TASK_TYPE_RELEASE_APPROVE`。
  - 若业务需要“生产负责人”独立于 eDHR release approve 规则，则新增显式配置，并在本功能中只读取该正式配置。
- 正式表单配置：
  - 批记录：工序设置逐工序正式批记录绑定。
  - 过程检验单：路线或项目正式过程检验报告配置。
  - 损耗单：路线或项目正式损耗报告配置。
- 字段映射配置：
  - 批记录字段映射复用现有字段规则。
  - 过程检验单和损耗单需要新增或复用正式字段映射，映射缺失时阻塞。
- 放行预检配置：
  - 复用 eDHR dossier requirement setting。
  - 申请前后均需执行预检，确保资料包满足放行要求。

## Secrets

- 第一版不新增 secrets。
- 申请接口不得接收或保存生产负责人签名密码。
- 若业务要求生产组长申请时电子签名，密码只用于当前请求校验，不得写入日志、申请记录、审计 payload 或前端缓存。
- E2E 测试签名密码只能来自环境变量，不得写入测试代码、截图、日志或任务文档。

## Permissions

- 生产组长申请权限：
  - `mes:pro-process-pool:team-leader-active-order-release-apply`
  - 仅允许申请当前登录生产组长负责的活跃订单。
- 活跃订单列表权限：
  - 复用现有生产组长活跃订单查询权限。
- 生产负责人放行权限：
  - 复用或扩展 `mes:pro-edhr-release:approve` / eDHR 工作任务处理权限。
  - 负责人必须是待办责任人或候选规则命中的用户。
- 审计查询权限：
  - 复用 eDHR operation audit 查询权限。
- 禁止仅靠前端按钮权限控制；后端必须校验对象归属。

## Security Controls

- 对象级授权：
  - 申请人必须是活跃订单负责人。
  - 放行人必须是 release approval task assignee 或候选用户。
- 租户隔离：
  - 活跃订单、生产工单、PQC 任务、批次执行、放行事务和工作任务必须同租户。
- 电子签名：
  - 不复制签名密码，只引用签名证据 ID、签名用户、签名时间、来源对象和证据 hash。
- 审计：
  - 记录申请、预检、阻塞、生成、待办创建、负责人放行、驳回和重复幂等命中。
- 错误暴露：
  - 用户可见错误显示业务对象和处理建议。
  - 日志不得包含密码、token、私钥或连接串。
- Fail fast：
  - 缺正式来源、缺权限、缺配置、缺字段映射、缺负责人时立即失败，不进行默认补齐。

## Deployment

- 第一阶段：仅新增文档和设计，不发布。
- 实现阶段需要：
  - 后端新增服务、接口、权限码、迁移和测试。
  - 前端新增 API、按钮、状态展示和静态合同测试。
  - 数据库迁移前按真实库核对 schema。
  - 菜单权限发布前核对租户包和角色绑定。
- 不需要新增运行时端口、外部服务、消息队列或定时任务。
- 若新增放行事务状态，需评估已有放行页面、统计、审批中心和归档逻辑的兼容影响。

## Observability

- 应记录结构化业务日志：
  - `activeOrderId`
  - `applicationId`
  - `batchExecutionId`
  - `releaseTransactionId`
  - `releaseApprovalWorkTaskId`
  - `sourceSnapshotHash`
  - `status`
  - `blockerType`
- 应提供申请结果查询或活跃订单列表状态字段，减少排查时直接查库。
- 操作审计应能回答：
  - 谁申请了放行资料。
  - 系统生成了哪些正式资料。
  - 每张资料引用了哪些来源。
  - 为什么某次申请被阻塞。
  - 谁最终放行或驳回。

## Open Questions

- OQ-01 菜单权限是否需要在生产组长角色默认包中自动加入，还是由系统管理员手动配置。
- OQ-02 操作审计 payload 的字段粒度是否需要满足 CSV/OQ/PQ 证据要求。
- OQ-03 是否需要在 eDHR 看板增加“待负责人放行资料包”统计。

## Design Blockers

- DB-01 无负责人配置规则时，部署后无法完成主流程。
- DB-02 无菜单权限和角色绑定时，按钮不可见或后端 403。
- DB-03 无测试签名和测试租户时，不能执行真实写入型放行链路验收。
