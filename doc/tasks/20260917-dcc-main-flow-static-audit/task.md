## BDD

- BDD: 受控浏览权限分层 -> Given 用户只有名称权限, When 浏览/搜索/关联候选发现文件, Then 只能看到名称候选且正文、详情、预览均需内容权限重新校验。
- BDD: 升版检出检入 -> Given 已有受控文件需要修改, When 授权人员检出并检入新内容, Then 新小版本/大版本按策略生成，旧版本保留，新版本审批与盖章 PDF 完成后才生效，关联不自动切换。
- BDD: 文件生命周期闭环 -> Given 新建或升版文件进入审批, When 审批、驳回、盖章 PDF、受控保存和替代发生, Then 状态、正文锁定、默认目录、历史版本和关联通知边界保持一致。
- BDD: 上传到受控保存 -> Given 上传人员选择项目和模板文件夹, When 首次上传源文件并完成审批和盖章 PDF, Then 保存逻辑文件与初始版本，使用正式默认目录受控保存并最终生效。

## TDD Notes

- RED: pending-subagent-findings -> 待子线程给出具体静态缺陷后，为确认缺陷补最小失败合同。
- GREEN: pending-fix -> 待确认缺陷修复后运行对应定向测试。
- REGRESSION: pending-final-sweep -> 待所有确认缺陷关闭后运行最终静态检查。

## Design Constraints Check

- 遵守无 fallback、无降级、无吞异常、无模拟成功。
- 受控浏览严格区分名称权限与内容权限。
- 关联候选发现、建立关联权限和业务范围独立校验。
- 上传新建与升版入口分离，首次上传不得创建新版本，已有同身份文件不得由上传入口升版。
- 新版本审批通过并完成盖章 PDF 受控保存后才生效；已有关系不自动切新版。
- 生效失败必须暴露真实原因，不允许只改状态。
- 文件、目录、版本切换必须重新校验权限与数据范围。
