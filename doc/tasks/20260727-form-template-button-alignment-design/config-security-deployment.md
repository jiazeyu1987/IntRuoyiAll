# Config, Security, and Deployment Design

## Purpose and Scope

本设计定义 FormCenter 表单模板三个按钮独立执行后的配置、权限、安全、部署和可观测性边界。目标是移除不必要的跨域依赖，不新增外部服务或降级路径。

## Evidence Reviewed

- 模板列表和模板操作已有 FormCenter 权限控制。
- `编辑`入口继续使用现有 `form:template:create` 权限指令和模板状态判断。
- `打开`、`编辑`、`填写`均可在当前模板页面内完成，不需要 MES 路由权限。
- 当前本机运行态使用 `int_main` 的前端 `8081`、后端 `48081`。

## Configuration

- 不新增环境变量、运行端口、服务发现、定时任务或跨模块配置。
- 不修改 Vite、Spring Boot 或数据库连接配置。
- 前端继续使用现有 FormCenter 路由和组件。

## Secrets

- 登录凭据继续只从本机 `.env` 配置读取，验证日志不记录密码、token 或 cookie。
- 真实 E2E 只记录身份标签 `芋道源码/admin`、本机 URL 和行为结果。

## Permissions

- 模板池读取继续使用既有 FormCenter 查询权限。
- `编辑`继续受现有前端权限指令和后端模板保存权限约束。
- `打开`和`填写`不借用 MES 批记录权限，也不通过构造 `reportId` 绕过权限。
- 权限不足或保存失败时显示真实错误，不默认成功。

## Security Controls

- 不向前端暴露无业务来源的批记录绑定字段，减少跨租户 `reportId` 泄漏和越权跳转风险。
- 三个按钮只使用当前租户模板池返回的当前模板上下文。
- 禁止用户输入、名称匹配或 URL 参数伪造批记录绑定。
- 不保留“检测到绑定才跳 MES”的隐藏兼容逻辑。

## Deployment

- 前端部署包含按钮行为和类型契约纠偏。
- 后端部署包含 FormCenter VO、DO 和运行态映射的错误字段移除。
- 删除未发布引用的错误新增迁移，不要求当前发布执行任何 schema 变更。
- 本次不操作远端环境、不执行删列。

## Observability

- 页面级验证应记录三个弹窗标题、当前路由和是否出现批记录绑定错误。
- 后端合同测试记录 VO、DO 和运行态不再暴露七个错误字段。
- 数据合同记录错误迁移不再存在；本地冗余列仅作为后续迁移审计事项。

## Open Questions

- 是否清理已存在环境中的冗余列和索引，需要单独迁移审计与授权。

## Design Blockers

- 当前按钮功能、API 和部署无 blocker。
- 物理 schema 清理不在当前任务授权范围，不能作为本次发布的隐式步骤。
