# 融合后批记录 Word 导入与工艺路线升版 E2E 验证

## Task Goal

在 `int_main` 融合运行态上，通过 Playwright 真实页面验证批记录表单 Word 导入、工艺流程重建开关、既有路线候选升版及发布前后绑定关系保留行为。验证不得使用 API 写入、SQL 直改、mock 或 admin 基线数据代替真实用户路径。

## Milestones

1. `M1 前置门禁`：确认融合代码来源、前后端端口归属、运行 Jar、登录租户/账号、页面入口、E2E 脚本及任务专用 Word/路线数据。
2. `M2 真实页面负向路径`：不勾选“工艺流程”导入时，不重建工艺流程图，不产生错误路线升版。
3. `M3 真实页面升版路径`：勾选“工艺流程”导入既有路线时，只生成或更新候选版本，发布前生效路线保持不变。
4. `M4 发布与绑定核验`：通过真实页面发布候选版本，确认旧工序正式批记录绑定身份、工序开始配置和表单槽位关系保留，新工序获得正式绑定身份，且不存在工序结束业务绑定。
5. `M5 清理与收尾`：通过真实页面清理或恢复任务自有数据，记录 Playwright 证据与最终结论。

## Expected Verification

- `int_main` 前端 `8081`、后端 `48081` 均可访问且进程归属 `E:\IntRuoyi`。
- 运行 Jar 的来源、哈希、关键 MES 类与融合源码一致。
- 使用已确认的本机测试租户/账号登录；密码和 token 不进入日志。
- 使用任务标识为 `E2E-WORD-ROUTE-20260815` 的可追踪、可清理 Word、DCC 项目与路线数据。
- Playwright 从真实批记录表单页面上传 Word，验证文件列表、请求、候选版本、发布动作和页面可见结果。
- API 仅用于只读最终状态核验；所有业务写入和清理均通过真实页面完成。
- 记录目标请求、业务码、页面断言、console/page error、截图、结果 JSON 和清理结果。

## BDD Scenarios

- `BDD: 未选择工艺流程时不重建路线 -> Given 已存在生效路线和任务自有 Word 文件；When 用户不勾选“工艺流程”并从批记录表单页导入；Then 只处理已选择的导入内容，生效流程图和路线版本保持不变。`
- `BDD: 选择工艺流程时创建候选升版 -> Given 已存在生效路线及正式逐工序批记录绑定；When 用户勾选“工艺流程”并按 Word 工序顺序导入；Then 系统生成或更新路线候选版本，发布前生效路线保持不变。`
- `BDD: 候选发布后保留既有绑定 -> Given 候选版本包含旧工序和 Word 新增工序；When 用户从真实页面发布候选；Then 旧工序正式批记录绑定身份、工序开始配置和表单槽位保持，新工序使用正式权限范围，工序结束不产生业务绑定。`

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否。
- `是否从根因和长期维护角度解决`：是；本任务仅验证融合运行态和正式业务链路，不修改或绕过正式数据来源。
- `是否存在临时补丁或绕过`：否。

## Applicable Experience Gates

- 融合 E2E 必须使用 `int_main` 成对端口 `8081/48081`，并证明监听进程和运行 Jar 归属 `E:\IntRuoyi`；运行 Jar 关键 MES 类与当前融合实现不一致时立即阻断。
- 写入型 E2E 只能使用已确认测试租户/账号和任务自有、可清理数据；只有 `芋道源码/admin` 基线身份而无任务专用 fixture 时不得写入。
- Word 路线导入必须锁定唯一未结束候选；待审批/待发布候选、来源漂移或候选身份漂移时不得继续导入或覆盖。
- 升版候选必须分别冻结逐工序批记录表单、表单槽位和工序开始配置；旧工序正式权限范围及两类冻结 hash 原样保留，新工序发布后才能建立正式身份，禁止工序结束业务绑定。
- Playwright 上传 Word 后必须看到上传列表或目标上传请求；API 和数据库只能用于只读最终核验，不得代替页面导入、发布或清理。
