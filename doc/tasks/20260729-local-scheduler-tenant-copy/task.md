# 20260729 本地排产数据租户复制验证

## Task Goal

在本地服务器数据库中，先备份并删除“测试租户”的排产相关数据，再从“芋道源码”租户导出排产员工作台全部数据包，导入到“测试租户”，最后分析导入前后与源租户是否一致。

## Milestones

1. 前置核对：确认本地数据源、源/目标租户 ID、排产相关表清单和删除顺序。
2. 目标备份：导出测试租户删除前排产相关数据快照，作为恢复依据。
3. 清空目标：仅删除测试租户排产相关数据，不触碰芋道源码或其它租户。
4. 导出导入：从芋道源码导出全部数据包，导入到测试租户。
5. 一致性分析：对比关键排产表行数、关键业务键和导入结果计数，记录差异。

## Expected Verification

- 租户核对：`system_tenant` 中准确识别“芋道源码”和“测试租户”。
- 安全备份：目标租户删除前快照写入任务目录，且记录恢复方式。
- 删除验证：测试租户排产相关表目标范围计数归零或符合保留规则。
- 导入验证：全量数据包导入接口返回成功，重排主数据/排产工单/运行态计数可见。
- 一致性验证：源租户与测试租户关键表行数和业务键对比报告。

## Recovery Plan

- 删除前先生成测试租户排产相关数据 JSON 快照，保存到本任务目录。
- 如果导入失败或一致性异常，使用该快照按原租户 ID 恢复测试租户排产数据。
- 在恢复未验证前，不标记任务完成。

## Applicable Experience Gates

- 写入型数据操作必须确认目标租户，不得污染生产租户、admin 基线数据或其它业务数据。
- 删除前必须有精确目标范围、备份和恢复路径。
- PowerShell 命令不得使用 `&&`；中文/JSON 文件必须 UTF-8 写入。
- 手动重排数据包必须承载排产工单快照、任务扩展、日历产能、用料/库存和运行态数据。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否。缺租户、缺表、导入失败或对比异常必须显式阻塞。
- `是否从根因和长期维护角度解决`：是。通过正式全量数据包接口验证跨租户导出导入，不用 mock 或手工补数据冒充成功。
- `是否存在临时补丁或绕过`：否。
