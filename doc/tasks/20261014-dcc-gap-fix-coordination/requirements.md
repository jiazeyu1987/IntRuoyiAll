# 已收到的需求与本轮范围

权威来源为本聊天用户上传/浏览需求与随后逐项修复授权。上轮分析是待复核结论，不代替源码证据。

## 上传
选择项目，加载三个默认属性并修改本次值，选文件夹、大类/小类或其他。维护类型带出审批矩阵、会签部门和批准规则；其他由编制人配置本次会签部门/批准人/文控职责，直接主管仍由组织关系取得。本次矩阵不新增公共矩阵且不改流程。上传人即编制人，不可任意选择；部门和主管从账号组织关系取得。提交先主管签名审核，再负责人签名指派本部门会签人，再实际会签；具体会签人不能系统自动选。

会签部门均可增删，不设不可删部门，空提示“请至少选择一个会签部门”并阻止。最终所选默认及新增部门全部必须通过。下发部门初始从类型默认会签部门复制，独立增删、保存，不修改会签/公共配置。受控且生效后向所选部门全部人员下发，逐人电子签名。

上传及升版多附件；全部源文件及本次所有附件上传/保存成功后才能提交，确认框列附件。本次申请和版本附件隔离。确认框包括名称、编号、初始版本、项目、文件夹、类型、编制人、主管、生效方式、三个属性、附件、关联、会签/下发、批准人、培训及部门全员下发说明。取消保留填写，不创建审批。

规定必填：项目/文件夹/类型/名称/编号/初始版本/生效方式/规定属性。无主管/负责人/批准人或上传保存失败/未完成均具体报错阻止。

培训checkbox默认不选。负责人在批准弹框确认，默认申请人，可调，不加批准后负责人节点。负责人组织培训/维护/文控交接；培训记录由本次原上传人通过培训记录单上传入口保存到文件附件，改负责人不改上传责任。培训记录保留申请/版本/上传人/时间，历史显示对应记录。

生效方式为“文控审核后立即生效”或“延迟生效”。立即：文控通过真实签名后记录实际生效时间。延迟：上传不填具体时间；文控后完成必要培训，然后给原编制人“延迟生效确认”任务；无需培训直接给任务。任务提示“文件生效时间由编制人根据文件输入、输出及来源之间的衔接关系确定。”生效时间不得早于本次确认时间；未选或未签不能完成/后续受控。以确认节点真实签名时间记录受控时间。标准化审核即文控。后续受控/生效/盖章/下发第8项尚未收到，不猜。

切项目/类型前对修改过的属性/部门/关联提示确认，重新加载并核对；跨项目关联清除，提交仍校验所属。草稿读保存实际值，不因默认变更覆盖；保存生效方式。新申请提交校验矩阵/人员，维护类型公共矩阵变化展示并确认；其他沿用本次配置不更新公共矩阵。驳回重提沿原保存矩阵并核对人员，主动改类型才匹配新矩阵，第6项细节未收到。

## 浏览
目录选项目/文件夹→列表→浏览；搜索名称/编号，当前项目或权限项目，结果展示来源项目、文件夹和版本状态。正文校验阅读权限，显示名称/编号/版本/状态/正文，有详情入口；各格式按规则缩放/旋转/翻页/正文搜索/水印/浏览时间。画面改变不能改系统原件。审批任务和历史读精确对应正文，不自动当前；小版本仅显示“草稿”不显示小版本号。日常不开放待生效或草稿。

详情各分区对应所选版本/申请不混其他版；基本信息含身份/状态/位置/类型/编制/备注/生效方式/延迟所选时间/实际生效/受控/保存属性/检出。升版含实际变更/说明/来源受控版/小版本草稿记录。附件查看下载分别授权；培训记录如上。关联引用分别显示固定关联版、引用来源、被引用项目明细及去重项目数；保留提交/后补/整改安排，不自动新版。文本在“相关版本作废后保”截断。
