# 岗位需求分解矩阵全链路差距收敛 PRD

## Purpose and Scope

本 PRD 将 `岗位需求分解矩阵.xlsx` 中的 62 项需求收敛为一个业务节点：**从 ERP 已确认生产订单进入 MES，到生产、PQC、正式批记录和放行完成的跨岗位可追溯闭环**。

本节点采用增量交付，不重复实现已经在 `20260731-team-leader-workbench-prd-plan` 中交付并通过真实 E2E 的班组配置、活跃订单、报工复核、FIFO/手工分配、订单工序完成、正式批记录回填和组长工作台。目标是统一权威来源、修复契约差异并补齐 Excel 要求的缺失链路。

### Actors

- 计划排产员：在 ERP/线下确认待执行订单。
- 生产班组长：维护班组执行配置、加入活跃订单、关联调拨、查看开工检查、复核与分配报工、上报生产异常和执行班组日结。
- 仓库 / 物料员：在 ERP 完成调拨、发货，并按正式调拨数据核对实物和批次。
- 生产员工：按 SOP 生产，按工序记录实际人员、设备、参数、数量、损耗、原因和签名。
- QA：维护和发布产品/路线版本/工序级检验规程。
- PQC 检验员：执行首检、上午巡检、下午巡检和适用的末检。
- PQC 组长：复核、退回 PQC 提交并跟进质量异常。
- 放行负责人：审核生产、检验、物料、签名和异常证据后放行或退回。

### System Boundary

- MES 不创建或编辑 ERP 生产订单、调拨申请和调拨单。
- MES 读取 ERP 已同步的候选事实，并负责跨角色关联、状态、验证、追踪和放行证据。
- 开工检查只给出通过项、缺失项和阻塞原因；不替生产班组长决定是否上报异常，也不自动创建异常。
- 原始生产事实允许在未分配订单时保存；订单归属由生产班组长复核后分配。

## Product Principles

- 单一事实来源：同一业务事实只能有一个权威写模型，其他页面通过服务或读模型引用。
- 事实先于归属：生产员工先提交工序事实，班组长后续把已复核数量分配到活跃订单。
- 配置版本化：QA 规程、生产系数、人员、设备、原因和签名在业务记录中保留当时快照。
- 正式来源不可猜测：缺订单、路线、系数、规程、批记录绑定、签名或调拨来源时 fail fast。
- 原始记录不可覆盖：退回、补正、确认和回填都保留修订链与审计。
- 真实用户路径：最终验收必须通过真实登录、菜单、页面、签名和任务数据执行。

## Authoritative Data Contracts

### Active Order

- `mes_pro_process_pool_active_order` 升级为生产、PQC、批记录、调拨追溯和放行共同使用的权威活跃订单聚合。
- `mes_pro_process_pool` 只保存订单工序的执行投影和事件指针，不再作为 PQC 独立活跃订单来源。
- 活跃订单唯一业务键至少包含租户、生产订单、正式路线/路线版本；生产组长责任关系单独建模，不再把 `leader_user_id` 作为跨角色活跃订单身份的一部分。
- 所有加入、移出、终止、完成和重新进入行为必须通过同一命令服务及状态机。

### Production Quantity

- ERP 下达的订单产品数量保持不变。
- 订单工序目标数量固定为：
  `ERP 固定订单数量 × 当前订单正式路线工序生产系数快照`。
- 生产系数正式来源为路线工序配置 `MesProRouteFlowProcessConfigDO.productionQuantityFactor` 或订单排程已冻结的同源快照。
- 系数缺失、为零、为负数或来源冲突时阻塞分配与完成，不得默认为 `1`。

### Production Report

- 原始报工以工序、实际员工、设备台账设备、设备参数、完成数量、损耗数量、原因、客户端时间和电子签名为核心事实。
- 原始报工不要求预先绑定生产订单、生产任务或工作站。
- 报工确认后由分配记录把一个原始报工拆分到一个或多个权威活跃订单；分配总量必须等于确认量。

### QA Regulation and PQC

- QA 规程唯一业务键为产品、正式路线版本、路线工序和规程版本。
- 发布版本不可原地修改；新版本只影响新生成任务，历史任务保留原规程快照。
- PQC 任务身份至少包含活跃订单、路线工序、检验类型、业务日期、班次、轮次和规程版本。
- PQC 提交不依赖最新生产事件，不复制生产员工的设备或工作站上下文。

### Batch Record

- 正式批记录表单只读取 `MesProRouteFlowProcessBatchRecordDO` 中当前路线工序的正式绑定。
- `工序开始` 只处理开始节点附件/责任动作。
- `formBindings` 只处理特殊表单/动态表单槽位。
- 三条链路不得互相替代。
- 订单工序完成时，系统按该订单工序全部已确认分配及源报工做确定性聚合，不得使用一个代表事件代替全部事实。

### Release

- 放行预检必须读取真实来源：订单工序完成、正式批记录、已确认 PQC 任务、调拨和物料批次、阻塞异常、返工/报废/库存状态及签名。
- 现有“来源未接入”检查只能作为明确阻塞，不能返回默认通过；对应来源接入完成前不得宣布 Excel 放行目标完成。

## Requirements

### RQ-01 ERP 候选与权威活跃订单

覆盖 `M01`、`M03-M04`。MES 读取已确认 ERP 候选，授权人员可触发正式同步；生产班组长核对后加入权威活跃订单。只有该聚合中的有效订单可进入报工分配、PQC、批记录、调拨追溯和放行。

### RQ-02 调拨、物料和开工检查

覆盖 `M02`、`M05-M08`。活跃订单可关联多个调拨申请/调拨单/发货批次，支持分批发货、补料、退料、多物料和多批次。物料员的实物核对结果形成追溯证据。开工检查展示正式来源和缺项，但不自动创建异常。

### RQ-03 班组配置、设备台账和责任范围

覆盖 `D01-D10`。生产班组长可维护员工、原因、设备绑定、参数上下限和责任范围。设备只能从正式设备台账选择；报修/禁用设备不可用于新报工。范围扩展到员工、工序、工作站、产线、设备和订单。所有变更留审计。

### RQ-04 工序事实、报工复核、分配和批记录

覆盖 `M10-M11`、`M16-M19`、`D11`。员工按 SOP 生产并提交订单无关的工序事实；组长通过或退回且不覆盖原始记录；确认量可按 FIFO 建议或手工分配到活跃订单；目标数量使用生产系数；完成后对全部事实做确定性批记录回填。

### RQ-05 生产侧日结和只读状态

覆盖 `D12-D14`。生产班组长可查看班组日结、PQC 只读状态和批记录进度，不获得 QA/PQC 判定权限，也不手工拼接批记录。

### RQ-06 QA 规程生命周期

覆盖 `M09`、`D15-D23`。QA 可查看正式工序上下文，维护检验项目、首检、上午巡检、下午巡检和末检规则，执行草稿校验、完整性检查和发布。发布版本不可污染历史任务。

### RQ-07 PQC 任务、提交、复核和过程检验

覆盖 `M12-M15`、`M20-M21`、`D24-D37`。系统按规程生成首检/巡检/末检任务；检验员选择实际人员、逐件填写、记录不合格/损耗/失败原因并签名；PQC 组长筛选、查看、确认或退回，禁止自我确认；确认数据汇集为过程检验记录并可形成质量异常。

### RQ-08 PQC 日结、快照、完整性和放行

覆盖 `M22-M23`、`D38-D39`。PQC 日结列出未提交、未确认、退回未补正、不合格未处理和影响放行事项。配置变更不改写历史。完整性检查通过后才生成放行待办，放行或退回均保留签名、原因和审计。

## Business Rules

- FIFO 是可编辑建议，保存时仍执行活跃状态、路线工序、数量、系数、重复分配和并发硬校验。
- 上午/下午巡检数量按对应规则比例向上取整；例如订单数量 `301`、比例 `5%`，检验数量为 `16`。
- 首检数量使用发布规程中的固定数量。
- 末检必须显式配置“需要”或“不适用”；未配置不是“不适用”。
- 退回提交不参与订单完成、过程检验完成或放行完整性。
- 同一人可以是 PQC 组长和某次实际检验人，但不得确认自己作为实际检验人的提交。
- 生产异常和质量异常使用不同类型、责任角色、处理入口和状态机。
- 历史缺少必要上下文的数据不得用默认值补齐后参与新状态判断。

## BDD Scenarios

### BDD-01 ERP 候选进入统一活跃订单

Given ERP 已同步一个已确认订单且正式路线唯一
When 生产班组长在 MES 生产工单中核对并加入活跃订单
Then 生产、PQC、调拨追溯、批记录和放行读取同一个活跃订单 ID，重复加入或冲突路线被阻塞。

### BDD-02 多调拨与开工检查

Given 一个活跃订单需要多个物料批次且存在分批发货、补料和退料
When 班组长关联调拨、物料员核对实物并查看开工检查
Then 系统按物料、数量、批次和状态给出覆盖结果，缺项明确阻塞系统就绪状态，但不自动创建异常。

### BDD-03 班组配置只绑定正式设备

Given 正式设备台账中存在启用、报修和禁用设备
When 班组长配置工序设备和参数规则
Then 只能绑定台账设备，报修/禁用设备不能用于新报工，历史报工仍显示原设备快照。

### BDD-04 工序事实优先报工

Given 员工已按 SOP 完成一段生产但尚未确定归属订单
When 员工选择工序、实际人员、台账设备、参数、数量、损耗、原因并签名
Then 原始报工成功保存且订单/任务/工作站可为空，原始内容不可被组长覆盖。

### BDD-05 退回修订与系数分配

Given 一笔原始报工和两个同工序活跃订单
When 组长退回补正后确认，并使用 FIFO 建议或手工调整分配
Then 原始、退回、补正、确认和分配均可追溯，目标数量按固定 ERP 数量乘生产系数计算，ERP 数量不变。

### BDD-06 确定性批记录回填

Given 某订单工序由多员工、多设备、多次报工共同完成
When 累计确认量达到目标数量
Then 系统锁定完成状态，按正式逐工序批记录绑定和明确聚合策略回填全部事实，并发重试不重复回填。

### BDD-07 QA 规程版本生命周期

Given QA 为产品、路线版本和工序创建规程草稿
When QA 配置项目、首检、上午/下午巡检和末检后发布
Then 缺项或冲突阻塞发布，发布版本不可原地修改，新任务使用新版本，历史任务保留旧版本。

### BDD-08 首检与巡检任务计算

Given 权威活跃订单存在且有发布规程
When 系统按业务日期、班次和轮次生成任务
Then 首检使用固定数量，上午/下午巡检按比例向上取整，末检按显式适用性生成或标记不适用。

### BDD-09 PQC 逐件检验与签名

Given PQC 检验员从活跃订单选择正式路线工序和实际人员
When 按规程逐件填写并签名提交
Then 保存规程版本、类型、日期、班次、轮次、数量、逐件明细、结果、原因和签名快照，且不要求存在生产事件。

### BDD-10 PQC 复核职责隔离与补正

Given PQC 提交处于待确认
When PQC 组长确认、退回或尝试确认自己的提交
Then 合法确认形成复核记录，退回进入待补正并保留修订链，自我确认被阻塞。

### BDD-11 过程检验和质量异常

Given PQC 组长确认一笔合格或不合格提交
When 系统汇集过程检验记录
Then 只汇集已确认数据；不合格按规则形成质量异常，质量异常不进入生产异常处理流。

### BDD-12 批记录完整性和放行

Given 一个订单的调拨、生产工序、批记录、PQC、异常和签名来源可查询
When 系统执行放行预检
Then 缺任一正式来源或存在阻塞异常时不生成可放行结果；全部通过后才允许放行负责人签名放行或退回。

### BDD-13 班组/PQC 日结和只读看板

Given 当天存在未分配报工、未确认 PQC、退回未补正和批记录缺项
When 生产班组长和 PQC 组长分别执行日结
Then 两个看板按职责显示未闭环事项，生产班组长只能只读查看 PQC 状态。

### BDD-14 缺少正式前置条件

Given 订单、路线、生产系数、调拨、规程、人员范围、签名或正式批记录绑定任一缺失
When 用户提交对应系统动作
Then 系统返回可定位来源的错误并停止，不使用默认值、旧字段、`formBindings` 或最新生产事件补齐。

### BDD-15 并发与幂等

Given 两个请求同时分配同一报工、提交同一 PQC、完成同一订单工序或执行同一放行
When 请求并发提交
Then 最多一个状态转换成功，不超额、不重复回填、不重复汇集、不重复放行，失败请求返回明确冲突。

### BDD-16 三类工艺路线配置互不替代

Given 同一工序分别存在工序开始、正式批记录表单和 `formBindings`
When 页面展示、批次执行、批记录回填和验证分别读取配置
Then 三条链路各自使用正式来源，修改任一配置不会改变另外两条链路的值、状态或链接。

## Acceptance Criteria

- `AC-M01` 至 `AC-M23`、`AC-D01` 至 `AC-D39` 的唯一映射和逐条可观察验收见 `development-plan.md` 的 Excel Traceability Matrix。
- 每个验收项必须同时满足对应 Excel 行的“输出什么”和“怎么测试”，不能只证明接口返回或数据库有记录。
- 已交付基线能力必须继续通过原有定向回归和真实 E2E。
- 新行为必须先获得行为型 RED，再以最小正式实现达到 GREEN，并执行相邻回归。
- 所有写入链路必须保留租户、业务 ID、操作人、时间、状态、版本或签名等审计上下文。
- 所有历史快照必须在配置变更后仍可按当时内容还原。
- 所有放行检查必须给出来源对象、检查结果、阻塞原因和解除条件。
- 62 个验收项全部完成且真实 E2E、并发、迁移、权限和清理证据通过前，实施任务不得标记 completed。

## Open Questions

以下问题必须在对应里程碑开始前以代码/数据证据关闭；无法关闭则阻塞实施：

1. 金蝶生产订单、调拨申请、调拨单、发货、补料、退料和物料批次的正式本地表、同步任务和查询接口分别是什么？
2. QA 规程的正式所有权放在 MES 还是现有 QMS；若复用 QMS，版本、工序和任务生成接口由谁维护？
3. 上午/下午巡检的业务日期、班次边界、跨午夜规则和重复生成幂等键是什么？
4. 活跃订单从当前 `leader_user_id + work_order_id` 唯一关系迁移到跨角色聚合时，多个组长已加入同一订单如何归并责任范围？
5. 历史开放 PQC/订单缺少路线版本或规程版本时，哪些记录可确定性迁移，哪些必须阻塞关闭后再切换？
6. 质量异常、返工、报废和库存一致性的正式来源服务是否已存在；若不存在，必须拆为明确前置节点，不能在放行服务中写占位成功。
