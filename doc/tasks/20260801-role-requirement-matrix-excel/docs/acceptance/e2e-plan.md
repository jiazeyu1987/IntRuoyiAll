# 岗位需求矩阵真实 E2E 计划

## Purpose and Scope

本文件定义从正式登录、菜单和页面操作验证 Excel 目标的真实用户路径。E2E 证明用户可见闭环，API 仅用于最终只读核验和规则允许的任务数据清理，不替代页面操作。

## Evidence Reviewed

- `docs/e2e-rules.md`、`docs/login-access.md`、`docs/local-runtime.md`、`docs/database-rules.md`。
- `prd.md` 的角色和业务状态机。
- `test-plan.md` 的 62 项验收矩阵、E2E 前置和测试数据。
- 已交付生产组长工作台真实 E2E 基线。

## User Paths

### E2E-01 ERP 到放行正向主链路

覆盖 ERP 候选、统一活跃订单、调拨、QA 规程、生产事实、组长复核分配、PQC、批记录、异常、完整性和放行。主路径必须验证 `AC-M01` 至 `AC-M23` 中所有用户可见行为。

### E2E-02 班组配置和责任范围

覆盖员工、原因、正式设备绑定、设备状态、参数上下限、范围和审计，验证 `AC-D01` 至 `AC-D10`。

### E2E-03 报工修订和只读看板

覆盖退回补正、班组日结、PQC 只读、批记录进度和三类工艺路线配置分离，验证 `AC-D11` 至 `AC-D14`。

### E2E-04 QA 规程和动态 PQC

覆盖规程配置/发布、任务生成、实际人员、签名、逐件明细、失败原因和事件生成，验证 `AC-D15` 至 `AC-D29`。

### E2E-05 PQC 复核、质量异常和日结

覆盖退回补正、筛选、详情、确认、自我确认阻塞、质量异常、过程检验汇集和日结，验证 `AC-D30` 至 `AC-D38`。

### E2E-06 历史快照

先完成报工/PQC，再修改员工、设备、原因、参数和规程，验证 `AC-D39` 及相关历史记录仍显示原快照。

## Browser or Client Steps

1. 通过正式登录页进入非生产测试租户。
2. 分别使用生产员工、生产组长、QA、PQC 检验员、PQC 组长和放行负责人账号。
3. 只通过正式菜单进入生产工单、班组工作台、QA 规程、PQC、批记录和放行页面。
4. 按 `RRM-20260801-` 前缀创建或选择任务自有真实业务数据。
5. 每个写操作等待并核验目标网络请求、业务 code、页面状态和后续列表/详情刷新。
6. 每个权限场景同时验证页面入口和直接后端拒绝。
7. 每个失败场景断言具体缺项、来源对象、阻塞原因和解除条件，不只检查通用 toast。
8. 最终通过只读 API 核验业务 ID、数量、版本、状态、签名、批记录和审计。
9. 按正式页面优先清理任务数据，并核验剩余计数。

## API Verification

- ERP 候选、活跃订单和正式路线 ID 一致。
- ERP 固定数量未被报工分配修改，工序目标量等于固定数量乘系数。
- 报工修订、分配和累计数量守恒。
- PQC 任务身份包含类型、日期、班次、轮次和规程版本。
- 批记录聚合包含全部源报工且幂等。
- 过程检验只包含最终已确认修订。
- 放行检查项包含来源模块、对象 ID、结果、原因和处理建议。
- 历史快照在配置修改后保持原值。

## Console and Log Checks

- 目标链路不得出现未归因的 console error、requestfailed 或 HTTP 4xx/5xx。
- 外部资源异常必须与目标业务链路分开记录，不得全局忽略错误。
- 后端日志不得出现吞异常、默认成功、重复终态或租户越界。
- 写请求数量必须与用户动作一致，取消/阻塞场景写请求为 `0`。
- 并发场景记录两个请求的状态、业务 code 和最终唯一终态。
- E2E 证据记录 URL、角色标签、数据前缀、业务 ID、断言、截图/日志路径和清理结果，不记录凭据。

## Test Blockers

- 前后端服务、数据库、Redis、浏览器、账号、权限、签名或真实样本缺失时停止。
- 前端没有正式菜单/页面入口时，先按批准范围补入口并走 BDD/TDD；不得改用 API-only。
- 不允许直接 SQL 写业务数据来绕过真实路径。
- 不允许在生产租户或未授权真实数据上执行写入型 E2E。
