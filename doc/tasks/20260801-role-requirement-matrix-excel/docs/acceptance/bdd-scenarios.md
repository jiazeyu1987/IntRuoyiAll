# 岗位需求矩阵 BDD 场景

## Purpose and Scope

本文件把源 Excel 的 62 项需求转换为实现前必须确认的可观察业务行为。每个场景先由产品、业务和开发共同确认，再允许创建 RED 测试；场景未确认、正式来源未确定或测试前置缺失时，禁止进入生产代码实现。

## Evidence Reviewed

- `岗位需求分解矩阵.xlsx`：23 项主需求、39 项衍生需求。
- `prd.md`：角色、权威来源、状态机和业务规则。
- `development-plan.md`：M0-M6、实施区域 A1-A6 和 Excel 追踪矩阵。
- `test-plan.md`：62 项验收测试矩阵、失败路径、E2E 和测试数据。
- `20260731-team-leader-workbench-prd-plan`：已交付生产组长能力基线。

## Feature Scenarios

### BDD-01 ERP 候选进入统一活跃订单

Given ERP 已同步已确认订单且正式路线唯一
When 生产班组长核对并加入活跃订单
Then 生产、PQC、调拨、批记录和放行读取同一 `activeOrderId`，覆盖 `AC-M01`、`AC-M03`、`AC-M04`。

### BDD-02 多调拨与开工检查

Given 活跃订单存在分批发货、补料、退料、多物料和多批次
When 班组长关联调拨且物料员完成实物核对
Then 系统按正式 ID 计算物料覆盖、展示缺项和来源，但不自动创建异常，覆盖 `AC-M02`、`AC-M05`、`AC-M06`、`AC-M07`、`AC-M08`。

### BDD-03 班组配置只绑定正式主数据

Given 正式员工、原因和设备台账包含启用、报修和禁用状态
When 班组长维护班组配置
Then 新业务只使用当前有效配置，历史记录保持原快照，覆盖 `AC-D01`、`AC-D02`、`AC-D03`、`AC-D04`、`AC-D05`、`AC-D06`、`AC-D07`、`AC-D08`。

### BDD-04 工序事实优先报工

Given 员工完成工序生产但尚未确定订单归属
When 员工提交工序、人员、设备、参数、数量、损耗、原因和签名
Then 原始事实成功保存且不可覆盖，订单、任务和工作站不是强制前置，覆盖 `AC-M10`、`AC-M11`。

### BDD-05 退回修订与系数分配

Given 原始报工和多个同工序活跃订单
When 组长退回补正、确认并执行 FIFO 建议或手工分配
Then 修订链完整、分配量守恒、目标量使用正式生产系数且 ERP 数量不变，覆盖 `AC-M16`、`AC-M17`、`AC-M18`、`AC-D11`。

### BDD-06 确定性批记录回填

Given 一个订单工序由多员工、多设备和多次报工共同完成
When 累计确认量达到工序目标量
Then 全部事实按正式逐工序绑定和明确策略幂等回填，覆盖 `AC-M19`。

### BDD-07 QA 规程版本生命周期

Given QA 选择产品、正式路线版本和工序
When QA 配置项目、首检、上午巡检、下午巡检和末检并发布
Then 缺项阻塞、发布版本不可改写、新任务使用新版本且历史任务保持旧版本，覆盖 `AC-M09`、`AC-D15`、`AC-D16`、`AC-D17`、`AC-D18`、`AC-D19`、`AC-D20`、`AC-D21`、`AC-D22`、`AC-D23`。

### BDD-08 首检、巡检和末检任务

Given 权威活跃订单存在且规程已发布
When 系统按业务日期、班次和轮次生成任务
Then 首检使用固定数量、上午和下午巡检分别向上取整、末检按显式适用性处理，覆盖 `AC-M12`、`AC-M13`、`AC-M14`、`AC-M15`。

### BDD-09 PQC 逐件检验与签名

Given PQC 任务、实际检验人和电子签名可用
When 检验员逐件填写并提交
Then 系统保存任务身份、规程版本、逐件明细、原因和签名且不依赖生产事件，覆盖 `AC-D24`、`AC-D25`、`AC-D26`、`AC-D27`、`AC-D28`、`AC-D29`。

### BDD-10 PQC 复核职责隔离与补正

Given PQC 提交处于待确认
When PQC 组长筛选、查看、确认、退回或尝试自我确认
Then 合法确认进入完成、退回形成修订链、自我确认被后端阻塞，覆盖 `AC-M20`、`AC-D30`、`AC-D32`、`AC-D33`、`AC-D34`、`AC-D35`。

### BDD-11 过程检验和质量异常

Given PQC 组长确认最终有效修订
When 系统汇集过程检验记录
Then 只汇集已确认最终修订，不合格进入独立质量异常流程，覆盖 `AC-M21`、`AC-D36`、`AC-D37`。

### BDD-12 完整性检查和放行

Given 调拨、生产、PQC、批记录、异常和签名正式来源均可查询
When 系统执行预检且放行负责人审核
Then 缺项或阻塞异常禁止放行，全部通过后才可签名放行或退回，覆盖 `AC-M22`、`AC-M23`。

### BDD-13 日结、范围、只读和历史快照

Given 多角色范围、未闭环事项和配置变更同时存在
When 生产组长或 PQC 组长查看日结、状态和历史
Then 后端按范围隔离、日结逐项解释、生产组长只读查看质量状态且历史快照不变，覆盖 `AC-D09`、`AC-D10`、`AC-D12`、`AC-D13`、`AC-D38`、`AC-D39`。

### BDD-14 正式前置缺失

Given 订单、路线、系数、调拨、规程、人员、签名或批记录绑定任一缺失
When 用户提交对应动作
Then 系统返回可定位来源的阻塞错误且不使用默认值或占位成功，覆盖 `AC-D31` 及所有验收项的失败路径。

### BDD-15 并发与幂等

Given 两个请求同时转换同一订单、报工、PQC、批记录或放行对象
When 请求并发提交
Then 最多一个转换成功且不超额、不重复回填、不重复汇集、不重复放行，作为 M1-M6 的跨切面门禁。

### BDD-16 三类工艺路线配置互不替代

Given 同一工序分别配置工序开始、正式批记录表单和 `formBindings`
When 页面展示、批次执行和批记录回填分别读取配置
Then 三条链路只使用各自正式来源，覆盖 `AC-D14` 及正式批记录跨切面门禁。

## Failure Scenarios

- Given ERP 订单未确认或正式 ID 缺失，When 同步或加入活跃订单，Then 阻塞且不创建猜测订单。
- Given 正式生产系数缺失、为零或为负数，When 分配报工或完成工序，Then 阻塞且不默认 `1`。
- Given 正式批记录绑定缺失，When 查看进度或回填，Then 阻塞且不读取 `formBindings`、`MAIN` 或工序开始。
- Given QA 规程缺项目、数量或末检适用性，When 发布，Then 返回逐字段错误且版本不生效。
- Given 实际 PQC 人员与签名人不一致，When 提交，Then 后端拒绝且不生成有效事件。
- Given PQC 组长确认自己的检验，When 提交确认，Then 后端拒绝且原状态不变。
- Given 放行来源仍为“来源未接入”，When 预检，Then 保持 blocker，禁止转为 PASS。
- Given 用户越权访问班组、QA、PQC 或放行操作，When 调用页面或 API，Then 前后端均拒绝。

## Boundary Scenarios

- 订单数量 `301`、巡检比例 `5%` 时，计划检验数量必须为 `16`。
- 工序系数分别为 `1.0` 和 `3.0` 时，固定订单数量 `300` 的目标量分别为 `300` 和 `900`。
- 一个报工拆分到多个订单时，分配总量必须等于确认量且任何订单不得超剩余量。
- 跨午夜、跨班次或规程版本切换时，已生成任务保持原快照，新任务使用新身份。
- 多调拨、补料和退料同时存在时，覆盖量按正式来源净额计算。
- 多员工、多设备、多次报工的列表聚合必须稳定排序并保持幂等。
- 关闭 legacy 数据可只读保留，但不得参与新完成、汇集或放行判断。
- 一对多列表分页必须先聚合再分页，避免重复行和错误总数。

## Open Questions

- 金蝶订单、调拨、发货、补料、退料和批次的正式本地表/API。
- QA 规程在 MES 或 QMS 的唯一所有权。
- 质量异常、返工、报废和库存一致性的正式来源服务。
- 班次边界、跨午夜规则和巡检任务幂等键。
- 历史双活跃来源和缺版本 PQC 数据的确定性迁移方案。

## Test Blockers

- 正式来源、测试租户、六类角色、权限、签名、数据库、Redis、浏览器或运行服务缺失时，对应测试标记 BLOCKED。
- 测试类不存在、package script 不存在或 No tests 只能算前置缺失，不算 RED。
- 不允许使用 mock、SQL 直写、API-only 用户路径、默认值或静态合同代替真实 E2E。
