# 岗位需求矩阵测试数据计划

## Purpose and Scope

本文件定义完整验证 62 项需求所需的真实、可追踪、可清理测试数据。测试数据必须属于已确认的非生产租户，并支持正向、失败、边界、权限、并发、迁移和历史快照场景。

## Evidence Reviewed

- `test-plan.md` 的验收矩阵、失败路径、并发和性能要求。
- `bdd-scenarios.md` 的 Feature、Failure 和 Boundary 场景。
- `e2e-plan.md` 的六条真实用户路径。
- 项目登录、数据库、E2E 和任务数据清理规则。

## Required Test Data

| 数据域 | 正向数据 | 失败/边界数据 |
|---|---|---|
| 租户与角色 | 非生产测试租户；生产员工、生产组长、QA、PQC 检验员、PQC 组长、放行负责人 | 越权角色、无范围角色、PQC 组长兼实际检验人 |
| ERP 订单 | 固定数量 `300`、正式产品、交期、批次、唯一 ERP ID | 未确认订单、缺正式 ID、冲突路线、关闭订单 |
| 工艺路线 | 正式版本、至少两个工序、系数 `1.0` 和 `3.0` | 缺路线版本、系数缺失/`0`/负数、冲突系数 |
| 三类配置 | 同工序分别配置工序开始、正式批记录和 `formBindings` | 缺正式批记录、只有 `formBindings`、错误 `MAIN` |
| 调拨物料 | 两个调拨/发货批次、多物料、补料、退料 | 单号无正式 ID、数量不足、批次不符、退料后净额不足 |
| 班组配置 | 启用员工、原因、正式设备、参数规则 | 禁用员工、报修/禁用设备、超上限/下限参数 |
| 生产报工 | 多员工、多设备、多次报工、一次退回补正 | 缺人员/设备/数量/原因/签名、超额和重复分配 |
| QA 规程 | 首检固定数量、上午/下午 `5%`、末检适用/不适用 | 缺项目、缺数量、末检未配置、已发布版本修改 |
| PQC | 首检、上午/下午巡检、末检、逐件明细、退回补正 | 无生产事件、自我确认、签名不一致、跨天重复任务 |
| 异常与放行 | 生产异常、质量异常、全部来源齐全的可放行订单 | 阻塞异常、未确认 PQC、缺批记录/调拨/签名、占位来源 |
| 历史快照 | 完成后修改人员、设备、原因、参数、规程 | legacy 缺版本、不可确定性迁移记录 |
| 并发 | 两个独立会话和同一业务对象 | 重复加入、确认、分配、回填、汇集和放行 |
| 性能 | 合理规模活跃订单、逐件明细、日结和审计数据 | N+1、重复 JOIN、分页总数漂移样本 |

所有任务数据使用可检索前缀 `RRM-20260801-`，并记录订单、路线、工序、调拨、规程、报工、PQC、签名、批记录、异常和放行 ID。

## Reset Procedure

1. 执行前确认目标租户和任务前缀。
2. 优先通过正式页面撤销、退回、终止或关闭测试业务对象。
3. API 只用于最终只读核验和项目规则明确允许的任务自有清理。
4. 不删除 append-only 审计和签名证据；记录其保留原因和业务 ID。
5. 清理后核验候选、活跃订单、报工待办、PQC 待办、异常和放行列表的任务前缀剩余计数。
6. 并发或失败测试中断时先保留证据，再按对象状态执行幂等清理。

## Data Ownership

- 所有测试数据归当前实现任务所有，不得复用生产租户、系统基线或其他任务数据。
- 测试日志只记录账号标签，不记录密码、token、私钥或签名凭据。
- ERP 正式样本由明确责任人提供；MES 不通过猜测或直接 SQL 创建 ERP 主事实。
- QA、生产、PQC 和放行数据分别由对应角色通过正式页面创建。
- 清理负责人和不能删除的 append-only 证据必须写入实施任务日志。

## Test Blockers

- 未确认测试租户、角色账号、权限、签名或数据所有权时停止写入测试。
- ERP 调拨和批次正式来源未确定时停止调拨/放行测试。
- 缺少路线版本、生产系数、正式批记录绑定或发布规程时，对应主链路保持 BLOCKED。
- 无法保证任务数据可识别、可核验或可安全清理时，不执行真实 E2E。
