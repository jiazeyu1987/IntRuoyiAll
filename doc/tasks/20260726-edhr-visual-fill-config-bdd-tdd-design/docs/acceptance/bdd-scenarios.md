# BDD Scenarios

## Purpose and Scope

本文件定义 eDHR 可视化填写配置的可观察业务行为。范围包括统一配置入口、单元格类型纠错、辅助行编排、员工或角色分配、运行态可见与可写范围、执行快照和版本隔离。场景只描述用户或 API 可观察结果，不规定内部组件拆分。

## Evidence Reviewed

- 现有可视化规则编辑器 `BatchRecordCellRulesConfirmDialog.vue`。
- 现有 `GET/PUT /mes/pro/batch-record-report/cell-rules` 与 `BatchRecordReportCellRuleVO`。
- 现有 `edhrCellRule`、`edhrSignature`、字符串单选选项约束。
- 现有 `get-by-report`、`save-by-report` 和用户/角色候选来源。
- 现有 `ExecutionPage.vue` 辅助模式、`draftFieldValues`、字段审计保存和签名入口。
- 现有 `fillableScopeJson`、`BATCH_SHARED`、执行 `fields` 快照和版本治理。
- `design.md` 中确定的“辅助行是唯一责任单元”约束。

## Feature Scenarios

### F01 统一填写配置入口

Given 管理员位于批记录表单列表且拥有规则查询和更新权限  
When 管理员点击某个报表的“填写配置”  
Then 系统在现有弹窗中同时展示原表预览、辅助行列表、选中单元格类型配置和辅助行填写人配置  
And 系统不要求进入新的菜单或第二个设计器

### F02 原表与辅助行双向定位

Given 报表已配置辅助行 `AR_001` 且包含两个单元格  
When 管理员点击右侧 `AR_001`  
Then 左侧同时高亮该行映射的两个原表单元格  
When 管理员点击其中任一已映射单元格  
Then 右侧自动定位并选中 `AR_001`

### F03 将识别错误单元格改为文本

Given 一个可填写单元格被错误识别为数字  
When 管理员将字段类型改为文本并保存  
Then 重新读取配置时该单元格为 `STRING/input-text`  
And 原坐标、字段值身份和辅助行归属不变

### F04 将识别错误单元格改为数字

Given 一个可填写单元格被错误识别为文本  
When 管理员将字段类型改为数字并配置合法最小值和最大值  
Then 重新读取配置时该单元格为 `NUMBER/input-number`  
And 运行态按现有数字校验规则拒绝超出范围的值

### F05 将识别错误单元格改为日期

Given 一个可填写单元格被错误识别为文本  
When 管理员将字段类型改为日期并保存  
Then 重新读取配置时该单元格为 `DATE/date`  
And 原表模式和辅助模式都使用同一日期值

### F06 将单元格配置为签名

Given 管理员选中了一个可填写单元格  
When 管理员将字段类型改为签名并通过现有签名配置启用同坐标签名标记  
Then 保存后规则为 `SIGNATURE/signature`  
And 运行态复用现有电子签名动作和签名审计链

### F07 将单元格配置为下拉框

Given 管理员选中了一个文本类可填写单元格  
When 管理员选择下拉框控件并维护至少两个合法选项  
Then 保存后规则保持 `valueType=STRING`  
And `constraints.selectionMode` 为 `single`  
And 运行态按保存顺序展示选项

### F08 编辑下拉框选项

Given 下拉框当前包含“合格”和“不合格”  
When 管理员新增“待复核”、调整顺序并保存  
Then 重新读取配置后展示三个选项及新的顺序  
And 已发布历史执行仍保留其原快照选项

### F09 创建多单元格辅助行

Given 两个可填写单元格尚未归属辅助行  
When 管理员新建辅助行、输入描述并依次选择这两个单元格  
Then 右侧显示一条包含两个单元格的辅助行  
And 左侧两个单元格显示相同的辅助行标识

### F10 创建单单元格责任行

Given 管理员只需要把一个签名单元格交给员工乙  
When 管理员创建仅包含该单元格的辅助行并选择员工乙  
Then 系统保存一条单单元格辅助行  
And 员工乙的有效责任范围只包含该单元格

### F11 多个单元格共享同一填写人

Given `AR_001` 包含生产批号和实际数量两个单元格  
When 管理员将 `AR_001` 分配给员工甲  
Then 两个单元格都属于员工甲的有效填写范围  
And 系统不额外创建单元格级填写人记录

### F12 在辅助行之间移动单元格

Given 单元格 A 已属于 `AR_001` 且管理员正在编辑 `AR_002`  
When 管理员选择将单元格 A 移动到 `AR_002` 并确认  
Then 单元格 A 从 `AR_001` 移除并加入 `AR_002`  
And 单元格 A 最终只有一个辅助行归属

### F13 保存并重新读取完整配置

Given 所有可填写单元格均已配置类型、辅助行、描述和有效填写人  
When 管理员点击“保存填写配置”且两个现有保存接口均成功  
Then 界面提示保存成功  
And 重新打开后规则、下拉选项、辅助行顺序、描述、归属和填写人均与保存前一致

### F14 当前用户只看到自己的辅助行

Given 执行快照中 `AR_001` 分配给员工甲、`AR_002` 分配给员工乙  
When 员工甲通过自己的填写任务进入辅助模式  
Then 页面只展示 `AR_001`  
And 不展示 `AR_002` 的描述或填写控件

### F15 原表保留上下文但限制编辑

Given 员工甲打开包含员工甲和员工乙责任单元格的执行  
When 员工甲切换到原表模式  
Then 页面展示完整原表  
And 员工甲责任单元格可编辑  
And 员工乙责任单元格为只读

### F16 两种模式共享字段值

Given 员工甲在辅助模式填写生产批号  
When 员工甲切换到原表模式  
Then 原表对应单元格立即显示相同值  
When 员工甲在原表修改该值并切回辅助模式  
Then 辅助行显示修改后的同一值  
And 页面不存在独立的辅助模式草稿对象

### F17 后端执行精确单元格授权

Given 员工甲只负责同一原表行中的列 2，员工乙负责同一行中的列 4  
When 员工甲保存列 2 的值  
Then 后端接受并写入字段审计链  
When 员工甲尝试写入列 4  
Then 后端拒绝请求并指出单元格不在当前用户填写范围内

### F18 版本隔离

Given 已发布 V1 的辅助行和填写人配置已用于创建执行 E1  
When 管理员在草稿 V2 中移动单元格并更换填写人  
Then E1 继续使用 V1 的辅助行和责任快照  
And 新创建的 V2 执行使用 V2 配置

### F19 历史执行不可变

Given 一个执行已经提交并形成字段审计和审批快照  
When 当前报表草稿的描述、下拉选项或辅助行顺序发生变化  
Then 历史执行详情仍展示提交时的描述、选项、顺序和值  
And 历史执行不读取当前报表 JSON

## Failure Scenarios

### X01 可填写单元格未映射

Given 报表存在至少一个可填写单元格未加入任何辅助行  
When 管理员保存完整配置或提交版本发布  
Then 系统拒绝操作并返回缺失坐标

### X02 单元格重复映射

Given 同一坐标同时出现在两个辅助行请求中  
When 客户端提交配置  
Then 后端拒绝请求并返回冲突的 `rowKey` 和坐标

### X03 辅助行标识无效

Given 请求存在空 `rowKey` 或重复 `rowKey`  
When 客户端提交配置  
Then 后端拒绝请求且不重新生成标识掩盖错误

### X04 辅助行描述为空

Given 一个辅助行的描述仅包含空白字符  
When 管理员保存配置  
Then 前端阻止提交  
And 绕过前端直接调用 API 时后端仍拒绝

### X05 辅助行没有字段

Given 一个辅助行的 `fields` 为空  
When 客户端提交配置  
Then 后端拒绝请求并指出该 `rowKey` 没有单元格

### X06 坐标无效或不可填写

Given 辅助行引用越界坐标、不存在坐标或不可填写单元格  
When 客户端提交配置  
Then 后端拒绝请求并返回具体坐标

### X07 下拉选项无效

Given 下拉框少于两个有效选项、存在空值或重复值  
When 管理员保存配置  
Then 前端阻止提交  
And 后端对绕过前端的请求同样拒绝

### X08 签名标记缺失

Given 单元格规则为 `SIGNATURE` 但同坐标签名标记未启用  
When 管理员保存或发布配置  
Then 系统拒绝操作并指出签名单元格坐标

### X09 填写人覆盖缺失

Given 一个辅助行没有启用的责任配置  
When 管理员保存责任配置或发布版本  
Then 系统拒绝操作并指出缺少责任的 `rowKey`

### X10 员工或角色不可用

Given 责任配置引用不存在、停用或无法解析出有效用户的员工或角色  
When 管理员保存责任配置  
Then 后端拒绝请求且不自动改用其他人员

### X11 新旧责任载荷混用

Given 同一请求同时包含 `fillRule` 和 `fillAssignments`  
When 客户端调用 `save-by-report`  
Then 后端拒绝请求并要求使用唯一的新结构

### X12 第二步保存失败不得提示成功

Given 单元格规则和辅助行保存成功但填写人保存接口失败  
When 管理员点击一次“保存填写配置”  
Then 弹窗保持打开并显示填写人保存失败  
And 页面不得提示整体保存成功  
And 版本发布因责任覆盖不完整而被阻止

### X13 责任快照缺失或损坏

Given 工作任务缺少有效 `responsibilityScopeJson`  
When 用户打开任务或保存字段  
Then 后端拒绝操作并报告责任快照无效  
And 系统不读取当前模板配置作为运行时替代

### X14 越权字段写入

Given 员工甲构造请求写入员工乙负责的坐标  
When 字段审计保存接口处理请求  
Then 后端返回明确的越权错误  
And 字段值和审计链均不发生变化

## Boundary Scenarios

### B01 同一原表行按列分配给不同员工

Given 同一原表行有两个可填写单元格并分别属于两个辅助行  
When 两名员工分别打开自己的任务  
Then 每人只可写自己负责的列  
And 后端不会因为行号相同而放大权限

### B02 辅助行包含非相邻单元格

Given 两个业务相关单元格位于不同原表行  
When 管理员将它们加入同一辅助行  
Then 系统允许保存并按一个描述展示  
And 每个底层字段仍保留自己的坐标和值身份

### B03 角色责任解析为多个员工

Given 一个辅助行分配给包含多个有效员工的角色  
When 创建填写任务责任快照  
Then 快照冻结解析出的用户集合  
And 角色后续成员变化不改变已创建任务

### B04 辅助模式未配置

Given 执行快照没有 `assistRows`  
When 用户点击辅助模式  
Then 页面显示“未配置辅助模式”并不展示推导行  
And 原表模式仍按执行快照和有效权限工作

### B05 空责任结果

Given 当前用户属于填写任务候选并集但没有任何辅助行责任  
When 当前用户打开辅助模式  
Then 页面显示当前没有可填写辅助行  
And 后端拒绝其写入任意单元格

### B06 旧规则显式迁移

Given 旧版本只有一条全表 `fillRule`  
When 一次性迁移完成  
Then 数据中存在显式 `scopeKey=ALL` 和精确单元格范围  
And 运行时代码不保留旧结构双读或动态推导分支

## Open Questions

当前没有阻塞文档设计的开放问题。实现阶段固定采用以下口径：

- 员工精确分配通过单用户 `USER` 候选来源表达，角色继续复用现有候选来源。
- 一个辅助行只有一条启用责任规则；需要单独负责人时创建单单元格辅助行。
- 首版使用上移/下移排序，不实现拖拽。
- 配置入口收敛到现有单元格规则弹窗，不新建菜单。

## Test Blockers

- 后端单元测试需要可运行的 Java 17、Maven 和 `yudao-module-mes` 测试依赖。
- 前端静态合同需要已安装的 Node/pnpm 依赖与可读取源码。
- 真实 E2E 需要本任务专用测试租户、管理员、员工甲、员工乙、角色、可编辑草稿版本和可创建执行的真实业务数据。
- 真实 E2E 需要确认 `int_main` 前端 `8081`、后端 `48081` 运行且登录、菜单和权限可用。
- 任一前置条件缺失时必须记录 blocker，不能以 mock、API-only 主路径或历史截图代替。
