# Test Data Plan

## Purpose and Scope

本文件定义可重复、可追踪且不影响真实业务记录的测试数据。数据用于后端单元测试、前端静态合同和 Playwright 真实路径，重点覆盖同一行不同列授权、多单元格辅助行、单单元格责任、五类字段、版本隔离和失败门禁。

## Evidence Reviewed

- 现有批记录规则使用 `sourceTableIndex/rowIndex/columnIndex` 标识字段。
- 现有责任候选来源支持用户和角色解析。
- 现有执行、工作任务、字段值和字段审计具备版本与用户上下文。
- 项目 E2E 规则要求真实租户、真实账号、真实 UI 路径和任务自有数据。

## Required Test Data

### 测试命名

所有真实 E2E 数据使用前缀 `CODX-VFC-20260726`，包括：

- 批记录名称：`CODX-VFC-20260726-批记录`。
- 工单/批次编码前缀：`CODX-VFC-20260726-WO`、`CODX-VFC-20260726-BATCH`。
- 辅助行描述中可附加同一前缀，便于清理定位。

### 租户与账号

| 数据 | 要求 |
| --- | --- |
| 测试租户 | 非生产租户，具备 MES/eDHR 菜单 |
| 模板管理员 | 可查询/更新批记录规则、签名位和填写责任，可创建草稿版本 |
| 员工甲 | 有填写任务访问权限，无模板配置权限 |
| 员工乙 | 有填写任务访问权限，无模板配置权限 |
| 测试角色 | 启用，至少包含员工甲和员工乙，用于角色快照边界场景 |

账号 ID、用户名和密码只通过本地 E2E 环境变量提供，不写入任务文档或提交记录。

### 报表 V2

从 V1 创建草稿 V2，并执行以下变更：

- 将 `0:10:2` 从 `AR_004` 移到新行 `AR_005`。
- 描述改为“复核并选择检测结论”。
- 责任从员工甲改为测试角色。
- 下拉选项顺序改为“待复核、合格、不合格”。

V1 执行在 V2 修改前创建，V2 执行在 V2 发布后创建。

### 失败夹具

单元测试通过复制合法基础对象构造以下独立变体：

- 缺失映射坐标 `0:10:2`。
- `0:4:2` 同时出现在 `AR_001` 和 `AR_002`。
- 空和重复 `rowKey`。
- 空描述、空字段列表。
- 越界坐标 `0:999:999`。
- 指向不可填写单元格的坐标。
- 只有一个下拉选项、空 `value`、重复 `value`。
- 签名规则存在但 `edhrSignature.enabled=false`。
- `AR_004` 无责任规则。
- 停用员工、停用角色和空角色成员。
- 同时包含 `fillRule` 与 `fillAssignments`。
- 缺失、非法 JSON 或不匹配任务的责任快照。

## Reset Procedure

真实 E2E 必须使用 `try/finally` 执行恢复：

1. 记录测试创建的报表定义、V1/V2 版本、路线绑定、工单、批次、执行、任务和审计记录 ID。
2. 测试失败时先保留失败截图、页面 URL、接口错误和 ID 清单。
3. 通过正式 UI 或项目已有测试清理入口删除任务创建的数据。
4. 若测试修改了共享测试角色成员，在 `finally` 中恢复原成员并重新查询确认。
5. 若已发布版本按业务规则不可删除，则使用专用测试定义并按现有作废/归档流程处理，不直接改数据库状态。
6. 清理后按前缀查询，确认没有遗留可继续执行的工作任务或活动批次。

单元测试数据由事务回滚或测试 schema 清理；不得依赖真实租户数据。

## Data Ownership

- 所有 `CODX-VFC-20260726` 数据归本功能实现与 E2E 任务所有。
- 不修改生产租户、管理员基线、其他任务的草稿版本或并发测试数据。
- 测试角色若为共享资源，只允许临时成员变更且必须记录前后快照。
- 账号凭据、token、签名密码和连接信息不得写入源码、日志、截图文件名或任务文档。
- 失败证据保留业务 ID 和脱敏用户名，不保留秘密。

## Test Blockers

- 目标原表实际坐标与本计划坐标不一致时，必须先创建等价的任务专用报表夹具并记录坐标映射，不能修改其他真实模板迁就测试。
- 缺少可签名账号、签名密码或电子签名初始化时，签名真实路径被阻塞，不能用文本值代替签名。
- 缺少可发布草稿版本、路线绑定、工单或批次数据时，版本和执行 E2E 被阻塞，不能直接插入运行态字段值绕过主路径。
- 清理入口无法安全识别任务自有数据时，停止写型 E2E，先补齐可追踪数据所有权。
