# 工序多物料一线报工与系统同步批号读取 PRD

## Document Status

- 文档日期：2026-08-31
- 文档状态：需求基线
- 首版原则：复用现有配置、两个颜色、一次提交、不增加复杂校验

## Purpose and Scope

本需求解决一线生产中“同一工序需要对多个物料分别报工，而正式批号只能在 ERP 完工后获得”的业务问题。

以粗洗工序为例，弹簧和杠杆需要分别记录完成数量、损耗数量、不良明细和对应生产参数。现场先完成这些数据的填写，再点击一次“正式提交”；工序进度取各物料完成数量最小值。批号不直连 ERP，而是只读系统每日同步落库的 ERP 表单数据；系统内没有批号就保持为空。

首版保持最小实现：复用现有工艺路线产品 BOM 作为工序物料的唯一来源；一线生产只增加物料页签和分物料数据草稿；页签只有灰色和绿色，完成数量被明确填写后即变绿，不使用其它字段参与颜色判断。

## Evidence Reviewed

- 用户提供的粗洗生产记录截图：同一粗洗工序下分别列出弹簧、杠杆，并分别记录批号、生产数量、不合格数量和工艺参数。
- 用户提供的一线生产页面截图：页面当前只有一套完成数量、损耗数量、不良明细和设备参数输入区，红框位置可承载物料页签。
- 用户确认：物料页签初始为灰色，完成数量填写后变为绿色，只使用这两种颜色，不增加其它变绿校验，点击“正式提交”时一起提交。
- 用户确认：需要在统一位置设置不同工序需要填写的物料。
- 用户确认：多物料完成数量不一致时直接取最小值；不直连 ERP，只从系统每日同步表读取批号，系统内没有就没有。
- 现有工艺路线产品 BOM：已经按产品、工序和 BOM 物料维护关系，并在路线候选版本中保存快照。
- 现有一线生产：当前正式提交只包含一套完成数量、损耗明细、设备和参数，需要扩展为同一次提交中的多条物料明细。
- 现有系统同步表：`erp_kingdee_production_pick_list_item` 同时具备生产订单号、物料编码和批号，可作为首版唯一批号读取来源。
- 项目术语契约：工序开始、批记录表单、表单槽位是三条独立配置链路，不能作为报工物料来源。

## Product Summary

产品形成一条完整业务链：

`路线产品 BOM 按工序配置物料 → 订单冻结配置 → 一线按物料页签填写 → 一次正式提交全部物料 → 进度取最小值 → 系统同步表按订单和物料只读批号`

首版不新增独立的“报工物料主表”。工艺路线中某产品、某工序已经配置的 BOM 物料，就是该工序在一线生产需要显示和填写的报工物料。

例如，在压力泵产品的粗洗工序下配置弹簧和杠杆后，一线生产进入该产品的粗洗工序时显示两个页签：

`弹簧`　`杠杆`

每个页签保存自己的完成数量、损耗数量、不良明细和参数。页签背景只有灰色和绿色；点击“正式提交”时，两种物料的数据作为同一笔粗洗报工一起提交。

## Terminology

| 术语 | 本文含义 |
|---|---|
| 路线产品 | 当前工艺路线所适用的成品或产品物料 |
| 工序报工物料 | 路线产品 BOM 中归属当前工序、需要在一线生产分别填写数据的物料 |
| 物料页签 | 一线生产用于切换不同报工物料填写内容的触屏入口 |
| 完成数量已填写 | 用户对该物料的完成数量进行了明确输入；输入 `0` 也属于已填写，初始空值不属于已填写 |
| 正式提交 | 一线人员完成当前工序数据填写后，使用现有签名与确认流程一次提交本工序全部物料数据 |
| 系统同步批号 | 系统每日从 ERP 同步落库后，按生产订单号和物料编码读取的非空批号集合 |
| 批记录表单 | 工序设置中逐工序绑定的正式生产批记录载体，不是报工物料配置来源 |
| 表单槽位 | `formBindings` 对应的特殊表单或动态表单配置，不是报工物料配置来源 |

## Target Users

- 工艺路线维护人员：在路线候选版本中为不同产品、不同工序配置 BOM 物料。
- 一线生产人员：按物料分别填写完成数量、损耗和参数，并一次正式提交。
- 生产组长：查看同一次工序报工中各物料的正式提交事实。
- ERP 同步运维人员：保障既有每日表单同步任务正常执行，本功能不直接调用 ERP。
- 质量与批记录人员：使用正式提交事实和系统同步批号形成可追溯记录，但不改变报工物料来源。

## First Version Scope

### 1. 统一配置位置

- 使用现有路径：`工艺路线 → 产品配置 → 编辑产品 → 产品 BOM 配置`。
- 产品 BOM 配置继续按工序页签展示；在“粗洗工序”下添加弹簧、杠杆，即表示这两个物料需要在粗洗一线生产中分别报工。
- 首版直接复用现有产品、工序、BOM 物料和用料比例，不新增“是否参与报工”、颜色规则或额外配置表。
- 只有路线候选版本可以修改配置；发布后形成正式版本。

### 2. 生产任务冻结

- 生产订单进入执行后，使用该订单锁定路线版本中的工序物料配置。
- 后续修改或发布新路线版本，只影响之后进入执行的新订单，不改变已经执行中的订单。
- 一线生产不能增加、删除或替换工序报工物料。

### 3. 一线生产物料页签

- 在用户截图红框区域显示当前工序的全部报工物料页签。
- 页签至少显示物料名称；物料名称可能重复时，同时显示物料编码。
- 默认选中第一个物料，点击其它页签即可切换。
- 选中态通过边框、加粗或下划线表达，不增加第三种页签状态颜色。
- 一个工序只有一个报工物料时仍显示一个页签，以保持页面和数据行为一致。

### 4. 分物料填写

- 每个物料分别保存自己的完成数量、损耗数量、不良明细、选用设备和设备参数实际值。
- 订单、工序、员工等本次报工公共信息不随物料页签变化。
- 切换页签后，已填写的数据必须保留，不能被另一个物料的数据覆盖。
- 页面“重填”作用于本次工序全部物料；执行前沿用现有确认方式，首版不增加分物料重填按钮。

### 5. 灰绿状态

- 初始未填写完成数量时，物料页签为灰色。
- 用户明确填写该物料的完成数量后，页签立即变为绿色。
- 用户填写 `0` 也视为已填写并变绿。
- 用户清空完成数量后，页签恢复灰色。
- 损耗数量、不良明细、设备、参数、签名和 ERP 批号都不参与页签颜色判断。
- 页签绿色只表示“完成数量已填写”，不表示正式提交成功，也不表示 ERP 批号已返回。

### 6. 一次正式提交

- 页面保留一个“正式提交”按钮。
- 用户正式提交时，系统提交当前工序下所有已配置物料的数据，不按页签分别提交。
- 每个配置物料必须已经明确填写完成数量；缺少时提示具体物料“请填写完成数量”，且不发送正式提交请求。
- 除“各物料完成数量已填写”外，本需求不增加新的业务校验；现有正式提交、签名和系统安全规则保持不变。
- 同一次提交中的所有物料必须整体成功或整体失败，不能出现弹簧成功、杠杆失败但页面显示整单成功。
- 提交失败时保留本次所有物料的填写内容，页面不得显示成功。
- 重复点击必须沿用现有幂等机制，不能生成重复报工。
- 本次工序进度取所有物料完成数量的最小值。例如弹簧为 `5`、杠杆为 `3`，本次进度为 `3`；逐物料事实仍保留 `5` 和 `3`。

### 7. 系统同步批号读取

- 正式提交时现场不填写批号，批号区域保持只读。
- 查询报工物料详情时，按生产工单编号和物料编码读取 `erp_kingdee_production_pick_list_item` 的全部非空 `lot_number`。
- 同一订单物料存在多个批号时全部去重、排序展示，不任取一个。
- 系统同步表没有目标批号时返回空集合并保持空白，这不是提交失败。
- 同步表查询发生真实系统错误时明确报错，不用库存表、当前最新批号、默认值或 ERP 直连替代。
- 本功能不写入、不更新 ERP 同步表，也不把批号复制到报工物料事实表。

### 8. 正式记录使用

- 一线正式提交形成每个物料的数量、损耗、参数、人员和时间事实。
- 正式记录按生产订单号和物料编码关联系统同步批号集合。
- 批记录表单若需要展示这些数据，应读取正式报工事实和系统同步表查询结果；批记录表单本身不负责决定当前工序有哪些报工物料。

## Non-Goals

- 不增加黄色、红色、蓝色等第三种页签状态颜色。
- 不根据损耗、参数、设备、签名或批号决定页签是否变绿。
- 不新增独立的报工物料主数据表或第二套工序物料来源。
- 不允许一线人员临时增加、删除或替换物料。
- 不支持按物料分别点击正式提交。
- 不支持现场手工填写、预估或生成批号。
- 不在首版增加物料显示顺序字段；使用正式配置返回的稳定顺序。
- 不在首版增加跨刷新长期草稿保存；页面会话中的切换必须保留数据。
- 不按返回顺序或最新时间任取一个批号；同步表存在多个批号时全部展示。
- 不直连 ERP，不新增批号回调或本地回填接口。
- 不改变工序开始、批记录表单和表单槽位 `formBindings` 的既有职责。
- 不改变现有损耗、设备参数、电子签名和组长归属规则。

## Functional Requirements

### FR-01 工序物料配置来源

系统必须从订单冻结路线版本的产品 BOM 配置中，按“路线产品 + 当前工序”读取报工物料。不得从当前最新路线、生产记录文本、批记录表单、表单槽位或默认物料推断。

### FR-02 配置维护

路线维护人员在候选版本的产品 BOM 配置中切换工序页签，添加或删除该工序的 BOM 物料。保存和发布后，新订单按该版本使用该配置。

### FR-03 物料页签生成

一线生产进入某订单、某工序后，系统必须为该工序的每个正式报工物料生成一个页签。粗洗配置弹簧和杠杆时必须显示两个页签，不能只显示产品本身或任取第一个 BOM 物料。

### FR-04 独立草稿

每个物料页签必须持有独立填写内容。切换物料页签时，页面输入区显示所选物料的数据；切回后必须恢复此前填写值。

### FR-05 页签颜色

物料页签颜色只能由该物料的完成数量是否被明确填写决定。初始空值为灰色；填写任意允许的数字后为绿色；清空后恢复灰色。

### FR-06 统一提交

点击一次“正式提交”必须携带当前工序全部配置物料及其填写数据，并继续使用当前工序、员工、工作站、签名和提交幂等上下文。任何物料未形成正式事实时，整次提交不得返回成功。

### FR-07 提交后锁定

正式提交明确成功后，本次提交中的物料数据成为不可直接修改的正式事实。后续更正必须使用现有正式更正流程，不得在一线页面覆盖原记录。

### FR-08 进度最小值

后端必须根据全部物料明细计算 `min(outputQuantity)` 作为本次工序进度。客户端不得单独指定或覆盖该进度。

### FR-09 批号展示

系统按生产工单编号和物料编码从同步领料单明细读取全部非空批号；没有数据时返回空集合。批号不参与现场页签颜色，不作为正式提交前置条件。

### FR-10 审计与追溯

系统应能从一次工序正式提交追溯到全部物料明细，并按生产订单号和物料编码追溯到系统同步批号来源行。

## Business Rules

- BR-01：工序报工物料的唯一首版来源是订单冻结路线版本中的产品 BOM 工序关系。
- BR-02：物料身份以正式物料编号为准；物料名称和编码用于展示，不能作为唯一关联条件。
- BR-03：同一个物料出现在不同工序时，是不同工序范围内的报工明细，不得互相覆盖。
- BR-04：页签初始灰色；完成数量被明确填写后绿色；清空后灰色。
- BR-05：完成数量填写 `0` 也属于已填写。页面初始不得用默认显示的 `0` 冒充用户已填写。
- BR-06：绿色只表达完成数量填写状态，不表达其它字段完整性、提交结果或批号结果。
- BR-07：正式提交粒度是“当前订单的当前工序”，不是单个物料页签。
- BR-08：同一次正式提交中的全部物料必须作为同一业务操作处理，不允许静默部分成功。
- BR-09：工序进度直接取各物料完成数量最小值，不按 BOM 比例折算。
- BR-10：批号只读系统每日同步领料单明细；没有就为空，不能人工编造、默认生成、直连 ERP 或改读缺订单身份的数据源。
- BR-11：路线新版本的物料调整不能改变已经进入执行的订单及其历史提交。
- BR-12：报工物料配置与工序开始、批记录表单、表单槽位彼此独立，任何一条链路不得替代另一条。
- BR-13：物料页签仅切换物料明细；订单、工序和实际员工属于本次提交公共上下文。
- BR-14：实现不得另建与产品 BOM 并行且需要人工双重维护的物料清单。

## States and Transitions

### 物料页签显示状态

| 当前状态 | 触发条件 | 页面颜色 | 下一状态 |
|---|---|---|---|
| 未填写 | 完成数量为空 | 灰色 | 用户填写完成数量后进入“已填写” |
| 已填写 | 完成数量被明确输入，包括 `0` | 绿色 | 用户清空完成数量后回到“未填写” |

物料页签没有其它颜色状态。是否选中只用边框、加粗或下划线区分。

### 工序报工业务状态

| 当前状态 | 触发动作 | 结果 |
|---|---|---|
| 填写中 | 用户在多个物料页签间切换和填写 | 分物料保存页面会话草稿 |
| 待正式提交 | 全部配置物料均已填写完成数量 | 允许进入现有正式提交与签名流程 |
| 正式提交中 | 用户确认正式提交 | 只发送一次包含全部物料的正式请求 |
| 已正式提交 | 正式提交成功 | 数据成为正式事实，进度取完成数量最小值 |
| 同步批号为空 | 系统同步表无目标订单物料批号 | 只读批号保持空白 |
| 同步批号可见 | 系统同步表有非空批号 | 展示全部去重批号 |
| 提交失败 | 正式提交失败或结果明确失败 | 保留所有填写内容，不显示成功 |
| 同步表读取失败 | 查询系统同步表发生错误 | 显示真实错误，不切换数据源 |

## Edge Cases

### 工序没有配置物料

页面必须提示“当前工序未配置报工物料”，并阻止正式提交。不得回退为产品物料、首个 BOM 物料、默认物料或空物料成功。

### 只有一个物料

页面显示一个物料页签，填写和统一提交行为与多物料保持一致。

### 只填写了一个物料

已填写完成数量的物料为绿色，另一个保持灰色。点击正式提交时明确指出未填写完成数量的物料，不发送请求。

### 完成数量填写为零

用户明确输入 `0` 后页签变绿；页面初始空值不能自动变成绿色。

### 清空完成数量

已变绿的物料页签在完成数量被清空后立即恢复灰色，该物料的其它草稿内容保留。

### 快速切换物料

切换过程中不得把前一个物料的完成数量、损耗、设备或参数写入后一个物料。

### 正式提交失败

页面保留所有物料草稿和原幂等上下文，显示正式错误；不得清空、变成新会话或显示提交成功。

### 重复点击正式提交

同一填写会话只能形成一次正式提交结果，不得因重复点击生成重复的多物料报工。

### 路线配置发生变化

已经进入执行的订单继续使用自己的冻结版本；新发布版本只影响之后进入执行的新订单。

### 系统仅同步部分物料批号

有同步批号的物料显示批号，没有同步批号的物料保持空白；不把空白改成占位值。

### 同一订单物料存在多个批号

系统返回全部非空批号并去重排序，不按最新时间、返回顺序或任意规则只取一个。

### 同名物料

页签必须补充显示物料编码，正式关联仍使用物料编号。

## Acceptance Criteria

详细 Given/When/Then 验收标准见同目录 `acceptance-criteria.md`。首版验收至少覆盖：

- 粗洗工序配置弹簧、杠杆后，一线生产显示两个物料页签。
- 两个页签初始均为灰色。
- 弹簧完成数量填写后只有弹簧页签变绿。
- 杠杆完成数量填写后杠杆页签变绿。
- 填写 `0` 后页签变绿，清空后恢复灰色。
- 损耗、参数和批号变化不影响页签颜色。
- 切换页签后两种物料的数据互不覆盖。
- 点击一次正式提交形成同一次工序报工下的两条物料明细。
- 弹簧完成数量 `5`、杠杆完成数量 `3` 时，工序进度为 `3`。
- 一个物料未填写完成数量时不发送正式提交，并指出具体物料。
- 系统同步表中的弹簧、杠杆批号按订单号和物料编码分别只读展示；缺少时为空。
- 路线新版本修改物料后，既有订单仍显示冻结版本物料。
- 工序没有正式物料配置时明确阻塞，不使用任何替代来源。

## Open Questions

- 首版假设某工序产品 BOM 下的全部物料都需要一线分别报工。若实际存在只消耗、不需要填写完成数量的 BOM 物料，需要另行确认是否增加“参与一线报工”显式标记；不得用前端隐藏名单处理。

## Product Blockers

- 当前一线正式提交只表达一套完成数量、损耗、设备和参数，尚不能表达同一次工序提交中的多条物料明细；实施前必须扩展正式请求、持久化和读取模型。
- 路线产品 BOM 使用产品、MES 工序和物料身份，一线运行态使用订单冻结路线工序身份；实施必须证明两者能在冻结版本中唯一映射，映射不唯一时必须阻塞。
- 真实页面验证需要目标测试订单在 `erp_kingdee_production_pick_list_item` 中具有可识别样本；没有样本时只能验证空集合路径，不能伪造同步成功。
