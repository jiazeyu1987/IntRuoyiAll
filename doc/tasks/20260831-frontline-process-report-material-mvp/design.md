# 工序多物料一线报工 MVP 设计

## 1. 设计目标

在不新增第二套工序物料配置的前提下，把冻结路线产品 BOM 投影到一线生产运行态；一次正式提交保存多个物料的独立数量、损耗和设备参数，进度取完成数量最小值，批号只读系统每日同步数据。

## 2. 已确认边界

- 物料来源：活跃订单锁定路线版本的 `routeSnapshotJson.configSnapshots.productBoms`。
- 产品身份：活跃订单对应生产工单的正式产品物料。
- 工序身份：当前活跃订单冻结的 `routeProcessId + processId`。
- 页面状态：物料页签仅灰色/绿色；完成数量从空值变为明确输入后绿色，输入 `0` 也绿色，清空恢复灰色。
- 提交粒度：当前工序一次请求，包含全部配置物料。
- 配置隔离：工序开始、批记录表单、表单槽位 `formBindings` 均不参与物料解析。

## 3. 后端设计

### 3.1 冻结物料解析

新增单一职责的冻结工序物料解析服务：

1. 按 `activeOrderId` 读取活跃订单及锁定 `routeVersionId`。
2. 按 `workOrderId` 读取正式产品物料。
3. 解析锁定版本 `productBoms`。
4. 只保留 `productId + processId` 精确命中的物料。
5. 物料身份缺失、重复、BOM 比例非正数或物料主档缺失时明确失败。

运行态响应和一线会话快照都携带同一组冻结物料，正式提交授权只接受快照内完整且不重复的物料集合。

### 3.2 正式提交契约

请求新增 `materialDetails[]`，每项包含：

- `materialId`、编码、名称和冻结 BOM 比例；
- `outputQuantity`、`lossQuantity`、`lossDetails[]`；
- `selectedDevice`、`deviceParameterReadings[]`。

后端要求提交集合与会话快照物料集合完全一致。每个物料必须明确携带完成数量；不按名称或顺序补齐。全部明细、主报工、签名和工序池事件处于同一事务。

### 3.3 持久化

新增 `mes_pro_feedback_material` 作为 `mes_pro_feedback` 的正式子表，每条记录保存：

- 报工、订单、冻结路线版本、路线工序和物料身份；
- 冻结 BOM 比例；
- 完成数量、损耗数量；
- 损耗、设备和参数 JSON 快照；
- 不复制 ERP 批号；批号查询时从系统同步表读取。

唯一约束为租户内 `feedback_id + material_id`。删除不在本任务范围；回滚方案为回滚应用后保留新表，避免丢失已形成的正式事实。

### 3.4 系统同步批号读取

按报工物料的生产工单编号和物料编码查询 `erp_kingdee_production_pick_list_item`，读取全部非空 `lot_number`，去重后排序返回。没有同步记录时返回空集合；查询失败时暴露真实错误。禁止改读缺少生产订单身份的库存表、直连 ERP、写回同步表或生成占位批号。

### 3.5 主报工聚合

逐物料明细是完成数和损耗的正式源事实。旧单行主报工继续满足既有数量守恒：合格数量等于逐物料完成数最小值，不合格数量等于逐物料损耗合计，总报工数量等于两者之和；工序池事件与初始分配只使用最小值进度，不把损耗重复计入订单进度。

## 4. 前端设计

- 运行态增加 `materials`。
- 以 `materialId` 为键维护独立草稿，草稿包含完成数量、损耗明细、设备选择和参数读数。
- 红框区域渲染大号触屏物料页签；未填写完成数量为灰色，明确填写后为绿色。
- 选中态只通过边框和字重表达，不引入第三种状态色。
- 切换前保存当前草稿，切换后恢复目标物料草稿。
- 正式提交前只新增“全部配置物料必须明确填写完成数量”门禁；其它现有签名和正式提交规则不由本需求改变。
- 正式请求只发送一次，`materialDetails` 按冻结物料集合构建。

## 5. 已确认业务决定

### 5.1 单一工序进度数量

现有工序池使用一个进度数量。用户确认：

`工序进度数量 = min(各物料完成数量)`

例如弹簧和杠杆完成数量分别为 `5`、`3` 时，粗洗进度为 `3`。逐物料事实继续保留原始 `5` 和 `3`。

### 5.2 批号数据源

不实现 ERP 外部调用或内部回填接口。批号只从系统每日同步的生产领料单明细读取；系统内没有就返回空集合。
