# Execution Log

## User Intent

- 用户提供多段生产报工、批记录电子化和 PQC 检验会议内容。
- 用户要求提炼需求，并按既有设计控制矩阵 Excel 的结构填写工作簿。
- 本任务沿用用户上一轮明确要求：不保存 Git，直接生成 Excel。
- 用户于 2026-08-01 补充订单确认周期、异常订单停做、工艺路线工序生产系数和报工设备参数归集规则，要求继续按生产开始到生产结束顺序整理。

## BDD

- BDD: 会议需求结构化 -> Given 多段会议纪要包含决策、建议、冲突和待确认项；When 生成需求矩阵；Then 每项可实施需求具有唯一编号、主要设计输入、级联设计输入和设计输出。
- BDD: 报工与批记录边界清晰 -> Given 会议明确报工与订单级批记录不能一一对应；When 建模两条业务链路；Then 批记录不得由报工状态自动触发，且填写主体分别表达。
- BDD: 简化一线操作 -> Given 一线员工不适合记忆设备编码或手输复杂参数；When 设计参数填报；Then 系统应提供设备勾选、默认中值、加减微调和异常视觉提示。
- BDD: 异常数据真实留存 -> Given 参数或数量可能超出规则；When 用户保存异常数据；Then 系统应警示、记录异常原因并支持管理复盘，不得静默丢弃或伪造。
- BDD: 原始记录合规 -> Given 会议提出日期倒推和对外调整；When 形成正式设计输入；Then 原始时间和数据必须不可篡改，更正需留痕审批，对外规则需 QA/法规批准。
- BDD: 订单池与异常订单 -> Given 计划员和班组长可能每周、每两周或当天确认紧急订单；When 班组长上报原材料异常或客户取消等异常；Then 系统应将确认订单进入可执行订单池，并把异常订单从待生产范围移出且留痕。
- BDD: 工序生产系数 -> Given 生产订单要求 300 个产品且工序生产系数可能为 1.0 或 3.0；When 系统计算京订单下每个工序应完成数量；Then 应按订单数量乘以工序系数计算目标，例如 300*3.0=900。
- BDD: 工序设备参数归集 -> Given 员工报工填写完成数量、损耗数量、设备和设备参数；When 工序达到订单对应目标数量；Then 系统应将该工序设备参数归集到对应批记录表单并更新订单进度。
