# E2E 执行计划

## Purpose and Scope

通过真实 Playwright 页面验证一次新大版本发布后的通知、影响评估和升版衔接。API/DB 只在业务动作全部完成后做只读对账。

## Evidence Reviewed

- 项目 `docs/e2e-rules.md` 和 AGENTS E2E 门禁。
- `user-flows.md`、`acceptance-criteria.md`、现有 DCC 页面入口。

## User Paths

1. 文控通过真实页面发布任务自有 B/1。
2. 在详情“发布后续”确认可见范围、收件人与影响任务摘要。
3. 实际收件账号从站内通知打开新版。
4. Y 负责人处理“无需升版”。
5. Z 负责人处理“需要升版”，打开大版本入口或关联已有开放版本。
6. 文控查看发送状态、任务结论和异常列表。

## Browser or Client Steps

- 每次切换角色都从真实登录页进入测试租户。
- 用真实按钮完成发布、决定、转派、重试和升版入口操作。
- 记录页面可见文件编号、版本、关系方向、收件原因、状态和时间。
- 对目标页面保存脱敏截图；刷新后再次确认持久状态。

## API Verification

- 页面动作完成后才允许只读查询批次、收件人、任务、决定、升版链接和审计。
- 不允许 `fetch`、`apiGet`、直接 HTTP 或 SQL 更新承担任何验收动作。
- 只读结果必须与页面展示逐项一致。

## Console and Log Checks

- 浏览器目标链路 console error 为 0。
- 后端无吞异常、默认用户、重复消息或越权成功。
- 日志与截图不保存密码、token、密钥和完整敏感请求头。

## Test Blockers

- 未获当轮 E2E、数据库写入、账号重置或 48081 重启授权时不执行。
- 缺任务自有 X/Y/Z 新文件、关系或真实账号时标记 BLOCKED。
- 页面缺少任何必需业务入口时不得改用 API 替代。
