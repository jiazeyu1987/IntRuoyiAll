# 测试数据计划

## Purpose and Scope

定义二阶段真实验收所需的最小任务自有数据，避免修改既有业务文件或通过历史数据猜测关系和负责人。

## Evidence Reviewed

- `prd.md`、`e2e-plan.md` 和项目测试数据规则。
- 当前 DCC 同项目关联文件约束和新文件生命周期入口。

## Required Test Data

- X：主发布文件，完整走 A/1 发布、检出检入 A/2、创建并批准 B/1。
- Y：与 X 正向关联的当前正式文件，具有有效责任人。
- Z：当前正式版本反向引用 X，负责人不同于 Y。
- 文控账号：可批准并独立发布 B/1、查看全部后续记录。
- 收件账号：至少一人同时命中文件责任人和正式分发对象，用于去重验证。
- Y/Z 负责人账号：分别处理无需升版和需要升版。
- 无权限账号：验证消息不授予 VIEW 和非负责人不能处理。
- 真实可读取源文件、盖章 PDF 和统一任务标识。

## Reset Procedure

- 工作草稿、未提交关系或失败通知只通过正式页面允许的撤回、删除或重试入口处理。
- 已发布版本、通知发送记录、影响决定和审计不物理删除，保留为测试证据。
- 测试结束按任务标识只读盘点所有增量，明确哪些记录依法保留。

## Data Ownership

- 所有 X/Y/Z、关系、通知和任务均属于测试租户与本任务标识。
- 不修改既有业务文件，不跨租户，不复用历史失败数据冒充验收。

## Test Blockers

- 同项目无法准备三份新文件、责任人停用场景或分发对象时，对应场景保持 BLOCKED。
- 缺真实盖章文件、有效文控/负责人账号或页面入口时不创建半成品数据。
- 不允许通过 SQL 改状态、API 写入、默认项目或默认用户补齐前置。
