# DCC 发布通知与影响评估用户流程

## Purpose and Scope

描述新大版本发布后，文控、通知收件人和关联文件负责人在真实页面上的主要操作路径。只覆盖新发布，不处理历史数据。

## Evidence Reviewed

- 二阶段 PRD。
- 当前 DCC 发布、详情、工作台、关联文件选择和站内通知入口。
- 一阶段发布后快照衔接要求。

## Primary User Flows

### Flow 1 文控发布并查看后续状态

1. 文控在待发布页面确认大版本并执行发布。
2. 页面先显示新版 ACTIVE 和旧版 SUPERSEDED。
3. “发布后续”显示可见范围快照、通知人数、影响任务数和异常数。
4. 文控可进入列表查看每个收件原因和相关文件任务。

### Flow 2 收件人查看新版通知

1. 文件责任人或正式分发对象在站内通知收到新版发布消息。
2. 消息显示文件编号、版本和生效时间。
3. 用户点击后按当前 VIEW 权限进入详情；消息不改变权限。

### Flow 3 负责人判断无需升版

1. 关联文件负责人打开 DCC 工作台“我的影响评估”。
2. 页面展示发布文件、相关文件、发布时版本和关系方向。
3. 负责人选择“无需升版”、填写原因并提交。
4. 任务变为已完成，两个文件的版本状态均不变化。

### Flow 4 负责人判断需要升版

1. 负责人选择“需要升版”并填写原因。
2. 任务显示“需要升版/未开始”。
3. 有 OWNER 权限时点击“开始升版”，进入现有大版本创建流程并明确选择来源。
4. 如果已有开放大版本，页面要求关联已有版本而不是再建一个。
5. 关联版本正式发布后，影响跟踪变为已解决。

## Alternate Flows

- 同一用户既是文件责任人又是分发对象：只收到一条消息，详情显示两个原因。
- 文件没有关联文件：后续区域显示无需影响评估，通知仍正常发送。
- 正反向关系指向同一 Master：只显示一项任务，方向标签同时包含“关联”和“被引用”。
- 文控在任务未处理前转派：选择新负责人、填写原因，原负责人失去处理按钮，新负责人获得任务。

## Error Flows

- 通知失败：文件保持 ACTIVE；文控看到失败原因并只重试失败行。
- 负责人缺失或停用：任务显示待文控分配，不发给无效账号。
- 收件人权限已撤销：点击消息时显示无权访问，不展示文件内容。
- 并发提交评估：后提交者看到任务已被处理，不覆盖先提交结论。
- 需要升版但无 OWNER 权限：保留决定，提示联系项目 OWNER。
- 关联修订失败或被驳回：任务仍未解决并显示真实版本状态。

## Out-of-Scope Flows

- 邮件、短信、企业微信通知。
- 自动催办或自动升版。
- 历史发布补通知、补任务。
- 跨项目关联影响。
- 培训、分发签收阻塞生效。

## Open Questions

- 截止时间和催办由后续阶段定义。
- 外部通知渠道需要外部平台与模板审批后另行评估。
