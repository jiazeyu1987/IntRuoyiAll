# PQC 生产放行一致性修复

## Task Goal

修复 `int_main` 静态审查发现的四项生产放行缺口：不合格审查必须冻结工单并阻止生产/出库；返工和作废必须终结放行申请及 PQC 待办；资料未就绪时前端放行按钮必须禁用；PQC 签名必须使用稳定幂等键并支持响应不确定后的权威回执恢复。

## Milestones

- [x] M0：建立 BDD 场景和 RED 测试，冻结现有缺口。
- [x] M1：实现不合格审查工单冻结、生产/出库门禁及冻结状态恢复。
- [x] M2：实现返工/作废申请与 PQC 待办原子终结。
- [x] M3：实现后端放行就绪投影、前端按钮禁用和签名幂等恢复。
- [x] M4：完成相关回归、类型检查、完整构建和静态链路审查。
- [ ] M5：提交、融合 `int_main` 并完成 worktree/slot 收尾。

## Expected Verification

- 后端测试覆盖申请级评审创建冻结、让步/返工恢复原冻结状态、作废保持冻结、返工/作废终结申请和待办。
- 后端测试覆盖冻结工单无法新增正式生产提交，也无法提交、拣货或完成领料出库。
- 后端测试覆盖待放行分页只对当前页执行资料预检，并返回放行就绪状态和结构化阻塞原因。
- 前端静态合同覆盖按钮按后端就绪状态禁用、稳定幂等键、明确失败与响应不确定分流、只读回执恢复。
- 运行相关 JUnit、前端静态合同、`pnpm ts:check`、`mvn -pl yudao-server -am -DskipTests package`、branch runtime guard 和 `git diff --check`。

## Applicable Experience Gates

- 冻结必须落在正式工单状态，并由生产和领料出库写入口共同执行；不得只在 PQC 放行时检查。
- 返工/作废是终态处置，申请与待办必须同事务终结；让步放行仍需 PQC 电子签名。
- 写请求响应不确定时必须按稳定业务 ID 查询权威回执；不得生成新幂等键碰运气。
- 按钮禁用只能消费后端正式就绪结果，不能由前端猜测映射或物料平衡。
