# G32 历史登记最终执行入口准备

状态：in_progress。G32清单工具已完成主管理审查，G33一次性维护入口仍在开发和独立审查。当前内部`activateVerifiedScope`服务和严格factory已通过工程验证，但入口、实际批准和运行证据尚未齐备，不能因为服务测试通过就声称历史名称已登记。

## 有限分工

- legacy_occupancy_core仅在既有详情任务准备G32证据生成工具／输入合同／离线验证，不改已封存生产代码，不连接数据库、执行Maven或登记历史占用。缺实际39完整MATCH时只输出阻塞诊断，禁止生成ready manifest。
- missing_object_recovery仅在既有后端任务审查现有正式认证接口及一次性本机维护入口设计，不改生产、执行服务、读取token或模拟已认证admin。Root审查后才决定必要实现边界。
- Root核对完整证据、认证来源、同事务审计、当前批准状态，不伪造质量签名或把持久目标当数据库写入授权。

## BDD和必要性

Given旧claim／Master／版本原预像及真实源bytes回执，When生成server-only封存manifest，ThenJava canonical rowHash、NULL、Long字符串、时区微秒、完整scope主键集及用户历史口径完全一致；35MATCH／4NoSuchKey必须没有可执行manifest，不借候选本地附件证明对象已恢复。

Given已有正式OAuth2账号身份和已配置权限，When设计内部维护调用，Then身份只能由正式认证解析，启用同租户doc_control与update权限重查，缺认证立即失败；不能从manifest或账号名构造admin／SYSTEM_ACTOR。配置登记与真实Gxp append同物理事务，缺实际质量生效及登记具体授权时不执行。
