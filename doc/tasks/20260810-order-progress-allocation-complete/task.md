# 订单分配满额后生产进度更新

## Task Goal

修复活跃订单池中订单生产进度未随分配满额更新的问题：无论 FIFO 自动分配还是手动分配给订单，只要订单分配数量达到订单生产数量，对应订单的生产进度必须更新；分配数量允许为空或 0，空按 0 处理。

## Milestones

- [ ] 建立复现口径，确认 FIFO 自动分配和手动分配共用或分离的后端链路。
- [ ] 编写或更新回归测试，先证明“分配满额但生产进度未更新”的失败行为。
- [ ] 在正式业务链路中修复生产进度更新，不引入 fallback、吞异常或默认成功值。
- [ ] 调整分配数量校验，允许空值和 0，并保持负数/非法数字阻断。
- [ ] 运行定向回归验证，并记录 RED/GREEN/REGRESSION 证据。
- [ ] 完成收尾记录和经验沉淀。

## Expected Verification

- 后端定向测试覆盖 FIFO 自动分配满额更新生产进度。
- 后端定向测试覆盖手动分配满额更新生产进度。
- 如涉及前端展示契约，运行对应前端静态或真实路径验证。
- 前端和后端定向测试覆盖分配数量为空或 0 时按 0 保存，不再提示“分配数量必须为正整数”。
