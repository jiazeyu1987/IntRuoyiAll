# 20260728 批次执行批记录表单产品信息表单缺失修复

## Task Goal

修复批次执行中“批记录表单”链路下产品信息表单缺失的问题，确保批记录表单按工序设置中的正式逐工序批记录绑定展示和打开，不被表单槽位、工序开始或动态表单链路替代。

## Milestones

1. 建立缺陷复现与批记录表单数据来源 BDD。
2. 定位批次执行详情、批记录任务生成或前端展示中导致产品信息表单缺失的根因。
3. 先补充失败回归测试，再实施最小正式修复。
4. 运行目标回归与必要的相邻验证，记录 RED/GREEN/REGRESSION 证据。
5. 完成收尾、经验沉淀、提交与推送。

## Expected Verification

- 后端或前端聚焦回归测试可稳定覆盖“产品信息表单作为正式批记录表单出现”的场景。
- 相邻批次执行/批记录表单静态合同或单元测试通过。
- 如运行态前置齐备，再通过真实批次执行页面只读路径验证批记录表单中可见产品信息表单。

## Applicable Gates

- 工艺路线三类配置术语契约：批记录表单必须来自工序设置逐工序正式批记录绑定，不得由 `formBindings`、表单槽位或工序开始配置推断。
- eDHR 批次任务配置来源门禁：当前 BATCH 工序配置存在时必须使用当前正式绑定；缺正式绑定时 fail fast，禁止发布快照通用 fallback。
- Bug Regression Fix Loop：必须先复现并添加 RED 回归测试，再实施最小修复并记录 GREEN。
- 前端静态契约隔离门禁：若宽契约存在无关历史失败，应新增任务专用最小静态合同覆盖当前行为。
- PowerShell/Git 门禁：工作区已有脏改动和 ahead 状态，当前任务文件不得混入既有脏工作区基线提交。

## 设计约束检查

- `是否引入 fallback/降级/吞异常`：否。
- `是否从根因和长期维护角度解决`：是；若正式逐工序批记录绑定来源缺失，将阻塞并补齐正式链路。
- `是否存在临时补丁或绕过`：否。
