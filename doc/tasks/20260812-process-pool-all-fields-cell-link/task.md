# 一线生产完整字段到批记录单元格映射

## Task Goal

把批记录单元格链接页面的“报工数据”来源从 3 个数量字段扩展为当前工序一线生产可提交的完整运行数据字段，使设备、设备参数、checkbox 勾选状态、人员/日期和基础报工数量都可以映射到对应工序的正式批记录表单单元格。

## Milestones

- M1：冻结字段来源边界、现有实现和 BDD 场景。
- M2：用 RED 证明当前字段目录只覆盖数量，不覆盖设备/参数/勾选状态。
- M3：后端补齐 `PROCESS_POOL_REPORT` 字段目录和保存校验。
- M4：前端补齐字段展示、选择和聚合策略合同。
- M5：运行聚焦后端、前端静态/类型检查和必要只读页面验证。

## Expected Verification

- 后端：`MesProBatchRecordCellLinkServiceImplTest` 相关 `PROCESS_POOL_REPORT` 用例。
- 前端：批记录单元格链接 `PROCESS_POOL_REPORT` 静态合同。
- 前端：`pnpm ts:check`。
- 可选：本机真实页面只读验证，不保存映射、不写业务数据。

## Applicable Gates

- 目标仍然只能是工序设置中的正式批记录表单；不得把过程检验、损耗单或表单槽位当作批记录表单目标。
- `PROCESS_POOL_REPORT` 是一线生产/生产组长报工回填专用来源；通用预填继续跳过。
- 多笔报工继续要求显式聚合策略，不允许后端猜测。
- 字段目录必须来自当前路线版本/工序的正式运行配置和参数规则，不允许前端硬编码业务字段。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是；扩展正式来源字段目录而不是前端写死字段。
- 是否存在临时补丁或绕过：否。
