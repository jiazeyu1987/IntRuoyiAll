# Config, Security, and Deployment Design

## Purpose and Scope

本设计定义 eDHR 单元格链接自动落库的配置、权限、安全、部署和可观测性要求。目标是在不引入 fallback 或静默降级的前提下，让系统自动预填具备可追溯、可审计、可验证的运行行为。

范围不包含远端服务器操作、发布执行、密钥变更、运行态重启或数据库数据修复。

## Evidence Reviewed

- 项目规则要求缺失前置条件 fail-fast，禁止吞异常、默认成功和临时兜底。
- eDHR 批次任务打开接口已有 `mes:pro-edhr-batch-execution:update` 权限保护。
- 字段审计保存服务已有草稿保存证据路径 `recordFieldChangeDraftSave`，说明非人工密码场景也需要审计证据。
- 单元格链接规则已通过后台配置启用，生产工单来源字段白名单包含 `batchCode`。
- 只读预览和归档渲染依赖已保存的 `cellValuesJson`，因此自动落库必须发生在后端。

## Configuration

- 阶段一不新增全局开关。自动落库是单元格链接规则启用后的正式行为，避免环境间配置漂移。
- 继续使用现有规则字段：`sourceType`、`sourceFieldCode`、`targetReportId`、`targetCellKey`、`ruleVersion`、`overwritePolicy`、启用状态。
- 生产工单来源字段仍受白名单控制，`batchCode` 是允许字段。
- 若后续增加 `required_on_open` 或类似配置，必须提供迁移、管理端配置说明、默认值策略和 E2E 证据。

## Secrets

- 自动预填不需要新密钥、第三方凭据或电子签名密码。
- 系统预填原因、规则 ID、来源字段和目标单元格可写入审计日志；不得记录用户密码、数据库连接串或原始敏感环境变量。
- 验证日志和任务文档只能记录脱敏后的命令意图和结果。

## Permissions

- 创建批次执行记录时的自动落库继承创建批次/创建执行记录的后端业务权限。
- 打开工序任务时的自动落库继承 `task/open` 的 `mes:pro-edhr-batch-execution:update` 权限和工作任务可见性校验。
- 对填报或返工任务，缺少有效 `workTaskId` 时不得执行用户打开态补齐。
- 系统自动预填不要求人工电子签名密码，但必须标记为系统来源审计动作，不能伪装成当前用户手工填写。
- 只读详情接口不应执行写入，避免查询权限间接修改业务数据。

## Security Controls

- 服务端必须验证目标执行记录、工作任务、批次任务和规则 scope 的一致性，禁止客户端传目标单元格后直接写值。
- 自动落库只写当前规则匹配出的目标单元格，不能接受前端提交的任意值列表。
- 生产工单来源字段必须来自服务端白名单映射，不能通过反射读取任意字段。
- 目标值类型必须按 execution snapshot 字段定义校验和规范化。
- 并发打开必须使用事务锁和幂等键保护字段审计链。
- 错误必须显式返回，禁止写空字符串、默认批号或继续显示成功状态。

## Deployment

- 阶段一设计不执行发布。
- 实现阶段预计包含后端服务变更、VO 字段扩展、前端展示调整和测试补充。
- 如果不新增数据库列，发布不需要 schema migration；如果增加审计元数据列，必须先完成正式 SQL、迁移元数据和 schema contract。
- 发布前需按项目规则运行受影响 Maven 测试、前端静态契约和真实 eDHR 路径 E2E。
- 不允许通过生产库手工 SQL 回填来代替代码修复。

## Observability

- 操作审计应记录自动预填触发点：`EXECUTION_CREATE` 或 `TASK_OPEN`。
- 操作审计应记录结果：应用数量、冲突数量、阻断原因、执行记录 ID、批次任务 ID、规则 ID 和目标单元格。
- 字段审计详情应能追溯每个自动预填单元格的前值、后值、来源字段和规则版本。
- 后端日志应记录业务错误码和上下文 ID，不记录敏感凭据。
- E2E 证据应包含：打开任务响应、执行详情 `cellValuesJson`、字段审计 hash verification、只读预览可见文本。

## Open Questions

- 自动预填是否需要单独的操作审计 action，例如 `CELL_LINK_AUTO_PREFILL`。
- 字段审计页面是否需要筛选“系统自动预填”来源。
- 是否需要在监控中增加自动预填失败数量告警，阶段一可先通过操作审计和日志定位。

## Design Blockers

- 若实现阶段无法通过现有字段审计模型记录系统来源，则必须先设计正式审计元数据迁移，不能直接绕过审计链。
- 若真实打开路径绕过 `task/open`，必须先补齐受权限保护的写边界，不能让只读接口产生隐式写入。
