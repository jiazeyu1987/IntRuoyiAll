# 后续正式修复计划

## 当前结论

任务 `35` 已证明官方批量分类链路可运行，但现有规则不能覆盖全部 DCC 项目代码关联文件。继续重跑同一任务不会消除 `AMBIGUOUS` 和 `UNCLASSIFIED`，必须先修复正式匹配规则。

## 推荐路径

1. 新开“DCC 文件类别可维护别名/评分规则”正式改造任务。
2. 为 `dcc_file_category` 增加可维护匹配别名能力，或新增受控的文件类别匹配规则表；不要继续扩大硬编码别名。
3. 为 OQ/PQ 与“工序卡/作业指导书”建立明确优先级：文件名命中 `OQ报告`、`PQ报告`、`OQ方案`、`PQ方案`、`OQPQ验证方案/报告` 时，应优先命中对应过程确认类别。
4. 为图纸/零配件、记录表/表单、OQ/PQ 参数组、验证方案/报告、BOM/清单等高频未识别形态补充业务确认后的正式别名。
5. 使用任务 `35` 导出的明细作为回归样本，先写 BDD/RED，再实现，最后重跑同一官方批量分类接口。

## 不推荐路径

- 不建议通过直接 SQL 更新 `dcc_controlled_file.fileTypeLevel2/fileTypeLevel3/fileTypeTaxonomyId`，因为会绕过分类依据且无法复用。
- 不建议批量循环调用单文件接口或元数据接口来“填平”结果，因为这不是规则层修复。
- 不建议直接改类别名称来兼容文件名，除非业务确认这些名称就是正式类别名称；否则会影响类别列表、权限、审批、分发和培训等上下游语义。
- 不建议继续仅用当前 `existingRecordPolicy=OVERWRITE_ALL` 重跑；在规则未变时结果预计仍会保留同类歧义和未识别。

## 下一轮 BDD / TDD 建议

BDD: 文件类别别名可维护 -> Given 类别“过程运行确认（OQ）报告”配置别名 `OQ报告`，When 文件名为 `注塑工艺验证OQ报告.pdf`，Then 分类为“过程运行确认（OQ）报告”且不再命中“工序卡/作业指导书”。

BDD: 图纸类文件可识别 -> Given 类别“零配件图纸”配置图纸/零件别名规则，When 文件名为 `公鲁尔接头.sldprt` 或 `图纸.pdf`，Then 分类到业务确认的图纸类文件类型。

BDD: 未识别导出计数一致 -> Given 批量任务存在 `unclassifiedCount`，When 导出 `UNCLASSIFIED` 明细，Then 导出记录数与任务计数一致，或接口明确返回过滤/分页总数。

RED: 使用任务 `35` 样本构造单元/集成测试，证明当前逻辑会对 OQ/PQ 与工序卡产生同分歧义，并对图纸/零配件名称返回未识别。

GREEN: 规则改造完成后，样本分类 `failedCount/conflictCount/ambiguousCount` 为 0，`UNCLASSIFIED` 只保留业务确认无法归类的文件。
