# 20260807-production-leader-process-loss-reasons-random

## Task Goal

在本机 `int_main` 的生产组长工序配置列表中，为每个可见工序通过真实页面随机新增 1~6 个损耗原因。只写入当前确认的登录租户，记录每个工序新增数量和生成的原因编码，避免重复写入或污染其它租户数据。

- [x] 通过真实页面确认登录用户、租户和生产组长工序配置列表。
- [x] 为每个目标工序随机新增 1~6 个损耗原因。
- [x] 通过页面结果和只读接口核对新增数量、名称和编码。
- [x] 完成任务记录、清理临时浏览器产物并收尾。

## Expected Verification

- Playwright 真实页面路径：生产组长 -> 工序配置列表 -> 每个工序新增损耗原因。
- 每个目标工序的新增数量在 1~6 之间，数量和名称/编码可追溯。
- 只读最终核验不修改数据，目标写请求仅为本任务新增损耗原因请求。
- 记录当前前端入口、后端入口、登录租户标签、账号标签和页面实际工序数量。

## Design Constraint Check

- `是否引入 fallback/降级/吞异常`：否；失败时停止并记录具体工序和接口错误。
- `是否从根因和长期维护角度解决`：是；通过正式生产组长工序配置页面和新增损耗原因接口写入，不使用直接 SQL 或 API-only 绕过页面。
- `是否存在临时补丁或绕过`：否。

## Data Safety

- 环境：仅允许本机 `int_main`，前端 `http://127.0.0.1:8081`，后端 `http://127.0.0.1:48081`。
- 租户/账号：执行前从真实登录页面确认并记录标签，不记录密码或 token。
- 写入范围：当前页面展示的生产组长工序配置列表；不删除、不修改已有损耗原因。
- 随机规则：每个目标工序使用独立随机整数 `1..6`；名称使用任务标识前缀，避免与既有业务原因重名。
- 回滚：本任务只新增数据；如需撤销，必须由用户另行明确授权后按记录的原因编码逐条停用或删除，当前任务不自动回滚。
