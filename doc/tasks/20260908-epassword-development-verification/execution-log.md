## BDD / TDD Summary

BDD: 4.1 account uniqueness -> Given a system user is created, When username is reused including deleted accounts, Then the system rejects duplicate canonical usernames.

BDD: 4.2 password strength -> Given a user password is set or reset, When the password misses required length or character groups, Then the system rejects it.

BDD: 4.3 first/reset login password change -> Given a new or reset user logs in, When default or temporary password is still active, Then signature-capable use requires password change first.

BDD: 4.4 password expiry -> Given a password exceeds configured age, When authentication/signature reauthentication occurs, Then the system rejects it until changed.

BDD: 4.5 password history -> Given recent password history exists, When the user reuses a recent password, Then the system rejects reuse.

BDD: 4.6 lockout -> Given repeated password failures occur inside the configured window, When threshold is exceeded, Then account/signature authentication is locked.

BDD: 4.7 content binding -> Given a business object is signed, When content changes after signing, Then stored content/evidence hash verification detects mismatch.

BDD: 4.8 server signed time -> Given a signature is created, When signed time is recorded, Then it is generated by server-side trusted-time evidence and cannot be user-supplied.

BDD: 4.9 audit trail -> Given a signature or privileged evidence access occurs, When auditors query history, Then signer, time, reason, hashes, algorithm, key version, before/after evidence and access audit are available.

BDD: 4.10 periodic review -> Given quarterly or special compliance review is due, When review is created or overdue, Then review batch and escalation evidence are persisted.

BDD: 4.11 ordered approvals -> Given BPM/DCC/MES approval signatures are required, When signing happens, Then signature evidence binds workflow/process context through the unified kernel.

BDD: 4.12 signer identity -> Given a formal electronic signature is attempted, When the signer provides credentials, Then the system uses unique account session plus password reauthentication and rejects temporary employee independent signature passwords.
