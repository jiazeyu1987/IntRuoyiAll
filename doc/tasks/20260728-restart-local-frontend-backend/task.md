# 重启本地前后端

## 任务目标

重启 `E:\IntRuoyi` 的 `int_main` 前端与后端运行态，并确认前端 `8081` 与后端 `48081` 可用。

## 里程碑

- [x] 读取本地运行、worktree、PowerShell、任务收尾规则。
- [x] 核对 `8081/48081` 当前监听进程与工作区归属。
- [ ] 停止当前任务目标的旧前后端进程。
- [ ] 使用标准本地运行脚本重新启动前后端。
- [ ] 验证前端 HTTP 200、后端健康状态 UP，并记录新 PID。
- [ ] 完成任务清理与最终记录。

## 预期验证

- `http://127.0.0.1:8081/` 返回 HTTP 200。
- `http://127.0.0.1:48081/actuator/health` 返回 `status=UP`。
- 新监听进程命令行归属 `E:\IntRuoyi` 的 `int_main` 前后端运行态。

## 适用经验门禁

- 标准本地重启必须使用 `IntRuoyiFronted` 正式前端路径，不得创建旧硬编码目录绕过。
- 后端保持 tokenless Runner 模式，不生成或注入 `CODEX_TEST_RUNNER_TOKEN`。
- 长期运行后端必须使用 `output\runtime\int_main` 下的稳定 Jar 副本与稳定日志目录。
- 端口被未知进程或其他 profile 占用时立即阻塞，不得强杀或随机换端口。
- 前端依赖损坏时只能按 lockfile 正式恢复，不得手工复制包或创建链接。

- `是否引入 fallback/降级/吞异常`：否。

- `是否存在临时补丁或绕过`：否。
