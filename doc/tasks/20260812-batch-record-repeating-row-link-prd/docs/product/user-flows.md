# 一线生产重复行组批记录链接用户流程

## Purpose and Scope

描述配置人员如何在现有批记录单元格链接页面建立重复行组，以及生产组长申请放行时如何使用该对应关系生成当前工序正式批记录。配置和一线生产提交阶段均不生成批记录。

## Evidence Reviewed

- 用户提供的四条重复生产记录示例。
- 用户确认模板记录、重复区域和候选记录必须由用户选择并确认。
- 用户确认当前功能只做对应关系，正式数据在生产组长点击“申请放行”时生成。
- 现有“报工数据”完整字段目录和固定单元格链接能力。

## Primary User Flows

### Flow-01 Create Repeating Row Group

1. 配置人员从当前工艺路线版本进入目标工序。
2. 打开该工序绑定的正式批记录表单链接页面。
3. 页面显示路线版本、工序、批记录表单和表单版本。
4. 用户将模式切换为“重复行组”。
5. 用户点击“选择模板记录”，框选第一条完整生产操作记录。
6. 用户点击“选择重复区域”，框选全部可重复记录。
7. 系统按模板结构识别候选记录，并标记第 1、2、3……条。
8. 用户检查候选结果，删除误识别记录、补选漏识别记录或调整顺序。
9. 用户确认候选记录。
10. 用户在左侧选择当前工序“报工数据”字段，再点击模板记录目标单元格建立链接。
11. 系统将模板链接投影到全部候选记录并显示预览。
12. 用户检查设备、参数、checkbox、数量、操作时间、操作人和复核人映射。
13. 用户保存。
14. 系统完成结构、冲突、版本和必填字段校验后启用配置。
15. 保存成功后不生成批记录、不写目标单元格、不预占候选记录。

### Flow-02 Frontline Production Submission

1. 一线员工进入当前工序一线生产 UI。
2. 员工选择实际人员、设备，填写参数、checkbox 和数量。
3. 员工完成正式提交。
4. 系统保存该次正式生产事实及其实际员工、提交时间和业务顺序。
5. 本次提交不调用重复行组生成，不写批记录，也不占用第 1 条或其它目标记录。
6. 后续提交继续各自形成独立正式生产事实。

### Flow-03 Generate Records on Release Application

1. 生产组长进入活跃订单并点击“申请放行”。
2. 既有申请放行门禁确认生产和检验等正式前置已经满足，生产数据已封口。
3. 系统按当前活跃订单锁定的路线版本逐工序读取正式一线生产提交事实。
4. 系统按正式提交顺序形成第 1、2、3……条来源记录。
5. 系统读取该工序和正式批记录表单版本的已启用重复行组。
6. 第 1 条来源写入第 1 条目标记录，第 2 条来源写入第 2 条目标记录，后续依次对应。
7. 每条记录的操作人和操作时间来自对应一线生产提交。
8. 每条记录的复核人取本次申请放行的生产组长；本期不配置、不生成复核时间字段。
9. 系统一次性完成正式批记录资料生成并继续申请放行流程。

### Flow-04 Fewer Sources Than Candidate Records

1. 当前工序配置了多条重复记录。
2. 本次申请放行只存在较少的正式一线生产提交事实。
3. 系统只按顺序生成对应数量的前 N 条记录。
4. 其余候选记录保持未使用，不填默认值，也不复制最后一条来源。

## Alternate Flows

### AF-01 Correct Candidate Recognition

系统识别结果完全正确时，用户直接确认候选记录，无需逐条重新选择。

### AF-02 Repair Candidate Recognition

系统漏识别或误识别时，用户在重复区域内增删候选记录并调整顺序；系统实时重新生成投影预览。

### AF-03 Multiple Repeating Sections

若同一正式表单存在多个独立重复区域，用户分别建立重复行组。各组必须使用独立名称和非重叠目标范围。

### AF-04 Duplicate Release Request

同一申请放行因重复点击或网络重试再次到达时，系统返回原生成结果或继续同一次生成，不再生成第二套资料。

### AF-05 New Form Version

批记录发布新版本后，旧配置只用于旧版本历史资料。用户可查看旧配置作为参考，但必须在新版本中重新确认模板、候选记录和目标位置。

## Error Flows

### EF-01 Missing Formal Batch Record

当前工序没有正式批记录表单或正式版本时，页面阻断配置并指出缺失身份，不切换到表单槽位。

### EF-02 Structural Mismatch

候选记录无法承载模板全部字段时，保存失败，页面突出显示具体记录和不匹配单元格。

### EF-03 Target Conflict

重复行组与固定单元格链接或其它重复行组目标重叠时，保存失败并展示冲突双方。

### EF-04 Missing or Invalid Mapping

申请放行时，当前锁定版本缺少已启用重复行组、必填字段链接或目标结构已失效，系统明确阻断，不改用其它表单或旧版本配置。

### EF-05 Concurrent Release Requests

同一活跃订单两个申请放行请求同时到达时，只允许一个生成；另一个返回同一幂等结果或明确冲突，不生成重复资料。

### EF-06 Version Changed During Editing

用户配置期间路线或表单版本变化时，保存失败并要求重新打开最新版本，不把旧坐标写入新版本。

## Out-of-Scope Flows

- 从生产工单读取生产批号。
- 从领料单读取物料批号。
- 修改一线生产数量校验、剩余数量或超报规则。
- 在本功能中处理申请放行时的数量不一致问题。
- 在一线提交时提前生成或预占批记录行。
- 新增独立的生产组长复核操作或复核时间判断。
- 自动迁移并启用旧版本重复行组。
- 申请放行后正式资料的更正、作废或受控再生成。

## Open Questions

- 申请放行后正式资料需要更正或作废时的受控处理方式。
- 各工序启用重复行组前必须映射的最小字段集合。
