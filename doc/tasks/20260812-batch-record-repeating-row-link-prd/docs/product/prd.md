# 一线生产重复行组批记录链接 PRD

## Purpose and Scope

本需求只负责配置“当前工序一线生产数据”与“当前工序正式批记录表单重复记录区域”之间的对应关系，不在配置页面生成批记录数据，也不在一线员工每次提交时写入或占用批记录行。

系统应在现有“批记录单元格链接”页面增加“重复行组”模式。业务人员为当前路线版本、当前工序和当前正式批记录表单版本选择一条模板记录、选择全部可重复区域、确认候选记录顺序，并在模板记录中建立字段链接。

这些链接在生产组长点击“申请放行”时才被使用。系统读取该活跃订单已经封口的正式一线生产提交事实，按正式提交顺序将第 1、2、3……次提交分别投影到第 1、2、3……条已确认重复记录，并一次性生成放行所需的正式批记录资料。

## Evidence Reviewed

- 用户提供的光固 I 工序生产记录截图及红、蓝、绿、黄四条示例记录区域。
- 用户确认该结构不是光固 I 特例，绝大多数工序的一线生产内容对应批记录中的重复记录行。
- 用户确认采用“首条模板记录 + 全部重复区域 + 用户确认候选记录”的配置方式。
- 用户确认本功能只做对应关系；批记录数据在生产组长点击“申请放行”时统一生成。
- 用户确认申请放行时数据已经封口，不会在本功能中出现数量不一致，也不存在需要本页面处理的复核时间逻辑。
- 现有任务 20260811-process-pool-report-cell-link-config：已经支持“报工数据”来源到固定单元格的链接。
- 现有任务 20260812-process-pool-all-fields-cell-link：已经把报工来源扩展到当前工序完整一线生产字段。
- 项目术语契约：目标必须是工序设置中逐工序绑定的正式批记录表单，不得由表单槽位 formBindings、过程检验记录或损耗单替代。

## Product Summary

### Core Relationship

唯一允许的正式配置关系是：

当前路线版本 + 当前工序的一线生产字段 -> 当前工序绑定的正式批记录表单版本中的重复行组。

申请放行时的使用关系是：

当前工序第 N 条正式一线生产提交事实 -> 当前工序重复行组中用户确认的第 N 条记录。

不同工序必须独立配置。即使两个工序使用相似表单，也不能仅按工序名称、表单名称或字段名称自动共用链接。

### Page Strategy

功能继续放在现有“批记录单元格链接”页面，不新建平行页面。页面增加模式切换：

- 单元格链接：保留现有固定目标单元格能力。
- 重复行组：配置一条正式生产提交事实如何投影到一组可重复记录。

两种模式可以在同一张正式批记录表单中并存，但目标区域不得互相冲突。配置页面只保存对应关系，不提供“生成批记录”操作。

### Generation Timing

- 一线员工完成正式生产提交时，只形成正式生产事实，不写批记录、不占用重复行。
- 生产组长点击“申请放行”时，系统才读取已封口的正式生产事实并生成批记录。
- 申请放行既有完成性门禁负责保证生产数据完整；本功能不新增单次提交数量、剩余数量或超报判断。

## Target Users

- 工艺路线或批记录配置人员：选择当前工序、正式批记录表单和重复记录区域。
- 生产工艺或质量负责人：确认模板记录结构、字段含义和记录顺序。
- 一线生产员工：按当前工序 UI 形成正式生产提交事实。
- 生产组长：点击“申请放行”，触发正式批记录资料生成；若表单配置了复核人字段，生成链路使用该生产组长。
- 审计和批记录管理员：查看对应关系、来源提交、目标记录和生成证据。

## First Version Scope

1. 在现有页面提供“重复行组”模式。
2. 只允许选择当前工序绑定的正式批记录表单及其正式版本。
3. 用户选择第一条完整逻辑记录作为模板记录。
4. 用户选择包含全部可重复记录的连续区域。
5. 系统依据模板的列边界、合并单元格和结构识别候选记录。
6. 用户必须明确确认候选记录及其第 1、2、3……条顺序。
7. 用户可以删除误识别记录，也可以在重复区域内补选漏识别记录。
8. 用户只在模板记录中建立字段链接，系统预览这些链接在后续记录中的对应位置。
9. 保存路线版本、工序、正式批记录表单版本、重复行组、候选顺序和字段链接关系。
10. 一线生产提交阶段不生成批记录，也不占用候选记录。
11. 生产组长申请放行时，按正式提交顺序一次性使用对应关系生成重复记录。
12. 生成结果保留来源提交、目标记录、操作人与时间、申请放行生产组长以及配置版本的可追溯证据。

逻辑记录通常是一行，但允许包含合并单元格；其边界以用户确认的完整模板记录为准，而不是全局假定每条记录只占一个物理表格行。

## Non-Goals

- 本阶段不从生产工单提取生产批号。
- 本阶段不从领料单提取物料批号。
- 不修改一线生产提交、数量计算或生产完成性规则。
- 不在一线生产每次提交时生成批记录或预占重复行。
- 不在链接配置页面提供生成、补生成或重新生成正式批记录的入口。
- 不新增独立的生产组长复核步骤；申请放行人就是本次资料的生产组长复核人。
- 不把表单槽位 formBindings、过程检验记录表单或损耗单当作正式批记录目标。
- 不按光固 I、工序名称、设备编码或固定 4 条记录硬编码。
- 不在没有用户确认的情况下自动保存系统识别结果。
- 不自动迁移旧表单版本或旧路线版本的重复行组配置。
- 不以隐藏错误、跳过字段或部分写入方式完成资料生成。

## Functional Requirements

### FR-01 Current Process Context

页面必须明确显示当前路线版本、当前工序、当前正式批记录表单及表单版本。缺少其中任一正式身份时，不允许保存重复行组。

### FR-02 Mode Selection

用户可以在“单元格链接”和“重复行组”之间切换。切换模式不得删除另一模式已经保存的有效配置。

### FR-03 Template Record Selection

用户点击“选择模板记录”后，在表单预览中框选第一条完整生产记录。模板范围必须覆盖一次正式生产提交需要写入的全部目标单元格，包括可能存在的合并单元格。

### FR-04 Repeat Area Selection

用户点击“选择重复区域”后，框选从第一条到最后一条可用生产记录的完整区域。区域必须连续，且必须包含模板记录。

### FR-05 Candidate Recognition and Confirmation

系统根据模板结构识别候选记录，并用编号和不同颜色显示第 1、2、3……条记录。识别结果只是候选；用户必须确认后才能保存。

用户可以删除误识别记录、在已选重复区域内补选漏识别记录、调整候选记录顺序，或者重新选择模板和重复区域。

### FR-06 Template Field Mapping

用户从“报工数据”来源中选择当前工序一线生产字段，再点击模板记录中的目标单元格建立链接。

首版字段范围包括：

- 本次生产数量、合格数量、不合格数量和损耗数量。
- 选用设备及设备选择状态。
- 设备是否在计量有效期内。
- 参数参考值、实际值、单位、上下限、标准值和运行状态。
- checkbox、清场、物料、清洁和生产自检等确认状态。
- 操作日期：对应正式一线生产提交的时间。
- 操作人：对应正式一线生产提交的实际员工。
- 复核人：点击本次“申请放行”的生产组长；仅在目标表单存在该字段并建立链接时写入。
- 复核时间：本期不作为可配置、可生成字段；如后续表单确需复核日期或复核时间，必须另行冻结业务规则后再纳入。

### FR-07 Projection Preview

用户完成模板记录映射后，系统必须预览相同字段在每条后续候选记录中的目标位置。预览必须显示记录序号、来源字段、模板目标单元格、每条候选记录的投影目标单元格，以及聚合或值转换规则。

### FR-08 Save Validation

保存前至少校验：

- 路线版本、工序、批记录表单和表单版本身份完整。
- 模板记录属于重复区域。
- 候选记录顺序唯一且连续。
- 每条候选记录结构可承载全部已映射字段。
- 同一目标单元格没有多个冲突来源。
- 重复行组目标不与其它启用的固定单元格链接或重复行组冲突。
- 必填生产字段已建立链接。
- 配置对应的表单版本仍是用户开始配置时的版本。

任一校验失败都必须指出具体记录序号和目标单元格。

### FR-09 Configuration-Only Boundary

保存重复行组只保存对应关系。保存、启用或查看配置均不得：

- 创建批记录执行数据。
- 向正式批记录目标单元格写值。
- 给任何一线生产提交分配或预占候选记录。
- 改变一线生产数量、状态或完成性结果。

### FR-10 Release-Time Use of Mapping

生产组长点击“申请放行”并通过既有放行前置门禁后，系统按当前活跃订单和路线版本逐工序使用本页面保存的对应关系：

1. 读取当前工序已经形成且纳入本次放行的正式一线生产提交事实。
2. 按正式提交顺序形成稳定的第 1、2、3……条来源记录。
3. 使用本次路线版本、工序和正式批记录表单版本对应的已启用重复行组。
4. 将第 N 条来源记录的全部已映射字段写入用户确认的第 N 条目标记录。
5. 在同一次申请放行事务中完成该工序正式批记录资料生成。

不得在申请放行前提前写值，也不得按目标单元格是否为空猜测来源顺序或目标记录。本功能不重新比较生产数量是否一致；生产数据是否已经满足放行条件由既有申请放行门禁负责。

### FR-11 Operator and Reviewer Field Source

- 每条目标记录的操作日期取其对应正式一线生产提交时间。
- 每条目标记录的操作人取其对应正式一线生产提交所选的实际员工。
- 每条目标记录的复核人取点击本次“申请放行”的生产组长。
- 本功能不新增独立复核动作，也不配置或生成复核时间。

### FR-12 Unused Records and Generation Boundary

- 正式提交事实数小于重复记录数时，只生成前 N 条记录，其余记录保持未使用。
- 正式提交事实数等于重复记录数时，生成全部记录。
- 不允许覆盖、循环使用、跳过或动态扩展用户未确认的重复记录。
- 一次申请放行要么完整使用已启用对应关系生成当前要求的资料，要么不留下部分批记录。

本功能不把“生产数量是否一致”作为自身规则；申请放行点击时生产数据已经封口，不把数量差异作为重复行组配置页的验收或 blocker。

### FR-13 Version Isolation

重复行组按路线版本、路线工序身份、正式批记录定义和批记录版本隔离。

路线或批记录发布新版本后：

- 旧版本配置继续服务旧版本历史资料。
- 新版本不得静默继承为已启用配置。
- 用户可以参考旧配置重新确认，但必须在新表单预览中重新校验候选记录和目标单元格后才能启用。

申请放行必须使用该活跃订单已经锁定的路线版本和对应正式批记录版本，不能改用当前最新版本。

### FR-14 Auditability

每次资料生成应能追溯重复行组配置版本、来源提交顺序和身份、目标记录序号和范围、操作人/提交时间、申请放行生产组长、来源值与最终目标值，以及成功、失败、重试或冲突结果。

### FR-15 Idempotency and Concurrency

- 同一申请放行因重复点击、网络重试或幂等重放再次到达时，不得重复生成批记录或改变来源到目标的顺序。
- 同一活跃订单的两个申请放行请求不能并发生成两套资料。
- 失败重试必须使用同一组来源事实、同一配置版本和同一目标记录顺序。

## Business Rules

1. 当前工序正式批记录表单是唯一目标来源。
2. 本功能只配置对应关系，不在配置或一线提交阶段生成正式批记录。
3. 重复记录数量由用户确认，不由系统全局固定。
4. 自动识别只提供候选，不代表用户确认。
5. 一条正式一线生产提交事实对应一条逻辑记录。
6. 来源和目标均按稳定顺序一一对应，不通过目标单元格是否为空推断。
7. 正式资料只在生产组长申请放行时统一生成。
8. 操作人和操作时间来自各条一线生产提交；复核人来自本次申请放行生产组长。
9. 本功能不处理数量不一致，也不新增复核时间逻辑。
10. 固定单元格链接和重复行组可以并存，但目标不能重叠。
11. 本功能不改变申请放行既有完成性门禁。

## States and Transitions

### Configuration States

- 未配置：当前工序和表单版本没有重复行组。
- 草稿：已选择模板、区域或字段，但尚未通过全部校验。
- 待确认：系统已识别候选记录，等待用户确认数量和顺序。
- 已启用：配置通过校验，可在申请放行时使用。
- 版本失效：路线或表单版本变化，当前配置不能用于新版本。
- 已停用：管理员明确停止该配置；历史资料仍可追溯。

### Release Generation States

- 未生成：存在已启用对应关系，但生产组长尚未申请放行。
- 生成中：申请放行已开始，正在按冻结来源和配置生成资料。
- 已生成：正式批记录资料完整生成，并与放行申请关联。
- 生成阻断：缺配置、结构不匹配或其它正式前置失败；不得留下部分资料。

一线生产提交本身不会改变以上批记录生成状态，也不会让某条候选记录进入“已占用”。

## Edge Cases

- 模板记录包含合并单元格：按用户确认的逻辑记录边界识别，不按单个物理行截断。
- 某条候选记录列结构不同：标记具体记录和差异，不允许启用。
- 参数在部分工序不存在：只能映射当前工序正式运行配置中实际存在的字段。
- 某次可选字段为空：申请放行时仍按该正式提交事实生成一条对应记录，后续来源不能前移覆盖。
- 来源记录少于候选记录：只使用前 N 条，剩余记录保持未使用。
- 来源记录数量异常：不作为本页面配置问题；申请放行既有门禁通过后才使用本对应关系。
- 用户重复点击申请放行：同一幂等业务事实只产生一套批记录资料。
- 两个申请放行请求并发：只能有一个生成成功，另一个返回同一结果或明确冲突。
- 配置保存期间表单版本变化：拒绝保存并要求重新打开新版本。
- 申请放行时配置失效、目标单元格被删除或冲突：阻断并保留精确错误，不改用其它表单或其它记录。
- 固定链接目标与重复行目标重叠：拒绝启用并显示冲突来源。
- 一线生产数量不一致：不属于本功能；申请放行既有完成性门禁未通过时，不进入本对应关系的资料生成阶段。

## Acceptance Criteria

- AC-01：用户能在现有链接页面切换到“重复行组”，且固定单元格链接仍可使用。
- AC-02：页面只允许为当前工序绑定的正式批记录表单版本配置重复行组。
- AC-03：用户可选择模板记录和重复区域，并确认系统识别的候选记录数量、顺序和边界。
- AC-04：候选识别错误时，用户可增删候选记录并重新排序。
- AC-05：用户只映射模板记录，页面能够预览所有候选记录的投影目标。
- AC-06：设备、参数、checkbox、数量、操作时间、操作人和复核人均可链接。
- AC-07：保存或启用对应关系不会生成批记录、写目标值或预占重复记录。
- AC-08：生产组长申请放行时，第 1、2、3 次正式生产提交依次生成到第 1、2、3 条目标记录。
- AC-09：操作人和操作时间来自各条一线生产提交，复核人来自本次申请放行生产组长。
- AC-10：来源记录少于候选记录时，多余候选记录保持未使用。
- AC-11：本功能不处理数量不一致，也不要求配置页判断复核时间。
- AC-12：同一申请放行重试不会重复生成或改变来源到目标的顺序。
- AC-13：路线或表单新版本不能静默复用旧版本启用配置。
- AC-14：每条生成记录可以追溯配置、来源提交、目标记录、来源值、目标值和人员证据。
- AC-15：本功能不新增生产数量一致性校验，也不新增独立复核动作。

## Open Questions

### OQ-01 Correction and Void

申请放行后，如果某条一线生产事实被正式更正或作废，是在原资料保留修订证据，还是重新生成受控新版本，需要单独冻结。未冻结前不得直接覆盖已生成资料。

### OQ-02 Required Mapping Set

不同工序哪些字段属于“启用前必须映射”的最小集合，需要由业务确认。系统设计不得把所有字段默认为可选，也不得全局写死光固 I 的字段集合。

## Product Blockers

- PB-01：开发前必须冻结不同工序启用重复行组所需的最小必填映射集合。
- PB-02：真实 E2E 前必须准备一个当前工序正式批记录表单，其中包含至少两条用户可确认的结构一致重复记录。
- PB-03：真实 E2E 前必须准备至少两条同工序正式一线生产提交事实，以及一个有权申请放行的生产组长账号；该数据应已满足既有申请放行门禁。
- PB-04：真实 E2E 必须能够验证申请放行前目标记录未生成，申请放行后才按顺序完整生成。
