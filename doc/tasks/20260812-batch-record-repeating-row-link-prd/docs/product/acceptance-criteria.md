# 一线生产重复行组批记录链接验收标准

## Purpose and Scope

本文件用于把“只配置对应关系、申请放行时才生成批记录”的重复行组需求转为可执行的前端、后端、集成和真实 E2E 验收门禁。

## Evidence Reviewed

- 主 PRD。
- 用户流程。
- 当前固定单元格链接与完整报工字段来源能力。
- 用户提供的多次提交顺序写入示例。
- 用户确认数据生成时点为生产组长点击“申请放行”。

## Acceptance Criteria

### AC-01 Entry and Identity

Given 用户从某路线版本的目标工序进入批记录链接页面
When 页面加载
Then 页面显示准确的路线版本、工序、正式批记录表单和表单版本，并提供“单元格链接 / 重复行组”模式。

### AC-02 Formal Source Boundary

Given 当前工序不存在正式逐工序批记录表单绑定
When 用户进入重复行组模式
Then 页面明确阻断，不使用 formBindings、过程检验表单或损耗单补齐。

### AC-03 Template and Repeat Area

Given 表单存在多条结构一致的生产记录
When 用户选择第一条模板记录和全部重复区域
Then 系统显示编号候选记录，且候选数量不固定为 4。

### AC-04 User Confirmation

Given 系统已经识别候选记录
When 用户尚未明确确认候选数量、边界和顺序
Then 保存按钮不能把识别结果直接启用。

### AC-05 Candidate Repair

Given 系统存在漏识别或误识别记录
When 用户增删候选记录或调整顺序
Then 预览立即反映用户确认后的最终记录集合。

### AC-06 Template Projection

Given 用户只在模板记录中映射了当前工序字段
When 系统生成预览
Then 每条后续候选记录都显示对应投影位置，且目标结构一致。

### AC-07 Full Field Coverage

Given 当前工序一线生产 UI 存在设备、参数、checkbox、数量和人员时间字段
When 用户配置模板记录
Then 这些正式字段以及申请放行生产组长均可选择并链接，不退回只有数量字段；本期不配置或生成复核时间字段。

### AC-08 Configuration Does Not Generate Data

Given 用户完成并启用重复行组配置
When 保存成功或一线员工完成一次正式生产提交
Then 系统只保存配置或生产事实，不创建批记录资料、不写目标单元格、不预占任何候选记录。

### AC-09 Generate Only on Release Application

Given 当前活跃订单已经形成多条正式一线生产提交事实且满足申请放行既有门禁
When 生产组长点击“申请放行”
Then 系统才使用已启用对应关系生成正式批记录资料。

### AC-10 Ordered Source-to-Target Mapping

Given 某工序存在三条按正式顺序排列的生产提交事实和至少三条已确认目标记录
When 生产组长申请放行
Then 第 1、2、3 条来源分别完整写入第 1、2、3 条目标记录，顺序稳定且互不覆盖。

### AC-11 Operator and Reviewer Source

Given 不同一线员工在不同时间完成多条正式提交
When 某生产组长申请放行并生成批记录
Then 每条记录的操作人和操作时间来自对应提交，复核人来自申请放行生产组长；本功能不新增复核时间判断。

### AC-12 Unused Candidate Records

Given 正式提交事实数少于已确认目标记录数
When 生产组长申请放行
Then 只生成前 N 条目标记录，其余目标记录保持未使用。

### AC-13 No Quantity-Mismatch Logic

Given 申请放行既有门禁已经确认生产数据完整
When 生产组长申请放行并使用重复行组对应关系
Then 本功能不重新比较单次或累计生产数量，也不把数量不一致作为本页面配置问题。

### AC-14 Atomicity and Idempotency

Given 同一申请放行发生字段写入失败、重复点击或网络重试
When 系统处理该申请
Then 失败不留下部分资料，重试仍使用同一来源、配置和目标顺序，不产生第二套批记录。

### AC-15 Version Isolation

Given 路线或批记录发布新版本
When 用户配置新版本或历史活跃订单申请放行
Then 新版本不静默启用旧配置，历史订单只使用其锁定版本对应的正式配置。

### AC-16 Target Conflict

Given 重复行目标与现有固定链接或另一重复行组重叠
When 用户保存
Then 保存失败并显示具体冲突目标。

### AC-17 Audit Trace

Given 任一申请放行已生成批记录
When 管理员查看追溯信息
Then 可以看到配置版本、来源提交身份及顺序、目标记录、来源值、目标值、操作人/时间和申请放行生产组长。

### AC-18 No Quantity or Separate Review Logic

Given 申请放行既有门禁已经确认生产数据完整
When 重复行组生成批记录
Then 本功能不再次比较单次或累计生产数量，也不要求生产组长执行申请放行之外的独立复核动作。

## Rejection Criteria

- 任一工序按名称或固定编号硬编码重复记录。
- 所有表单统一假定只有 4 条记录。
- 系统识别候选后未经过用户确认就启用。
- 保存配置或一线生产提交时提前生成批记录或预占目标行。
- 申请放行时按目标单元格是否为空判断来源或目标顺序。
- 同一申请放行重试生成第二套资料或改变映射顺序。
- 在本功能中新增数量不一致判断。
- 使用登录账号代替实际操作人。
- 使用配置负责人代替实际申请放行生产组长。
- 在本功能中新增独立复核步骤或复核时间判断。
- 新表单版本静默复用旧版本目标坐标。
- 用 formBindings、过程检验表单或损耗单代替逐工序正式批记录表单。

## Product Blockers

- 各工序启用重复行组所需的最小必填映射集合未冻结时，不得宣称配置完整性规则已完成。
- 没有包含至少两条结构一致重复记录的正式测试表单时，真实 E2E 阻塞。
- 没有至少两条同工序正式一线生产提交事实、数据已满足既有申请放行门禁和有权申请放行的生产组长账号时，生成链路真实 E2E 阻塞。
- 无法证明申请放行前目标记录未生成、申请放行后才生成时，不得把 API-only 或配置保存结果当作真实验收通过。
