# 生产组长职责修改刷新回退修复

## 任务目标

- 修复生产组长职责在页面提示保存成功后，刷新页面又恢复为旧值的问题。
- 找到正式写入与读取链路不一致的根因；租户隔离缓存只解决正式请求返回前的首帧陈旧值，不得作为正式读取失败时的降级数据源。

## 预期验证

- 定向自动化测试覆盖修改请求与刷新读取结果一致。
- 相关前端或后端回归测试通过。
- 前端真实用户路径中，修改后刷新仍显示新值；若真实运行前置缺失，则按项目规则记录精确 blocker，不以 API 或 mock 冒充 E2E。
- bug regression evidence validator 通过。

## 适用经验门禁

- 前端写入成功与列表刷新失败分层门禁：写请求成功与后续读取必须是可区分的正式状态；不得用本地行更新和成功 toast 冒充持久化成功。
- 前端静态契约隔离门禁：先用本页面专用静态合同锁定写接口、刷新读取和持久化字段，再实施最小修复。
- Strict No-Fallback：正式持久化读取失败必须暴露错误，不得静默回退为旧的硬编码描述并继续显示成功。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是；必须核对保存接口、刷新查询接口与正式数据源的一致性。
- 是否存在临时补丁或绕过：否。
