# 验证报告

## 结论

PASS：目标账套可通过 IntRuoyi 现有的用户名密码 `ValidateUser` 方式建立有效会话。两个感叹号的候选密码成功，一个感叹号的候选密码失败。

## 验证范围

- 复用当前运行配置中的金蝶基础地址，使用用户确认的目标账套、中文用户名和 `lcid`。
- 保持账套、用户名、语言和地址不变，仅对用户指定的两个候选密码执行对照测试。
- 仅调用 `AuthService.ValidateUser.common.kdsvc`，不保存配置、不查询业务数据、不执行 ERP 写入。

## 结果

| 候选密码 | HTTP | LoginResultType | IsSuccessByAPI | Cookie | 结论 |
| --- | ---: | ---: | --- | --- | --- |
| 两个感叹号 | 200 | 1 | true | 有 | 登录成功 |
| 一个感叹号 | 200 | 0 | false | 有 | 用户名或密码错误 |

先前探针未为 MySQL 客户端指定 `utf8mb4`，中文用户名在探针中变成问号；此前失败结果因此无效，不能用于判断候选密码。最终对照验证使用正确 UTF-8 用户名和 URL 编码请求体。

Cookie 不能单独证明登录成功；正式成功条件要求 HTTP 200、金蝶业务登录状态成功并返回会话 Cookie。两个感叹号候选密码满足全部条件。

## 范围边界

- 已证明目标账套能够建立 WebAPI 登录会话。
- 未调用 `ExecuteBillQuery`，因此本报告不证明具体表单或字段的业务查询权限。
- 未使用单点登录链接、第三方签名或替代认证方式。

## 数据与安全

- 未记录或输出密码、Cookie、临时签名、Base64 单点登录参数或完整接口响应。
- 未修改本地配置、数据库、ERP 账套或任何业务数据。
