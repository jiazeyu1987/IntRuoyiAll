## 验证证据

- 复核发现：先前 PowerShell 探针通过未指定字符集的 MySQL 客户端读取配置 JSON，中文用户名在探针中变成问号；因此此前所有“用户名或密码错误”结果只证明错误编码后的用户名无法登录，均不作为候选密码有效性的证据。
- 初始探针直接在配置地址后拼接服务名，返回 HTTP 403；核对当前 Java 客户端后确认正式实现会在基础地址未以 `/K3Cloud` 结尾时自动补齐该路径，因此该初始探针不作为最终结论。
- 修正方式：MySQL 客户端显式使用 `utf8mb4`，请求体由 .NET UTF-8 URL 编码，并以用户确认的中文用户名执行对照验证。
- 两个感叹号候选密码：HTTP 200，`LoginResultType=1`，`IsSuccessByAPI=true`，响应包含会话 Cookie，登录成功。
- 一个感叹号候选密码：HTTP 200，`LoginResultType=0`，`IsSuccessByAPI=false`，响应包含 Cookie，消息为“用户名或密码错误”，登录失败。
- 成功判定严格要求 HTTP 200、`LoginResultType=1` 或 `IsSuccessByAPI=true`，并返回会话 Cookie；只有两个感叹号候选密码满足全部条件。
- 验证脚本首次读取响应 Cookie 时遇到当前 PowerShell 响应头类型不支持 `TryGetValues`；改用同一响应头字典的 `ContainsKey` 读取，不改变认证参数和成功判定条件。
- 未输出或写入密码、Cookie、签名、完整配置或完整响应；未调用任何业务查询/写入接口。
- 收尾清理：`task-closeout-cleanup` preview 与 apply 均通过；保留 `task.md`、`execution-log.md`、`verification-report.md`，无删除项、阻塞项或警告。
- 经验沉淀：在既有 `docs/login-access.md` 金蝶登录门禁中补充中文用户名的 UTF-8/`utf8mb4` 读取与验证要求，未新建长期经验文档。
