# QA 发布规则正式工序匹配真实 E2E 验证

## Milestones

- [ ] 运行本机前后端可用性与 Playwright 前置检查。

- [ ] 触发发布规程目标动作并验证不再出现“清洗”未匹配激活路线工序提示。
- [ ] 写入 verification-report.md 并更新任务状态。

## Expected Verification

- 本机前端 http://127.0.0.1:8081 可访问，后端 http://127.0.0.1:48081/actuator/health 为 UP。
- Playwright 使用真实登录页和 QA 规程配置页面，不用 API-only 替代页面路径。
- 目标产品选择后，页面加载正式工艺路线/工序范围。
- 点击“发布规程”后不再出现“外观的正式工序‘清洗’未匹配激活路线版本中的任何路线工序”提示。
- 记录目标接口响应、目标提示、写请求数量、截图/JSON 证据路径。

## 设计约束检查

- 是否引入 fallback/降级/吞异常：否。
- 是否从根因和长期维护角度解决：是；本任务只验证正式页面路径与正式工序映射，不改用 formBindings、表单槽位或默认匹配。
- 是否存在临时补丁或绕过：否。

## Applicable Experience Gates

- Playwright 登录重定向与目标接口监听门禁：目标接口监听必须先于页面跳转/操作安装，禁止复用旧结果。
- Playwright 目标链路与外部资源异常归因门禁：目标链路错误、非目标异常、console/page error 需要分开记录。
- QA 多工序发布门禁：QA 业务工序、路线工序身份和批记录表单链路必须分离，禁止用 formBindings 或表单槽位替代正式工序。
