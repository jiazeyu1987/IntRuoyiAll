- `docs/frontend-development.md#前端按钮文案与行为一致性门禁`：本任务命中“按钮文案显示新增但点击仍执行刷新”风险，静态合同已同时锁定文案、`data-*` 锚点、点击处理器和正式维护弹窗链路。
- `docs/backend-development.md#MES 一线设备账号权限门禁`：本任务命中“拥有正式权限但仍按岗位/快照绑定拒绝”的同类风险，后端授权必须调用系统标准 `PermissionApi.hasAnyPermissions(userId, permission)`，不得用前端放行或空列表成功掩盖权限链路未命中。

## Expected Verification

- 目标组件不再在工序配置模块头部展示“刷新”按钮。
- 工序配置模块头部展示“新增”按钮。
- 按钮绑定 `openCreateProcessConfigDataDialog`，不得继续绑定 `loadProcessConfigRows`。
- 新增入口必须能选择路线工序和新增类型，且按类型复用损耗原因、设备映射、设备参数标准的正式保存弹窗。
- 若本地 `processConfigRows` 为空，点击“新增”必须先调用正式 `getTeamLeaderProcessConfigList` 加载候选；加载后有正式候选才打开新增弹窗。
- 正式接口返回空候选时，提示当前账号缺少可维护路线工序授权，不得再要求用户手动确认列表是否加载。
- `admin / 芋道源码` 这类拥有 `mes:pro-process-pool-team-leader:maintain` 权限的维护账号，应能从 active 路线版本获取可维护路线工序候选，即使不在每条路线的“工序开始”生产组长快照中。
- 工序开始快照授权的普通生产组长逻辑继续保留，未授权用户不得因本次修复扩大权限。
- 不修改已有 ERP 同步相关脏改动。
