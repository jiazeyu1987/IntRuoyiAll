# E2E Plan

## Purpose and Scope

本计划定义实现后的真实用户路径验证。E2E 必须通过 Playwright 操作真实前端页面，覆盖班组长配置、员工报工提交、参数超限红色提醒、班组长报工管理列表展示和最终只读 API/DB 核验。API 只能用于最终核验或只读辅助检查，不能替代真实页面路径。

## Evidence Reviewed

- `docs\e2e-rules.md`：E2E 必须使用真实前端页面，写入型 E2E 必须使用确认的测试租户、账号和任务自有数据。
- `TeamLeaderWorkbenchPage.vue`：班组长工作台已有 `报工管理`、`损耗管理`、`班组配置` 页签。
- `FrontlineFixedTemplatePanel.vue`：员工生产报工界面已有数量、不良明细、设备和设备参数输入区域。
- `team-leader-workbench-real-flow.e2e.js`、`p0-production-execution-loop-real.e2e.js`：已有班组长与生产闭环真实路径脚本可作为相邻参考。
- `MesProFrontlineFeedbackRawLimitBypassTest`：后端已允许超限值进入正式提交链路，E2E 重点验证页面红色提示和列表还原。

## User Paths

### Path: 班组长配置当前工序损耗、设备和参数

Given 生产组长登录测试租户。  
When 进入 `生产组长工作台 > 损耗管理`，为工序 A 配置 `密封件划伤`、`装配不到位`。  
And 进入 `班组配置`，绑定工序 A 的设备 `PT-A-03`，配置 `压力` 下限 `20`、上限 `40`、单位 `MPa`，配置 `时间` 下限 `30`、上限 `60`、单位 `秒`。  
Then 页面保存成功，并且刷新后仍能看到配置。

### Path: 员工提交超限参数但允许报工

Given 员工使用设备账号进入生产报工界面并选择工序 A。  
When 员工填写完成数量 `115`。  
And 填写 `密封件划伤=3`、`装配不到位=2`。  
And 选择设备 `PT-A-03`，填写 `压力=50`、`时间=45`。  
Then `压力=50` 在填写界面标红。  
When 员工点击提交并完成签名。  
Then 提交成功，页面显示成功反馈，不因压力超上限被阻断。

### Path: 班组长报工管理列表展示完整提交参数

Given 上一步报工已成功进入班组长报工管理。  
When 生产组长打开 `报工管理` 页签并按提交日期筛选。  
Then 表格不显示 `生产工单`、`PQC`、`提交内容` 三列。  
And 表格显示 `完成数量=115`、`损耗数量=5`。  
And `损耗明细` 显示 `密封件划伤 3件` 与 `装配不到位 2件`。  
And `选用设备` 显示 `PT-A-03`。  
And `设备参数` 显示 `压力 50 MPa` 和 `时间 45 秒`。  
And `压力 50` 在表格或详情中显示为红色异常值。

### Path: 切换工序后配置不串用

Given 工序 B 配置了不同设备或不同参数上下限。  
When 员工切换到工序 B。  
Then 页面显示工序 B 的损耗原因、设备和设备参数。  
And 工序 A 的仅属配置不会出现在工序 B。  
When 两个工序存在同名损耗原因或同名设备。  
Then 提交和列表展示仍按当前工序配置 ID 和快照还原。

## Browser or Client Steps

- 打开本机前端 `http://127.0.0.1:8081` 或项目规则确认后的等价 int_main 入口。
- 使用确认的生产组长账号登录测试租户，不记录密码或 token。
- 进入生产组长工作台，使用可见页签文本和稳定 `data-*` marker 定位 `损耗管理`、`班组配置`、`报工管理`。
- 配置损耗原因、工序设备绑定和设备参数上下限，保存后刷新页面复核。
- 使用员工设备账号登录或通过正式入口切换到员工报工界面。
- 使用可见控件填写完成数量、损耗原因数量、设备和参数；断言超限值所在输入框或数值节点具备红色异常类。
- 提交时捕获目标写请求，确认请求包含 `lossDetails[]`、`selectedDevice`、`deviceParameterReadings[]`。
- 回到生产组长报工管理，按日期筛选任务自有记录，断言列头、单元格文本、异常颜色和详情内容。
- 若 Element Plus 表格有重复 header/body DOM，行定位必须限定可见 body 行并用任务自有唯一标识定位。

## API Verification

- 最终只读调用 `/mes/pro/process-pool/team-leader/submission/page`，确认返回结构化字段：完成数量、损耗数量、损耗明细、设备、设备参数和异常状态。
- 最终只读调用提交详情接口，确认原始 payload 与列表展示一致。
- 最终只读核验生产报工、记录本事件和工序池事件均创建成功，且没有因为参数超限产生拒绝状态。
- 最终只读核验损耗数量等于损耗明细合计。
- API 核验必须在真实页面提交成功后执行，不能作为创建数据或替代页面提交的路径。

## Console and Log Checks

- Playwright 必须记录 `pageErrors=[]`。
- 目标业务接口不得出现 HTTP 非 2xx 或业务码失败。
- 外部图片、头像或非当前页签请求异常必须按目标链路归因规则单独记录，不得掩盖目标写接口失败。
- 后端日志若出现配置缺失、权限缺失、签名失败或校验异常，E2E 必须判定失败或前置 blocker。

## Test Blockers

- 本地前端或后端端口未启动、端口归属不符合 int_main 或合法 worktree slot 时，真实 E2E 阻塞。
- 测试租户缺少生产组长账号、员工设备账号、签名凭证、活跃生产订单或当前工序配置时，真实 E2E 阻塞。
- 页面缺少真实入口或菜单权限时，先记录入口 blocker，不能用 API-only 创建报工。
- 若新增 E2E 脚本或命令入口缺失，必须先补脚本入口合同并通过，再记录业务 RED。
