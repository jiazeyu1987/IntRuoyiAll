# 批次执行历史追溯详情系统异常修复

## 目标

修复历史追溯详情读取“批记录上市放行”正式审计事件时因历史事件元数据遗漏 `releaseTransactionId` 而抛出 `ACTIVE_ORDER_MARKET_RELEASE_TRANSACTION_ID_MISSING`、最终被页面显示为“系统异常”的问题。新审计事件记录正式放行事务 ID；详情按审计事件持久化的批次执行 ID 读取唯一正式放行事务，并校验元数据显式事务 ID（若存在）与正式事务一致，以同时支持历史事件和防止关联错配。

## 设计约束检查

- 放行事务与批次执行之间由数据库唯一约束正式关联；详情只允许按审计行的 `batchExecutionId` 查询该唯一事务，不根据签名或时间推断。
- 新审计事件必须记录放行流程传入的正式 `releaseTransactionId`；如果事件同时提供事务 ID 与批次关联记录不一致，详情必须失败。
- 不增加 fallback、异常吞噬、兼容分支、数据库写入或历史数据伪造。
- 只提交本任务拥有且已审核的文件；不提交其它工作区脏改动。
- 不执行远端发布；本地 `int_main` 重启按本机 runtime 归属门禁单独确认。

## 里程碑

1. `completed`：记录复现行为与根因，并增加审计写入、历史详情关联及错配拒绝的失败回归测试。
2. `completed`：写入正式事务 ID，通过批次执行唯一关系解析正式事务，并通过 7 项定向测试。
3. `completed`：完成定向测试重跑、差异检查、证据 validator 与验证报告。
4. `in_progress`：在用户授权后完成本任务提交、推送及本地运行态检查。

## 预期验证

- 新增/扩展的回归测试在修复前因 metadata 中 `releaseTransactionId` 缺失而失败（RED）。
- 相同测试在修复后通过（GREEN）。
- 批次执行详情服务的正式放行事务签名关联测试通过。
- `git diff --check` 通过，任务证据结构检查通过。
