# 压力泵生产组长切换范围重构

## Task Goal

按用户确认的新口径重构生产填写切换逻辑：菜单权限只控制批次执行页签可见性；压力泵生产填写中的工序切换和员工切换，不再由额外全局菜单权限、岗位或工作站绑定决定，而由工艺路线“工序开始”卡片中的“生产组长”配置决定。生产组长可绑定账号或角色；命中配置的账号进入生产填写界面后，只能切换其负责产线范围内的工序和对应员工。一个组长可负责多个产线，一个产线可配置多个组长。

## BDD

- BDD: 菜单权限只控制页签可见 -> Given 用户拥有批次执行页签菜单权限 When 进入批次执行/生产填写页面 Then 页面可见性由现有菜单权限决定，不要求额外压力泵全工序切换菜单权限。
- BDD: 生产组长按工序开始配置授权切换 -> Given 工艺路线的工序开始卡片配置了生产组长账号或角色 When 命中配置的账号进入生产填写界面 Then 可切换其负责产线下的工序和员工。
- BDD: 未配置生产组长不扩大授权 -> Given 登录账号未命中当前路线工序开始生产组长配置 When 进入生产填写界面 Then 不因菜单权限、岗位或工作站绑定获得压力泵跨工序/跨员工切换能力。
- BDD: 多组长多产线可共存 -> Given 一个组长负责多个产线且一个产线有多个组长 When 不同组长登录生产填写界面 Then 各自只能看到并切换配置范围内的工序和员工。

## Design Constraint Check

- `是否引入 fallback/降级/吞异常`：否；未命中生产组长配置时保留原有普通设备账号绑定链路，不把额外菜单权限、岗位或工作站绑定作为压力泵组长授权兜底。
- `是否从根因和长期维护角度解决`：是；切换授权收敛到工艺路线“工序开始”业务配置，菜单权限仅保留页面可见职责。
- `是否存在临时补丁或绕过`：否；不硬编码账号、角色、岗位、工作站或压力泵路线名称特例。
