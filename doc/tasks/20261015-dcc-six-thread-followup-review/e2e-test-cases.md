# DCC 业务 E2E 用例设计

## 范围与执行边界

- 来源：本次聊天已提供的上传、审批、生效、下发和浏览需求。共24个业务场景；异常值、账号和文件格式采用参数化子用例，执行时分别记录结果，不把某一子用例通过当作整组通过。
- 当前仅设计，未执行E2E，以下均为预期结果，不表示系统已经通过。
- 最新第2项尾部及第6、8项原文未完整提供；作废关联的保留规则、盖章细节及未收到的重提规则不补造验收结论。旧文档中上传时预填延迟日期的规则不适用。
- 实际执行须用Playwright操作真实前端。数据准备、配置、上传、指派、签名、审批、培训记录、下发签收均走页面；不直接调用fetch/API，不用API或DB替代动作及页面业务断言，不用mock模拟通过。
- 每个用例留存任务自有数据编号、参与账号标签、版本/申请、关键页面断言、实际终态及trace。测试数据不得覆盖共享业务基线；不在文档中保存密码、token。

## 数据与角色

- 同一已确认测试租户内准备项目P1/P2；另准备无权访问P2的账号，分别验证当前项目搜索和授权范围搜索。
- 项目各有三个默认属性及文件夹；准备已维护类型T1/T2、其他类型，各自配置可区分的矩阵。缺人员的负例使用任务自有配置。
- 作者U、直接主管S、两个会签部门负责人L1/L2、各自部门会签人C1/C2、批准人A、文控D、调整后的负责人O和下发部门人员R1/R2/R3。使用真实角色账号；不得只用管理员代替全部角色证明权限成立。
- 源文件、至少两个普通附件、培训记录单内容各不相同；准备能在页面辨认正文内容差异的历史受控版、当前版和草稿。

## 上传、切换与保存（01—10）

|编号|Given 前提|When 页面操作|Then 通过标准|
|---|---|---|---|
|E2E-01 默认值及编制人|U已登录，P1属性、组织关系及T1矩阵已维护|进入上传，选P1、文件夹及T1；修改本次三个属性|默认值正确带出；编制人固定U，部门及主管来自组织；本次属性可改；矩阵与默认下发部门正确；培训默认未选。|
|E2E-02 提交前完整性拦截|有一份可正常提交的任务自有申请|分别清空项目、文件夹、类型、名称、编号、初始版本、生效方式、规定必填属性；分别使用缺主管/部门负责人/批准人的自有配置；会签全部删除|每种变体均具体提示并阻止提交，无审批待办；会签为空明确提示“请至少选择一个会签部门”，恢复有效选择后可继续。延迟模式在上传阶段不要求具体日期。|
|E2E-03 源件与多附件|分别准备上传及升版申请、两个不同附件|上传源件与多个附件；分别在上传中、失败及页面可触达的保存失败状态尝试提交，再恢复成功重试|源件和每个附件全部上传、保存成功才可提交；失败明确定位；确认框清单完整，提交后对应申请和版本可查看全部附件，不串版。失败状态须由真实页面流程观察，不伪造成功。|
|E2E-04 会签与下发名单独立|T1默认两个会签部门|增删会签部门，再单独增删下发部门；在新申请中重新选T1|会签部门均可删除；至少保留一个才可提交；两名单分别保存、互不串改；本次调整不修改公共矩阵，新申请仍取原默认配置。|
|E2E-05 “其他”自定义矩阵|P1可选“其他”|配置本次会签部门、批准人、文控职责，保存草稿重开并提交；另开新申请检查|本次自定义准确保存并用于本次流程；主管仍取组织；不新增或改写公共矩阵；另一申请不继承本次私有配置。|
|E2E-06 项目内关联|P1、P2均有可区分的文件版本|在P1关联窗口选择文件；切换至P2后核对关联并重新选择；对旧页面保留的原项目选择尝试提交|P1关联窗口仅能选择P1文件；项目切换后旧关联不能直接带入；任何残留跨项目选择均被拦截；合法关联保留所选版本。|
|E2E-07 二次确认与取消|申请字段、附件、关联和名单均已填写|点击确认，逐项核对汇总；取消后再打开；最后再次确认提交|汇总包含名称、编号、版本、项目、文件夹、类型、编制人/主管、生效方式、三个实际属性、附件、关联、会签、下发、批准人和培训；明确接收人为所选下发部门全部人员。取消保留输入且无审批任务；最终确认后进入主管待办。|
|E2E-08 项目/类型切换保护|已经手改属性、会签、下发及关联|分别尝试切项目、切已维护类型、切“其他”；各执行取消和确认|有相关手改时先提示；取消保留原项目/类型及全部选择；确认切项目重载属性/文件夹/适用配置并重新选关联；切已维护类型重载矩阵/默认下发；“其他”由作者配置并核对下发。|
|E2E-09 草稿恢复|已保存实际属性、名单、关联、生效模式及附件；随后通过配置页面修改项目默认值|关闭后重新进入原草稿|恢复原草稿实际保存值及生效方式，不被新默认属性覆盖；附件及关联仍对应原申请；延迟日期仍在后续确认任务填写。|
|E2E-10 矩阵变化与重提规则|分别准备已维护类型新草稿、“其他”草稿及已驳回申请|通过配置页调整公共矩阵后提交各申请；驳回申请另测主动换类型与人员不可用|新申请展示公共矩阵变化并重新确认；“其他”沿用本次私有矩阵；驳回重提沿用原保存矩阵且核对人员可用性；仅主动变更类型时重新匹配，不能自动用新矩阵覆盖原申请。|

## 审批、生效与下发（11—17）

|编号|Given 前提|When 页面操作|Then 通过标准|
|---|---|---|---|
|E2E-11 主管先审并签名|U已最终提交|U、S及会签人分别查看待办；S分别取消签名、完成签名并通过|先由S审核；未签名不能推进；S通过并签名后才进入会签，页面记录正确签名人、时间及申请。|
|E2E-12 部门指派与全部会签|本次会签包括保留的默认部门和增补部门|L1/L2分别签名并指派本部门C1/C2；分别由部分人员及全部人员完成签名会签|系统不自动选定具体会签人；各负责人完成本部门指派并签名；全部选入会签任务都须完成且通过，部分通过或任一未通过时不能进入批准。|
|E2E-13 批准时确认负责人|申请进入A批准，默认申请人为U|A打开批准弹框，分别保留U和调整为O，完成签名批准；U与O查看培训记录单上传入口|弹框负责人默认U且可调整；不另增批准后负责人选择节点；负责人为本次确认者；即使改为O，培训记录单仍由原上传人U负责上传，不能把职责自动转给O。|
|E2E-14 文控后立即生效|本次选择立即生效，已完成前置审批|D取消签名后重试，最后签名审核通过；回到文件详情及日常目录查看|未完成文控审核及签名不生效；完成后记录真实实际生效时间，文件按已收到的规则进入相应受控/生效状态；不得用预填日期代替实际时间。盖章细节待第8项原文补充。|
|E2E-15 延迟生效，无培训|上传时选择延迟，未勾培训|D审核通过；U打开延迟生效确认任务，分别不填日期、不签名、选择早于确认时刻日期，再选未来有效日期并签名；到期后刷新页面|上传不要求日期；文控后直接给原作者U任务；任务提示“文件生效时间由编制人根据文件输入、输出及来源之间的衔接关系确定。”；缺日期、缺签名或早于实际确认时间均不能完成及后续受控。成功时受控时间取本节点签名时间；到选定时间前不作为已生效文件开放正文，到期按实际生效状态验收。|
|E2E-16 延迟生效，需培训|上传选择延迟并勾培训，A已把负责人改为O|D通过；按真实培训入口完成培训及必要记录，由U上传记录单；再由U执行延迟确认|培训完成前不提前派发可完成的延迟确认；完成后任务给原作者U，日期及签名规则同15；记录单保存申请、版本、上传人U及时间，负责人变更不改变上传职责。|
|E2E-17 全员下发与逐人签收|下发部门包含R1/R2/R3；每人仅归属一个部门，不构造同人多部门场景（2026-10-20用户确认）|分别在未受控、受控未生效和受控已生效时查看收件人页面；生效后各人登录签收|仅受控且生效后下发；所选部门全部人员均能收到，非所选范围不应因默认会签混入；每个接收人分别电子签名，一人签收不能代替其他人；页面可追踪未签收人员。|

## 升版、浏览与版本隔离（18—24）

|编号|Given 前提|When 页面操作|Then 通过标准|
|---|---|---|---|
|E2E-18 升版申请与历史附件|存在受控版及可选择的小版本草稿，旧版有附件和培训记录|从真实入口选择草稿发起升版、填写实际变更类型及说明、添加多个附件并完成相应流程；回看新旧详情|升版详情正确展示来源受控版、所选草稿记录、实际变更类型和说明；新旧附件、培训记录及申请信息各自归属原版本；草稿在用户页面不暴露小版本号。|
|E2E-19 目录与搜索|P1/P2有可区分且权限不同的文件|按项目/文件夹浏览；按名称、编号搜索当前项目及授权项目；分别打开结果|列表和搜索显示正确来源项目、文件夹及版本状态；仅展示可访问范围；浏览按钮打开选中版本；无权限项目不能通过搜索结果泄露正文。|
|E2E-20 日常入口与正文权限|同链存在已生效版、待生效版、草稿，账号有不同阅读权限|从目录、搜索、详情入口及浏览器地址访问正文；已打开页面再通过真实页面撤销权限并操作|每个入口均校验阅读权限；日常入口不开放待生效和草稿正文；拒绝时不显示正文；已撤权后的重新读取/后续操作不继续取得正文，历史缓存不能冒充新的授权。|
|E2E-21 审批/历史固定正文|任务及历史记录对应旧版，当前正式版内容已不同|分别从审批任务、审批历史及版本历史打开正文并切换查看|显示对应任务/记录的固定正文及明确状态，不跳到当前版；检入小版本仅显示“草稿”，不显示小版本号；各入口仍按相应任务/历史权限校验。|
|E2E-22 详情与关联引用隔离|不同版本有不同属性、时间、关联、引用及检出记录；同一项目有多个引用|选择每个版本查看详情分区；打开关联的固定版本；查看被引用项目明细|名称/编号/状态/属性/备注/编制人/项目/文件夹/类型/检出人及时间与所选版本一致；生效方式、作者所选日期、实际生效及受控时间分开显示；关联/引用不自动追新版，按项目去重计数且明细准确；提交时、后补及整改记录可追溯，不混版。|
|E2E-23 附件独立权限及历史培训记录|分别准备可查看不可下载、可查看可下载、均无权限账号；不同版本有不同附件|逐个打开/下载附件及培训记录；切历史版复查；在下载确认框取消，另测连续点击及离开页面|查看与下载分别校验；拒绝时不能取得文件；每版记录单及上传人/时间正确；取消不下载，旧页面迟到结果不落到新版本；重复点击不能绕过确认或权限。|
|E2E-24 正文工具、水印与浏览时间|准备PDF、Office、图片、文本及实际支持的其他格式，内容有可辨识标记|打开每种格式，放大/缩小/旋转/翻页并按适用规则搜索；观察水印及浏览时间；失焦、切版、关闭后重开|真实内容可见而非只有加载容器；PDF须完成非空画布渲染；各格式按正式能力逐项记录结果，不能以按钮存在代替实际效果，不能把不支持项直接算通过；阅读只改变画面，重开源件内容不变且不能保存回原件；水印和浏览时间对应当前人/版本。音频、视频仅作为附件，不作为正式受控正文，不纳入本例正文工具、翻页或正文搜索验收（2026-10-20用户确认）；附件的查看、下载权限仍按E2E-23规则执行，不自动宣称已验证音视频附件。|

## 结果记录与优先顺序

- 先跑E2E-01、07、11—17，分别形成立即生效、延迟无培训、延迟需培训三条真实完整主链；再覆盖配置变化、失败拦截、版本和权限。
- 每个参数化子用例分别记录PASS/FAIL/BLOCKED及原因；一个接收人、一种格式或一种入口通过不能代表全员、全格式或全入口通过。
- 生效与下发必须到页面可见终态，不能在提交成功或审批受理时提前记为完整链路PASS。时间等待不改系统时钟，不直接写库推进。
- 第8项补齐前，已明确的时间选择、签名和下发条件可分别验证；盖章及缺失的受控处理细则保持待补充，不宣称完整需求均已验证。
