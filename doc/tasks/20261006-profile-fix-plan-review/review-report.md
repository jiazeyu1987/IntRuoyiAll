## 评审标准

1. F01：只纳入当前用户、当前租户且符合正式批次可见性规则的 TODO 与 OVERDUE；不放宽办理权限或引入 DOING。列表与角标采用相同任务集合。
2. F02：源合同真实，完整结果可达；筛选及隐藏恢复不限于首批数据；分页、排序、身份、计数一致。明确展厅实际页上限 20、数组返回形状与已有消费者保护。
3. F02：核心架构、容量边界和数据变化时的一致性语义明确；完整性无法证明时必须显式失败，不以部分结果代替完整列表。
4. F02：旧请求响应不可覆盖更新后的查询、身份或权限上下文；隐藏/恢复刷新与分页回退有确定行为。
5. F03：缺失、空字符串、空白字符串和有效联系方式分别处理；非空非法输入仍拒绝；修改昵称不误删除已有联系方式，不以保存成功掩盖用户未被接受的清空操作。
6. F04：校验前取得提交锁，请求期间不可重入或改变已提交内容；失败可重试，成功清空三项密码与校验状态，所有结束路径释放锁。
7. 验证计划：每项验收映射到实际执行生产逻辑的行为测试；静态文本断言只作辅助；命令、工作目录、测试归属真实；本轮与后续验证状态分开。
8. 范围：不恢复已撤回设计，不迁移配置，不扩展交接、权限、密码安全和会话策略。
