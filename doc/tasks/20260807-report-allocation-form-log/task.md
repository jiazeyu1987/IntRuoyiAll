# 报工分配按钮与表单日志修改记录迁移

## Task Goal

将生产组长工作台报工行操作中的“修改记录”移出当前列表，改为“分配”按钮；点击“分配”应使用正式后端分配链路，将本次报工分配给当前登录生产组长的活跃订单。报工修改记录改在“表单日志”中以日志形式查看。

## Milestones

- [x] M1：建立 BDD/TDD 合同，覆盖工作台按钮、正式分配链路、表单日志报工修改记录展示。
- [x] M2：调整生产组长工作台前端，移除行内“修改记录”入口，增加“分配”入口并复用正式活跃订单分配接口。
- [x] M3：扩展表单日志前后端接口和页面，展示报工修改日志，不使用工作台内嵌弹窗。
- [x] M4：运行定向前端静态合同、后端合同/服务测试，并记录 RED/GREEN 证据。
- [x] M5：完成验证报告和任务收尾记录。
- [x] M6：追加真实登录态 Playwright 只读验收，确认表单日志页签和分页接口在当前运行态可用。

## Expected Verification

- 前端静态合同：工作台行操作不再包含“修改记录”按钮/弹窗，包含“分配”按钮且绑定正式分配入口。
- 前端静态合同：表单日志页面包含“报工修改日志”入口、列表、详情和正式 API wrapper。
- 后端合同/服务测试：表单日志可按当前登录用户范围分页读取报工修改记录，并查看可读字段差异详情。
- 回归检查：已有生产组长分配 API、复核/分配相邻合同、表单填写日志原有链路仍通过。

## Applicable Experience Gates

- 前端按钮文案与行为一致性门禁：按钮文案、`data-*` 锚点、`@click` 正式动作和旧方法禁用必须同时被静态合同锁定。
- Vue Scoped Slot 静态合同门禁：表单日志页面如使用具名 slot，静态合同必须允许 scoped slot props。
- 业务修订审计身份服务端归属门禁：报工修改日志的身份、范围和签名校验必须来自服务端，不信任前端提交身份。
- 一对多读模型聚合门禁：表单日志页主列表分页必须以修订记录为主对象，字段差异明细批量加载，不直接一对多 JOIN 撑爆分页。
- 前端写入成功与列表刷新失败分层门禁：分配写入成功后与刷新失败分层处理，不把刷新失败误报为分配失败。
