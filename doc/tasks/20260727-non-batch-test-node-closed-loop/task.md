# 非批记录测试项节点闭环改写

## Task Goal

将当前本机测试管理中除 `批记录` 外的现有测试项，改写为类似批记录的“测试节点 + 闭环可重复执行”类型：每个节点都包含业务可读测试方法、测试目标、固定样本或任务自有标识、前置复位、页面操作、页面验证和测后清理/恢复方式。

## Milestones

1. [x] 核对测试管理 schema、当前租户和除 `批记录` 外的现有项目/测试项。
2. [x] 设计非批记录项目的节点闭环测试方法和测试目标。
3. [x] 写入当前租户测试管理数据，仅更新目标项目测试项和检查点。
4. [x] 验证节点数量、方法项数量、目标项数量、闭环关键词和业务可读性。
5. [ ] 更新任务证据、验证报告和收尾状态。

## Expected Verification

- 当前库 `system_codex_test_case`、`system_codex_test_checkpoint` 必需字段存在。
- 除 `批记录` 外的现有项目和测试项先经只读核对，不凭历史记忆改写。
- 写入后目标测试项均为节点化名称或节点化内容，每项包含固定样本/前置复位/页面操作/页面验证/清理恢复闭环。
- 写入后不修改 `批记录` 项目测试项。
- 测试方法和测试目标不包含只能由程序员判断的接口、内部字段、状态码、hash、英文内部状态或代码视角描述。

## 经验门禁

### 测试管理 schema 迁移门禁

- Trigger: 修改或运行 `system_codex_test_case`、测试项分页、测试管理页面相关接口。
- Preflight check: 写入前核对当前数据源存在 `system_codex_test_case.project` 及检查点关联字段。
- Blocker: 当前库缺少项目字段、检查点关联字段或无法确认写入租户范围时必须停止。
- Verification: 记录 schema 核对结果、写入目标、影响行数和写入后复核结果。
- Forbidden action: 禁止用默认 project、吞掉数据库异常、mock 成功或 API-only 空结果替代真实数据核验。
- Evidence: `docs/database-rules.md#测试管理-schema-迁移门禁`。

### 测试管理测试节点闭环门禁

- Trigger: 新增或修改 `系统管理 > 测试管理` 的自然语言测试项，尤其是会新建、修改、删除或作废业务数据的测试节点。
- Preflight check: 每个节点必须说明固定样本或任务自有测试标识、前置复位、页面操作、页面可见验证、清理/恢复方式。
- Blocker: 只创建不清理、只删除不先准备样本、目标只能由程序员判断、或下次执行会被残留数据阻塞时必须停止。
- Verification: 记录节点数量、方法项数量、目标项数量、固定样本/清理/恢复闭环核验和内部词扫描结果。
- Forbidden action: 禁止用 API-only 清理、生产或 admin 基线数据、一次性人工清库或程序员专用字段替代测试节点自身闭环。
- Evidence: `docs/e2e-rules.md#测试管理测试节点闭环门禁`。
