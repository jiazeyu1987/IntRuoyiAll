# 生产组长工作台改造 PRD

## Purpose and Scope

将现有生产组长页签从“后台表格 + ID 手输表单”改造为班组级生产执行工作台。生产组长先维护班组执行配置，再围绕活跃订单完成异常上报、员工报工确认、订单工序数量分配，并在订单工序完成时触发正式批记录回填。

## Evidence Reviewed

- 用户确认：生产组长负责员工、设备、参数、异常、活跃订单和报工确认。
- 用户确认：员工填报页填写好的数据需要在班组长界面看到。
- 用户确认：员工填写的设备、参数、不良原因来自生产组长配置。
- 用户确认：报工数量只能分配给活跃订单。
- 用户确认：订单某工序累计确认分配数量达到订单生产数量后，该订单该工序完成并自动填写该工序绑定的批记录表格。
- 用户澄清：设备状态是“报修”，不是“保修”或保修期管理。
- 用户澄清：报工分配需要支持先进先出 FIFO 自动分配，同时允许生产组长手动分配或调整。
- 当前页面：`IntRuoyiFronted/src/views/mes/pro/processpool/TeamLeaderWorkbenchPage.vue` 已有生产组长页签和提交看板、异常上报、班组维护入口。
- 当前接口：`IntRuoyiFronted/src/api/mes/pro/processpool/teamLeader.ts` 已有提交分页、详情、复核、异常上报、员工绑定、不良原因、设备参数保存接口骨架。

## Product Summary

第一版采用“外壳复用、内容重构”：

- 保留当前路由、权限点、生产组长 / PQC 组长顶层页签和接口模块入口。
- 重构生产组长页签内容为“班组配置中心”和“报工确认工作台”。
- 员工填报页从班组配置读取工序可用员工、设备、参数、不良原因。
- 组长确认报工时，系统可按先进先出 FIFO 自动分配到活跃订单，组长也可手动分配或调整。
- 系统按订单工序累计确认数量判断完成，并回填正式批记录。

## Target Users

- 生产组长：维护班组执行配置、确认报工、使用 FIFO 自动分配或手动分配活跃订单、上报订单异常。
- 生产员工：在员工填报页面选择组长配置允许的工序、设备、参数、不良原因并提交报工。
- PQC 组长：从活跃订单中选择待检订单；本 PRD 仅保留订单来源约束，不展开 PQC 组长完整功能。
- 质量 / 批记录管理员：查看由报工完成触发的正式批记录回填结果。

## First Version Scope

- 活跃订单池：生产组长从生产订单中选择当前活跃订单；异常上报、PQC 订单选择和报工分配只能使用活跃订单。
- 员工维护：生产组长维护本班组员工；临时工可作为班组员工档案新增，不强制关联用户系统。
- 设备维护：生产组长维护班组设备名称、设备编号、状态和工序可用关系。
- 设备参数维护：每个设备维护参数、取值范围、默认值和展示单位；员工填报时使用默认值并校验范围。
- 工序关系维护：维护工序-员工、工序-设备、工序-异常原因关系。
- 异常上报：从活跃订单选择订单，从当前工序允许异常原因选择异常类型并上报。
- 报工确认：展示员工提交的员工、工序、设备、参数、不良原因、完成数量、损耗数量；组长确认时可使用 FIFO 自动分配到一个或多个活跃订单，也可手动分配或调整。
- 订单工序完成：某订单某工序累计确认分配数量达到订单生产数量时，该订单该工序完成。
- 批记录回填：订单工序完成后，按工序设置中绑定的正式批记录表单和字段映射，把报工设备参数等数据写入对应位置。

## Non-Goals

- 不在第一版开发完整 PQC 组长工作台，只保证活跃订单来源口径可复用。
- 不把临时工自动同步为系统登录用户。
- 不设计复杂排产优化算法；第一版自动分配仅按活跃订单 FIFO 队列和剩余数量顺序分配。
- 不使用 `formBindings`、表单槽位、工序开始配置或默认 `MAIN` 槽位替代正式批记录表单。
- 不用 mock、默认成功、空批记录、前端固定文案或前端静态数据掩盖后端数据链路缺失。

## Functional Requirements

### FR-01 活跃订单池

- 生产组长可查看可加入活跃订单的生产订单。
- 生产组长可将订单加入或移出活跃订单池。
- 活跃订单应展示订单编号、产品、目标数量、当前已分配数量、涉及工序状态。
- 异常上报和报工分配的订单选择器只显示活跃订单。

### FR-02 班组员工维护

- 生产组长可新增班组员工档案，字段至少包括员工姓名、员工编号、员工类型、启用状态。
- 临时工可直接新增为班组员工档案，不要求系统用户 ID。
- 生产组长可禁用班组员工；禁用后员工不可作为新报工填报人或新工序绑定对象。

### FR-03 班组设备维护

- 生产组长可新增设备，字段至少包括设备名称、设备编号、设备状态。
- 设备状态至少支持启用、报修、禁用；恢复后可重新用于工序。
- 禁用或报修设备不可作为员工新报工可选设备。

### FR-04 设备参数维护

- 生产组长可为设备维护参数编码、参数名称、单位、下限、上限、默认值。
- 默认值必须在上下限范围内。
- 员工选择设备后，页面按设备参数默认值带出，并校验提交值在范围内。

### FR-05 工序关系维护

- 生产组长可维护工序-员工、工序-设备、工序-异常原因关系。
- 员工填报页只能展示当前工序允许员工、设备和异常原因。
- 若工序缺少必需关系配置，员工端应明确提示缺少正式配置，不能使用默认列表。

### FR-06 员工填报提交展示

- 班组长可看到员工填报的提交时间、员工、工序、设备、设备参数、完成数量、损耗数量、不良原因、关联上下文。
- 原始 payload 可以保留为审计辅助，但页面必须优先展示结构化字段。

### FR-07 报工确认与订单分配

- 生产组长确认员工报工时，必须把确认数量分配给一个或多个活跃订单。
- 系统必须提供 FIFO 自动分配能力：按活跃订单进入队列的先后顺序，将本次确认数量优先分配给最早进入且当前工序仍有剩余数量的活跃订单。
- FIFO 自动分配结果必须在提交前展示给生产组长，生产组长可手动调整订单和数量。
- 手动分配和手动调整仍必须满足活跃订单、当前工序、剩余数量和总数校验。
- 分配总数量必须等于本次确认报工数量。
- 单个订单某工序累计分配数量不得超过该订单该工序剩余可分配数量，除非后续业务明确允许超产并定义状态。
- 确认后的报工分配应有审计记录，包含确认人、确认时间、源提交、工序、订单、数量。

### FR-08 订单异常上报

- 生产组长只能从活跃订单选择异常订单。
- 异常原因只能来自当前工序允许异常原因。
- 异常上报必须保留订单、工序、原因、说明、来源提交记录。

### FR-09 订单工序完成

- 系统按订单 + 工序累计确认分配数量判断完成。
- 当累计确认分配数量达到订单生产数量，该订单该工序状态变为完成。
- 重复提交、重复确认或并发确认不得重复完成或重复回填。

### FR-10 正式批记录回填

- 系统只读取工序设置中该工序绑定的正式批记录表单。
- 报工设备参数、不良原因、数量等字段按正式映射写入批记录对应位置。
- 缺少正式批记录绑定、缺少字段映射、映射目标不可写时必须阻塞并提示原因。

## Business Rules

- 活跃订单是异常上报、PQC 选择订单、报工分配的唯一订单来源。
- 员工端设备、参数、不良原因必须来自生产组长维护的配置。
- 设备参数默认值必须处于参数范围内。
- 默认报工分配算法为 FIFO：按活跃订单进入队列时间升序分配，先补足最早活跃订单当前工序剩余数量，再进入下一个活跃订单。
- 若 FIFO 自动分配后的结果不符合现场实际，生产组长可在确认前手动调整；系统必须重新校验手动结果。
- FIFO 自动分配和手动分配都不得分配给非活跃订单。
- 报工确认分配总数必须等于确认数量。
- 订单工序完成以组长确认后的累计分配数量为准，不以员工单次提交为准。
- 正式批记录来源只允许使用工序设置中的逐工序批记录表单绑定。
- 接口或快照缺少正式逐工序批记录绑定时必须阻塞，禁止使用 `formBindings`、默认 `MAIN`、工序开始配置或其它特殊表单替代。

## States and Transitions

- 员工状态：启用 -> 禁用；禁用员工不可用于新填报和新绑定。
- 设备状态：启用 -> 报修 -> 恢复启用；启用 -> 禁用；禁用或报修不可用于新填报。
- 活跃订单状态：未加入 -> 活跃 -> 移出 / 完成后不可分配。
- 员工提交状态：已提交 -> 待确认 -> FIFO 预分配 -> 已确认 / 手动调整后已确认 / 退回 / 标记异常。
- 订单工序状态：未开始 -> 进行中 -> 已完成；达到累计数量后转已完成。
- 批记录回填状态：待回填 -> 回填成功 / 回填阻塞；阻塞必须暴露缺失前置。

## Edge Cases

- 临时工没有系统用户 ID：可作为班组员工档案参与工序绑定和报工展示。
- 员工提交数量大于活跃订单剩余数量：组长不能确认超额分配，除非后续明确超产规则。
- 活跃订单剩余数量不足以承接本次报工：FIFO 自动分配应提示剩余不足并阻塞确认，生产组长不能用手动分配绕过。
- FIFO 自动分配结果为多订单拆分：页面必须展示每个订单分配数量，组长确认后逐条生成分配记录。
- FIFO 队列顺序相同：按活跃订单加入时间后，再按生产订单 ID 或订单编号稳定排序，避免同一数据多次自动分配结果不一致。
- 多名员工同时分配同一订单工序：后端必须按事务校验剩余数量，避免超分配。
- 设备参数默认值超出上下限：保存配置时阻塞。
- 工序无设备场景：员工端使用无设备模板，但仍必须从工序配置读取员工和异常原因。
- 工序缺正式批记录绑定：订单工序可以记录达到数量，但批记录回填必须阻塞并提示缺少正式绑定。
- 字段映射缺失：不得把参数写入任意默认单元格。

## Acceptance Criteria

- AC-01：生产组长可维护活跃订单，异常上报和报工分配只显示活跃订单。
- AC-02：生产组长可维护员工、设备、设备参数、工序-员工、工序-设备、工序-异常关系。
- AC-03：员工填报页设备、参数、不良原因由组长配置驱动，不再依赖固定静态列表。
- AC-04：班组长可看到员工提交的结构化设备参数、不良原因和数量数据。
- AC-05：班组长确认报工时可一键 FIFO 自动分配到活跃订单，也可手动分配或调整；分配总数必须等于确认数量。
- AC-06：累计确认分配数量达到订单生产数量后，订单该工序完成。
- AC-07：工序完成后按正式批记录表单绑定与字段映射回填数据。
- AC-08：缺少正式批记录绑定或字段映射时阻塞并显示明确原因。

## Open Questions

- FIFO 队列的第一排序键已按“活跃订单加入时间”设计；如果现场希望按计划开工时间、订单创建时间或交期排序，需要在实施前替换排序键。
- 同一订单某工序是否允许超产、返工或冲销；当前第一版按不得超额分配设计。
- 批记录字段映射由哪个角色维护，以及映射失败后的补救流程是否需要独立审批。

## Product Blockers

- 缺少正式批记录表单逐工序绑定来源会阻塞批记录回填能力。
- 缺少可写测试租户、生产组长账号、员工账号、可用生产订单、正式批记录模板和字段映射会阻塞真实 E2E。
- 当前页面若仅保留手输 ID 表单，无法满足活跃订单和配置驱动的用户体验要求。
